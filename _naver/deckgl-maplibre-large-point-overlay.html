deck.gl과 MapLibre GL JS 통합 — 대용량 포인트 데이터 오버레이 렌더링

GIS

한 줄 요약 — 수백만 건의 포인트는 마커나 GeoJSON으로는 버벅입니다. MapboxOverlay 인터리브 모드로 deck.gl을 통합해 GPU 인스턴싱으로 렌더링하는 방법을 정리했습니다.

 

왜 지금 deck.gl 통합을 알아야 하는가

수천 건은 MapLibre 기본 마커나 GeoJSON circle 레이어로 충분하지만, 수십만~수백만 건 규모가 되면 DOM·지오메트리 처리 비용이 기하급수적으로 늘어납니다. deck.gl은 WebGL 인스턴싱으로 수백만 포인트를 한 번의 draw call로 렌더링하도록 설계됐습니다.

 

 

별도 캔버스 오버레이의 함정과 MapboxOverlay 인터리브 모드

deck.gl 캔버스를 지도 위에 얹는 방식은 두 캔버스가 독립적인 렌더 루프에서 그려져 확대·드래그 시 미세한 어긋남이 생깁니다. MapboxOverlay를 인터리브 모드로 쓰면 deck.gl 레이어가 같은 WebGL 컨텍스트와 프레임 안에서 다른 지도 레이어와 순서대로 합성돼 이 문제가 사라집니다.

 

GPU 인스턴싱이 수백만 포인트를 감당하는 원리

deck.gl은 포인트를 CPU에서 하나씩 그리지 않고, 속성을 GPU 버퍼에 통째로 업로드한 뒤 인스턴싱으로 동일 도형을 반복해 그리는 작업을 GPU에 위임합니다. CPU는 카메라 변환 행렬 정도만 갱신하면 되므로 포인트 개수가 늘어도 병목이 크게 늘지 않습니다.

방식 감당 규모 특징
MapLibre 마커(DOM) 수백~수천 개 개수에 취약
GeoJSON 레이어 수만 개 벡터 스타일링 통합 쉬움
deck.gl (GPU 인스턴싱) 수십만~수백만 개 대규모에 강함

 

예제 — MapboxOverlay로 deck.gl ScatterplotLayer 인터리브
const overlay = new MapboxOverlay({
  interleaved: true,
  layers: [
    new ScatterplotLayer({
      id: 'sensor-points',
      data: sensorPoints,
      getPosition: (d) => [d.longitude, d.latitude],
      getRadius: 30,
      getFillColor: (d) => (d.value > 80 ? [220, 50, 50] : [50, 130, 220]),
      radiusMinPixels: 2,
    }),
  ],
});

map.on('load', () => map.addControl(overlay));

 

실무 포인트

interleaved: true 설정을 잊지 마세요. 기본값(오버레이 모드)으로 두면 별도 캔버스 방식과 동일하게 동작해 정확한 합성 이점을 놓치게 됩니다.

데이터 갱신 빈도가 높다면 updateTriggers를 명확히 지정하세요. 데이터 배열 참조가 바뀌지 않으면 GPU 버퍼를 재생성하지 않으므로 명시가 필요합니다.

주의 — GPU 인스턴싱은 렌더링 병목을 해결하지만, 수백만 건 원본 데이터를 매번 네트워크로 통째로 내려받는 것 자체는 별도 최적화 대상입니다. 서버 단 다운샘플링이나 타일링을 함께 고려하세요.
