Redis가 뭔가요 — 언제 캐시로 쓰고 언제 DB로 쓸까

2026. 9. 2. · 데이터베이스

한 줄 요약 — 캐시 용도는 TTL로 관리하고 유실돼도 복구 가능하지만, DB 대체 용도로 쓸 때는 영속성과 복제 설정이 필수입니다.

 

Redis는 캐시인가 DB인가

Redis는 인메모리 저장소지만 캐시로도, 메인 DB처럼도 쓰입니다. 메모리 기반이라 빠르면서도 디스크 백업(영속성) 기능을 함께 제공하기 때문입니다. 다만 "가능하다"와 "안전하다"는 다른 문제입니다.

 

캐시로 쓸 때 vs DB로 쓸 때
관점 캐시 주 DB
데이터 유실 허용(원본에서 재생성) 허용 안 됨
데이터 원본 다른 DB가 원본 Redis 자체가 원본

 

예제 — 캐시로 쓰는 전형적인 패턴
def get_product(product_id, redis_client, db):
    cached = redis_client.get(f"product:{product_id}")
    if cached:
        return json.loads(cached)

    product = db.query("SELECT * FROM products WHERE id = %s", product_id)
    redis_client.setex(f"product:{product_id}", 300, json.dumps(product))
    return product

setex로 TTL을 걸면 메모리가 무한히 쌓이지 않고, 원본 데이터가 바뀌어도 일정 시간 후 자동 갱신됩니다.

 

Redis가 DB처럼 쓰이는 대표 사례

세션 저장소, 실시간 랭킹(Sorted Set), 분산 락, Pub/Sub 메시지 브로커 등입니다. 이 경우 Redis 자체가 유일한 데이터 소스라 영속성 설정과 복제가 필수입니다.

 

실무 포인트

캐시 용도라면 영속성 설정에 크게 신경 쓰지 않아도 됩니다. 서버 재시작으로 캐시가 날아가도 원본 DB에서 다시 채워지기 때문입니다.

주의 — 메모리가 가득 차면 maxmemory-policy에 따라 오래된 키를 자동으로 지웁니다. 중요한 데이터라면 이 정책이 예상치 못한 유실로 이어질 수 있습니다.
