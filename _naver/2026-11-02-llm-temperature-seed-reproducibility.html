한 줄 요약 — LLM은 확률적 샘플링으로 텍스트를 생성하기 때문에 같은 입력에도 결과가 달라질 수 있습니다. temperature와 seed로 재현 가능한 범위까지 좁힐 수 있습니다.

 

왜 같은 입력인데 매번 다른 답이 나오나

LLM은 다음 단어를 확률 분포에서 샘플링하는 방식으로 텍스트를 생성합니다. 이 비결정성은 프로토타입 단계에서는 문제없지만, 테스트 자동화를 시작하면 "어제는 통과했던 테스트가 오늘은 실패한다"는 문제로 이어집니다.

 

 

temperature와 seed

temperature는 확률 분포의 뾰족한 정도를 조절합니다. 값이 낮을수록 항상 가장 확률 높은 토큰을 선택하는 쪽으로 수렴합니다. 다만 temperature=0을 설정해도 100% 완전히 동일한 출력이 보장되지는 않는다는 점을 알아야 합니다.

response = client.chat.completions.create(
    model="gpt-4o",
    temperature=0.7,
    seed=42,
    messages=[{"role": "user", "content": "..."}]
)

seed는 내부 난수 생성기의 시작값을 고정해, 같은 조건이면 결과가 훨씬 안정적으로 재현되게 합니다. temperature를 반드시 0으로 낮추지 않아도 어느 정도 창의성을 유지하면서 재현성을 얻을 수 있습니다.

주의 — seed를 지원하더라도 모델 버전이 서버 쪽에서 업데이트되면 같은 seed·같은 프롬프트라도 결과가 달라질 수 있습니다. system_fingerprint 같은 값으로 같은 모델 스냅샷인지 확인하는 습관이 필요합니다.

 

실무 포인트

완전한 결정론이 필요하다면 애플리케이션 레벨에서 첫 호출 결과를 캐싱해 재사용하는 편이 안전합니다. 테스트 코드에서는 문자열이 완전히 같은지보다 JSON 스키마 만족 여부, 특정 키워드 포함 여부 같은 느슨한 기준으로 검증하는 것이 비결정성과 공존하는 현실적인 전략입니다.
