Popover API와 dialog — JS 없이 네이티브로 만드는 모달·팝오버 상태관리

프론트엔드

한 줄 요약 — 브라우저의 top layer에서 동작하는 Popover API와 dialog가 z-index 경쟁과 포커스 트랩을 어떻게 표준으로 대체하는지 정리했습니다.

 

왜 지금 Popover API를 다시 봐야 하는가

모달·드롭다운을 직접 구현하면 z-index 경쟁, 포커스 트랩, 바깥 클릭 감지라는 세 가지 골칫거리를 겪습니다. Popover API와 dialog 요소는 이를 브라우저 엔진의 새로운 렌더링 계층인 top layer에서 처리하도록 표준화해, 상당 부분을 JS 없이 해결합니다.

 

Top Layer: DOM 트리 순서와 무관하게 항상 맨 위

popover 속성이 붙은 요소나 showModal()로 연 dialog는 일반 DOM 렌더링 트리와 완전히 분리된 별도 레이어에서 그려져 항상 문서의 다른 콘텐츠보다 위에 렌더링됩니다. 부모의 overflow나 z-index 설정이 아예 영향을 주지 못합니다.

 

선언적 상호작용: HTML 속성만으로 열고 닫기

popovertarget 속성을 가진 버튼은 대상 id를 가리키기만 하면 클릭 시 자동으로 열리고 닫힙니다. 바깥 클릭이나 Esc로 자동 닫히는 light dismiss도 내장돼 있습니다. dialog도 showModal()로 열면 배경 backdrop이 생기고 포커스가 내부로 트랩되며 Esc로 닫힙니다.

항목 기존 JS 모달 Popover/dialog
렌더링 위치 z-index 의존 top layer(항상 최상단)
바깥 클릭 닫기 이벤트 직접 부착 light dismiss 내장

 

JS 없이 동작하는 팝오버 예제
<button popovertarget="user-menu">메뉴</button>
<div id="user-menu" popover>
  <a href="/profile">프로필</a>
  <a href="/logout">로그아웃</a>
</div>

<dialog id="confirm-dialog">
  <p>정말 삭제하시겠습니까?</p>
  <form method="dialog"><button>취소</button></form>
</dialog>

 

실무 포인트

Popover API와 dialog는 목적이 다릅니다. dialog의 showModal()은 배경을 완전히 막는 진짜 모달에, Popover API는 드롭다운·툴팁처럼 배경과 동시 상호작용 가능한 UI에 적합합니다.

브라우저 지원 범위를 반드시 확인하세요. 비교적 최신 표준이라 구형 브라우저나 특정 WebView에서는 폴리필이 필요할 수 있습니다.

주의 — 완전히 JS를 없앨 수 있는 것은 아닙니다. 애니메이션 트랜지션, 정교한 위치 계산, 다단계 폼 흐름에는 여전히 JS/CSS 로직이 필요합니다. 기본 동작은 표준에 맡기고 필요한 만큼만 커스텀 로직을 얹는 것이 실용적입니다.
