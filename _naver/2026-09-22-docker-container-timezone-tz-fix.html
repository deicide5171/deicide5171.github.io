Docker 컨테이너 시간대가 안 맞을 때 — TZ 환경변수로 타임존 맞추기

인프라

한 줄 요약 — 대부분의 Docker 베이스 이미지는 기본 시간대가 UTC라, TZ 환경변수와 tzdata 패키지로 컨테이너 레벨에서 맞춰줘야 합니다.

 

왜 로컬에선 멀쩡하던 시간이 틀어지나

로컬 개발 환경에서는 OS의 로컬 타임존을 그대로 물려받아 문제를 못 느끼지만, 컨테이너는 격리된 환경이라 호스트의 타임존 설정을 자동으로 상속받지 않습니다. 그래서 로그 시각이 9시간 어긋나거나 자정에 돌아야 할 배치가 낮에 실행되는 문제가 생깁니다.

 

 

잘못된 접근 vs 올바른 접근

코드에서 매번 9시간을 더하거나 빼는 임시방편은 코드베이스 전체에 하드코딩된 오프셋을 남기고, 로그 라이브러리나 스케줄러처럼 애플리케이션이 직접 못 건드리는 부분의 시간은 여전히 UTC로 남습니다.

FROM eclipse-temurin:21-jre-alpine
RUN apk add --no-cache tzdata
ENV TZ=Asia/Seoul

Alpine 이미지는 tzdata 패키지가 기본 미포함이라 ENV TZ만 설정해서는 아무 효과가 없습니다. tzdata를 먼저 설치해야 TZ 환경변수가 실제로 반영됩니다. docker-compose나 Kubernetes에서는 environment/env 항목으로 실행 시점에 주입할 수도 있습니다.

주의 — Java의 -Duser.timezone 옵션이나 TimeZone.setDefault() 호출이 컨테이너의 TZ 환경변수보다 우선 적용될 수 있습니다. 두 설정이 어긋나면 예상과 다른 결과가 나오니 함께 확인하세요.

 

더 나은 대안: UTC로 통일하기

실무에서 더 권장되는 방향은 컨테이너 시간대를 억지로 바꾸기보다, 내부적으로는 모든 시간을 UTC로 통일하고 사용자에게 보여주는 시점에서만 로컬 시간대로 변환하는 것입니다. 작은 단일 리전 서비스라면 TZ를 맞추는 쪽이 당장 편하지만, 다중 리전으로 확장할 서비스라면 UTC 통일 전략이 장기적으로 유리합니다.
