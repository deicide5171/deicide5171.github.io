Spring Boot Whitelabel Error Page, 뭘 확인해야 할까

2026. 8. 31. · 백엔드

한 줄 요약 — Whitelabel 화면 자체보다 서버 로그의 스택트레이스를 확인하는 것이 핵심이며, 상태 코드별로 확인 순서를 정해두면 빠릅니다.

 

Whitelabel Error Page가 알려주지 않는 것

Whitelabel Error Page는 Spring Boot가 에러 페이지를 별도로 설정하지 않았을 때 보여주는 기본 화면입니다. HTTP 상태 코드와 짧은 메시지만 나올 뿐, "어디서 왜 터졌는지"는 알려주지 않습니다.

 

상태 코드별 확인 우선순위
상태 코드 의미 먼저 확인할 것
404 매핑된 컨트롤러 없음 URL·HTTP 메서드 일치 여부
401/403 인증/인가 실패 Security 경로 패턴, 토큰 유효성
500 서버 내부 에러 애플리케이션 로그의 스택트레이스

 

진짜 원인을 보는 방법

Whitelabel 페이지는 기본적으로 스택트레이스를 화면에 노출하지 않습니다. 개발 환경에서만 아래 설정으로 자세한 정보를 켤 수 있습니다.

# application-dev.yml (운영에는 절대 넣지 않는다)
server:
  error:
    include-message: always
    include-stacktrace: always

더 확실한 방법은 서버 로그를 직접 보는 것입니다. Whitelabel 페이지가 떠도 로그에는 항상 전체 스택트레이스가 출력됩니다.

 

예제 — 전역 예외 핸들러
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(Exception.class)
    public ResponseEntity<Map<String, String>> handleGeneral(Exception ex) {
        return ResponseEntity.internalServerError()
                .body(Map.of("error", "서버 내부 오류가 발생했습니다."));
    }
}

@RestControllerAdvice로 전역 예외 처리기를 두면 Whitelabel 대신 일관된 JSON 에러 응답을 내려줄 수 있습니다.

 

실무 포인트

404가 예상 밖으로 떴다면 HTTP 메서드부터 의심하세요. 경로는 맞는데 메서드가 다른 경우가 매우 흔합니다.

주의 — 운영 환경에서 include-stacktrace: always를 켜두면 내부 구조가 그대로 노출되는 보안 문제가 됩니다. 반드시 프로파일별로 분리하세요.
