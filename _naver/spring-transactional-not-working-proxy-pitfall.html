Spring @Transactional이 동작하지 않는 흔한 이유 — 프록시 함정

백엔드

한 줄 요약 — @Transactional은 AOP 프록시로 구현되어 있어, 같은 클래스 안에서 메서드를 직접 호출하는 자기 호출(self-invocation)에는 적용되지 않습니다.

 

왜 이 문제가 반복되는가

같은 클래스 안에서 @Transactional이 붙은 메서드를 호출했는데 "예외가 났는데 DB에 데이터가 남아있다"는 버그가 자주 발생합니다. Spring은 @Transactional이 붙은 빈을 감싸는 프록시 객체를 만드는데, 같은 클래스 내부에서 호출하면 프록시를 거치지 않고 원본 메서드가 직접 호출되기 때문입니다.

public void placeOrder(OrderRequest request) {
    validateStock(request);
    saveOrder(request); // 자기 호출 - 트랜잭션 적용 안 됨
}

@Transactional
public void saveOrder(OrderRequest request) { ... }

 

잘못된 접근 vs 올바른 접근

REQUIRES_NEW 같은 전파 옵션을 붙이면 해결될 거라 생각하기 쉽지만, 전파 옵션은 트랜잭션이 이미 시작된 이후의 동작을 결정할 뿐 자기 호출 자체를 해결하지 못합니다.

@Service
public class OrderTransactionService {
    @Transactional
    public void saveOrder(OrderRequest request) { ... }
}
// OrderService에서 이 빈을 주입받아 호출

트랜잭션이 필요한 로직을 별도의 빈으로 분리해 외부 호출로 프록시를 거치게 하는 것이 가장 확실한 해결책입니다.

함정 원인
자기 호출 프록시를 거치지 않는 내부 호출
private 메서드 프록시가 오버라이드 불가능
Checked Exception 기본은 RuntimeException만 롤백

 

주의 — 체크 예외(IOException 등)를 던지는 코드는 rollbackFor = Exception.class를 명시하지 않으면 예외가 나도 그대로 커밋됩니다.

 

실무 포인트

트랜잭션 로그 레벨(org.springframework.transaction)을 DEBUG로 켜서 실제로 트랜잭션이 시작·커밋되는지 확인하는 습관이 문제를 빨리 찾게 해줍니다. 테스트 클래스에 @Transactional을 붙이면 각 테스트 후 자동 롤백되는데, 이 편의 기능과 실제 서비스 코드의 동작을 혼동하지 마세요.
