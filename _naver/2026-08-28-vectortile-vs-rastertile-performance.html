지도 타일, 그림으로 줄까 좌표로 줄까 — 벡터타일 vs 래스터타일 성능 비교

2026. 8. 28. · GIS

한 줄 요약 — 지도 타일을 미리 그려진 이미지로 줄지, 스타일링 가능한 좌표 데이터로 줄지에 따라 네트워크 전송량, 렌더링 방식, 다국어·다크모드 대응력이 어떻게 달라지는지 벡터타일 vs 래스터타일 성능 관점에서 비교했습니다.

 

같은 타일이라는 이름, 다른 내용물

웹 지도에서 타일이라는 단위는 같지만, 그 안에 무엇이 들어있는지는 두 갈래로 갈립니다. 하나는 서버가 미리 렌더링해둔 PNG/JPEG 이미지를 그대로 내려주는 래스터 타일이고, 다른 하나는 도로·건물·라벨의 실제 좌표와 속성을 담은 압축 바이너리(MVT)를 내려줘 클라이언트가 그 자리에서 그리는 벡터 타일입니다.

"그림을 받아서 붙이는가"와 "좌표를 받아서 그리는가"라는 근본적인 차이가 성능·용량·표현력 전반에 걸쳐 서로 다른 트레이드오프를 만듭니다.

 

핵심 개념 1 — 무엇을 미리 계산하고 무엇을 그 자리에서 계산하나요

래스터 타일은 서버가 스타일까지 반영해 완성된 이미지를 미리 만들어둡니다. 스타일을 바꾸려면 타일 자체를 재렌더링해서 재배포해야 합니다. 벡터 타일은 원본 지리 데이터만 압축해서 내려주고, 실제 그리기는 클라이언트의 스타일 명세를 기준으로 WebGL이 그 자리에서 수행합니다. 스타일 JSON 하나만 바꾸면 다크모드, 다국어 라벨을 서버 재배포 없이 즉시 적용할 수 있습니다.

핵심 개념 2 — 네트워크 전송량과 확대·축소 체감
기준 래스터 타일 벡터 타일
스타일 변경 타일 재생성·재배포 필요 스타일 JSON만 교체
확대·축소 체감 새 이미지 로딩 전 흐릿함 GPU 재투영으로 매끄러움
클라이언트 부담 낮음 높음(GPU 렌더링)

 

 

핵심 개념 3 — 클라이언트 성능이라는 반대급부

벡터 타일은 클라이언트가 매 프레임 스타일 규칙을 적용해 그려야 하므로 저사양 모바일에서는 프레임 드랍이 생길 수 있습니다. 반대로 래스터 타일은 이미지를 붙이기만 하므로 오래된 기기에서도 예측 가능합니다. 위성영상처럼 연속 톤 이미지는 벡터화 자체가 불가능하므로 래스터가 유일한 선택지입니다.

예제 — MapLibre GL JS로 벡터 타일 스타일 전환
import maplibregl from "maplibre-gl";

const map = new maplibregl.Map({
  container: "map",
  style: "/styles/light.json",
  center: [127.0, 37.5],
  zoom: 11,
});

// 다크모드 전환: 같은 벡터 타일 데이터를 재요청하지 않고 스타일만 교체
function toggleDarkMode(isDark) {
  map.setStyle(isDark ? "/styles/dark.json" : "/styles/light.json");
}

같은 타일 소스를 두고 paint 속성만 바꾼 스타일 JSON을 여러 개 준비해두면, 서버에 새 요청을 보내지 않고도 클라이언트에서 즉시 스타일을 전환할 수 있습니다.

 

실무 도입 시 이것만은 챙기세요
1. 저사양 기기가 타깃이면 벡터 타일 레이어 수를 제한하세요 — 줌 레벨별로 표시 레이어를 줄이는 것이 일반적입니다.
2. 위성·항공 이미지는 벡터화 대상이 아닙니다 — 이 경우는 래스터 타일이 유일하게 맞는 선택입니다.
3. 하이브리드 구성도 고려하세요 — 배경 지도는 벡터, 위성영상·열지도 오버레이는 래스터로 겹쳐 쓰는 구성이 흔합니다.

 

마무리 — 3줄 요약

① 래스터 타일은 완성된 이미지를 미리 전송해 클라이언트 부담이 낮지만 스타일 변경 시 재배포가 필요합니다.
② 벡터 타일은 좌표 데이터만 전송해 스타일 전환·다국어·고해상도 대응이 유연하지만 GPU 부담이 큽니다.
③ 위성·항공 원본처럼 벡터화가 불가능한 이미지는 래스터가 유일한 선택지이며, 배경은 벡터·오버레이는 래스터인 하이브리드 구성도 흔합니다.
