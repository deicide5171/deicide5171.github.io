HTTP Keep-Alive가 뭔가요 — 연결을 재사용해 빠르게

2026. 9. 18. · 시스템 디자인

한 줄 요약 — Keep-Alive는 한 번 맺은 연결을 여러 요청에 재사용해 핸드셰이크(특히 TLS) 반복을 없애 지연을 줄입니다.

 

요청마다 연결을 새로 맺으면 느리다

HTTP 요청 전에 서버와 연결(TCP 핸드셰이크)을 맺어야 합니다. 요청마다 매번 새로 연결·끊으면 왕복 시간이 쌓여 느려지죠. Keep-Alive는 맺은 연결을 끊지 않고 재사용해 이를 줄입니다.

 

연결 재사용
없음: 요청1(연결-응답-끊기) 요청2(연결-응답-끊기)
있음: 연결 -> 요청1 -> 요청2 -> ... -> 끊기
      (한 연결로 여러 요청)

 

효과
항목 효과
지연 핸드셰이크 반복 제거
TLS 암호화 핸드셰이크도 재사용

 

실무 포인트

HTTP/1.1은 기본으로 켜져 있지만, 프록시·LB 설정에서 꺼져 있으면 확인하세요. 백엔드→외부 API 호출은 커넥션 풀로 Keep-Alive 연결을 재사용하도록 설정합니다.

주의 — 연결을 무한정 열어두면 자원이 묶입니다. 유휴 타임아웃으로 일정 시간 요청이 없으면 닫되, 균형을 맞추세요.
