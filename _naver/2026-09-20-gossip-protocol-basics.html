가십 프로토콜이 뭔가요 — 소문처럼 퍼지는 정보 전파

시스템 설계

한 줄 요약 — 각 노드가 무작위 몇 노드에게 정보를 전해 소문처럼 퍼뜨리는 확장성 좋은 전파 방식입니다.

 

노드 수천 개에 어떻게 알리나

중앙 서버가 모든 노드에 직접 알리면 병목·단일 장애점이 됩니다. 가십 프로토콜은 각 노드가 아무나 몇 명에게 전하고 그들이 또 전하는 방식으로 퍼뜨립니다.

 

어떻게 퍼지나
1. A가 새 정보를 안다.
2. A → 무작위 몇 노드(B, C)에게 전함.
3. B, C도 각자 무작위 몇 노드에게.
4. 반복 → 지수적으로 퍼져 곧 전체가 앎.

한 라운드마다 아는 노드가 대략 배로 늘어, 전체 전파가 로그 시간에 이뤄집니다.

 

특성
특성 설명
확장성 노드 많아도 각자 몇 명에게만
견고성 일부 실패해도 다른 경로로
최종 일관성 "결국" 모두 알게 됨

 

실무 포인트

Cassandra·Consul 등이 노드 생존 정보나 클러스터 구성을 가십으로 공유합니다. 같은 정보를 여러 번 받을 수 있어 버전·타임스탬프로 오래된 소문을 거릅니다.

주의 — 전파에 시간이 걸립니다. "지금 당장 전원이 알아야 하는" 강한 일관성엔 맞지 않습니다.
