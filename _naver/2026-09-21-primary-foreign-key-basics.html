기본키와 외래키가 뭔가요 — 테이블을 연결하는 열쇠

데이터베이스

한 줄 요약 — 기본키(PK)는 각 행을 고유하게 식별하고, 외래키(FK)는 다른 테이블의 PK를 참조해 테이블을 연결하고 참조 무결성을 지킵니다.

 

특정 행을 어떻게 콕 집나

수백만 행에서 "이 사용자"를 정확히 가리키려면 겹치지 않는 식별자가 필요합니다. 그것이 기본키(PK)이고, 주문이 어느 사용자 것인지 연결하는 것이 외래키(FK)입니다.

 

기본키(PK)의 조건
조건 설명
유일성 중복되지 않음
NOT NULL 비어 있을 수 없음

 

외래키(FK)로 연결
CREATE TABLE orders (
    id BIGINT PRIMARY KEY,
    user_id BIGINT,
    FOREIGN KEY (user_id) REFERENCES users(id)
);

orders.user_id가 users.id를 참조해 "이 주문이 누구 것인지" 연결합니다. DB가 존재하지 않는 사용자의 주문이 생기지 않도록 무결성을 지킵니다.

 

참조 무결성
users에 없는 user_id로 주문 생성 -> 거부
주문 딸린 사용자 삭제 -> 거부(또는 함께 삭제)
-> 고아 데이터가 생기는 것을 DB가 막아준다

 

실무 포인트

기본키로 의미 없는 값(자동 증가 ID, UUID)을 쓰는 것이 안전합니다. 이메일 같은 의미 있는 값을 PK로 쓰면 바뀔 때 참조하는 모든 곳을 고쳐야 합니다.

주의 — 외래키 컬럼에는 인덱스를 거세요. JOIN과 무결성 검사에 자주 쓰여 인덱스가 없으면 데이터가 많을 때 느려집니다.
