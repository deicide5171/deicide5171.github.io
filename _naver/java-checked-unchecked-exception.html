체크 예외 vs 언체크 예외 — 자바 예외 처리 기초

2026. 9. 6. · 백엔드

한 줄 요약 — 체크 예외는 컴파일러가 처리를 강제하고 언체크는 강제하지 않으며, 실무는 코드 간결성을 위해 언체크 예외를 선호합니다.

 

왜 어떤 예외는 try-catch를 강제하나

어떤 메서드는 예외를 처리하지 않으면 컴파일이 안 되고, 어떤 예외는 강제가 없습니다. 이 차이가 체크 예외와 언체크 예외의 구분입니다.

 

항목 체크 예외 언체크 예외
처리 강제 강제(컴파일) 강제 안 함
예시 IOException NullPointerException
의미 복구 가능 대부분 프로그래밍 오류

 

코드로 보는 차이
// 체크: 반드시 처리해야 컴파일됨
try { Files.readString(path); } catch (IOException e) { ... }

// 언체크: 강제 안 함
return a / b; // b가 0이면 ArithmeticException

 

실무 포인트

Spring은 체크 예외(SQLException 등)를 언체크 예외(DataAccessException)로 감싸서 비즈니스 로직이 불필요한 try-catch로 지저분해지지 않게 합니다.

예외를 잡아 다시 던질 때는 원인 예외(e)를 함께 넘겨야 스택트레이스가 이어집니다.

주의 — 예외를 잡고 아무것도 안 하는 빈 catch 블록은 최악입니다. 문제가 조용히 사라져 원인 추적이 극도로 어려워집니다.
