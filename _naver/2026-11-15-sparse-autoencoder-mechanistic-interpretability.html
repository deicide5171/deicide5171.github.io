한 줄 요약 — 뉴런의 다의성 때문에 읽어낼 수 없던 LLM 내부를, 훨씬 많은 수의 해석 가능한 특징으로 재구성하는 Sparse Autoencoder와 특징 서킷 분석을 정리했습니다.

 

왜 지금 모델 내부를 다시 봐야 하는가

LLM이 스스로 만들어내는 설명(chain-of-thought)조차 실제 내부 계산 과정과 다를 수 있다는 것이 여러 연구에서 확인됐습니다. 트랜스포머의 한 뉴런은 서로 전혀 관련 없는 개념 여러 개에 동시에 반응하는 경우가 흔한데, 이 다의성(polysemanticity) 때문에 뉴런 단위 분석으로는 의미를 하나로 특정할 수 없습니다.

 

중첩 가설과 과대완비 사전

모델이 표현해야 하는 개념의 수가 실제 뉴런 수보다 훨씬 많을 때, 모델은 여러 개념을 뉴런들의 선형 결합(방향 벡터)으로 압축해 저장합니다. SAE는 원래 활성화 벡터를 뉴런 수보다 몇 배 더 많은 차원의 특징 공간으로 인코딩했다가 다시 디코딩하도록 학습하고, 손실 함수에 희소성 페널티를 걸어 각 입력에서 극소수의 특징만 활성화되도록 강제합니다. 학습이 끝나면 각 특징 방향은 놀랍도록 단일한 의미를 갖는 경우가 많습니다.

특징에서 서킷으로: 개입과 스티어링

개별 특징을 찾은 뒤 유용해지는 지점은 이 특징들을 인위적으로 켜거나 끄면서 모델 행동에 어떤 영향을 주는지 확인하는 개입 실험입니다. Anthropic이 공개한 사례처럼 "골든게이트 브리지" 특징을 극단적으로 높이면 모델은 어떤 질문에도 골든게이트 브리지 이야기로 답을 유도합니다. 특징들이 서로 어떻게 연결돼 다음 특징을 활성화시키는지 추적하면 특징 서킷(feature circuit)을 그릴 수 있습니다.

SAE 손실 함수 예제
class SparseAutoencoder(nn.Module):
    def __init__(self, d_model, d_hidden):
        super().__init__()
        self.encoder = nn.Linear(d_model, d_hidden)
        self.decoder = nn.Linear(d_hidden, d_model)

    def forward(self, activations):
        features = torch.relu(self.encoder(activations))
        reconstruction = self.decoder(features)
        return reconstruction, features

def loss_fn(reconstruction, original, features, l1_coeff=1e-3):
    recon_loss = ((reconstruction - original) ** 2).mean()
    sparsity_loss = features.abs().sum(dim=-1).mean()
    return recon_loss + l1_coeff * sparsity_loss

L1 계수를 높일수록 활성화되는 특징 수는 줄지만 재구성 오차는 커지므로, 이 둘 사이의 균형점을 찾는 것이 핵심입니다.

 

실무 포인트

SAE로 찾은 특징이 항상 완벽하게 단의적이지는 않습니다. dead feature나 특징 흡수 같은 알려진 실패 모드가 있어 결과 해석에 주의가 필요합니다.

이 기법은 프로덕션 안전장치가 아니라 연구·감사 도구에 가깝습니다. 현재는 위험 행동의 원인을 사후 분석하는 용도로 주로 쓰입니다.

주의 — 특징 수와 모델 규모에 따라 학습 비용이 상당합니다. 수백만~수천만 개의 특징을 학습시키려면 대량의 활성화 데이터 수집과 별도의 GPU 학습 파이프라인이 필요합니다.
