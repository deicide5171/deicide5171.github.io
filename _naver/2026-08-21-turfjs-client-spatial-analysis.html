브라우저에서 끝내는 공간 분석 — Turf.js로 버퍼·교차·거리 계산하기

2026. 8. 21. · GIS

한 줄 요약 — PostGIS 같은 공간 DB나 별도 분석 서버 없이, 브라우저에서 Turf.js로 버퍼·교차·거리 계산을 직접 수행해 지도 인터랙션에 지연 없이 반영하는 방법을 정리했습니다.

 

왜 지금 클라이언트 공간 연산인가

"반경 500m 안에 있는 매장은?", "이 배달 구역과 저 배달 구역이 겹치는가?" 같은 질문에 답하려면 보통 PostGIS 같은 공간 DB에 쿼리를 던지거나 별도의 공간 분석 API를 호출해야 한다고 생각하기 쉽습니다. 하지만 사용자가 지도 위에서 마커를 드래그하거나 반경 슬라이더를 움직일 때마다 서버 왕복이 발생하면, 그 지연만큼 지도 조작감이 떨어집니다. 실시간성이 중요한 인터랙션이라면 연산을 아예 클라이언트로 가져오는 편이 낫습니다.

Turf.js는 GeoJSON을 입력·출력으로 삼는 순수 JavaScript 공간 연산 라이브러리입니다. 서버나 네이티브 바인딩 없이 브라우저에서 바로 동작하기 때문에, OpenLayers·MapLibre·Leaflet 같은 웹 지도 라이브러리와 함께 쓰면 사용자가 그린 도형이나 실시간 좌표를 그 자리에서 분석해 지도에 바로 그려낼 수 있습니다. 서버 사이드 GIS 분석(PostGIS 등)이 대용량·정밀 배치 작업에 강하다면, Turf.js는 소규모 데이터에 대한 즉각적인 클라이언트 반응성에 강합니다.

 

핵심 개념: Turf.js와 PostGIS의 역할 분담

두 도구는 경쟁 관계가 아니라 역할이 다릅니다. 서버에서 대량 데이터를 미리 걸러 GeoJSON으로 내려보내고, 그 이후 사용자 조작에 따라 달라지는 세부 연산은 Turf.js가 클라이언트에서 담당하는 조합이 흔합니다.

구분 Turf.js (클라이언트) PostGIS (서버)
실행 위치 브라우저(사용자 기기) DB 서버
강점 지연 없는 즉시 반응, 인터랙션 연동 대용량 데이터, 공간 인덱스 기반 질의
적합한 규모 화면에 보이는 수십~수백 개 피처 수만~수억 건의 영속 데이터
대표 연산 buffer, intersect, distance, nearestPoint ST_Buffer, ST_Intersection, GiST 인덱스

 

대표 연산 세 가지

buffer는 점·선·면 주변에 지정한 거리만큼 영역을 확장한 폴리곤을 생성합니다. 반경 상권 분석, 위험구역 표시에 쓰입니다. intersect / union / difference는 두 폴리곤을 겹쳐 교집합·합집합·차집합을 구하며, 배달 구역 중첩 확인이나 관할 구역 병합에 활용됩니다. distance / nearestPoint는 두 지점 사이 거리를 구하거나 여러 후보 중 가장 가까운 지점을 찾을 때 사용합니다.

Turf.js는 이 연산들을 각각 독립된 함수(turf.buffer, turf.intersect, turf.distance 등)로 제공하며, 모든 함수는 GeoJSON을 받아 GeoJSON을 반환하므로 지도 라이브러리의 소스 데이터로 바로 연결할 수 있습니다.

 

예제: 반경 버퍼와 교차 여부 판단 (JavaScript)

아래는 특정 매장 기준 500m 반경 버퍼를 만들고, 사용자가 그린 배달 구역 폴리곤과 겹치는지 확인한 뒤, 가장 가까운 매장까지의 거리를 구하는 예제입니다.

import * as turf from '@turf/turf';

// 1) 특정 지점 기준 500m 반경 버퍼 생성
const store = turf.point([127.0276, 37.4979]); // [경도, 위도]
const serviceArea = turf.buffer(store, 0.5, { units: 'kilometers' });

// 2) 사용자가 그린 배달 구역 폴리곤과 겹치는지 확인
const deliveryZone = turf.polygon([[
  [127.020, 37.495],
  [127.035, 37.495],
  [127.035, 37.503],
  [127.020, 37.503],
  [127.020, 37.495],
]]);

const overlap = turf.intersect(
  turf.featureCollection([serviceArea, deliveryZone])
);

if (overlap) {
  console.log('겹치는 영역 존재 - 지도에 강조 표시');
  map.getSource('overlap-layer').setData(overlap);
}

// 3) 사용자 위치에서 가장 가까운 매장 찾기
const userLocation = turf.point([127.030, 37.498]);
const nearest = turf.nearestPoint(userLocation, turf.featureCollection([store]));
const km = turf.distance(userLocation, nearest, { units: 'kilometers' });
console.log('가장 가까운 매장까지 ' + km.toFixed(2) + 'km');

이 코드는 서버 호출 없이 지도 위 이벤트 핸들러 안에서 즉시 실행할 수 있습니다. 사용자가 반경 슬라이더를 움직이면 turf.buffer를 다시 호출해 결과 GeoJSON을 지도 소스에 갱신하는 식으로, 프레임마다 자연스럽게 반응하는 UI를 만들 수 있습니다.

 

실무 도입 시 이것만은 챙기세요
1. 좌표계는 항상 위경도(EPSG:4326) 기준 — 대부분의 Turf.js 함수는 대권 거리 계산을 내부 처리하므로 별도 투영좌표 변환이 필요 없습니다
2. 대용량 폴리곤 연산은 메인 스레드 부담 주의 — 좌표점이 많으면 프레임 드랍 가능성이 있어, 필요 시 Web Worker로 분리를 검토하세요
3. 정밀도가 중요한 통계·집계는 서버에서 교차 검증 — 법적·회계적으로 정확해야 하는 값은 PostGIS 등과 함께 검증하는 것이 안전합니다
4. 번들 크기 관리 — 전체 패키지 대신 실제 쓰는 연산만 개별 패키지로 임포트하면 트리쉐이킹에 유리합니다

 

마무리 — 3줄 요약

① Turf.js는 GeoJSON을 입출력으로 쓰는 순수 JS 공간 연산 라이브러리로, 서버 왕복 없이 브라우저에서 buffer·intersect·distance 연산을 즉시 수행합니다.
② 대용량·영속 데이터의 정밀 분석은 PostGIS 같은 서버 사이드 도구가, 화면 위 실시간 인터랙션은 Turf.js가 맡는 역할 분담이 자연스럽습니다.
③ 좌표계는 위경도 기준으로 그대로 쓰되, 무거운 연산은 Web Worker 분리와 개별 패키지 임포트로 성능·번들 크기를 관리해야 합니다.
