Web Components로 프레임워크 독립적인 버튼 만들기

프론트엔드

한 줄 요약 — Web Components와 Shadow DOM을 쓰면 React·Vue·바닐라 어디서나 재사용 가능한 컴포넌트를, 스타일 충돌 걱정 없이 한 번만 만들 수 있습니다.

 

왜 프레임워크마다 다시 만들게 되는가

여러 프로젝트가 React·Vue·바닐라를 각각 쓰는 조직에서 "브랜드 버튼"을 한 번만 만들어 재사용하고 싶어도, React 컴포넌트는 Vue 프로젝트에서 그대로 쓸 수 없습니다. 결국 같은 버튼을 프레임워크 수만큼 중복 구현하게 됩니다. Web Components는 브라우저 네이티브 표준으로 이 문제를 해결합니다.

 

잘못된 접근 vs 올바른 접근

클래스 이름만 신경 쓴 div.my-button 방식은 다른 팀이 같은 클래스명을 다른 용도로 쓰면 스타일이 깨지는 근본적인 위험이 있습니다.

class MyButton extends HTMLElement {
  connectedCallback() {
    const shadow = this.attachShadow({ mode: 'open' });
    shadow.innerHTML = `
      <style>button { padding: 8px 16px; }</style>
      <button><slot></slot></button>
    `;
  }
}
customElements.define('my-button', MyButton);

attachShadow({ mode: 'open' })로 만든 Shadow DOM은 내부 스타일과 마크업을 외부와 완전히 격리합니다. style 블록의 선택자는 오직 이 컴포넌트 내부에만 적용되고, 페이지의 전역 CSS도 내부로 새어 들어오지 못합니다.

주의 — CSS 커스텀 속성(변수)은 Shadow DOM 경계를 넘어 상속됩니다. --brand-color 같은 변수를 컴포넌트 내부에서 참조하게 만들면, 사용하는 쪽에서 값만 바꿔 색상을 조정할 수 있습니다.

실무 포인트

Shadow DOM은 접근성을 자동으로 보장하지 않으므로 시맨틱 태그와 ARIA 속성을 직접 챙겨야 합니다. 폼 요소로 쓰려면 ElementInternals API로 폼 연동을 명시적으로 구현해야 합니다. 여러 프레임워크에 걸쳐 쓰일 디자인 시스템 컴포넌트에 특히 적합하며, 하나의 React 프로젝트에서만 쓰인다면 일반 컴포넌트가 더 실용적일 수 있습니다.
