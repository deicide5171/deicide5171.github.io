Spring Bean이 뭔가요 — IoC 컨테이너 개념 처음 이해하기

백엔드

한 줄 요약 — IoC는 객체 생성과 연결을 개발자가 아니라 Spring 컨테이너가 대신 책임지는 원칙이며, Bean은 그 컨테이너가 관리하는 객체입니다.

 

왜 직접 new로 객체를 만들지 않는가

일반 자바 코드는 객체가 필요하면 직접 생성합니다. Spring 코드는 @Autowired로 필드에 객체가 알아서 채워집니다. 이 동작의 정체가 IoC(제어의 역전)입니다.

 

Bean과 IoC 컨테이너란
용어 의미
Bean 컨테이너가 생성·관리하는 객체
의존성 주입(DI) 필요한 객체를 컨테이너가 대신 넣어주는 것

 

코드로 보는 차이
// IoC 없이: 직접 생성
private PaymentService paymentService = new PaymentService();

// Spring IoC: 생성자로 주입받음
@Service
public class OrderService {
    private final PaymentService paymentService;

    public OrderService(PaymentService paymentService) {
        this.paymentService = paymentService;
    }
}

PaymentService는 Spring이 애플리케이션 시작 시점에 미리 만들어두고, OrderService가 필요할 때 생성자를 통해 주입해줍니다.

 

왜 이렇게 번거로운 방식을 쓰는가

직접 생성하면 구체적 구현에 강하게 결합되고 테스트에서 Mock으로 바꾸기 어렵습니다. IoC/DI는 역할에만 의존하게 해 테스트와 유지보수를 쉽게 만듭니다.

 

실무 포인트

필드 주입보다 생성자 주입을 권장합니다. 필수 의존성을 명확히 드러내고, 테스트 코드에서도 컨테이너 없이 바로 조립할 수 있습니다.

주의 — Bean은 기본적으로 싱글톤입니다. 상태를 갖는 필드를 두면 여러 요청이 상태를 공유해 동시성 버그가 생길 수 있습니다.
