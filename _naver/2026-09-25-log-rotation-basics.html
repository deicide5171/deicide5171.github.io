로그 로테이션이 뭔가요 — 로그로 디스크가 꽉 차는 걸 막기

인프라

한 줄 요약 — 로그 로테이션은 로그 파일을 잘라 새 파일로 넘기고 오래된 것은 압축·삭제해 디스크가 차는 것을 막습니다.

 

로그 파일이 디스크를 다 먹어버렸다

앱은 계속 로그를 남깁니다. 하나의 파일에 무한정 쌓이면 결국 디스크가 꽉 차 서버가 멈추는 사고로 이어지죠. 로그 로테이션은 로그 파일을 주기·크기 기준으로 잘라 새 파일로 넘기고, 오래된 파일은 압축·삭제해 디스크를 지킵니다.

 

무엇을 하나
동작 설명
자르기 app.log → app.log.1, 새 파일 시작
압축 오래된 로그 gzip
보관 기간 기간 넘으면 삭제

 

logrotate 설정 예시
/var/log/myapp/*.log {
    daily        # 매일 자른다
    rotate 14    # 14일치만 보관
    compress     # 오래된 건 압축
    notifempty   # 비어 있으면 안 자름
}

 

실무 포인트

로테이션 후 앱이 옛 파일 핸들을 붙잡으면 새 로그가 사라집니다. copytruncate 옵션이나 재열기 시그널이 필요합니다. 컨테이너 환경은 stdout으로 내보내고 플랫폼이 수집하게 하세요. maxsize로 크기 기준도 함께 걸면 급증에 안전합니다.

주의 — 도커/쿠버네티스에선 컨테이너 안에서 직접 파일 로테이션을 하기보다, stdout 로그를 플랫폼이 로테이션·수집하게 하는 것이 좋습니다.
