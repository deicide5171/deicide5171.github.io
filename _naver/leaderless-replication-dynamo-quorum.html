리더 없는 복제(Leaderless Replication) — Dynamo 스타일 Quorum 합의 설계

아키텍처·시스템 설계

한 줄 요약 — 리더 장애 시 쓰기가 막히는 문제를, 어떤 노드로든 읽고 쓰되 N, W, R Quorum 수식으로 일관성을 지키는 Dynamo 스타일로 해결하는 법을 정리했습니다.

 

왜 지금 리더리스 복제를 다시 봐야 하는가

리더-팔로워 복제는 모든 쓰기가 리더 한 곳으로 몰리는 제약이 있습니다. 리더가 죽으면 새 리더 선출까지 쓰기를 받을 수 없습니다. Dynamo 스타일 리더리스 복제는 특별한 리더 역할 없이, Quorum 메커니즘으로 일관성을 관리합니다.

 

N, W, R: 복제본 수와 성공 기준을 숫자로 표현하기

N은 복제 노드 총 개수, W는 쓰기 성공 최소 노드 수, R은 읽기 성공 최소 노드 수입니다. N개에 요청을 보내되 W개(또는 R개) 응답만 받으면 완료로 간주합니다.

 

W + R > N 이면 최소 하나는 최신 값을 포함한다

W+R>N을 만족하면 쓰기 성공 집합과 읽기 응답 집합이 최소 하나의 노드에서 겹칩니다. 그 노드는 최신 쓰기를 반영하므로 읽기 응답에 항상 최신 값이 하나는 포함됩니다.

설정 지연 일관성
N=3, W=3, R=1 쓰기 높음 강함
N=3, W=2, R=2 중간 Quorum 보장
N=3, W=1, R=1 낮음 약함

 

예제 — Quorum 읽기에서 최신 버전 선택
def quorum_read(key, N, R):
    responses = []
    for node in select_replica_nodes(key, N):
        try:
            responses.append(node.get(key))
        except Timeout:
            continue
        if len(responses) >= R:
            break

    if len(responses) < R:
        raise QuorumNotReachedException()

    return resolve_latest(responses)

resolve_latest가 버전 벡터로 인과관계를 추적하면 진짜 동시 쓰기 충돌을 감지해 애플리케이션이 병합할 수 있습니다.

 

실무 포인트

W, R 값은 읽기/쓰기 비율에 맞춰 조정하세요. 읽기가 많으면 W를 높이고 R을 낮춰 읽기 지연을 최소화하는 것이 유리합니다.

Quorum이 강한 일관성을 완전히 대체하지 못한다는 점을 이해하세요. 최신 값이 후보에 포함된다는 보장일 뿐, 자동으로 골라주지는 않습니다.

주의 — 노드가 일시적으로 다운됐을 때의 동작(Sloppy Quorum, Hinted Handoff)을 함께 설계하세요. 그래야 실제 가용성이 이론적 수치만큼 나옵니다.
