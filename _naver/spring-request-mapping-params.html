@RequestParam vs @PathVariable vs @RequestBody, 언제 뭘 쓸까

2026. 9. 3. · 백엔드

한 줄 요약 — 자원 식별은 @PathVariable, 조회 조건은 @RequestParam, 생성·수정 데이터는 @RequestBody가 기본 공식입니다.

 

셋 다 요청 데이터를 받는데 뭐가 다른가

이 셋은 데이터가 요청의 어느 위치에 담겨 오는지에 따라 나뉩니다. 위치를 알면 무엇을 써야 할지 자연스럽게 결정됩니다.

 

애노테이션 데이터 위치 예시
@PathVariable URL 경로 /users/1
@RequestParam 쿼리 스트링 /users?page=2
@RequestBody 요청 본문(JSON) POST /users + 바디

 

코드 예제
@GetMapping("/users/{id}")
public User getUser(@PathVariable Long id) { ... }

@GetMapping("/users")
public List<User> getUsers(@RequestParam(defaultValue = "1") int page) { ... }

@PostMapping("/users")
public User createUser(@RequestBody CreateUserRequest request) { ... }

 

언제 무엇을 쓰는가
자원 식별(회원 ID) -> @PathVariable
조회 조건(페이지, 검색어) -> @RequestParam
생성·수정 데이터 덩어리 -> @RequestBody

 

실무 포인트

GET 요청에는 보통 @RequestBody를 쓰지 않습니다. GET은 본문을 갖지 않는 것이 관례이므로 조회 조건은 @RequestParam으로 받습니다.

주의 — @RequestParam은 required=false나 defaultValue를 지정하지 않으면 파라미터 누락 시 400 에러가 납니다. @RequestBody DTO에는 @Valid 검증을 함께 쓰세요.
