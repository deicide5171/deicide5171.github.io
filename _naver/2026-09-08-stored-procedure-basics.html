저장 프로시저가 뭔가요 — DB 안에 저장해두는 SQL 묶음

2026. 9. 8. · 데이터베이스

한 줄 요약 — 저장 프로시저는 여러 SQL 문을 DB 안에 이름으로 저장해두고 호출하는 기능으로, 네트워크 왕복을 줄이지만 로직이 DB에 숨는 단점이 있습니다.

 

자주 쓰는 SQL을 매번 짜야 하나

"주문 넣고, 재고 줄이고, 로그 남기는" 여러 SQL을 매번 앱에서 보내야 할까요? 저장 프로시저는 이런 여러 SQL을 DB 안에 하나의 이름으로 미리 저장해두고, 필요할 때 이름만 불러 실행하는 기능입니다. 함수처럼 파라미터도 받습니다.

 

일반 SQL과 저장 프로시저
구분 일반 SQL 저장 프로시저
위치 앱 코드 DB 안에 저장
실행 매번 SQL 전송 이름으로 호출

 

만들고 쓰기
CREATE PROCEDURE count_orders(IN customer_id INT)
BEGIN
    SELECT COUNT(*) FROM orders WHERE cust_id = customer_id;
END;

CALL count_orders(42);

한 번 정의해두면 앱은 긴 SQL 대신 CALL 한 줄만 보내면 됩니다.

 

실무 포인트

여러 SQL을 한 번 호출로 처리해 네트워크 왕복을 줄일 수 있습니다. 다만 로직이 앱과 DB로 나뉘면 흐름 파악과 버전 관리가 어렵고, DB마다 문법이 달라 이식이 힘듭니다. 요즘은 로직을 앱에 두는 경우가 많습니다.

주의 — MySQL·PostgreSQL·Oracle의 프로시저 문법이 제각각이라, 다른 DB로 옮길 때 다시 짜야 할 수 있습니다.
