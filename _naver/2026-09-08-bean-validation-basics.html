Bean Validation 입문 — @NotNull로 입력값 검증하기

2026. 9. 8. · 백엔드

한 줄 요약 — Bean Validation은 입력 검증 규칙을 애너테이션으로 선언해 반복 코드를 없애며, 컨트롤러에서 @Valid로 검사합니다.

 

입력값 검증을 if문으로 다 짜야 하나

회원가입에서 이메일이 비었는지, 나이가 음수인지 등을 일일이 if로 검사하면 코드가 지저분해집니다. Bean Validation은 검증 규칙을 애너테이션으로 선언해 이 반복을 없앱니다. 스프링에서는 필드에 @NotNull 같은 애너테이션만 붙이면 자동 검사됩니다.

 

자주 쓰는 애너테이션
애너테이션 의미
@NotBlank 비거나 공백만이면 안 됨
@Size(min,max) 길이/크기 범위
@Min / @Max 숫자 최소/최대
@Email 이메일 형식

 

사용 예제
public class SignupRequest {
    @NotBlank private String name;
    @Email @NotBlank private String email;
    @Min(0) @Max(150) private int age;
}

@PostMapping("/signup")
public String signup(@Valid @RequestBody SignupRequest req) {
    // 검증 통과한 값만 여기 도달
}

@Valid를 붙이면 스프링이 요청 시 자동으로 규칙을 검사하고, 위반 시 예외를 던집니다.

 

실무 포인트

@ControllerAdvice로 검증 예외를 잡아 어떤 필드가 왜 틀렸는지 깔끔한 JSON으로 돌려주세요. message 속성으로 안내 문구도 지정할 수 있습니다. 프론트에서 검증했어도 서버 검증은 필수입니다.

주의 — 프론트엔드 검증만 믿으면 안 됩니다. 요청은 조작될 수 있으므로 서버에서도 반드시 검증하세요.
