자바 NullPointerException, 원인 찾고 예방하기

백엔드

한 줄 요약 — Java 14부터는 정확히 어떤 변수가 null이었는지 알려주며, null을 반환하지 않고 Optional·빈 컬렉션을 쓰는 것이 예방의 핵심입니다.

 

가장 흔하지만 자주 당황하는 예외

NPE는 null인 참조로 무언가를 하려 할 때 발생합니다. user.getName()을 호출했는데 user가 null이면 없는 객체의 메서드를 부른 것이라 NPE가 터집니다.

 

전형적인 상황
String name = getUserName();     // null 반환 가능
int length = name.length();      // name이 null이면 NPE

users.get("없는키").getEmail();  // get이 null 반환 -> NPE

 

최신 자바의 친절해진 에러 메시지
과거: java.lang.NullPointerException (어느 변수인지 모름)

Java 14+:
Cannot invoke "String.length()" because "name" is null
  -> name이 null이었다는 것을 정확히 알려준다

이 메시지만 잘 읽어도 어느 변수가 null인지 바로 알 수 있어 디버깅 시간이 크게 줄어듭니다.

 

예방하는 패턴
// 1. Optional로 "값이 없을 수 있음" 명시
public Optional<User> findUser(Long id) { ... }

// 2. 컬렉션은 null 대신 빈 컬렉션
return orders != null ? orders : Collections.emptyList();

// 3. 외부 입력 조기 검증
Objects.requireNonNull(param, "param은 null일 수 없습니다");

핵심 원칙은 "null을 반환하지 않기"입니다.

 

실무 포인트

Optional은 메서드 반환 타입으로 쓰는 것이 원래 의도입니다. 필드나 매개변수에 쓰는 것은 권장되지 않습니다.

주의 — API 응답·DB 조회·사용자 입력 등 외부에서 오는 값은 항상 null 가능성을 의심하되, 내부 코드까지 null 체크로 도배하지 말고 경계에서 검증하세요.
