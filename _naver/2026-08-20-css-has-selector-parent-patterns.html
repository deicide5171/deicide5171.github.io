CSS :has()로 열리는 부모 선택자 시대 — 실전 활용 패턴 정리

2026. 8. 20. · 프론트엔드

한 줄 요약 — 그동안 자바스크립트로 클래스를 토글해야 해결할 수 있었던 부모·형제 조건부 스타일링을, CSS :has() 하나로 처리하는 실전 패턴과 브라우저 지원 현황을 정리했습니다.

 

왜 지금 :has()가 반가운 걸까요

CSS는 오랫동안 자식이나 형제의 상태를 보고 부모를 스타일링하는 선택자를 제공하지 않았습니다. .card img처럼 조상에서 자손으로 내려가는 선택자는 있어도, 그 반대 방향인 부모 선택자는 명세에 존재한 적이 없었습니다. 그래서 "이미지가 있는 카드만 여백을 다르게 준다"거나 "체크박스가 선택된 항목의 부모에 배경색을 넣는다" 같은 흔한 요구사항조차 CSS만으로는 해결할 수 없었습니다.

결국 자바스크립트로 자식 요소의 상태를 감지해 부모에 클래스를 토글하는 방식이 사실상 표준 관행이 되었는데요, 이벤트 리스너를 등록하고 DOM을 순회하는 이 모든 로직은 원래 스타일링 문제인데도 자바스크립트 레이어로 새어 나간 셈이었습니다. :has() 의사클래스는 이 구조적 공백을 정면으로 메워줍니다. 인자로 받은 선택자에 매칭되는 자손이나 형제가 하나라도 존재하는 요소를 선택할 수 있게 되면서, 조건부 스타일링의 상당 부분을 순수 CSS로 되돌려 놓았습니다.

 

핵심 개념 1 — 기본 문법과 동작 원리

:has()는 관계형 의사클래스로 분류됩니다. A:has(B)는 "B에 해당하는 요소를 하나 이상 포함하는 A"를 의미하고, B 자리에는 자손 결합자뿐 아니라 인접 형제(+), 일반 형제(~) 결합자도 함께 쓸 수 있습니다. 예를 들어 .card:has(img)는 img 자손을 가진 .card를 뜻하고, h2:has(+ p)는 바로 다음에 p가 오는 h2를 뜻하는데요, 후자는 기존 CSS 선택자 체계에서는 아예 표현할 방법이 없던 관계였습니다.

여기서 중요한 점은, :has()의 인자는 문서 트리 안에서 매칭 여부만 판단하는 조건일 뿐이고, 실제로 스타일이 적용되는 대상은 항상 :has() 앞에 놓인 요소라는 것입니다. .card:has(img)를 적용해도 img 자체의 스타일은 바뀌지 않고 .card의 스타일만 바뀝니다. 또한 다른 의사클래스처럼 체이닝과 중첩이 가능해서, 상태 조건을 여러 개 조합할 수도 있습니다.

 

핵심 개념 2 — 실전에서 자주 쓰이는 패턴

가장 널리 쓰이는 패턴은 폼 유효성 스타일링입니다. 입력값이 유효하지 않을 때 입력창뿐 아니라 그 입력창을 감싸는 필드 그룹 전체의 테두리나 배경을 바꾸고 싶다면, 과거에는 blur 이벤트를 걸어 부모에 클래스를 추가해야 했습니다. .field:has(input:invalid) 같은 선택자 하나로 자바스크립트 없이 동일한 효과를 낼 수 있습니다.

두 번째로 흔한 패턴은 콘텐츠 유무에 따른 레이아웃 분기입니다. 카드 컴포넌트에 이미지가 있을 때와 없을 때 그리드 배치를 다르게 하고 싶다면, 예전에는 렌더링 단계에서 조건부로 클래스를 붙여야 했는데요, :has(img) 여부로 CSS 셀렉터 단에서 바로 분기할 수 있어 마크업을 생성하는 쪽의 책임이 줄어듭니다. 이 밖에도 label:has(input:checked)로 체크된 라벨을 강조하거나, 에러 메시지가 있을 때만 모달 크기를 키우는 식의 패턴도 자주 쓰입니다.

주요 브라우저는 모두 안정 버전에서 :has()를 지원하는 단계에 이르렀습니다. 다만 여전히 구형 브라우저를 지원해야 하는 프로젝트라면, 폴리필 없이 사용할 경우 해당 규칙만 조용히 무시된다는 점을 감안해 점진적 향상 관점에서 도입하는 것이 안전합니다.

 

예제 1 — 체크박스 상태에 따른 부모 스타일링
/* 유효하지 않은 입력이 있는 필드 그룹만 강조 */
.field:has(input:invalid) {
  border-color: #e53e3e;
  background-color: #fff5f5;
}

.field:has(input:invalid) label {
  color: #e53e3e;
}

/* 체크된 체크박스의 부모 항목 강조 */
.todo-item:has(input[type="checkbox"]:checked) {
  text-decoration: line-through;
  opacity: 0.6;
}

첫 번째 규칙은 입력값이 유효하지 않을 때 필드 그룹 전체를 강조하고, 두 번째 규칙은 체크박스가 선택된 할 일 항목에 취소선을 그어줍니다. 두 경우 모두 이벤트 리스너 없이 순수 CSS만으로 동작합니다.

 

예제 2 — 이미지 유무에 따른 카드 레이아웃
.card {
  display: grid;
  grid-template-columns: 1fr;
  gap: 8px;
}

.card:has(img) {
  grid-template-columns: 96px 1fr;
  align-items: center;
}

.card:has(img) img {
  width: 96px;
  height: 96px;
  object-fit: cover;
}

이미지가 없는 카드는 세로 1단 레이아웃을 그대로 쓰고, 이미지가 있는 카드만 썸네일 열이 추가된 2단 레이아웃으로 자동 전환됩니다. 마크업을 생성하는 쪽에서 별도로 클래스를 분기할 필요가 없어집니다.

 

실무 도입 시 이것만은 챙기세요
1. 선택자를 과도하게 중첩하지 않기 — 여러 단계로 조합할수록 어떤 조건에서 스타일이 적용되는지 파악하기 어려워집니다
2. 변경이 잦은 영역은 선택자 범위를 좁게 유지 — 실시간으로 갱신되는 리스트에 걸어두면 재계산 비용이 누적될 수 있습니다
3. 구형 브라우저용 폴백 전략을 세워두기 — 핵심 기능은 :has() 없이도 동작하게 설계하고, :has()는 시각적 개선 용도로 얹는 편이 안전합니다
4. 성능이 걱정되면 개발자 도구로 직접 확인 — 정확한 비용은 브라우저와 문서 구조에 따라 달라지므로 실측이 가장 확실합니다

 

마무리 — 3줄 요약

① CSS에는 원래 부모 선택자가 없어 자바스크립트로 클래스를 토글해야 했지만, :has()가 관계형 의사클래스로 이 공백을 메워줍니다.
② 폼 유효성 강조, 콘텐츠 유무에 따른 카드 레이아웃 분기 등에서 자바스크립트 없이 조건부 스타일링을 구현할 수 있습니다.
③ 주요 브라우저는 대체로 지원하지만, 복잡한 :has() 남용은 가독성과 성능 모두를 해칠 수 있어 범위를 좁게 유지해야 합니다.
