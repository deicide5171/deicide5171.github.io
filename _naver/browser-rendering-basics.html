브라우저 렌더링 과정이 뭔가요 — HTML이 화면이 되기까지

2026. 9. 9. · 프론트엔드

한 줄 요약 — 브라우저는 HTML·CSS를 파싱해 렌더 트리를 만들고 레이아웃·페인트로 화면을 그리며, 레이아웃(리플로우)이 가장 비쌉니다.

 

HTML 텍스트가 어떻게 화면이 되나

브라우저는 받은 HTML·CSS "텍스트"를 화면으로 바꿉니다. 이 과정을 알면 왜 어떤 코드가 화면을 느리게 만드는지 이해할 수 있죠. 크게 파싱 → 트리 구성 → 배치 → 그리기 단계를 거칩니다.

 

렌더링 단계
단계 하는 일
파싱 HTML→DOM, CSS→CSSOM
렌더 트리 그릴 요소만 모음
레이아웃 위치·크기 계산(리플로우)
페인트 픽셀로 색 칠하기

 

흐름
HTML -> DOM,  CSS -> CSSOM
      \    /
   렌더 트리 -> 레이아웃 -> 페인트 -> 화면 표시

 

실무 포인트

레이아웃(리플로우)이 가장 비쌉니다. 반복문 안에서 스타일을 계속 바꾸면 느려지니 변경을 모아 적용하세요. 애니메이션은 리플로우를 안 부르는 transform·opacity로 하는 게 부드럽습니다.

주의 — head의 큰 CSS나 동기 스크립트는 화면 표시를 지연시킵니다. JS는 defer/async로, CSS는 꼭 필요한 것만 먼저 불러오세요.
