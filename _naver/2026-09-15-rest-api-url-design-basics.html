REST API URL 설계가 뭔가요 — 좋은 엔드포인트 짓는 규칙

2026. 9. 15. · 백엔드

한 줄 요약 — URL엔 자원(명사)을, 동작은 HTTP 메서드로 표현하는 일관된 규칙으로 예측 가능한 엔드포인트를 짓습니다.

 

URL을 마음대로 지으면 헷갈린다

/getUser, /deleteUserById처럼 규칙 없이 지으면 매번 문서를 봐야 합니다. REST API URL 설계는 자원 중심의 일관된 규칙으로 예측 가능하게 만드는 것입니다.

 

핵심 규칙
규칙 좋은 예 나쁜 예
명사로 /users /getUsers
동작은 메서드 DELETE /users/1 /deleteUser?id=1

 

메서드로 동작 표현
GET    /users      목록 조회
POST   /users      생성
PUT    /users/1    수정
DELETE /users/1    삭제
-> URL=자원, 메서드=동작

 

실무 포인트

동사를 URL에 넣지 마세요(POST /users). 필터·정렬·페이징은 /users?role=admin&page=2처럼 쿼리 파라미터로 둡니다. 일관성이 최고의 문서입니다.

주의 — 예외를 남발하면 규칙의 의미가 사라집니다. 팀 전체가 일관되게 지켜야 이름만 보고 동작을 짐작할 수 있습니다.
