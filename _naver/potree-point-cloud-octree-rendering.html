한 줄 요약 — 수억 개 점을 한 번에 로드하지 않고도 매끄럽게 탐색하게 해주는 Potree의 옥트리 기반 LOD 스트리밍 구조를 정리했습니다.

 

왜 지금 Potree를 알아야 하는가

라이다 스캔이나 드론 사진측량 포인트클라우드는 수천만~수억 개의 점으로 구성되는 경우가 흔합니다. 일반 3D 라이브러리로 통째로 로드하면 브라우저 메모리가 감당하지 못합니다. Potree는 데이터를 옥트리로 미리 전처리해 카메라 위치에 따라 필요한 부분만 스트리밍합니다.

 

 

옥트리 전처리: 공간을 재귀적으로 8분할한다

Potree Converter로 원본 LAS/LAZ를 전처리하면, 전체 공간을 하나의 박스로 감싼 뒤 8개의 하위 박스로 재귀적으로 나누는 옥트리 구조가 만들어집니다. 각 노드에는 서브샘플링된 대표 점이 저장되고 하위로 갈수록 세밀한 포인트가 추가됩니다.

 

카메라 거리 기반 LOD 스트리밍

화면을 렌더링할 때마다 카메라 절두체 안의 노드만 후보로 삼고, 거리에 따라 어느 깊이까지 하위 노드를 불러올지 결정합니다. 가까운 영역은 조밀하게, 먼 영역은 상위 노드의 성긴 포인트로 충분한 인상을 줍니다.

항목 설명
옥트리 노드 공간을 재귀 8분할한 단위
LOD 결정 기준 카메라 거리 + 투영 크기
Frustum Culling 시야 밖 노드는 로드 제외

 

예제 — Potree 뷰어 초기화와 포인트클라우드 로드
window.viewer = new Potree.Viewer(document.getElementById('potree_render_area'));
viewer.setEDLEnabled(true);
viewer.setPointBudget(2000000);

Potree.loadPointCloud('pointclouds/site-scan/metadata.json', 'siteScan', (e) => {
  const pointcloud = e.pointcloud;
  const material = pointcloud.material;

  material.size = 1;
  material.pointSizeType = Potree.PointSizeType.ADAPTIVE;
  material.shape = Potree.PointShape.CIRCLE;

  viewer.scene.addPointCloud(pointcloud);
  viewer.fitToScreen();
});

setPointBudget으로 지정한 예산 안에서 자동으로 로드할 노드를 조절하므로, 저사양 기기에서는 값을 낮춰 프레임 드롭을 막을 수 있습니다.

 

실무 포인트

전처리(옥트리 변환)는 반드시 배포 전에 완료해두세요. CPU와 디스크 I/O를 많이 쓰는 배치 작업이므로 업로드 파이프라인 단계에서 미리 수행해야 합니다.

pointBudget을 기기군별로 다르게 설정하세요. 데스크톱과 모바일이 같은 예산을 쓰면 한쪽은 버벅이고 한쪽은 상세도가 과도하게 낮아집니다.

주의 — 좌표계 변환을 전처리 단계에서 미리 처리하세요. 라이다 원본이 로컬 측량 좌표계인 경우가 많아, 웹 지도와 정렬하려면 변환 행렬을 미리 구워두는 것이 실행 시점 계산보다 안전합니다.
