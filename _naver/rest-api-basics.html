REST API가 뭔가요 — HTTP 메서드와 설계 기초

2026. 9. 1. · 백엔드

한 줄 요약 — REST는 URL로 자원을, HTTP 메서드로 동작을 표현하는 설계 스타일이며, URL에 동사가 들어가면 설계를 다시 검토할 신호입니다.

 

REST는 왜 이렇게 자주 언급되나

프론트엔드와 백엔드가 통신할 때 가장 널리 쓰이는 방식이 REST API입니다. 특정 기술이 아니라 HTTP를 활용해 자원을 다루는 설계 스타일입니다. 잘 설계된 REST API는 URL과 메서드만 보고도 무슨 동작인지 예측할 수 있습니다.

 

HTTP 메서드와 CRUD의 대응
메서드 의미 예시
GET 조회 GET /users/1
POST 생성 POST /users
PATCH 부분 수정 PATCH /users/1
DELETE 삭제 DELETE /users/1

 

좋은 URL 설계 vs 나쁜 URL 설계
나쁜 예: GET /getUser?id=1, POST /deleteUser
좋은 예: GET /users/1, DELETE /users/1

URL은 "무엇"(자원)을 나타내고, "어떻게 할지"는 HTTP 메서드가 담당해야 합니다.

 

예제 — Spring Boot REST 컨트롤러
@RestController
@RequestMapping("/api/users")
public class UserController {
    @GetMapping("/{id}")
    public UserDto getUser(@PathVariable Long id) { ... }

    @PostMapping
    public UserDto createUser(@RequestBody CreateUserRequest req) { ... }
}

 

실무 포인트

생성 성공은 200이 아니라 201 Created, 자원이 없으면 404를 반환해야 클라이언트가 응답을 명확히 구분할 수 있습니다.

주의 — GET 요청은 상태를 변경하지 않아야 합니다. GET으로 데이터를 삭제·변경하면 캐시나 크롤러에 의해 의도치 않게 호출될 위험이 있습니다.
