AOP가 뭔가요 — 로깅·트랜잭션 같은 공통 관심사 분리하기

백엔드

한 줄 요약 — AOP는 로깅·트랜잭션 같은 횡단 관심사를 한곳에 모아 필요한 지점에 자동으로 끼워 넣습니다.

 

로깅 코드가 모든 메서드에 반복된다

메서드마다 "시작 로그·실행·끝 로그" 코드가 반복되면 핵심 로직이 파묻힙니다. 이렇게 여러 곳에 흩어지는 공통 관심사를 횡단 관심사라 하고, AOP는 이를 한곳에 모아 자동으로 끼워 넣습니다.

 

핵심 용어
용어 의미
Aspect 공통 기능 모듈
Advice 실제 부가 코드
Pointcut 어디에 적용할지

 

예시 (로깅 Aspect)
@Aspect @Component
public class LoggingAspect {
    @Around("execution(* com.app.service..*(..))")
    public Object log(ProceedingJoinPoint pjp) throws Throwable {
        System.out.println("시작");
        Object r = pjp.proceed();
        System.out.println("끝");
        return r;
    }
}

 

실무 포인트

스프링의 @Transactional도 AOP로 동작합니다(앞뒤에 시작·커밋을 자동 삽입). 로깅·권한·성능 측정 같은 공통 관심사에만 쓰고, 핵심 로직까지 AOP로 숨기지 마세요.

주의 — 스프링 AOP는 프록시 기반이라 같은 클래스 내부에서 자기 메서드를 직접 호출하면 적용되지 않습니다(@Transactional 안 먹는 흔한 원인).
