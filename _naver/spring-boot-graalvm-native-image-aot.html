GraalVM Native Image로 스프링 부트 컴파일하기 — AOT 처리와 리플렉션 함정

백엔드

한 줄 요약 — GraalVM Native Image는 콜드 스타트를 크게 줄이지만 런타임 리플렉션은 힌트 없이는 조용히 깨집니다. Spring AOT 처리 방식과 함정을 정리했습니다.

 

왜 지금 Native Image를 다시 봐야 하는가

인스턴스가 요청마다 뜨고 사라지는 서버리스 환경이나 오토스케일링 쿠버네티스 환경에서는 JVM의 시작 시간과 초기 메모리 사용량 자체가 비용이 됩니다. GraalVM Native Image는 애플리케이션을 빌드 시점에 미리 분석해 네이티브 실행 파일로 컴파일해 이 문제를 해결합니다. Spring Boot 3부터는 AOT 처리 인프라를 정식 지원합니다.

 

닫힌 세계 가정(Closed-World Assumption)

Native Image의 핵심 전제는 빌드 시점에 도달 가능한 모든 코드 경로를 정적으로 분석해서, 호출되지 않는 코드는 바이너리에서 제거하는 것입니다. 문제는 리플렉션·동적 프록시처럼 런타임에야 결정되는 코드를 정적 분석기가 미리 알아낼 수 없다는 점입니다. 이런 코드는 도달 불가능으로 판단돼 빠지고, 실행 중 ClassNotFoundException으로 터집니다.

 

Spring AOT가 이 간극을 메우는 방식

Spring Framework 6와 Spring Boot 3는 빌드 시점에 애플리케이션 컨텍스트를 실제로 구동해보고, 등록된 빈 정의·프록시·리플렉션 사용 지점을 분석해 힌트 파일로 미리 생성해두는 AOT 단계를 도입했습니다.

단계 기존 JVM 실행 Native Image(Spring AOT)
컴포넌트 스캔 런타임에 매번 수행 빌드 시점 1회, 코드로 생성
리플렉션 접근 제약 없음 metadata에 명시된 것만 허용
시작 시간 수백 ms~수 초 수십 ms 이내

 

예제 — 커스텀 리플렉션 힌트 등록
@Configuration
@ImportRuntimeHints(MyRuntimeHints.class)
public class AppConfig {
}

class MyRuntimeHints implements RuntimeHintsRegistrar {
    @Override
    public void registerHints(RuntimeHints hints, ClassLoader classLoader) {
        hints.reflection().registerType(
            LegacyDto.class,
            builder -> builder.withMembers(
                MemberCategory.INVOKE_DECLARED_CONSTRUCTORS,
                MemberCategory.DECLARED_FIELDS
            )
        );
    }
}

서드파티 라이브러리가 내부적으로 리플렉션을 쓰는데 Spring AOT 처리기가 자동 감지하지 못하는 경우, RuntimeHintsRegistrar로 수동 힌트를 등록해야 런타임 에러 없이 동작합니다.

 

실무 포인트

네이티브 빌드는 로컬에서 최소 한 번 반드시 통과시키세요. 일반 JVM에서는 멀쩡히 동작하던 코드가 Native Image 빌드 후에만 실패하는 경우가 흔하므로, CI에 네이티브 빌드+통합 테스트를 별도로 추가해야 합니다.

Jackson 직렬화 대상 DTO는 특히 주의하세요. @RegisterReflectionForBinding을 명시하지 않으면 빌드는 성공해도 런타임 역직렬화가 조용히 실패할 수 있습니다.

주의 — 네이티브 빌드 시간 자체가 깁니다. 정적 분석 특성상 애플리케이션이 커질수록 빌드 시간이 늘어나므로, 매 커밋마다 돌리기보다 배포 직전 단계에서만 수행하는 것이 현실적입니다.
