페이지네이션 구현 기초 — OFFSET과 커서 방식의 차이

백엔드

한 줄 요약 — OFFSET은 페이지 번호 이동에 적합하지만 뒤 페이지가 느려지고, 커서 방식은 성능이 일정하고 무한 스크롤에 적합합니다.

 

목록을 한 번에 다 주면 안 되나

게시글 10만 개를 한 번에 내려주면 감당이 안 됩니다. 페이지네이션은 목록을 나눠 보여주는 기법으로, OFFSET 기반과 커서 기반이 있습니다.

 

OFFSET 기반
SELECT * FROM posts ORDER BY id DESC LIMIT 10 OFFSET 20;
-- 앞 20개 건너뛰고 그다음 10개

구현이 직관적이지만 뒤 페이지로 갈수록 느려지고, 조회 중 새 글이 추가되면 항목이 밀려 중복·누락이 생깁니다.

 

커서 기반
SELECT * FROM posts WHERE id < 100 ORDER BY id DESC LIMIT 10;
-- 마지막으로 본 위치(100)부터

앞 행을 건너뛰지 않고 인덱스로 바로 위치를 찾으므로 뒤 페이지로 가도 성능이 일정합니다.

 

두 방식 비교
항목 OFFSET 커서
뒤 페이지 성능 나빠짐 일정
데이터 밀림 발생 안 발생
적합한 UI 페이지 번호 무한 스크롤

 

실무 포인트

무한 스크롤에는 커서 방식이 정답에 가깝습니다. 데이터 밀림이 없고 성능이 일정하기 때문입니다.

주의 — 커서는 정렬·커서 기준 컬럼에 인덱스가 있어야 빠릅니다. 인덱스가 없으면 커서 방식도 느려집니다.
