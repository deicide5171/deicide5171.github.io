deck.gl TripsLayer로 이동 경로 시간 애니메이션 만들기

GIS

한 줄 요약 — 좌표를 매 프레임 재계산하지 않고 GPU 셰이더에서 currentTime으로 직접 클리핑하는 TripsLayer의 동작 원리를 정리했습니다.

 

왜 지금 TripsLayer를 알아야 하는가

시간에 따라 위치가 바뀌는 궤적을 지도 위에서 움직이게 보여주는 요구는 흔합니다. 순진하게 구현하면 매 프레임 자바스크립트에서 좌표 배열을 다시 계산하게 되는데, 궤적 개수가 수백 개를 넘으면 이 자체가 프레임 드롭 원인이 됩니다. TripsLayer는 좌표 재계산을 반복하지 않는 방식으로 이를 해결합니다.

 

 

전체 경로와 타임스탬프를 한 번만 GPU에 올린다

TripsLayer는 전체 좌표와 타임스탬프 배열을 GPU 버퍼에 딱 한 번 업로드합니다. 이후 자바스크립트는 currentTime 하나만 매 프레임 갱신하며, 실제로 어디까지 그릴지는 GPU의 정점 셰이더가 직접 판단합니다.

 

trailLength로 궤적의 "꼬리" 길이를 제어한다

지나온 지점까지 선을 다 그리면 현재 위치를 알아보기 어렵습니다. trailLength로 현재 시각에서 얼마 이전까지만 꼬리로 그릴지 지정할 수 있고, 보통 현재 위치에 가까울수록 불투명하게 그라디언트를 줘 이동 방향과 속도감을 표현합니다.

파라미터 역할
getPath / getTimestamps 좌표·시각 배열 반환
currentTime 현재 재생 시각(매 프레임 갱신)
trailLength 꼬리로 표시할 구간 길이

 

예제 — TripsLayer로 차량 궤적 애니메이션 구성
const tripsLayer = new TripsLayer({
  id: 'vehicle-trips',
  data: vehicleTrips,
  getPath: (d) => d.path,
  getTimestamps: (d) => d.timestamps,
  getColor: [30, 144, 255],
  widthMinPixels: 3,
  trailLength: 60,
  currentTime: 0,
});

let time = 0;
function animate() {
  time = (time + 1) % maxTimestamp;
  deckOverlay.setProps({
    layers: [tripsLayer.clone({ currentTime: time })],
  });
  requestAnimationFrame(animate);
}
animate();

currentTime만 갱신해 레이어를 다시 만들면, 좌표·타임스탬프 데이터는 매번 재전송되지 않고 GPU에 이미 올라간 버퍼를 재사용합니다.

 

실무 포인트

타임스탬프의 시작 기준을 궤적마다 통일하세요. 실제 시각 기준이어야 여러 궤적이 currentTime에서 상대적으로 올바른 위치에 놓입니다.

대량 궤적을 다룰 때는 접근자 함수 비용에 주의하세요. 단순 필드 참조로 유지해 불필요한 변환 연산을 피해야 합니다.

주의 — 실시간 데이터라면 currentTime을 실제 시각과 동기화할지 배속 재생할지 정책을 먼저 정하세요. 라이브 트래킹과 과거 리플레이는 시간 매핑 방식이 달라야 합니다.
