GraphQL이 뭔가요 — REST와 무엇이 다른지 기초부터

시스템설계

한 줄 요약 — GraphQL은 클라이언트가 필요한 데이터의 모양을 직접 명시해 한 번에 딱 맞게 받는 방식이며, 단순 CRUD면 REST가 더 적합합니다.

 

REST의 불편함에서 출발한다

REST는 안 쓰는 필드까지 딸려오고(오버페칭), 사용자와 주문을 함께 보려면 여러 번 호출해야 합니다(언더페칭). GraphQL은 필요한 데이터 모양을 명시해 한 번에 받아옵니다.

 

GraphQL 쿼리 예시
query {
  user(id: 1) {
    name
    email
    orders { item, price }   // 주문까지 한 번에
  }
}

한 번의 요청으로 필요한 필드만 정확히 받습니다.

 

REST vs GraphQL
항목 REST GraphQL
엔드포인트 자원마다 여러 개 보통 하나
데이터 양 서버가 고정 클라이언트가 결정
캐싱 HTTP 캐싱 쉬움 까다로움

 

실무 포인트

GraphQL이 무조건 낫다는 건 오해입니다. 데이터 요구가 복잡할 때 빛을 발하지만, 단순 CRUD는 REST가 더 간단하고 캐싱·모니터링도 쉽습니다.

주의 — 서버에서 N+1 문제가 발생하기 쉽습니다. DataLoader 같은 배치 로딩으로 막아야 합니다.
