팝오버 위치 계산, JS 없이 CSS로 — CSS Anchor Positioning 실전

2026. 8. 24. · 프론트엔드

한 줄 요약 — 툴팁·드롭다운 위치 계산에 써온 Floating UI 같은 JS 라이브러리를, 브라우저 네이티브 CSS Anchor Positioning API가 어떻게 대체하는지 정리했습니다.

 

왜 지금까지 JS가 필요했을까요

드롭다운 메뉴가 화면 오른쪽 끝에서 잘리지 않게, 툴팁이 뷰포트를 벗어나면 반대편으로 뒤집히게 — 이런 "앵커 요소를 기준으로 다른 요소의 위치를 계산하는" 로직은 지금까지 거의 전부 JavaScript의 몫이었습니다. Floating UI(구 Popper.js)가 사실상 업계 표준으로 자리 잡은 이유도, 브라우저 뷰포트 충돌 감지와 위치 재계산을 순수 CSS로는 할 수 없었기 때문입니다.

CSS Anchor Positioning API는 이 문제를 플랫폼 레벨로 끌어올립니다. 임의의 요소를 앵커로 지정하고, 다른 요소를 그 앵커에 상대적으로 배치하며, 공간이 부족하면 자동으로 대체 위치로 전환하는 것까지 CSS만으로 표현할 수 있습니다.

 

핵심 개념 1 — anchor-name과 anchor()로 위치 연결하기

앵커가 될 요소에 anchor-name을 부여하고, 위치를 잡을 요소에서 position-anchor로 참조한 뒤 anchor() 함수로 좌표를 계산합니다. 기존에는 JS로 getBoundingClientRect()를 호출해 픽셀 값을 계산했던 작업을, 브라우저 레이아웃 엔진이 리페인트 없이 직접 처리한다는 점이 핵심 차이입니다.

.trigger-button {
  anchor-name: --my-anchor;
}

.tooltip {
  position: fixed;
  position-anchor: --my-anchor;
  top: anchor(--my-anchor bottom);
  left: anchor(--my-anchor left);
}

 

핵심 개념 2 — position-try-fallbacks, 충돌 시 자동 전환

Anchor Positioning의 진짜 가치는 공간 부족 시 자동 대체(fallback) 처리에 있습니다. position-try-fallbacks에 대체 위치 목록을 지정하면, 브라우저가 뷰포트 충돌을 감지해 순서대로 시도합니다. flip-block/flip-inline 같은 내장 키워드 외에 @position-try로 완전히 커스텀한 대체 위치 세트도 정의할 수 있습니다.

.tooltip {
  position-try-fallbacks: flip-block, flip-inline, --custom-fallback;
}

@position-try --custom-fallback {
  top: anchor(--my-anchor top);
  left: anchor(--my-anchor right);
}

 

핵심 개념 3 — 기존 JS 라이브러리 방식과의 비교
구분 Floating UI(JS) CSS Anchor Positioning
위치 계산 주체 JS가 매 프레임 재계산 브라우저 레이아웃 엔진
번들 크기 ~5-10KB 0 (플랫폼 기능)
브라우저 지원 전 브라우저 제한적(Chromium 계열 우선)

 

가장 큰 실무 이점은 성능입니다. JS 기반 위치 계산은 스크롤·리사이즈마다 레이아웃을 강제로 다시 읽어 재계산하는 비용이 들지만, 네이티브 Anchor Positioning은 브라우저 내부 레이아웃 파이프라인에 통합돼 있어 이 왕복이 없습니다.

 

실무 도입 시 이것만은 챙기세요
1. 브라우저 지원 범위를 먼저 확인하세요 — @supports (anchor-name: --a) 피처 쿼리로 미지원 브라우저에서는 Floating UI 폴백을 유지하는 이중 경로가 현실적입니다.
2. 네이티브 popover 속성과 함께 쓸 때 진가가 나옵니다 — 최상위 레이어에 렌더링되어 z-index 전쟁에서 자유로운 popover와 Anchor Positioning을 결합하면 JS 없이 완전한 팝오버를 만들 수 있습니다.
3. anchor-name은 전역 스코프임을 주의하세요 — 같은 이름을 재사용하면 예상과 다른 동작이 나올 수 있어 컴포넌트별 고유 이름 규칙이 필요합니다.

 

마무리 — 3줄 요약

① CSS Anchor Positioning은 anchor-name/anchor()로 임의 요소를 기준점 삼아 다른 요소를 배치하는 기능을 플랫폼 레벨로 제공합니다.
② position-try-fallbacks가 뷰포트 충돌을 감지해 대체 위치로 자동 전환해주어 Floating UI의 핵심 기능을 대체합니다.
③ 브라우저 지원이 제한적이므로 @supports 기반 점진적 향상 전략과 네이티브 popover API와의 조합이 실무 적용의 핵심입니다.
