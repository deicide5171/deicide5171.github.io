구조화된 동시성(Structured Concurrency)으로 JDK 21 비동기 코드 정리하기

백엔드

한 줄 요약 — 하위 작업의 생명주기를 코드 블록에 종속시켜 취소·예외 전파 보일러플레이트를 없애는 구조화된 동시성 API를 정리했습니다.

 

왜 지금 구조화된 동시성을 다시 봐야 하는가

여러 독립 작업을 병렬 실행 후 합치는 패턴을 CompletableFuture로 짜면, "하나가 실패하면 나머지도 취소" 같은 요구사항에 상당한 보일러플레이트가 필요합니다. 예외 스택 트레이스도 원래 호출 흐름과 단절되기 쉽습니다. 구조화된 동시성은 이 문제를 근본적으로 해결합니다.

 

작업의 생명주기를 코드 블록에 종속시킨다

StructuredTaskScope를 try-with-resources로 열면, 그 블록 안에서 fork한 모든 작업은 블록이 닫히기 전에 반드시 join되거나 취소됩니다. 스코프를 빠져나가면서 작업이 백그라운드에 좀비처럼 남는 상황이 구조적으로 불가능해집니다.

 

실패 정책(ShutdownOnFailure)이 취소 전파를 자동화한다

ShutdownOnFailure를 쓰면 하위 작업 중 하나라도 예외를 던지면 나머지 모두에 자동으로 취소 신호가 전파됩니다. throwIfFailed()를 호출하면 원본 예외가 원인 체인을 보존한 채 재발생해 디버깅도 명확해집니다.

항목 CompletableFuture Structured Concurrency
생명주기 명시적 수동 관리 스코프 종료 시 자동 정리
실패 전파 수동 처리 자동 전파
가상 스레드 별도 설정 필요 기본 fork 방식

 

예제 — 병렬 조회와 실패 시 자동 취소
try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
    Subtask<User> userTask = scope.fork(() -> fetchUser(userId));
    Subtask<List<Order>> orderTask = scope.fork(() -> fetchOrders(userId));
    Subtask<List<String>> recommendTask = scope.fork(() -> fetchRecommendations(userId));

    scope.join();
    scope.throwIfFailed();

    return new UserPageResponse(userTask.get(), orderTask.get(), recommendTask.get());
}

fetchOrders에서 예외가 나면 나머지 두 작업도 즉시 인터럽트되고, throwIfFailed()가 원본 예외를 던집니다. 무엇이 얼마나 진행됐는지 신경 쓰지 않아도 스코프 하나로 생명주기가 정리됩니다.

 

실무 포인트

JDK 버전과 API 안정화 상태를 먼저 확인하세요. 여러 버전을 거치며 프리뷰로 발전해 왔으므로 사용 중인 JDK의 API 상태를 확인해야 합니다.

가상 스레드와 함께 쓸 때 블로킹 I/O 라이브러리의 스레드 로컬 사용을 점검하세요. 기본적으로 가상 스레드 기반이므로 피닝 문제와 함께 검토해야 합니다.

주의 — 모든 병렬 작업에 무조건 적용하지 마세요. 결과에 순차적 의존성이 있는 로직에 억지로 적용하면 코드가 오히려 부자연스러워집니다.
