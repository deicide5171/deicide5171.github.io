로드밸런서란 무엇인가 — L4/L7 차이와 실무 선택 기준

2026. 8. 31. · 시스템설계

한 줄 요약 — L4는 IP·포트만 보고 빠르게 분배하고, L7은 URL·헤더까지 확인해 더 정교하게 라우팅합니다.

 

왜 서버 한 대로는 부족한가

서비스가 커지면 서버 한 대가 감당할 수 있는 트래픽에 한계가 옵니다. 여러 대의 서버로 트래픽을 나눠주는 장치가 로드밸런서이며, 동작하는 네트워크 계층에 따라 크게 L4와 L7로 나뉩니다.

 

L4 vs L7 로드밸런서
항목 L4 L7
동작 계층 전송 계층(TCP/UDP) 애플리케이션 계층(HTTP)
확인 가능 정보 IP, 포트 URL 경로, 헤더, 쿠키
대표 예시 AWS NLB, LVS AWS ALB, Nginx, HAProxy

 

언제 무엇을 쓸까
1. 단순히 트래픽만 고르게 나누면 되는가? → L4로 충분
2. URL 경로·헤더에 따라 다른 서버로? → L7 필요
3. SSL 종료를 로드밸런서에서? → L7에서 처리하는 것이 일반적
4. 매우 높은 처리량이 최우선? → L4를 앞단에 두는 계층 구조도 흔함

 

로드밸런싱 알고리즘

라운드 로빈은 순서대로 분배하고, 최소 연결은 연결 수가 가장 적은 서버로, IP 해시는 같은 클라이언트를 항상 같은 서버로 보냅니다.

 

실무 포인트

헬스체크를 반드시 설정해야 합니다. 죽은 서버로 계속 트래픽을 보내면 사용자에게 에러가 노출됩니다.

주의 — 세션을 서버 메모리에 저장하는 구조라면 스티키 세션이 필요하지만, 확장성을 해치므로 세션을 Redis 같은 외부 저장소로 옮기는 것이 더 나은 장기 해법입니다.
