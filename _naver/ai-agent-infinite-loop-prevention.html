AI 에이전트가 도구 호출을 무한 반복할 때 — 루프 방지와 종료 조건 설계

AI

한 줄 요약 — 에이전트의 무한 루프는 코드 버그가 아니라 모델이 그럴듯한 판단을 반복해서 내리는 구조적 문제입니다. 종료 조건은 프롬프트가 아니라 오케스트레이션 코드 레벨에서 강제해야 합니다.

 

왜 에이전트가 멈추지 않을까

AI 에이전트에게 다단계 작업을 맡겼는데, 로그를 보니 같은 파일을 읽고 같은 검색을 반복하며 몇 분째 끝나지 않는 경우를 겪게 됩니다. 결제 대시보드를 열어보면 토큰 사용량이 예상보다 몇 배는 더 찍혀 있습니다. 에이전트는 스스로 다음에 뭘 할지 판단하며 도구를 반복 호출하는 구조라, 이 판단 로직에 틈이 있으면 종료 조건을 스스로 찾지 못하고 계속 맴돌 수 있습니다.

이 문제가 골치 아픈 이유는 명백한 버그가 있는 게 아니라는 점입니다. 모델이 매번 "이 정보로는 부족하니 한 번 더 찾아보자"는 그럴듯한 판단을 반복하는 것이므로, 정상 동작과 무한 루프를 구분하기 어려울 때가 많습니다.

 

 

핵심 개념 1 — 루프가 생기는 세 가지 패턴

같은 도구를 같은 인자로 반복 호출하거나, A→B→A로 진동하거나, 컨텍스트 누적으로 판단력이 저하되어 이미 시도했던 접근을 다시 시도하는 경우입니다. 세 번째 패턴이 가장 알아채기 어렵습니다 — 겉으로는 조금씩 다른 시도처럼 보이지만 실제로는 몇 스텝 전 실패했던 접근을 형태만 바꿔 반복하는 경우가 많습니다.

 

핵심 개념 2 — 종료 조건은 코드로 강제해야 한다

모델에게 "충분하다고 판단되면 멈춰"라고 프롬프트로만 지시하는 것은 안전장치가 되지 못합니다. 모델은 확률적으로 다음 행동을 고르는 존재라, 드물지만 반복을 계속 고를 가능성이 항상 남아 있습니다. 신뢰할 수 있는 방식은 에이전트를 감싸는 오케스트레이션 코드 레벨에서 하드 리밋을 거는 것입니다.

 

예제 — 반복 횟수 제한과 반복 감지
class AgentLoopGuard:
    def __init__(self, max_iterations=15, max_repeat=3):
        self.max_iterations = max_iterations
        self.max_repeat = max_repeat
        self.iteration = 0
        self.call_history = []

    def check(self, tool_name, tool_args):
        self.iteration += 1
        if self.iteration > self.max_iterations:
            return False  # 절대적 상한선

        signature = (tool_name, tuple(sorted(tool_args.items())))
        self.call_history.append(signature)
        recent = self.call_history[-6:]
        if recent.count(signature) >= self.max_repeat:
            return False
        return True

이 가드는 두 겹으로 동작합니다. 절대적인 최대 스텝 수로 어떤 상황에서든 결국은 멈추게 하고, 최근 호출 이력에서 동일한 조합이 반복되는지 감지해 더 빨리 개입합니다.

실무 포인트

작업 유형별로 다른 반복 상한을 두세요. 단순 조회는 5회, 복잡한 리팩터링은 30회처럼 예상 복잡도에 맞춰야 조기 종료나 비용 낭비를 둘 다 피할 수 있습니다.

비용 상한도 함께 걸어두세요. 스텝 수뿐 아니라 누적 토큰 사용량 자체에 상한을 걸면 한 스텝에서 비정상적으로 큰 컨텍스트를 반복 처리하는 경우까지 방어할 수 있습니다.

주의 — 특정 반복 횟수를 넘기면 자동으로 계속하는 대신 사람에게 확인받는 체크포인트를 두면, 완전 자동화와 안전성 사이의 절충점을 만들 수 있습니다.
