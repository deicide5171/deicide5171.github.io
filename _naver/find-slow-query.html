느린 쿼리 찾기 — 어떤 쿼리가 DB를 느리게 하는지 잡아내기

2026. 9. 4. · 데이터베이스

한 줄 요약 — 슬로우 쿼리 로그로 범인 쿼리를 찾고, EXPLAIN으로 Full Table Scan 여부부터 확인하는 것이 튜닝의 첫걸음입니다.

 

"DB가 느려요"에서 시작하기

DB가 원인이라면 대부분 특정 쿼리 몇 개가 유독 느려서 전체 응답을 끌어내리는 경우입니다. 그 범인 쿼리를 찾는 것이 튜닝의 첫걸음입니다.

 

1단계: 느린 쿼리 로그 켜기
-- MySQL: 1초 이상 걸린 쿼리 기록
SET GLOBAL slow_query_log = 'ON';
SET GLOBAL long_query_time = 1;

-- PostgreSQL
-- log_min_duration_statement = 1000

 

2단계: 실행 계획 보기
EXPLAIN ANALYZE
SELECT * FROM orders WHERE user_id = 123 AND status = 'PAID';
봐야 할 것 의미
Full Table Scan(ALL) 인덱스 못 탐 → 인덱스 후보
정렬·임시 테이블 메모리·디스크 부담

 

흔한 원인과 처방
WHERE 컬럼에 인덱스 없음 -> 인덱스 추가
너무 많은 데이터 가져옴 -> 필요한 컬럼만, 페이지네이션
N+1로 쿼리 반복 -> JOIN·일괄 조회로 묶기

 

실무 포인트

인덱스를 걸었는데도 안 타는 대표 원인은 컬럼에 함수를 씌우는 것입니다. WHERE DATE(created_at)=...는 인덱스를 못 타지만 범위 조건으로 바꾸면 탑니다.

주의 — EXPLAIN ANALYZE는 실제로 쿼리를 실행합니다. UPDATE/DELETE에 붙이면 데이터가 진짜 바뀌므로 조회 쿼리에만, 가능하면 복제본에서 확인하세요.
