쿠버네티스 인그레스가 뭔가요 — 하나의 입구로 여러 서비스 노출

인프라

한 줄 요약 — 인그레스는 하나의 진입점에서 도메인·경로에 따라 여러 서비스로 트래픽을 라우팅하며 TLS도 처리합니다.

 

서비스마다 로드밸런서를 만들면 낭비다

외부 노출을 서비스 LoadBalancer 타입으로 하면, 서비스 10개엔 로드밸런서·공인 IP가 10개 필요해 비용·관리가 부담입니다. 인그레스는 하나의 진입점에서 도메인·URL 경로를 보고 알맞은 서비스로 라우팅합니다.

 

무엇으로 나누나
기준 예
호스트 api.example.com → api
경로 /shop → shop, /blog → blog

 

라우팅 예시
              /api  -> api-service
example.com   /shop -> shop-service
 (Ingress)    /blog -> blog-service
하나의 도메인/IP로 들어와 경로에 따라 분배

 

실무 포인트

규칙(YAML)만으로는 안 되고 Ingress 컨트롤러(nginx-ingress 등)를 설치해야 동작합니다. TLS(HTTPS)를 인그레스에서 한곳에서 처리하며, cert-manager로 인증서 자동 발급을 붙입니다. 흐름은 인그레스 → 서비스 → 파드입니다.

주의 — Ingress 규칙만 만들고 컨트롤러를 설치하지 않으면 규칙이 적용되지 않습니다.
