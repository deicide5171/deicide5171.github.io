무상태 토큰인데 로그아웃이 왜 어려울까 — JWT 즉시 폐기(Revocation) 전략 비교

백엔드

한 줄 요약 — JWT를 즉시 무효화하고 싶을 때 쓰는 블랙리스트·짧은 TTL+회전·토큰 버전 세 가지 전략을 비교했습니다.

 

왜 지금 JWT Revocation을 다시 봐야 하는가

JWT는 서버 상태 조회 없이 서명 검증만으로 인증을 끝내는 무상태 방식입니다. 그런데 서버가 상태를 들고 있지 않다면 발급된 토큰을 지금 당장 무효로 만들 방법이 원천적으로 없습니다. 계정 탈취가 의심될 때 즉시 접근을 차단해야 하는 요구사항과 JWT의 무상태 철학이 정면으로 충돌합니다.

 

블랙리스트: 폐기된 토큰만 별도로 기록

폐기하고 싶은 토큰을 Redis 같은 저장소에 만료 시각까지만 저장하고 매 요청마다 확인합니다. 이 토큰 하나만 콕 집어 죽이는 것이 정확히 가능하지만, 매 요청마다 조회가 추가되고 저장소 자체가 새로운 장애 지점이 됩니다.

 

짧은 TTL + Refresh 회전, 그리고 토큰 버전

Access Token 수명을 5~15분으로 짧게 주고 Refresh Token은 사용할 때마다 새 값으로 교체(회전)합니다. 탈취 감지 시 Refresh Token 레코드만 지우면 Access Token은 짧은 시간 안에 자연 소멸합니다. 토큰 버전 관리는 사용자 레코드의 버전 값을 클레임에 포함시켜, 버전을 올리면 그 사용자의 모든 토큰이 한꺼번에 무효화되는 방식입니다.

전략 즉시성 적합한 시나리오
블랙리스트 즉시 특정 토큰 하나만 정밀 폐기
짧은 TTL+회전 최대 TTL만큼 지연 일반적인 로그아웃
토큰 버전 즉시 계정 전체 강제 로그아웃

 

토큰 버전 검증 필터 예제
protected void doFilterInternal(HttpServletRequest req, HttpServletResponse res,
                                 FilterChain chain) throws IOException, ServletException {
    Jws<Claims> jws = parseJwt(req);
    Long tokenVersion = jws.getBody().get("ver", Long.class);
    Long currentVersion = versionCache.getVersion(jws.getBody().getSubject());

    if (!tokenVersion.equals(currentVersion)) {
        res.sendError(HttpServletResponse.SC_UNAUTHORIZED, "Token revoked");
        return;
    }
    chain.doFilter(req, res);
}

 

실무 포인트

즉시 폐기가 반드시 필요한지부터 먼저 따져보세요. 일반 로그아웃은 클라이언트에서 토큰을 지우는 것만으로 충분한 경우가 많습니다. 계정 탈취 대응처럼 서버 강제 차단이 꼭 필요한 시나리오에만 무거운 전략을 적용하는 것이 합리적입니다.

블랙리스트와 토큰 버전을 혼동하지 마세요. 블랙리스트는 토큰 하나를, 토큰 버전은 사용자의 모든 토큰을 대상으로 합니다.

주의 — Refresh Token 회전을 구현할 때는 재사용 탐지도 함께 넣어야 합니다. 이미 폐기된 Refresh Token이 다시 사용되면 탈취로 간주하고 해당 사용자의 모든 세션을 강제 종료해야 회전의 보안 이점이 완성됩니다.
