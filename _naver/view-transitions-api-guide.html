View Transitions API로 부드러운 페이지 전환 만들기

프론트엔드

한 줄 요약 — View Transitions API는 DOM 변경 전후 스냅샷을 브라우저가 자동으로 이어줘, 별도 애니메이션 라이브러리 없이 부드러운 화면 전환을 구현하게 해줍니다.

 

왜 지금 알아야 하는가

SPA에서 화면이 "뚝" 바뀌는 것과 자연스럽게 이어지며 바뀌는 것은 사용자 체감이 크게 다릅니다. 예전에는 Framer Motion 같은 라이브러리를 붙이거나 요소 위치를 수동 계산해야 했지만, View Transitions API는 이 작업을 브라우저가 대신 처리합니다.

 

기본 사용법
function updateDOM() {
  document.querySelector('#content').innerHTML = newContent;
}

if (document.startViewTransition) {
  document.startViewTransition(() => updateDOM());
} else {
  updateDOM();
}

DOM을 갱신하는 콜백만 넘기면 브라우저가 변경 전후 스크린샷을 자동으로 찍어 크로스페이드 애니메이션을 적용합니다. 이것만으로도 화면 전환이 눈에 띄게 부드러워집니다.

 

기존 방식 vs 새로운 방식

이전에는 FLIP(First-Last-Invert-Play) 기법으로 좌표를 직접 계산해야 했습니다. 요소마다 시작·끝 위치를 구하고 transform으로 애니메이션시켜야 해서, 레이아웃이 복잡해질수록 계산이 틀어지기 쉬웠고 페이지 전체 전환에는 사실상 적용이 불가능했습니다.

.hero-image {
  view-transition-name: hero;
}

같은 view-transition-name을 가진 요소가 전환 전후에 모두 존재하면, 브라우저가 그 요소만 골라 위치와 크기가 자연스럽게 이어지는 애니메이션을 적용합니다. 상품 썸네일이 상세 페이지 큰 이미지로 이어지는 효과를 CSS 한 줄로 구현할 수 있습니다.

주의 — view-transition-name은 페이지에서 유일해야 합니다. 같은 이름을 가진 요소가 전환 시점에 두 개 이상 존재하면 브라우저가 에러를 내며 트랜지션을 건너뜁니다.

 

실무 포인트

document.startViewTransition이 없는 브라우저에서는 즉시 DOM을 갱신하도록 분기하면 되므로 점진적 향상으로 안전하게 도입할 수 있습니다. 다중 페이지 사이트도 @view-transition { navigation: auto; } 선언으로 Cross-document 전환을 지원합니다. 사용자가 모션 감소를 켜뒀다면 prefers-reduced-motion으로 지속시간을 줄이는 것도 잊지 마세요.
