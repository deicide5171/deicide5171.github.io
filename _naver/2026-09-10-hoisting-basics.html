호이스팅이 뭔가요 — 선언 전에 쓴 변수가 왜 undefined인가

프론트엔드

한 줄 요약 — 호이스팅은 변수·함수 선언이 범위 맨 위로 끌어올려진 것처럼 처리되는 현상으로, var는 undefined·let/const는 에러(TDZ)가 됩니다.

 

선언보다 먼저 썼는데 에러가 안 난다
console.log(x); // undefined (에러 아님!)
var x = 5;

이는 호이스팅 때문입니다. JS는 실행 전에 변수·함수의 "선언"을 범위 맨 위로 끌어올린 것처럼 처리합니다. 위 코드는 var x;가 올라가고 값 할당은 원래 자리에 남습니다.

 

var / let / const
종류 선언 전 사용
var undefined (버그 유발)
let / const 에러(TDZ) — 더 안전

 

함수 호이스팅
sayHi(); // 정상 (함수 선언은 통째로 끌어올려짐)
function sayHi() { console.log("안녕"); }

sayBye(); // 에러 (함수 표현식은 변수 규칙)
const sayBye = function() {};

 

실무 포인트

var 대신 let·const를 쓰세요. 선언 전 사용이 에러로 잡혀 안전합니다. 변수는 쓰기 직전에 선언해 읽는 순서대로 동작하게 하고, 함수 선언문과 표현식의 차이를 알아두세요.

주의 — var의 호이스팅은 "선언 전 undefined" 같은 헷갈리는 버그를 만듭니다. 최신 코드에선 var를 지양하세요.
