Scheduler API 딥다이브 — scheduler.yield()로 메인 스레드 블로킹 직접 제어

프론트엔드

한 줄 요약 — setTimeout(fn, 0) 편법을 대체하는 네이티브 우선순위 기반 작업 스케줄링 API로, 브라우저 렌더링 파이프라인과 직접 협조합니다.

 

왜 지금 봐야 하는가

Core Web Vitals에 INP가 도입되면서, 무거운 JS 작업이 메인 스레드를 오래 점유해 입력 응답이 늦어지는 문제가 핵심 지표가 됐습니다. 오랫동안 setTimeout(fn, 0)으로 메인 스레드를 양보하는 편법을 써왔지만, 이 API는 애초에 스케줄링을 위해 설계되지 않았습니다.

 

postTask와 우선순위 큐

scheduler.postTask(callback, options)는 콜백을 우선순위와 함께 큐에 등록합니다. 우선순위는 user-blocking, user-visible(기본값), background 세 단계로 나뉘며, 브라우저는 이를 참고해 렌더링과 입력 처리 사이에서 어떤 작업을 먼저 실행할지 판단합니다.

scheduler.yield()로 긴 작업 쪼개기

scheduler.yield()는 현재 작업이 스스로 메인 스레드를 잠깐 양보하겠다고 선언하는 API입니다. setTimeout(fn, 0)은 콜백이 큐 맨 뒤로 밀려 대기 시간이 예측 불가능했지만, yield()는 더 급한 작업이 없다면 거의 지연 없이 원래 우선순위를 유지한 채 이어서 실행됩니다.

방식 우선순위 지정 렌더링 협조
setTimeout(fn, 0) 불가능 없음
scheduler.postTask 3단계 있음
scheduler.yield 현재 우선순위 유지 있음

 

긴 목록 렌더링 청크 분할 예제
async function processLargeList(items) {
  for (let i = 0; i < items.length; i++) {
    renderItem(items[i]);

    if (i % 50 === 0) {
      if ('scheduler' in window && 'yield' in scheduler) {
        await scheduler.yield();
      } else {
        await new Promise((r) => setTimeout(r, 0));
      }
    }
  }
}

scheduler.postTask(() => updateUI(), { priority: 'user-blocking' });

 

실무 포인트

React의 자체 스케줄러와 개념적으로 유사합니다. React 18+ concurrent 모드가 자체 구현해온 우선순위 기반 작업 분할이, 네이티브 API가 성숙하면 표준 API 위로 이전될 가능성이 큽니다.

브라우저 지원 여부를 반드시 확인하세요. scheduler.yield()는 상대적으로 최신 기능이라 지원 범위가 좁으므로 폴백 경로를 함께 구현해야 합니다.

주의 — 모든 작업을 user-blocking으로 등록하면 우선순위 큐가 무의미해집니다. 실제 사용자 입력에 직접 반응하는 작업에만 최상위 우선순위를 부여하세요.
