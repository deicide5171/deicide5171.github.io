Spring Boot 'Could not autowire' 에러 해결하기 — 빈 등록 문제 잡는 법

2026. 9. 1. · 백엔드

한 줄 요약 — 클래스 문제가 아니라 Spring이 그 클래스를 빈으로 인식하지 못한 것이며, 가장 흔한 원인은 컴포넌트 스캔 범위 밖에 위치한 경우입니다.

 

이 에러가 말하는 것

Could not autowire. No beans found는 Spring 컨테이너가 해당 타입의 빈을 하나도 찾지 못했다는 뜻입니다. 클래스는 존재하는데 이 에러가 난다면 Spring이 그 클래스를 빈으로 등록하지 않은 것입니다.

 

원인 후보 4가지
원인 확인 방법
애노테이션 누락 @Service, @Component 확인
스캔 범위 밖 메인 클래스 하위 패키지인지 확인
구현체 여러 개 @Qualifier, @Primary 필요 여부

 

가장 흔한 원인 — 컴포넌트 스캔 범위
// 메인 클래스: com.example.app.Application
@SpringBootApplication
public class Application { ... }

// com.example.other 패키지는 스캔 대상이 아니다!
package com.example.other;
@Service
public class PaymentService { ... }

@SpringBootApplication은 그 패키지의 하위 패키지만 자동으로 컴포넌트 스캔합니다.

 

해결 방법
@SpringBootApplication(scanBasePackages = {"com.example.app", "com.example.other"})
public class Application { ... }

@Autowired
@Qualifier("kakaoPayService")
private PaymentService paymentService;

 

실무 포인트

에러 로그를 끝까지 읽지 않고 첫 줄만 보면 진짜 원인을 놓칩니다. 순환 참조나 다른 빈 생성 실패가 진짜 원인인 경우가 많습니다.

주의 — 테스트 코드에서만 이 에러가 난다면 @SpringBootTest의 스캔 범위나 @MockBean 설정 누락을 의심하세요.
