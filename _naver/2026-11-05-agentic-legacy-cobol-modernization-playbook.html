한 줄 요약 — Claude Code의 COBOL 현대화 자동화 발표가 IBM 주가를 떨어뜨릴 만큼 업계를 흔들었습니다. 하지만 공개된 Code Modernization Playbook을 뜯어보면 에이전트가 실제로 맡는 건 탐색·분석 단계이고, 검증된 전환과 조직 변화는 여전히 사람의 몫입니다. 이 경계를 정리했습니다.

 

왜 지금 이 판단이 중요해졌는가

"이 코볼 시스템, 유지보수할 사람도 없는데 에이전트가 통째로 현대화해주세요." 수십 년 된 메인프레임을 안고 있는 조직이라면 한 번쯤 떠올리는 요구입니다. 최근 Anthropic이 Claude Code의 레거시 시스템 현대화 기능과 함께 Code Modernization Playbook을 공개했고, 이 발표는 같은 날 IBM 주가를 10% 넘게 떨어뜨릴 만큼 시장을 흔들었습니다. 하지만 주가 반응과 실제로 에이전트가 할 수 있는 일의 범위는 다른 이야기입니다.

공개된 내용을 보면 에이전트가 자동화하는 건 코드를 전부 알아서 새 언어로 바꿔 배포하는 것이 아니라, 탐색(exploration)과 분석(analysis) 단계입니다. 의존성을 매핑하고, 업무 흐름을 문서화하고, 위험 지점을 식별하는 작업입니다. 반면 업계 비평가들은 실제 현대화에는 비즈니스 범위 정의, 동작 동등성 검증, 데이터 마이그레이션 전략, 조직 변화 관리가 함께 필요하다고 지적합니다. 이 네 가지는 코딩 도구의 범위 밖입니다.

 

전체 시스템에서의 위치

레거시 현대화 파이프라인은 세 단계로 나뉩니다. 첫 단계는 탐색·발견으로, 수십만 줄의 코볼 코드에서 모듈 간 의존성과 숨겨진 업무 규칙을 뽑아냅니다. 사람이 하면 몇 주가 걸리던 일을 에이전트가 빠르게 의존성 그래프와 업무 흐름 문서로 정리합니다. 두 번째 단계는 위험 분석·기회 매핑으로, 전환 우선순위를 제안합니다.

세 번째 단계인 실제 전환에서는 신·구 시스템을 나란히 돌리며 같은 입력에 대한 출력을 비교하는 방식이 쓰입니다. 검증을 통과한 모듈부터 점진적으로 교체합니다. 에이전트의 산출물(의존성 맵, 위험 보고서, 변환된 코드 초안)은 입력일 뿐이고, "이 모듈을 지금 바꿔도 되는가"를 최종 승인하는 자리에는 여전히 사람이 앉습니다.

 

선택의 트레이드오프
기준전면 재작성(빅뱅)에이전트 보조 점진 전환현행 유지(래핑만)
초기 가시성 확보느림빠름 — 자동 매핑빠름 — 분석 생략
전환 중 장애 위험높음낮음 — 모듈 단위 검증없음
업무 규칙 유실 위험높음낮음 — 비교 검증없음
적합한 상황레거시가 작고 단순대규모·암묵적 업무 규칙 多전환 압박 없음

 

표가 가리키는 핵심은 에이전트 보조 방식이 "더 빠른 빅뱅 재작성"이 아니라 "검증 비용을 낮춘 점진적 전환"이라는 점입니다. 탐색·분석 단계의 자동화가 전체 일정을 줄이는 것은 맞지만, 검증 단계의 신중함까지 줄여도 된다는 뜻은 아닙니다.

 

실제 프로젝트 진행 순서

1) 현대화 대상을 통째로 던지지 않고, 먼저 에이전트에게 의존성 맵과 위험 보고서부터 뽑게 합니다.
2) 위험 보고서에서 가장 고립된(의존성이 적은) 모듈을 첫 전환 대상으로 고릅니다.
3) 신·구 모듈을 나란히 돌리는 비교 검증 하네스를 먼저 구축합니다.
4) 도메인 전문가를 검증 단계에 반드시 배치합니다.
5) 데이터 마이그레이션과 조직 변화 계획은 코드 전환과 별도 트랙으로 분리해 처음부터 함께 설계합니다.

 

주의 — 신·구 시스템 비교 검증은 "같은 입력, 같은 출력"만으로 끝나지 않습니다. 코볼 시스템의 부수 효과(배치 작업 순서, 외부 시스템 호출 타이밍)까지 재현해야 진짜 동등성 검증이 됩니다. 단순 입출력 비교만 통과했다고 안심하면 운영 중 타이밍 관련 장애로 이어질 수 있습니다.

 

정리

Claude Code의 COBOL 현대화 발표는 탐색·분석 단계의 자동화이지, 전환·검증·조직 변화까지 포괄하는 완전 자동 현대화가 아닙니다. 실제 파이프라인은 탐색 → 분석 → 검증된 점진적 교체 3단계로 쪼개지며, 마지막 승인은 여전히 사람의 몫입니다. 고립도가 낮은 모듈부터 비교 검증 하네스로 시작하고, 데이터 마이그레이션·조직 변화는 코드 전환과 별도 트랙으로 처음부터 함께 설계해야 일정이 밀리지 않습니다.
