레이트 리미팅이 뭔가요 — API 요청 제한이 필요한 이유

2026. 9. 3. · 시스템설계

한 줄 요약 — 레이트 리미팅은 특정 사용자의 과도한 요청으로부터 전체 서비스를 보호하는 기법이며, 토큰 버킷 방식이 가장 널리 쓰입니다.

 

왜 요청을 일부러 막는가

한 사용자가 실수나 악의로 초당 수천 번 요청을 보내면 서버 자원이 그 사용자에게 쏠려 다른 정상 사용자가 서비스를 못 쓰게 됩니다. 레이트 리미팅은 허용 요청 수에 상한을 둬 전체 서비스를 보호합니다.

 

필요한 상황
상황 없을 때의 문제
새로고침 봇 서버 과부하
로그인 무차별 대입 계정 탈취 시도 방치
유료 API 대량 사용 비용 폭증

 

대표적인 알고리즘
고정 윈도우: 시간 구간을 딱 나눠 센다 (경계 문제)
슬라이딩 윈도우: 최근 1분을 계속 이동하며 센다
토큰 버킷: 일정 속도로 토큰 충전, 요청마다 소비 (가장 널리 씀)

 

응답으로 알려주는 방법
HTTP/1.1 429 Too Many Requests
X-RateLimit-Remaining: 0
Retry-After: 30
-> 클라이언트는 30초 뒤에 재시도

 

실무 포인트

무엇을 기준으로 제한할지(IP·계정·API 키) 먼저 정해야 합니다. IP 기준은 같은 회사·학교에서 한 IP를 공유하는 사용자가 억울하게 막힐 수 있습니다.

주의 — 여러 서버 환경에서 각 서버가 따로 세면 실제 허용량이 서버 수만큼 늘어납니다. Redis 같은 공유 저장소에 카운트를 두어야 합니다.
