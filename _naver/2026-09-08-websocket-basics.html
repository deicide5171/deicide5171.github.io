웹소켓이 뭔가요 — 실시간 통신이 필요할 때

2026. 9. 8. · 시스템설계

한 줄 요약 — 웹소켓은 한 번 연결하면 양쪽이 언제든 메시지를 보낼 수 있는 양방향 통신으로, 실시간 채팅·협업에 적합합니다.

 

HTTP만으로는 실시간이 어렵다

일반 HTTP는 "요청하면 응답"하는 단방향이라 서버가 먼저 말을 걸 수 없습니다. 웹소켓은 연결을 한 번 맺으면 양쪽 모두 언제든 메시지를 보낼 수 있습니다.

 

HTTP 폴링 vs 웹소켓
항목 폴링 웹소켓
방향 물어봐야 함 양방향
연결 요청마다 새로 유지
실시간성 폴링 주기만큼 지연 즉시

 

웹소켓의 동작
1. HTTP로 "웹소켓으로 업그레이드" 요청(핸드셰이크)
2. 서버 수락 -> 웹소켓 연결로 전환
3. 양쪽이 자유롭게 메시지 주고받음
-> "전화를 걸어두고 계속 통화"하는 것과 비슷

 

언제 필요한가
적합: 채팅, 실시간 협업, 게임, 시세
과함: 가끔 오는 알림 -> SSE / 단순 조회 -> HTTP

 

실무 포인트

서버→클라이언트 한 방향 알림만 필요하면 SSE가 더 간단합니다. 진짜 양방향이 필요할 때만 웹소켓을 쓰세요.

주의 — 연결을 계속 열어두므로 동시 접속자가 많으면 관리 부담이 큽니다. 끊김 감지·자동 재연결 로직도 필요합니다.
