Docker와 가상머신, 뭐가 다른가요 — 컨테이너 기초 개념

2026. 9. 2. · 인프라

한 줄 요약 — 가상머신은 OS 전체를 통째로 격리하고, 컨테이너는 호스트 커널을 공유하며 프로세스 단위로 격리해 훨씬 가볍습니다.

 

왜 둘 다 "격리된 환경"인데 이름이 다른가

가상머신도 컨테이너도 여러 애플리케이션을 서로 영향받지 않게 격리한다는 목표는 같지만, 격리를 만드는 방식이 완전히 다릅니다. 이 차이를 알아야 컨테이너가 왜 이렇게 가볍고 빠른지 이해할 수 있습니다.

 

구조적 차이
항목 가상머신 컨테이너
격리 단위 OS 전체 프로세스 단위(커널 공유)
부팅 시간 수십 초~수 분 1초 내외
격리 강도 강함 상대적으로 약함

 

구조 차이
가상머신: 하드웨어 -> 하이퍼바이저 -> [Guest OS+앱A] [Guest OS+앱B]
컨테이너: 하드웨어 -> 호스트 OS 커널 -> [컨테이너A] [컨테이너B]

컨테이너는 호스트의 리눅스 커널을 그대로 빌려 쓰기 때문에 커널을 새로 부팅할 필요가 없어 압도적으로 빠릅니다.

 

실무 포인트

macOS나 Windows에서 Docker를 쓰면 내부적으로 경량 리눅스 VM을 하나 띄우고 그 위에서 컨테이너를 실행하는 구조입니다.

"컨테이너가 VM을 완전히 대체한다"는 오해입니다. 실무에서는 클라우드 VM 위에 쿠버네티스를 올리는 계층 구조가 흔합니다.

주의 — 여러 고객사 코드를 한 서버에서 돌리는 멀티테넌시 환경에서는 컨테이너의 격리 강도가 VM보다 약하다는 점을 고려해야 합니다.
