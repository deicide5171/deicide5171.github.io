"위성영상 서비스를 새로 여세요" — WCS를 걷어내고 OGC API - Coverages로 옮길지 판단하기

GIS

한 줄 요약 — 위성영상·기상 격자 같은 래스터 데이터를 조각(scene)과 밴드 단위로 내려주는 서비스를 새로 지을 때, 성숙하지만 무거운 WCS와 아직 초안 단계인 OGC API - Coverages 중 무엇을 선택해야 하는지의 판단 기준과 전환 절차를 정리했습니다.

 

왜 지금 이 판단이 중요해졌는가

"위성영상에서 이 지역, 이 시기, 적외선 밴드만 골라서 내려주는 서비스를 만들어주세요." 래스터(격자) 데이터를 다루는 팀이라면 익숙한 요구입니다. 지금까지 이 요구의 정답은 거의 자동으로 WCS(Web Coverage Service)였습니다. 그런데 OGC API 계열이 커버리지 쪽까지 확장되면서, OGC API - Coverages라는 후보 표준이 나왔습니다. ISO 19123-2 커버리지 구현 스키마가 재작성을 마치고 재채택 절차에 들어갔고, 위성영상처럼 여러 장면(scene)으로 구성된 데이터를 다루기 위한 scenes 리소스까지 정의됐습니다.

문제는 이 표준이 아직 초안·커뮤니티 모듈 단계라는 점입니다. "더 새롭고 REST 기반이니 무조건 이걸로 가자"는 판단은 섣부릅니다. 빌더 입장에서는 WCS의 성숙도와 OGC API - Coverages의 설계 방향을 모두 이해한 뒤, 지금 당장 무엇을 선택하고 무엇을 유예할지를 결정해야 합니다.

 

전체 시스템에서의 위치

커버리지 서비스는 저장 계층과 클라이언트 사이의 "조각내어 내려주는" 역할을 맡습니다. 아래에는 STAC·COG로 쌓인 원본 위성영상이 있고, 위에는 분석·시각화 클라이언트가 있습니다. WCS와 OGC API - Coverages는 같은 역할을 하지만 프로토콜의 모양이 다릅니다. WCS는 XML/GML 기반이고, OGC API - Coverages는 WMS·WFS가 OGC API - Tiles·Features로 옮겨간 흐름과 같이 REST/JSON과 OpenAPI 문서를 따릅니다.

위성영상은 단일 격자가 아니라 여러 번 촬영된 장면(scene)의 모음입니다. OGC API - Coverages는 이 다중 장면 커버리지에서 어떤 장면들이 있는지 조회하는 scenes 리소스를 표준 안에 명시적으로 넣었는데, 이는 WCS 설계 당시에는 이렇게 명확히 다뤄지지 않았던 부분입니다.

WCS는 GIS 전문 클라이언트가 복잡한 커버리지 질의를 정확히 표현하도록 만들어졌고, OGC API - Coverages는 일반 백엔드 개발자도 REST 호출 몇 번으로 커버리지에 접근하게 만드는 방향입니다. 위성영상 파이프라인을 외부 개발자에게도 열어줘야 하는 팀이라면 후자의 접근성이 결국 더 큰 가치가 됩니다.

 

실제 프로젝트 진행 순서

1) 지금 WCS로 풀어야 하는 요구인지부터 확인합니다 — 복잡한 공간 연산·레거시 클라이언트 호환이 필수면 WCS가 안전합니다.
2) 외부·범용 클라이언트 접근성이 중요한 신규 서비스라면 OGC API - Coverages를 제한된 범위(코어 기능)로 먼저 띄워봅니다.
3) 다중 장면 위성영상을 다룬다면 scenes 리소스 설계부터 우선 검증합니다.
4) WCS와 병행 운영 기간을 두고, 신규 클라이언트부터 점진적으로 비중을 옮깁니다.
5) GeoServer 커뮤니티 모듈의 기능 범위를 먼저 표로 정리해 기대치를 맞춥니다.

 

주의 — 표준이 아직 초안이라는 사실을 다른 팀·외부 파트너에게 숨기지 마세요. 레거시 GIS 데스크톱 클라이언트가 여전히 WCS만 지원하는 경우가 많으므로, 사용자층을 먼저 파악한 뒤 병행 기간의 길이를 정하고 WCS를 섣불리 완전히 버리지 않습니다.

 

정리

WCS는 성숙하고 검증됐지만 무거운 인터페이스이고, OGC API - Coverages는 REST/JSON과 scenes 리소스로 위성영상을 더 쉽게 다루게 하지만 아직 초안 단계입니다. 복잡한 공간 연산과 레거시 호환이 중요하면 WCS를, 외부 개발자 접근성과 다중 장면 관리가 중요하면 제한된 범위의 OGC API - Coverages 도입을 검토하고, 완전 교체가 아닌 병행 운영으로 점진적으로 전환하는 것이 지금 시점의 가장 안전한 전략입니다.
