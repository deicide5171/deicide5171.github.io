에이전트 도구 호출, 꼭 우리 서버를 거쳐야 할까 — Claude 서버사이드 도구 아키텍처 판단

AI

한 줄 요약 — 에이전트에 웹 검색·코드 실행 기능을 붙여달라는 요구는 보통 우리 인프라에 실행 서버를 하나 더 세우는 일로 번역됩니다. Claude가 제공하는 WebSearch·WebFetch·CodeExecution 같은 서버사이드 도구는 이 실행 계층 자체를 API 제공자 인프라로 옮기는 선택지입니다. 자체 MCP 서버와의 구조적 차이와 선택 기준을 정리했습니다.

 

왜 지금 이 판단이 필요한가

"에이전트가 최신 정보도 검색하고, 필요하면 코드도 돌려서 결과를 보여주게 해주세요." 이 요구를 받으면 보통 머릿속에 그려지는 그림은 정해져 있습니다. 모델이 도구 호출 의도를 뱉으면, 우리 서버가 그 요청을 받아 실제 검색 API를 때리거나 샌드박스에서 코드를 실행하고, 결과를 다시 모델에 넘겨주는 루프입니다. MCP(Model Context Protocol)가 표준화한 것도 바로 이 구조였습니다 — 클라이언트가 서버를 띄우고, 모델은 그 서버가 노출한 도구 목록만 보고 호출합니다.

그런데 2026년 Claude 5 세대부터 WebSearch, WebFetch, Code Execution, MCP 커넥터 같은 도구가 API 제공자 쪽 인프라에서 직접 실행되는 "서버사이드 도구"로 제공되기 시작했습니다. 겉보기엔 똑같이 "도구를 호출한다"지만, 실행 주체가 우리 서버에서 Anthropic 인프라로 넘어가면 지연시간·비용·데이터 통제권의 구조 자체가 달라집니다.

 

전체 시스템에서의 위치

기존 MCP 구조에서는 모델이 도구 호출 의도를 뱉을 때마다 응답이 클라이언트로 돌아오고, 클라이언트가 우리 MCP 서버를 호출하고, 그 결과를 다시 API 요청에 실어 모델에 돌려줘야 합니다. 멀티턴 도구 호출 하나당 왕복이 최소 두 번입니다. 서버사이드 도구는 이 왕복을 API 제공자 인프라 안에서 끝내, 모델이 도구 결과까지 받은 상태로 최종 응답만 클라이언트에 돌려줍니다.

두 경로는 배타적이지 않습니다. 범용 웹 검색·코드 실행은 서버사이드 도구로, 사내 DB 조회처럼 우리 데이터에만 접근해야 하는 도구는 자체 MCP 서버로 나눠 쓰는 하이브리드 구성이 2026년 기준 가장 흔한 형태입니다.

 

선택의 트레이드오프
기준 서버사이드 도구 자체 MCP 서버
지연시간 왕복 1회로 단축 호출마다 클라이언트 왕복
인프라 부담 거의 없음 샌드박스·API 키 직접 운영
데이터 통제권 제공자 인프라를 거침 우리 네트워크 안에서 완결
커스터마이징 제공자가 정한 범위로 제한 임의의 내부 시스템 연동 가능

 

판단 기준은 단순합니다. "이 도구가 다루는 데이터가 우리만 아는 것인가, 아니면 공개된 것인가"입니다. 공개 웹 검색이나 범용 계산처럼 실행 환경 자체에 민감 정보가 없다면 서버사이드 도구로 옮겨 왕복과 운영 부담을 줄이는 쪽이 이득입니다. 반대로 사내 데이터베이스, 결제 시스템, 망분리 구역 안의 리소스를 다뤄야 한다면 자체 MCP 서버로 남겨야 합니다.

 

실제 프로젝트 진행 순서

1. 현재 MCP 도구 목록을 데이터 민감도 기준으로 분류합니다.
2. "공개 데이터" 도구부터 서버사이드 도구로 전환합니다.
3. 전환 후 왕복 횟수와 응답 지연시간을 실측합니다.
4. 서버사이드 도구의 데이터 잔류·로깅 정책을 확인합니다.
5. 사내 전용 도구는 자체 MCP 서버로 명시적으로 남기고 그 이유를 문서화합니다.

 

예제 코드:

# 서버사이드 도구와 자체 MCP 도구를 한 요청에 함께 등록
response = client.messages.create(
    model="claude-sonnet-5-5",
    tools=[
        {"type": "web_search_20250305", "name": "web_search"},
        {"type": "code_execution_20250522", "name": "code_execution"},
        {"type": "mcp_connector", "server_url": "https://internal.example.com/mcp"},
    ],
    messages=[{"role": "user", "content": "최근 분기 매출과 업계 평균을 비교해줘"}],
)

 

주의 — 서버사이드 도구는 모델 제공자가 바뀌면 그대로 못 옮깁니다. 코드 실행 도구는 보통 시간·메모리 제한이 있는 공용 샌드박스라 장시간 배치 연산에는 맞지 않습니다. 과금은 토큰 사용량과 별도로 도구 호출량에 붙는 경우가 많으니, 트래픽이 큰 서비스는 전환 전 비용 시뮬레이션을 먼저 돌려보세요.

 

정리

서버사이드 도구는 도구 실행 주체를 우리 인프라에서 API 제공자 인프라로 옮겨 왕복과 운영 부담을 줄이는 선택지입니다. 판단 기준은 "이 도구가 다루는 데이터가 공개된 것인가, 사내 전용인가"이며, 둘을 섞어 쓰는 하이브리드 구성이 현실적인 기본값입니다.
