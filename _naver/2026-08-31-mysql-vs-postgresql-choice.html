MySQL vs PostgreSQL, 새 프로젝트엔 뭘 써야 할까 — 실무 선택 기준

2026. 8. 31. · 데이터베이스

한 줄 요약 — 팀의 기존 경험이 가장 큰 결정 요인이고, 반정형 데이터·GIS가 필요하면 PostgreSQL, 단순 CRUD 위주면 MySQL도 충분합니다.

 

왜 아직도 이 질문이 반복되는가

새 프로젝트를 시작할 때마다 "MySQL이냐 PostgreSQL이냐"는 질문이 다시 등장합니다. 둘 다 오픈소스이고 웬만한 CRUD 서비스에는 어느 쪽을 써도 문제가 없기 때문에 오히려 결정이 더 어렵게 느껴집니다. 이 글은 어떤 기준으로 판단하면 되는지를 구체적으로 정리했습니다.

 

핵심 차이 비교
항목 MySQL PostgreSQL
기본 철학 단순함, 빠른 읽기 중심 표준 SQL 준수, 풍부한 기능
데이터 타입 기본 타입 위주 JSONB, 배열, 사용자 정의 타입
인덱스 B-Tree, Full-text B-Tree·GiST·GIN·BRIN 등 다양
대표 채택 사례 전통적 웹서비스, WordPress 계열 복잡한 쿼리·분석, GIS(PostGIS)

 

판단 흐름
1. 팀에 이미 익숙한 DB가 있는가? → 있으면 그대로 간다
2. JSON을 관계형처럼 쿼리해야 하는가? → PostgreSQL JSONB+GIN
3. 공간 데이터(GIS)를 다루는가? → PostGIS가 사실상 표준
4. 단순 CRUD 위주인가? → MySQL도 충분

 

코드로 보는 차이 — UPSERT 문법
-- MySQL
INSERT INTO users (id, name) VALUES (1, 'Kim')
ON DUPLICATE KEY UPDATE name = VALUES(name);

-- PostgreSQL
INSERT INTO users (id, name) VALUES (1, 'Kim')
ON CONFLICT (id) DO UPDATE SET name = EXCLUDED.name;

문법 하나만 봐도 마이그레이션이 생각보다 손이 많이 간다는 걸 알 수 있습니다. 이런 차이가 나중에 DB를 바꾸기 어렵게 만드는 락인 요소가 됩니다.

 

실무 포인트

트랜잭션 격리수준 기본값이 다릅니다. MySQL(InnoDB)은 REPEATABLE READ, PostgreSQL은 READ COMMITTED가 기본이라 마이그레이션 시 동시성 버그를 옮길 수 있으니 주의하세요.

PostgreSQL은 확장(extension) 생태계가 강점입니다. pgvector, PostGIS, TimescaleDB로 하나의 DB를 확장할 수 있습니다.

주의 — MySQL은 복제와 운영 도구가 오래되고 검증된 편이라 대규모 트래픽 서비스에서 축적된 노하우가 많다는 점도 함께 고려하세요.
