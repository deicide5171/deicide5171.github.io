SQL JOIN 기초 — INNER, LEFT, RIGHT 헷갈리지 않기

2026. 9. 3. · 데이터베이스

한 줄 요약 — INNER는 매칭된 행만, LEFT는 왼쪽 테이블을 기준으로 매칭이 없어도 모두 살립니다. 핵심 차이는 매칭 안 되는 행의 포함 여부입니다.

 

JOIN이 왜 필요한가

관계형 DB는 데이터를 여러 테이블에 나눠 저장합니다. 회원은 users에, 주문은 orders에 따로 있죠. "각 회원의 주문 내역을 함께 보고 싶다"면 두 테이블을 연결해야 하는데, 이것이 JOIN입니다.

 

INNER / LEFT / RIGHT 차이
종류 결과
INNER JOIN 양쪽 모두에 매칭되는 행만
LEFT JOIN 왼쪽 전부 + 매칭되는 오른쪽
RIGHT JOIN 오른쪽 전부 + 매칭되는 왼쪽

 

-- INNER JOIN: 주문이 있는 회원만
SELECT u.name, o.item FROM users u
INNER JOIN orders o ON u.id = o.user_id;

-- LEFT JOIN: 주문 없는 회원도 포함(주문은 NULL)
SELECT u.name, o.item FROM users u
LEFT JOIN orders o ON u.id = o.user_id;

 

언제 무엇을 쓰나
주문한 적 있는 회원만 -> INNER JOIN
모든 회원 + 각자 주문 -> LEFT JOIN
주문 없는 회원 찾기 -> LEFT JOIN + WHERE o.id IS NULL

마지막 패턴(LEFT JOIN 후 IS NULL)은 한쪽에만 있는 데이터를 찾는 유용한 기법입니다.

 

실무 포인트

RIGHT JOIN은 실무에서 거의 안 씁니다. LEFT JOIN으로 테이블 순서만 바꾸면 같은 결과라 LEFT JOIN으로 통일하는 팀이 많습니다.

주의 — JOIN 조건(ON)의 연결 키에 인덱스가 없으면 데이터가 많을 때 매우 느려집니다. user_id 같은 키에는 인덱스를 걸어두세요.
