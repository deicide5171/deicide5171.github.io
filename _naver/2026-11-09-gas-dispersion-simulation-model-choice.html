공장 가스 누출, 확산 범위를 지도에 실시간으로 보여주세요 — 플룸 모델을 고르는 기준

GIS

한 줄 요약 — '유해가스가 새면 확산 범위를 지도에서 바로 보여주세요'라는 요구는 침수·가시권과는 다른 종류의 시뮬레이션 문제입니다. '사고가 나기 전에 미리 돌리는 설계용 시뮬레이션'과 '사고 난 순간 몇 초 안에 답해야 하는 대응용 시뮬레이션'이 서로 다른 모델을 요구하기 때문입니다. 가우시안 플룸과 SLAB 계열 모델의 선택 기준과 실시간 기상 연동 설계를 정리했습니다.

 

왜 지금 이 판단이 필요한가

"공장에서 유해가스가 새면, 그 확산 범위를 지도 위에 실시간으로 보여주세요. 대피해야 할 반경도 같이 알려주시고요." 화학 공장이나 가스 저장시설을 운영하는 조직에서 나오는 이 요구는, 겉보기에는 침수나 가시권 시뮬레이션과 비슷한 지도 위 영향 범위 그리기 문제처럼 보입니다. 하지만 실제로는 완전히 다른 제약이 숨어 있습니다. 가스 확산은 바람의 방향과 세기가 몇 분 단위로 바뀌는 입력값에 직접 좌우되고, 무엇보다 사고가 발생한 순간부터 몇 초 안에 대피 방향을 알려줘야 한다는 응답 시간 제약이 설계 전체를 지배합니다.

국내 가스안전 연구기관의 연구가 정확히 이 문제를 짚습니다. 기존의 모사 기반 확산 해석 시스템은 대부분 설계 단계의 사전 검토용으로 만들어져 있어서, 실제 사고가 터졌을 때 즉각 대응하기에는 적합하지 않다는 것입니다. 빌더가 답해야 할 질문은 "어떤 확산 모델이 가장 정확한가"가 아니라 "이 서비스가 사고 전 설계 검토용인가, 사고 중 실시간 대응용인가"입니다.

 

설계용 시뮬레이션과 대응용 시뮬레이션은 다른 제품이다

설계 단계에서 쓰는 시뮬레이션은 "이 설비를 지금 위치에 지어도 되는가"를 판단하는 용도입니다. 다양한 기상 시나리오를 수백 번 돌려서 가장 넓은 영향 범위를 찾아내는 식이므로 계산 시간이 몇 분에서 몇 시간씩 걸려도 괜찮습니다. CFD 기반 모델이 이 용도에 맞습니다. 반면 사고 대응용 시뮬레이션은 지금 이 순간의 실제 풍향·풍속을 입력받아 몇 초 안에 계산해 대피 경보에 반영해야 합니다. 이 시간 제약 때문에 대응용 시스템은 정확도를 일부 희생하더라도 계산이 빠른 모델을 택할 수밖에 없습니다. 두 용도를 하나의 시스템으로 묶으려는 시도가 실패하는 이유가 여기에 있습니다.

 

가우시안 플룸 vs SLAB, 가스의 성질이 모델을 가른다

가장 널리 쓰이는 가우시안 플룸 모델은 공기와 밀도가 비슷하거나 가벼운 가스가 바람을 타고 퍼지는 상황을 정규분포 형태의 수식으로 빠르게 근사합니다. 계산량이 적어 웹 서버에서 실시간으로 수백 번 돌려도 부담이 적습니다. 하지만 공기보다 무거운 가스(암모니아, 염소 등)는 바람을 타고 흩어지기보다 지면을 따라 낮게 깔려 흐르는 전혀 다른 물리 거동을 보이는데, 가우시안 플룸은 이 거동을 제대로 표현하지 못합니다. 이런 중가스 누출에는 SLAB 같은 전용 알고리즘이 필요합니다.

 

전체 시스템에서의 위치

이 파이프라인에서 가장 취약한 연결 고리는 실시간 기상 데이터 입력입니다. 설계용 시뮬레이션은 과거 기상 통계나 가정값을 쓰면 되지만, 대응용 시스템은 사고 발생 시점의 실제 풍향·풍속을 끊김 없이 공급받아야 합니다. 이 데이터 연동이 끊기거나 지연되면, 아무리 모델이 빨라도 틀린 바람 방향으로 대피 경보를 내보내는 더 위험한 상황이 됩니다.

실무에서는 취급 물질의 비중부터 확인하는 것이 모델 선택의 출발점입니다. 암모니아·염소처럼 중가스를 취급하는 시설이라면 가우시안 플룸만으로는 실제 위험 범위를 과소평가할 수 있으므로, 처음부터 SLAB 계열을 대응용 모델로 선택해야 합니다.

 

실제 진행 순서

가장 먼저 할 일은 모델을 고르는 게 아니라 이 서비스가 설계 검토용인지 사고 대응용인지를 요구사항 단계에서 명확히 구분하는 것입니다. 대응용으로 확정됐다면, 두 번째로 검증할 것은 실시간 기상 데이터 공급원의 안정성입니다. 기상청 API나 현장 풍향계 센서 중 무엇을 1차 소스로 쓸지, 그 소스가 끊겼을 때 어떤 값으로 대체할지를 먼저 정해야 합니다.

// 실시간 기상 입력으로 가우시안 플룸 농도를 좌표별로 계산
function gaussianPlumeConcentration(x, y, windSpeed, windDirDeg, stabilityClass) {
  const { sigmaY, sigmaZ } = stabilityCoefficients(x, stabilityClass);
  const downwind = rotateToDownwind(x, y, windDirDeg);
  if (downwind.x <= 0) return 0; // 풍상측은 농도 0으로 처리

  const concentration =
    (emissionRate / (Math.PI * windSpeed * sigmaY * sigmaZ)) *
    Math.exp(-(downwind.y ** 2) / (2 * sigmaY ** 2));

  return concentration;
}

이 계산을 지도 격자 전체에 대해 매 기상 업데이트 주기마다 반복해 등농도선을 그리면, 서버 한 대로도 충분히 실시간 처리가 가능합니다. 다만 풍향이 급변하는 구간에서는 이전 프레임의 확산 범위를 즉시 지우지 말고 짧게 보간해 넘기는 것이, 화면이 매 프레임 뚝뚝 끊겨 보이는 문제를 막는 실무 팁입니다.

 

주의 — 설계용(정확하지만 느린) 모델을 그대로 대응용에 가져다 쓰면 경보가 늦게 나가고, 대응용(빠르지만 단순한) 모델을 설계 검토에 쓰면 인허가 심사를 통과하지 못합니다. 두 용도는 처음부터 분리해서 설계하세요.

 

정리

가스 확산 시뮬레이션은 설계 단계 사전 검토용과 사고 발생 시 실시간 대응용이 서로 다른 모델과 인프라를 요구하므로, 요구사항 단계에서 둘을 구분해야 합니다. 공기보다 무거운 가스는 가우시안 플룸으로 과소평가되므로 취급 물질의 비중을 먼저 확인하고, 대응용 시스템의 가장 취약한 연결 고리인 실시간 기상 데이터 공급 전략을 미리 설계해야 합니다.
