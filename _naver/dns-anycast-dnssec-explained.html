DNS Anycast와 DNSSEC — 같은 IP로 전 세계에 응답하고 위조를 막는 원리

네트워크·OS·분산처리·DevOps

한 줄 요약 — 하나의 IP로 전 세계에서 가장 가까운 서버가 응답하는 Anycast 라우팅과, DNS 응답 위조를 막는 DNSSEC 서명 체인을 정리했습니다.

 

왜 지금 Anycast와 DNSSEC을 다시 봐야 하는가

1.1.1.1이나 8.8.8.8 같은 퍼블릭 DNS는 어디서 접속하든 같은 IP인데, 실제로는 물리적으로 가장 가까운 서버가 응답합니다. 인터넷 라우팅은 원래 하나의 IP가 하나의 위치를 가리키는 유니캐스트가 기본인데, Anycast는 이 전제를 의도적으로 깹니다. DNS 자체는 보안 없이 설계돼 응답 위조에 취약했고, DNSSEC이 이를 서명으로 보완합니다.

 

Anycast: 같은 IP를 여러 위치에서 동시에 광고

전 세계에 흩어진 서버들이 동일한 IP를 BGP로 동시에 광고합니다. 라우터들은 이 IP로 가는 여러 경로 중 가장 가까운 경로를 선택해 트래픽을 전달합니다. 클라이언트나 DNS 계층의 개입 없이, 순수하게 라우팅 테이블 수준에서 분산이 일어나며 DDoS 방어에도 강력합니다.

 

DNSSEC: 응답에 서명을 붙여 위조를 검증 가능하게

일반 DNS는 평문 프로토콜이라 위조된 응답을 먼저 주입하는 캐시 포이즈닝에 취약합니다. 각 DNS 존은 RRSIG 서명과 DNSKEY 공개키를 함께 배포하고, 이 신뢰가 루트부터 도메인까지 사슬처럼 이어집니다. 리졸버는 이 체인을 끝까지 검증해 중간에 위조가 있으면 응답을 폐기합니다.

항목 일반 DNS DNSSEC
응답 위조 방지 없음 서명으로 검증 가능
신뢰 근거 먼저 도착한 응답 신뢰 루트부터 이어지는 체인

 

DNSSEC 체인 확인 예제
dig +dnssec example.com A
# ad(Authenticated Data) 플래그가 있으면 검증 성공

delv example.com A  # 루트부터 체인 검증 과정 출력

dig @1.1.1.1 whoami.cloudflare.com TXT +short

 

실무 포인트

자체 Anycast 구축에는 자체 AS 번호와 BGP 피어링이 필요해 대부분 비현실적입니다. Cloudflare, AWS Global Accelerator 같은 관리형 Anycast 네트워크를 활용하는 것이 일반적입니다.

DNSSEC은 위조를 막을 뿐 가용성 문제를 만들 수도 있습니다. 서명 키 롤오버를 잘못하면 도메인 전체가 검증 실패로 응답 불가 상태에 빠질 수 있으니 TTL과 겹침 기간을 신중히 고려해야 합니다.

주의 — DNSSEC은 기밀성을 제공하지 않습니다. 응답이 변조되지 않았음을 보장할 뿐 질의 내용을 암호화하지는 않으므로, 프라이버시가 필요하면 DoH나 DoT를 별도로 검토해야 합니다.
