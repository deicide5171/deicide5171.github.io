Spring Security로 비밀번호 없는 로그인 만들기 — Passkey(WebAuthn)

2026. 8. 15. · 백엔드

한 줄 요약 — 개인키가 기기 밖으로 나가지 않는 패스키(Passkey) 인증을, Spring Security의 WebAuthn 지원으로 Spring Boot 서비스에 붙이는 방법을 정리했습니다.

 

왜 지금 패스키일까요

비밀번호는 여전히 가장 흔한 침해 경로입니다. 유출된 비밀번호 재사용, 피싱 사이트로 유도된 입력, 약한 비밀번호에 대한 크리덴셜 스터핑까지 — 문제의 근본 원인은 "서버가 검증할 수 있는 비밀이 사용자 손에도 똑같이 존재한다"는 구조 자체에 있습니다. 패스키(Passkey)는 이 구조를 뒤집습니다. 공개키 암호화를 이용해 개인키는 사용자의 기기 밖으로 절대 나가지 않고, 서버는 오직 공개키로 서명을 검증만 합니다.

주요 브라우저와 OS가 패스키 생성·저장을 표준 API로 지원하면서 채택이 빠르게 늘고 있고, Java 생태계에서도 Spring Security가 WebAuthn 기반 패스키 등록·인증을 정식 지원하기 시작했습니다. 기존 Spring Boot 서비스에 비밀번호 없는 로그인을 붙이는 진입 장벽이 눈에 띄게 낮아진 시점입니다.

 

WebAuthn 동작 원리

WebAuthn은 브라우저, 인증기(지문 센서나 보안 키), 서버 세 주체가 공개키 기반 challenge-response로 신원을 증명하는 W3C 표준입니다.

 

핵심은 비밀번호 자체가 존재하지 않는다는 점입니다. 등록 시 인증기가 공개키/개인키 쌍을 생성해 개인키는 기기 안 보안 영역에 저장하고 공개키만 서버로 보냅니다. 로그인 시 서버가 매번 새로운 challenge(난수)를 발급하고, 인증기는 지문·얼굴 인식으로 개인키를 잠금 해제해 challenge에 서명합니다. 서버는 등록 시 받은 공개키로 이 서명을 검증합니다. 서명은 challenge마다 달라지므로 리플레이 공격도, 피싱 사이트에 잘못 입력하는 시나리오 자체도 성립하지 않습니다.

 

인증 방식 비교
인증 방식 서버가 보관하는 비밀 피싱 내성
비밀번호 해시(유출 시 크래킹 위험) 낮음
OAuth2/OIDC(소셜 로그인) 없음(IdP 위임) IdP 의존
Passkey(WebAuthn) 공개키만(무의미한 정보) 높음(도메인 바인딩)

 

예제: Spring Boot에 WebAuthn 활성화하기
@Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/webauthn/**", "/login/**").permitAll()
                .anyRequest().authenticated()
            )
            .webAuthn(webAuthn -> webAuthn
                .rpName("My Spring App")
                .rpId("example.com")
                .allowedOrigins("https://example.com")
            );
        return http.build();
    }
}

rpId는 패스키가 어느 도메인에 바인딩되는지를 결정하는 값이라, 실제 서비스 도메인과 정확히 일치해야 합니다. 이 값이 틀리면 등록·로그인 자체가 실패하거나, 개발 환경에서 만든 패스키를 운영 도메인에서 재사용할 수 없는 문제가 생깁니다.

 

실무 도입 시 이것만은 챙기세요
1. 비밀번호 병행 전략을 먼저 검토하세요 — 인증기 분실 시 계정 복구 경로가 없으면 잠금 위험이 큽니다.
2. RP ID·오리진을 환경별로 분리하세요 — 로컬/스테이징/운영 도메인이 다르면 각각 별도 등록이 필요합니다.
3. 여러 인증기 등록을 허용하세요 — 노트북과 휴대폰 양쪽에서 로그인하려면 기기별 등록이 필요합니다.
4. 브라우저·OS 지원 현황을 계속 확인하세요 — 패스키 동기화 동작은 플랫폼별로 차이가 있습니다.

 

마무리 — 3줄 요약

① 패스키는 개인키가 기기 밖으로 나가지 않는 공개키 challenge-response 구조로 비밀번호 유출·피싱 문제를 구조적으로 없앱니다.
② Spring Security는 WebAuthn 기반 등록·인증 흐름을 표준 설정 DSL로 제공해 RP ID·오리진만 정확히 설정하면 도입할 수 있습니다.
③ 운영 도입 시에는 계정 복구 경로, 다중 인증기 등록, 환경별 도메인 설정을 함께 설계해야 안전하게 정착시킬 수 있습니다.
