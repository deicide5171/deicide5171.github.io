웹 성능 최적화 실전 — Core Web Vitals 2026

2026. 8. 15. · 웹 개발

한 줄 요약 — LCP·INP·CLS 세 지표를 랩 데이터와 필드 데이터로 함께 진단하고, 이미지·코드 스플리팅·프리로드로 개선하는 방법을 소개합니다.

 

Core Web Vitals, 왜 계속 중요할까요

Core Web Vitals는 검색 노출과 사용자 경험 모두에 영향을 주는 지표로, 몇 년째 프론트엔드 성능 최적화의 기준점 역할을 하고 있습니다. 2024년에 FID가 INP(Interaction to Next Paint)로 교체되면서, 첫 입력 반응 속도뿐 아니라 페이지 전체에 걸친 상호작용 반응성을 측정하게 되었습니다. 많은 팀이 Lighthouse 점수에만 집중하다가 실제 사용자 환경과의 차이를 놓치는 경우가 많아, 이번 글에서 핵심을 정리해봅니다.

 

세 가지 핵심 지표

Core Web Vitals는 LCP(가장 큰 콘텐츠 렌더링 시점), INP(상호작용 후 다음 화면 갱신까지 걸리는 시간), CLS(레이아웃 이동 누적치) 세 지표로 구성됩니다.

지표 의미 좋음 기준
LCP 가장 큰 콘텐츠 렌더링 시점 2.5초 이하
INP 상호작용 반응 시간 200ms 이하
CLS 레이아웃 이동 누적치 0.1 이하

 

랩 데이터와 필드 데이터, 둘 다 봐야 합니다

Lighthouse는 시뮬레이션 환경에서 즉시 측정 가능한 랩 데이터를 제공하고, CrUX(Chrome UX Report)는 실제 크롬 사용자들의 익명화된 필드 데이터를 제공합니다. 랩 데이터는 재현 가능하지만 실제 사용자 환경을 완전히 반영하지 못하고, 필드 데이터는 실제 경험을 보여주지만 원인을 바로 알려주지 않습니다. 그래서 PageSpeed Insights처럼 두 데이터를 함께 보여주는 도구를 활용하는 것이 효과적입니다.

LCP 이미지를 프리로드하고 나머지 이미지는 지연 로딩하는 예시입니다.

<head>
  <link rel="preload" as="image" href="/hero.avif" fetchpriority="high">
</head>
<body>
  <img src="/hero.avif" alt="히어로 이미지" width="1200" height="600">
  <img src="/below-fold.jpg" alt="아래쪽 이미지" loading="lazy" width="800" height="400">
</body>

 

실전 최적화 기법

이미지는 WebP/AVIF 같은 다음 세대 포맷과 반응형 이미지, 지연 로딩을 함께 활용하세요. 라우트/컴포넌트 단위로 코드 스플리팅을 하면 초기 JS 실행 비용이 줄어 INP 개선에 도움이 됩니다. 이미지나 광고 슬롯에는 명시적 크기나 aspect-ratio를 지정해 CLS를 줄이는 것도 중요합니다.

 

실무 도입 시 이것만은 챙기세요
1. 필드 데이터로 검증 — Lighthouse 점수만 보고 끝내지 말고 CrUX 데이터로 실제 사용자 경험을 확인하세요.
2. 백분위수 기준 목표 설정 — 평균이 아니라 75번째 백분위수 등 실제 평가 기준에 맞춰 목표를 잡으세요.
3. 서드파티 스크립트 점검 — 광고나 분석 스크립트가 INP와 LCP를 악화시키는 경우가 많습니다.
4. 성능 예산을 CI에 도입 — 회귀를 자동으로 감지하는 체계를 만들면 장기적으로 효과적입니다.

 

마무리 — 3줄 요약

① Core Web Vitals는 LCP, INP, CLS 세 지표로 구성됩니다.
② Lighthouse는 랩 데이터, CrUX는 필드 데이터를 제공하니 함께 확인해야 정확합니다.
③ 이미지 최적화, 코드 스플리팅, 프리로드, 레이아웃 이동 방지가 실전 핵심 기법입니다.
