SSL 인증서 만료 직전, 뭘 확인해야 할까 — Let's Encrypt 자동 갱신 점검

인프라

한 줄 요약 — 자동 갱신을 설정했다고 끝난 게 아니라 certbot renew --dry-run으로 정기적으로 실제 동작을 검증해야 합니다.

 

왜 자동 갱신을 설정했는데도 사고가 나는가

Let's Encrypt 인증서는 유효기간이 90일로 짧아 자동 갱신을 전제로 설계됐습니다. 문제는 설정만 해두고 확인을 안 하다가, 갱신 스크립트가 조용히 실패하고 있던 것을 만료 당일에야 알게 되는 경우입니다.

 

갱신 실패의 흔한 원인
원인 증상
cron 자체가 등록 안 됨 만료 직전까지 로그 없음
HTTP-01용 80포트 차단 갱신 시도 타임아웃
Nginx reload 누락 갱신은 성공, 서비스는 옛 인증서

 

확인 및 대응 명령
# 인증서 만료일 확인
echo | openssl s_client -servername example.com -connect example.com:443 2>/dev/null | openssl x509 -noout -dates

# 상태 확인
sudo certbot certificates

# 실제 발급 없이 갱신 시뮬레이션
sudo certbot renew --dry-run

--dry-run은 실제 인증서를 발급하지 않고 갱신 프로세스만 검증하므로 Rate Limit 걱정 없이 정기 점검할 수 있습니다.

 

실무 포인트

서버 안의 cron만 믿지 말고, 외부 모니터링 서비스로 인증서 만료일을 주기적으로 확인하는 것이 이중 안전장치가 됩니다.

주의 — Let's Encrypt는 짧은 기간 반복 발급 시 Rate Limit에 걸립니다. 테스트할 때는 반드시 --staging 옵션을 사용하세요.
