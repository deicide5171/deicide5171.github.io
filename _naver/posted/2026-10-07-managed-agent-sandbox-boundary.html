에이전트의 '손'은 누가 통제하는가 — Managed Agents 셀프호스티드 샌드박스 경계 설계

AI

한 줄 요약 — GA된 Claude Managed Agents의 셀프호스티드 샌드박스는 에이전트 루프를 '두뇌'와 '손'으로 쪼갭니다. 추론·오케스트레이션은 Anthropic이 맡고, 코드 실행·파일시스템·네트워크는 내 인프라 안에 둘 수 있게 된 이 경계 설계가 왜, 언제 필요한지 정리했습니다.

 

왜 지금 이 판단이 불거지는가

"고객 데이터를 다루는 에이전트를 운영하고 싶은데, 그 에이전트가 실제로 코드를 실행하는 환경만큼은 반드시 우리 VPC 안에 있어야 합니다." 금융·의료·공공 분야 고객을 상대하는 팀이라면 이런 요구를 숱하게 들어봤을 겁니다. 에이전트를 완전 관리형 서비스로 붙이자니 "우리 데이터가 외부 컨테이너에서 실행된다"는 컴플라이언스 벽에 막히고, 그렇다고 오케스트레이션·추론·에러 복구까지 전부 직접 구현하자니 결국 또 하나의 에이전트 프레임워크를 처음부터 만드는 셈이 됩니다.

이 긴장을 정면으로 다룬 것이 퍼블릭 베타를 거쳐 Claude API와 AWS Bedrock 플랫폼에서 정식 출시(GA)된 Claude Managed Agents의 셀프호스티드 샌드박스입니다. 핵심 아이디어는 단순합니다 — 에이전트 루프를 통째로 맡기거나 통째로 직접 만드는 양자택일 대신, 루프를 둘로 쪼개서 절반씩 나눠 가집니다. "에이전트 인프라를 쓸 것인가 만들 것인가"로 묻던 질문이 "루프의 어느 절반을 누구에게 맡길 것인가"라는 훨씬 세밀한 질문으로 바뀐 겁니다.

 

요구사항을 기술 문제로 번역하기

"코드 실행 환경은 우리 VPC 안에 있어야 한다"는 한 문장은 에이전트 루프 내부의 서로 다른 책임을 분리해야 하는 문제입니다. ①무엇을 할지 판단하는 오케스트레이션 레이어 — 컨텍스트 관리, 모델 추론, 도구 호출 실패 시 복구 전략. ②실제로 손을 움직이는 실행 레이어 — bash 명령, 파일 읽기·쓰기, 네트워크 요청. 기존 완전 관리형 구조에서는 이 둘이 전부 Anthropic 컨테이너 안에서 일어나지만, 셀프호스티드 샌드박스는 ①은 그대로 두고 ②만 떼어내 고객이 운영하는 샌드박스 호스트에서 실행하게 합니다.

 

전체 시스템에서의 위치

 

완전 관리형 구조에서는 요청이 Anthropic이 운영하는 단일 경계 안으로 들어가 추론부터 bash 실행까지 전부 그 안에서 끝납니다. 셀프호스티드 구조에서는 그 경계가 둘로 나뉩니다. 모델 추론과 에러 복구 판단은 여전히 Anthropic 쪽에서 일어나지만, 실제 도구 실행 요청은 API를 거쳐 고객이 운영하는 샌드박스 호스트로 전달됩니다. 라우팅·프록시·allowlist·파일 경로 감사까지 전부 고객의 책임 범위로 넘어온다는 점이 핵심입니다.

 

선택의 트레이드오프
기준 완전 관리형 셀프호스티드 샌드박스 완전 자체 구축
데이터 레지던시 실행 환경도 외부 실행 환경만 내 VPC 전부 내 인프라
구현 속도 가장 빠름 중간 가장 느림
운영 부담 Anthropic이 흡수 샌드박스 호스트는 내 몫 전부 내 몫
메모리 기능 완전 지원 미지원(2026-10 기준) 직접 설계

 

이 표에서 눈여겨볼 줄은 "메모리 기능"입니다. "일부만 넘긴다"는 선택이 공짜가 아니라 현재 시점의 기능 제약을 동반한다는 뜻입니다. AWS Bedrock에서는 이 조합이 아직 전면 지원되지 않으므로, 멀티클라우드 전략을 쓰는 팀이라면 플랫폼별 지원 범위부터 확인해야 합니다.

 

실제 프로젝트 진행 순서

1단계: "데이터가 외부로 나가면 안 된다"를 "실행 레이어만 내 VPC 안에 두면 충분한가, 추론 과정의 프롬프트 자체도 문제인가"로 쪼개서 확인합니다.

2단계: 샌드박스 호스트를 자체 Kubernetes 클러스터에 직접 운영할지, 전용 벤더에 위임할지 정합니다.

3단계: 에이전트가 호출할 수 있는 도메인·포트를 네트워크 egress allowlist로 먼저 설계합니다.

4단계: 에이전트가 읽고 쓸 수 있는 디렉터리를 최소 권한으로 좁혀 마운트하고 감사 로그를 수집합니다.

5단계: 메모리 기능 공백을 외부 저장소 기반 보완 설계로 먼저 검증합니다.

6단계: 데이터 민감도가 높은 워크플로 하나를 파일럿으로 골라 점진적으로 범위를 넓힙니다.

주의 — "샌드박스를 셀프호스팅한다"가 "보안을 책임진다"와 동의어라는 점을 가볍게 보지 마세요. 실행 레이어를 가져오는 순간 egress 통제, 파일 경로 감사, 호스트 패치까지 전부 떠안게 됩니다. 또한 추론 레이어는 여전히 Anthropic 인프라를 거치므로, 프롬프트에 담기는 내용 자체가 민감 정보라면 이 구조로는 해결되지 않습니다.

 

정리

Claude Managed Agents 셀프호스티드 샌드박스는 에이전트 루프를 오케스트레이션(두뇌)과 실행(손)으로 분리해, 추론은 Anthropic에 맡기고 코드 실행 환경만 자체 VPC 안에 둘 수 있게 합니다. 완전 관리형·셀프호스티드·완전 자체 구축 세 선택지 사이의 트레이드오프를 운영 역량 기준으로 판단하고, egress·파일 마운트 정책을 먼저 설계한 뒤 저위험 워크플로부터 점진적으로 확장하는 게 안전합니다.
