디스크 공간이 꽉 찼을 때 뭘 지워야 할까 — 리눅스 디스크 사용량 진단

인프라

한 줄 요약 — du -sh /* | sort -rh로 상위 디렉터리부터 점점 좁혀가는 것이 원인을 빠르게 찾는 방법입니다.

 

df는 꽉 찼다는데 뭘 지워야 할지 모르겠다면

디스크가 꽉 찬 것은 확인했는데 어느 디렉터리가 공간을 차지하는지 몰라 막막한 경우가 많습니다. 무작정 로그를 지우다가 필요한 데이터까지 삭제하는 사고를 피하려면 순서대로 좁혀가야 합니다.

 

진단 순서
# 1. 전체 사용률
df -h

# 2. 상위 디렉터리부터 큰 순서로
du -sh /* 2>/dev/null | sort -rh | head -10

# 3. 최근 급격히 커진 파일 찾기
find / -type f -size +100M -mtime -1 2>/dev/null

 

자주 범인으로 지목되는 위치
위치 흔한 원인
/var/log 로그 로테이션 누락
/var/lib/docker 사용 안 하는 이미지·볼륨 미정리
/tmp 임시 파일 누적

 

흔한 대응 명령
docker system prune -a
journalctl --vacuum-size=200M

 

실무 포인트

파일을 지웠는데도 프로세스가 계속 열고 있으면(파일 디스크립터가 살아있으면) 공간이 바로 회수되지 않습니다. 이 경우 프로세스를 재시작해야 합니다.

주의 — docker system prune -a는 태그 없는 이미지까지 광범위하게 삭제합니다. 운영 서버에서는 무엇이 삭제되는지 먼저 확인하세요.
