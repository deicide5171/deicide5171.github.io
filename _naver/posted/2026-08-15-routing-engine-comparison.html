오픈소스 라우팅 엔진 비교, OSRM vs Valhalla vs GraphHopper

2026. 8. 15. · GIS

한 줄 요약 — OSRM, Valhalla, GraphHopper는 같은 OSM 데이터를 쓰지만 알고리즘과 커스터마이징 철학이 달라 서비스 요구사항에 맞춰 골라야 합니다.

 

왜 오픈소스 라우팅 엔진을 직접 운영할까요

배달, 물류, 내비게이션 서비스에서 최적 경로를 계산하는 라우팅 엔진은 핵심 컴포넌트입니다. 상용 API는 빠르게 시작할 수 있지만 호출량이 많아지면 비용이 급격히 늘고, 화물차 규격 같은 커스텀 비용 함수를 적용하기 어렵다는 한계가 있습니다. 그래서 자체 인프라에 오픈소스 라우팅 엔진을 올려 운영하는 팀이 늘고 있는 것으로 보입니다.

 

세 엔진, 무엇이 다른가요

세 엔진 모두 OpenStreetMap 데이터를 기반으로 하지만 알고리즘 설계가 상당히 다릅니다. OSRM은 Contraction Hierarchies 전처리로 매우 빠른 속도를 자랑하고, Valhalla는 런타임 계산 비중이 커 유연하며, GraphHopper는 커스텀 모델 DSL로 그 중간을 노립니다.

항목 OSRM Valhalla GraphHopper
알고리즘 Contraction Hierarchies 양방향 A* CH + ALT
커스터마이징 제한적 유연함 유연함
다중 교통수단 차량 중심 통합 지원 별도 확장 필요

 

실행 및 커스텀 모델 예시

OSRM은 전처리 후 서버를 띄우는 방식이고, GraphHopper는 JSON 기반 커스텀 모델로 도로 속성별 가중치를 조정할 수 있습니다.

osrm-extract -p car.lua seoul.osm.pbf
osrm-contract seoul.osrm
osrm-routed seoul.osrm

 

어떤 상황에 어떤 엔진을 골라야 할까요

대량 정적 라우팅으로 쿼리 속도가 최우선이라면 OSRM이 유리하고, 시간대별 규제나 등시선 분석이 필요하다면 Valhalla가 적합합니다. 커스텀 비용 함수를 자주 바꿔야 하는 서비스라면 GraphHopper의 커스텀 모델이 운영 편의성 면에서 유리한 것으로 보입니다.

 

실무 도입 시 이것만은 챙기세요
1. OSM 데이터 품질 확인 — 세 엔진 모두 OSM 데이터 완성도에 크게 의존합니다.
2. 재전처리 배치 설계 — 전처리 기반 엔진은 도로 데이터 갱신 시 재전처리가 필요합니다.
3. 메모리 용량 산정 — 지도 범위와 프로필 수에 비례해 메모리 사용량이 커집니다.
4. 프로필 관리 방식 확인 — 도보, 자전거, 화물차 등 다중 프로필 운영 방식이 엔진별로 다릅니다.

 

마무리 — 3줄 요약

① OSRM은 CH 기반 전처리로 매우 빠르지만 동적 비용 함수 반영이 어렵습니다.
② Valhalla는 런타임 계산 비중이 커 유연하고 등시선 분석에 강합니다.
③ GraphHopper는 커스텀 모델 DSL로 두 엔진의 중간 지점을 노립니다.

읽어주셔서 감사합니다. 라우팅 엔진 도입을 검토 중이시라면 서비스 요구사항에 맞춰 세 엔진을 직접 비교해보시길 권해드립니다.
