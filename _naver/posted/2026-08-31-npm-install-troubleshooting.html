npm install이 자꾸 실패할 때 — 캐시와 lock 파일 문제 해결

프론트엔드

한 줄 요약 — 원인 모를 install 실패는 대부분 캐시나 lock 파일 문제이며, node_modules와 package-lock.json을 지우고 재설치하면 대부분 해결됩니다.

 

왜 어제까지 되던 install이 갑자기 안 될까

npm install이 갑자기 실패하면 대부분 코드 문제가 아니라 로컬 환경 상태 문제입니다. Node 버전 변경, 캐시 손상, package-lock.json 충돌이 대부분을 차지합니다.

 

흔한 에러와 원인
에러 메시지 주된 원인
ERESOLVE unable to resolve... 패키지 간 버전 충돌
EINTEGRITY npm 캐시 손상
gyp ERR! build error 네이티브 모듈 빌드 실패

 

진단 및 해결 순서
# 1. 버전 확인
node -v && npm -v

# 2. 캐시 정리
npm cache clean --force

# 3. 확실한 초기화 (가장 흔한 해결책)
rm -rf node_modules package-lock.json
npm install

# 4. 최후 수단
npm install --legacy-peer-deps

3번 완전 초기화만으로 대부분의 이상 증상은 해결됩니다. --legacy-peer-deps는 버전 충돌을 강제로 무시하는 것이므로, 팀 프로젝트에서는 원인 패키지를 찾아 버전을 맞추는 것이 더 안전합니다.

 

실무 포인트

package-lock.json을 git에 커밋하지 않으면 팀원마다 다른 버전이 설치돼 "내 컴퓨터에서는 되는데" 문제가 생깁니다. 반드시 커밋하세요.

Node 버전 관리자(nvm, fnm)로 프로젝트별 버전을 고정하면 팀원 간 불일치를 크게 줄일 수 있습니다.

주의 — CI 환경에서는 npm install 대신 npm ci를 써야 합니다. lock 파일을 그대로 신뢰해 설치하므로 재현 가능한 빌드를 보장하고 속도도 더 빠릅니다.
