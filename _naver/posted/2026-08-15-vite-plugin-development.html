Vite 플러그인 직접 만들어보기

2026. 8. 15. · 웹 개발

한 줄 요약 — Vite 플러그인은 몇 가지 핵심 훅(resolveId, load, transform)만 이해하면 생각보다 어렵지 않게 직접 만들 수 있습니다.

 

Vite 플러그인, 왜 직접 만들어야 할까요

Vite는 이제 대부분의 프런트엔드 프로젝트에서 기본으로 쓰이는 빌드 도구가 되었습니다. 그런데 대부분은 기존에 나와 있는 플러그인을 가져다 쓰는 데 그치고, 직접 만드는 경우는 드뭅니다. 하지만 회사 안에서만 쓰는 공통 컴포넌트를 자동으로 불러오거나, 특정 파일 형식을 변환하거나, 빌드할 때 특정 값을 코드에 주입하는 등의 요구사항은 결국 직접 플러그인을 만들어야 해결되는 경우가 많습니다.

 

플러그인이 코드를 처리하는 순서

Vite 플러그인은 아래 표에 있는 몇 가지 훅(hook)으로 이루어져 있습니다. 이 중 resolveId → load → transform 순서는 Rollup이라는 빌드 도구와 동일한 방식이라, Rollup을 몰라도 이 순서만 알면 충분히 이해할 수 있습니다.

훅 실행 시점 용도
resolveId 모듈 경로를 찾을 때 가상 모듈 생성, 경로 변경
load 파일 내용을 불러올 때 실제 파일 대신 동적으로 내용 제공
transform 코드를 변환할 때 코드 수정, 커스텀 문법 처리
configureServer 개발 서버가 시작될 때 커스텀 미들웨어 추가

 

Rollup 플러그인과의 관계

Vite 플러그인은 Rollup 플러그인 규격을 확장한 형태입니다. 그래서 순수 Rollup 플러그인은 대부분 Vite에서도 그대로 사용할 수 있습니다. 반대로 Vite 전용 기능(개발 서버 설정 등)을 쓰는 플러그인은 Rollup 단독 환경에서는 동작하지 않으니, 이 방향은 성립하지 않는다는 점을 기억해두시면 좋습니다.

// 간단한 변환 플러그인 예시
export default function myMacroPlugin(options = {}) {
  return {
    name: 'vite-plugin-simple-macro',
    transform(code, id) {
      if (!/\.[jt]sx?$/.test(id)) return null;

      let result = code;
      for (const [key, value] of Object.entries(options.define || {})) {
        result = result.replace(
          new RegExp(`__${key}__`, 'g'),
          JSON.stringify(value)
        );
      }
      return { code: result, map: null };
    },
  };
}

 

실무 도입 시 이것만은 챙기세요
1. 파일 필터링은 필수 — 모든 파일을 처리하면 빌드가 느려질 수 있습니다.
2. 소스맵을 챙기세요 — 없으면 디버깅할 때 원본 코드 위치를 찾기 어렵습니다.
3. 실행 순서를 명시하세요 — enforce 옵션으로 다른 플러그인과의 순서를 정할 수 있습니다.
4. 개발/빌드 범위를 분리하세요 — apply 옵션으로 불필요한 코드 실행을 막으세요.

 

마무리 — 3줄 요약

① Vite 플러그인은 resolveId, load, transform 같은 훅으로 구성됩니다.
② Rollup 플러그인은 대부분 Vite에서도 그대로 쓸 수 있습니다.
③ 파일 필터링, 소스맵, 실행 순서를 잘 챙기면 실무에서도 안전하게 쓸 수 있습니다.
