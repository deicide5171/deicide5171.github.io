curl로 API 테스트하기 — 개발자가 자주 쓰는 명령 정리

인프라

한 줄 요약 — curl은 별도 설치 없이 터미널에서 API를 테스트하는 도구이며, -X(메서드)·-H(헤더)·-d(본문)가 핵심 옵션입니다.

 

왜 curl을 익혀두면 좋은가

서버에 SSH로 접속해 빠르게 확인하거나, 스크립트로 자동화하거나, 문서에 예제로 남길 때 curl이 편합니다. 거의 모든 리눅스·맥에 기본 설치되어 있습니다.

 

자주 쓰는 옵션
옵션 의미
-X HTTP 메서드 지정
-H 헤더 추가
-d 요청 본문 전송
-v 전 과정 상세 출력(디버깅)

 

기본 예제
# GET
curl https://api.example.com/users/1

# POST로 JSON 전송
curl -X POST https://api.example.com/users \
  -H "Content-Type: application/json" \
  -d '{"name": "김철수"}'

# 인증 토큰
curl https://api.example.com/me \
  -H "Authorization: Bearer YOUR_TOKEN"

 

디버깅에 유용한 조합
# 전 과정 보기
curl -v https://api.example.com/users/1

# 상태 코드만 확인
curl -o /dev/null -s -w "%{http_code}\n" https://api.example.com/users/1

-v는 요청이 왜 실패하는지 모를 때 가장 먼저 써보는 옵션입니다. DNS·TLS·헤더까지 전부 보여줍니다.

 

실무 포인트

JSON 응답이 한 줄로 뭉쳐 읽기 어렵다면 curl ... | jq로 파이프하면 보기 좋게 정렬됩니다.

주의 — JSON 본문에는 큰따옴표가 들어가므로 바깥은 작은따옴표로 감싸세요. 복잡한 요청은 -d @data.json으로 파일 분리도 방법입니다.
