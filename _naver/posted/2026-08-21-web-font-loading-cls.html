웹폰트 로딩과 CLS — font-display와 size-adjust로 레이아웃 흔들림 잡기

2026. 8. 21. · 프론트엔드

한 줄 요약 — 커스텀 웹폰트가 늦게 도착하면서 텍스트 박스 크기가 바뀌어 생기는 CLS를, font-display 전략과 size-adjust 계열 폰트 메트릭 오버라이드로 줄이는 방법을 정리했습니다.

 

왜 지금 폰트 로딩을 다시 봐야 할까요

Core Web Vitals 이야기를 할 때 보통 CLS(레이아웃 흔들림) 해법으로 이미지나 광고 슬롯에 width·height를 미리 지정하라는 조언을 많이 듣습니다. 그런데 실제 서비스 데이터를 들여다보면 CLS의 상당 부분이 이미지가 아니라 커스텀 웹폰트가 늦게 로드되면서 글자 박스 크기가 바뀌는 순간에서 발생합니다. 폴백 시스템 폰트로 먼저 그려진 텍스트가 웹폰트로 교체되는 순간, 글자 폭과 줄바꿈 위치, 문단 높이가 달라지면서 그 아래 콘텐츠가 밀리는 것입니다.

이 문제는 이미지처럼 크기를 미리 지정하는 방식으로는 해결되지 않습니다. 텍스트 박스 크기는 폰트 자체의 메트릭(글자 폭, 상단·하단 여백)에 좌우되기 때문에, 폰트 로딩 전략과 메트릭 조정이 따로 필요합니다. 이 글에서는 font-display의 각 값이 실제로 무엇을 하는지, 그리고 최근 브라우저가 지원하는 size-adjust 계열 디스크립터로 폴백 폰트와 웹폰트의 박스 크기를 미리 맞추는 방법을 정리해보겠습니다.

 

핵심 개념 1: FOIT·FOUT·FOFT — 폰트가 늦게 도착할 때의 선택지

웹폰트가 아직 도착하지 않은 짧은 시간 동안 브라우저가 텍스트를 어떻게 그릴지는 크게 세 가지로 나뉩니다. FOIT(Flash of Invisible Text)는 폰트가 도착하기 전까지 텍스트를 아예 안 그리는 방식이고, FOUT(Flash of Unstyled Text)는 폴백 폰트로 즉시 그린 뒤 웹폰트로 교체하는 방식입니다. FOFT(Flash of Faux Text)는 웹폰트의 축약 버전을 먼저 쓰고 이후 전체를 교체하는 방식으로, FOUT과 비슷한 원리로 동작합니다.

세 전략 모두 폰트가 바뀌는 순간이 존재하는 한 CLS 위험은 남아 있습니다. 결국 관건은 그 전환 시점에 폴백 폰트와 웹폰트의 박스 크기 차이를 얼마나 줄이느냐에 달려 있습니다.

 

핵심 개념 2: font-display 값별 동작

@font-face의 font-display 속성은 폰트 로딩 중 브라우저가 텍스트를 어떻게 처리할지 지정합니다. 값별 특징을 표로 정리하면 다음과 같습니다.

값 텍스트 숨김 구간 특징
auto 브라우저 기본 정책 브라우저마다 동작이 달라질 수 있어 명시적 지정 권장
block 짧게 존재 폰트 없이는 의미가 깨지는 아이콘 폰트 등에 적합, FOIT 유발
swap 사실상 없음 즉시 텍스트 표시, FOUT 유발 — 가장 흔히 쓰이는 값
fallback 매우 짧음 텍스트 노출과 안정성의 절충
optional 매우 짧음 느린 네트워크에서는 웹폰트를 아예 포기해 흔들림 자체를 회피

정확한 구간 길이는 브라우저·스펙 버전에 따라 달라질 수 있어 단정하기는 어렵지만, 방향성은 분명합니다. 본문 텍스트처럼 CLS에 민감한 영역은 swap이나 optional이, 브랜드 아이덴티티가 중요한 헤드라인 정도만 block이 적합한 경우가 많습니다.

 

핵심 개념 3: size-adjust로 박스 크기 맞추기

font-display: swap을 쓰면 텍스트는 즉시 보이지만, 폴백 폰트와 웹폰트의 글자 폭·줄 높이가 다르면 교체 시점에 그 차이만큼 레이아웃이 밀립니다. 이 차이를 줄이는 최근 접근이 size-adjust, ascent-override, descent-override, line-gap-override 같은 @font-face 메트릭 오버라이드 디스크립터입니다. 폰트 전체 스케일과 상단·하단 여백, 줄 간격을 강제로 조정해 폴백 폰트와 웹폰트의 박스 크기를 비슷하게 맞추는 방식입니다.

이 값들은 폰트 파일을 직접 열어 계산하기보다, 두 폰트의 메트릭 차이를 분석해 자동으로 값을 산출해주는 도구를 활용하는 것이 실무에서 자리 잡고 있습니다. 프레임워크가 빌드 시점에 이 메트릭 매칭을 자동으로 해주는 흐름도 늘고 있어, 직접 손으로 튜닝하지 않아도 되는 경우가 많아졌습니다.

 

예제: 폴백 폰트 메트릭 오버라이드

아래는 웹폰트와 시스템 폰트(폴백)를 size-adjust 계열 디스크립터로 맞춰주는 기본 패턴입니다. 실제 값은 두 폰트를 비교 측정해서 산출해야 하며, 아래 수치는 개념 설명용 예시입니다.

/* 실제 서비스에서 쓸 웹폰트 */
@font-face {
  font-family: "BrandSans";
  src: url("/fonts/brand-sans.woff2") format("woff2");
  font-display: swap;
  font-weight: 400 700;
}

/* 시스템 폰트를 웹폰트와 비슷한 박스 크기로 맞춘 대체 정의 */
@font-face {
  font-family: "BrandSans Fallback";
  src: local("Arial");
  size-adjust: 104%;
  ascent-override: 92%;
  descent-override: 24%;
  line-gap-override: 0%;
}

body {
  font-family: "BrandSans", "BrandSans Fallback", sans-serif;
}

폰트를 무조건 전부 프리로드하는 것도 능사는 아닙니다. 화면 최상단에서 바로 보이는 텍스트에 쓰이는 폰트 파일 한두 개만 <link rel="preload" as="font">로 선별 지정하는 편이, LCP 이미지나 초기 JS 번들과 대역폭을 다투지 않아 안전합니다.

 

실무 도입 시 이것만은 챙기세요
1. 용도별로 font-display 값 구분 — 본문 텍스트는 swap·optional, 장식성 폰트는 block처럼 일괄 적용하지 않기
2. size-adjust 값은 도구로 산출 — 웹폰트 버전이 바뀌면 메트릭도 바뀌므로 수치를 고정해두지 않기
3. 가변 폰트(variable font) 도입 검토 — 굵기별 파일을 따로 받지 않으면 스왑 횟수 자체를 줄일 수 있음
4. 서드파티 폰트 CDN보다 자체 호스팅 우선 고려 — 외부 도메인 연결 비용 제거, 프리로드·캐시 정책 직접 통제
5. CLS는 실제 필드 데이터로 검증 — 로컬 환경은 캐시가 남아있어 폰트 스왑 자체가 재현되지 않는 경우가 많음

 

마무리 — 3줄 요약

① 웹폰트로 인한 CLS는 이미지와 달리 크기 지정만으로는 막을 수 없고, 폴백-웹폰트 간 박스 크기 차이 자체를 줄여야 합니다.
② font-display는 값에 따라 텍스트를 숨기는 시간과 스왑 허용 구간이 다르므로, 콘텐츠 성격에 맞춰 값을 구분해 적용하는 것이 핵심입니다.
③ size-adjust, ascent-override 등 메트릭 오버라이드로 폴백 폰트의 박스 크기를 웹폰트에 맞추면 스왑 시점의 레이아웃 이동을 크게 줄일 수 있습니다.
