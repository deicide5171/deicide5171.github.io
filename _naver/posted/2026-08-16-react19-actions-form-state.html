React 19 Actions로 폼 상태관리 다시 설계하기

2026. 8. 16. · 프론트엔드

한 줄 요약 — React 19에서 정식 안정화된 Actions와 useActionState를 활용하면, onSubmit과 useState를 손으로 조합하던 폼 상태관리 코드를 한결 단순하게 다시 설계할 수 있습니다.

 

왜 지금 Actions인가

React 19가 정식 릴리스되면서 useActionState, useFormStatus, useOptimistic 같은 훅이 실험 단계를 벗어나 안정 API로 자리 잡았습니다. 이 훅들이 공유하는 배경이 Actions입니다. <form action={'{fn}'}>처럼 폼 제출을 비동기 함수로 다루면, React가 제출 중 상태와 결과 상태를 자동으로 추적해줍니다.

지금까지는 폼 하나를 제대로 다루려면 isLoading, error, data 같은 state 서너 개를 useState로 따로 선언하고, onSubmit 안에서 로딩 시작-요청-에러 또는 성공 처리-로딩 종료를 손으로 맞춰야 했습니다. 요청이 겹치거나 컴포넌트가 언마운트되는 경계 케이스까지 챙기면 코드가 금세 지저분해지곤 했습니다. Actions는 이 반복 패턴을 훅으로 표준화해 폼 상태관리 코드의 기본 형태를 바꿔놓았습니다.

 

핵심 개념: 이전 방식과 무엇이 달라졌나

Action은 폼 데이터를 받아 새로운 상태를 반환하는 비동기 함수입니다. useActionState(action, initialState)에 이 함수를 넘기면 현재 상태, form에 바로 꽂을 수 있는 formAction, 진행 중 여부(isPending)를 반환받습니다. 아래 표로 이전 방식과 비교해 보겠습니다.

항목 이전 방식 (useState 수동 관리) React 19 Actions
상태 관리 isLoading·error·data 각각 useState 선언 useActionState 하나로 통합 관리
제출 처리 preventDefault + 수동 try/catch Action 함수 반환값이 자동 반영
하위 컴포넌트 연동 pending 상태를 props로 계속 전달 useFormStatus로 직접 구독
낙관적 업데이트 별도 로직으로 직접 구현 useOptimistic으로 선언적 표현

 

함께 쓰는 훅의 역할 분담

useActionState는 폼 전체의 제출 결과(성공/실패, 에러 메시지)와 pending 여부를 관리하는 최상위 훅입니다. useFormStatus는 form 내부의 자식 컴포넌트, 예를 들어 제출 버튼이 부모의 pending 상태를 props 전달 없이 직접 읽을 수 있게 해주는 훅입니다. useOptimistic은 서버 응답이 오기 전에 성공했다고 가정한 화면을 먼저 보여주고, 실제 응답이 오면 정정하는 훅입니다. 세 훅은 역할이 겹치지 않도록 설계되어 있어 조합해서 쓰기에 적합합니다.

 

예제: useActionState로 회원가입 폼 다시 짜기

아래는 이메일·비밀번호를 받는 회원가입 폼을 useActionState로 다시 작성한 예시입니다. isLoading, error, success를 각각 useState로 선언하던 코드가 훅 하나로 정리되고, 버튼의 disabled 처리도 별도 state 없이 isPending 값을 그대로 씁니다.

import { useActionState } from "react";

async function signupAction(prevState, formData) {
  const email = formData.get("email");
  const password = formData.get("password");

  if (!email.includes("@")) {
    return { error: "올바른 이메일을 입력하세요.", success: false };
  }

  const res = await fetch("/api/signup", {
    method: "POST",
    body: JSON.stringify({ email, password }),
  });

  if (!res.ok) {
    return { error: "가입에 실패했습니다.", success: false };
  }
  return { error: null, success: true };
}

export function SignupForm() {
  const [state, formAction, isPending] = useActionState(signupAction, {
    error: null,
    success: false,
  });

  return (
    <form action={formAction}>
      <input name="email" type="email" />
      <input name="password" type="password" />
      {state.error && <p>{state.error}</p>}
      <button type="submit" disabled={isPending}>
        {isPending ? "처리 중..." : "가입하기"}
      </button>
    </form>
  );
}

 

실무 도입 시 이것만은 챙기세요
1. 전면 마이그레이션은 불필요 — 검증이 단순한 폼은 그대로 두고, 서버 왕복이 있는 폼부터 전환
2. useFormStatus는 form 하위 컴포넌트에서만 동작 — form과 같은 레벨이나 부모에서 호출하면 값이 비어 있음
3. useOptimistic은 실패 롤백을 자동 처리하지 않음 — 요청 실패 시 최종 state를 되돌리는 로직을 Action 함수에 직접 작성
4. 메타프레임워크와 함께 쓸 때는 버전 확인 필수 — Server Actions 통합 방식은 프레임워크별로 세부 동작이 다를 수 있음

 

마무리 — 3줄 요약

① React 19에서 정식 안정화된 Actions는 useState로 손수 관리하던 폼의 pending·에러 상태를 useActionState 하나로 표준화합니다.
② useFormStatus는 하위 컴포넌트의 pending 구독을, useOptimistic은 응답 전 낙관적 UI 표현을 각각 담당하며 세 훅은 조합해서 씁니다.
③ 전면 마이그레이션보다는 서버 왕복이 잦은 폼부터 우선 적용하고, 낙관적 업데이트의 실패 롤백은 직접 챙겨야 합니다.
