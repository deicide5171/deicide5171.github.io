2026년 React 상태 관리 정리

2026. 8. 15. · 웹 개발

한 줄 요약 — 화면에서만 쓰는 상태와 서버 데이터를 구분해서, 상황에 맞는 도구를 나눠 쓰는 것이 요즘 React 상태 관리의 흐름입니다.

 

모든 상태가 같은 상태는 아닙니다

React 개발을 하다 보면 "상태 관리 라이브러리 뭐 쓸까요"라는 질문을 자주 받습니다. 그런데 사실 상태에는 두 종류가 있습니다. 모달이 열렸는지, 폼에 무엇을 입력했는지 같은 클라이언트 상태와, 서버에 저장된 데이터를 화면에 가져와 보여주는 서버 상태입니다.

이 둘을 같은 방식으로 다루면 불필요하게 복잡해지기 쉽습니다. 서버 데이터를 그냥 전역 상태에 넣으면 캐시를 언제 새로고침할지, 중복 요청은 어떻게 막을지를 직접 만들어야 하는데, 이런 문제는 이미 전용 도구가 잘 풀어놓았기 때문입니다.

 

도구별 비교
도구 특징 잘 맞는 상황
Zustand 간단한 스토어, 적은 보일러플레이트 중소 규모 클라이언트 상태
Jotai 원자 단위로 상태를 쪼갬 세밀한 리렌더링 최적화
TanStack Query 캐싱·재검증 자동화 서버에서 가져오는 모든 데이터
Redux Toolkit 엄격한 단방향 흐름 대규모 팀, 복잡한 상태 전이

 

코드로 보는 차이

클라이언트 상태는 Zustand로, 서버 데이터는 TanStack Query로 나눠서 다루는 예시입니다.

// 클라이언트 상태 - Zustand
const useCartStore = create((set) => ({
  items: [],
  addItem: (id) => set((s) => ({ items: [...s.items, id] })),
}))

// 서버 상태 - TanStack Query
const { data, isLoading } = useQuery({
  queryKey: ['products'],
  queryFn: () => fetch('/api/products').then((r) => r.json()),
})

 

실무 도입 시 이것만은 챙기세요
1. 서버 데이터는 전용 도구에 맡기세요 — 캐싱과 재검증을 직접 구현하면 버그가 늘어나기 쉽습니다.
2. 가벼운 게 항상 답은 아닙니다 — 팀이 크고 규약이 중요하다면 Redux Toolkit이 여전히 유리할 수 있습니다.
3. Context API는 상태관리 도구가 아닙니다 — 값이 자주 바뀌면 하위 트리 전체가 리렌더링될 수 있습니다.
4. 유행보다 팀 상황을 먼저 보세요 — 상태의 종류와 팀의 기존 관례를 기준으로 고르는 것이 안전합니다.

 

마무리 — 3줄 요약

① 클라이언트 상태와 서버 상태는 성격이 달라 도구도 다르게 쓰는 것이 일반적입니다.
② Zustand·Jotai는 가벼운 클라이언트 상태에, TanStack Query는 서버 데이터 관리에 강점이 있습니다.
③ Redux나 Context API도 팀 규모와 상황에 따라 여전히 합리적인 선택입니다.

읽어주셔서 감사합니다. 프로젝트에 상태가 어떤 종류인지 먼저 나눠보고 도구를 고르시길 권해 드립니다.
