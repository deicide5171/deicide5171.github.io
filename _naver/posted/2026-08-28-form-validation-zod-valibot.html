폼 검증 규칙을 타입과 함께 — Zod·Valibot 스키마 기반 검증 패턴

프론트엔드

한 줄 요약 — 폼 검증 로직을 타입과 별개로 관리하다 둘이 어긋나는 문제를, 스키마 하나에서 타입과 런타임 검증을 동시에 얻는 Zod와, 번들 크기를 줄인 Valibot으로 해결하는 패턴을 정리했습니다.

 

타입은 런타임에 사라진다는 문제

TypeScript의 타입은 컴파일 시점에만 존재하고 런타임에는 완전히 사라집니다. 폼 입력값처럼 실행 중에 들어오는 데이터는 아무리 타입을 선언해봤자, 실제로 그 값이 이메일 형식인지 검증하는 로직을 직접 짜야 합니다. 문제는 이 검증 로직과 타입 선언이 서로 다른 곳에 따로 존재하면 둘이 어긋나는 상황이 반복된다는 것입니다.

Zod와 Valibot 같은 스키마 검증 라이브러리는 스키마를 하나만 정의하면 타입과 런타임 검증이 동시에 나온다는 방식으로 이 문제를 해결합니다.

 

핵심 개념 1 — 스키마에서 타입을 추론합니다
import { z } from "zod";

const signupSchema = z.object({
  email: z.string().email(),
  password: z.string().min(8),
});

// 타입은 스키마에서 자동으로 추론됨
type SignupInput = z.infer<typeof signupSchema>;

스키마를 고치면 타입도 자동으로 따라 바뀌므로, 둘이 어긋나는 상황 자체가 구조적으로 발생하지 않습니다.

핵심 개념 2 — 파싱은 타입 단언이 아니라 실제 검증입니다

as 타입 단언은 컴파일러에게 믿어달라고 말할 뿐 실제로 값을 확인하지 않습니다. 스키마의 safeParse()는 실제로 값을 검사하고, 검증에 성공한 경우에만 타입이 보장된 값을 반환합니다.

핵심 개념 3 — Zod vs Valibot, 번들 크기와 API 스타일
기준 Zod Valibot
API 스타일 메서드 체이닝 함수 조합(pipe)
번들 크기 상대적으로 큼 매우 작음
적합한 상황 서버 코드 번들 크기가 중요한 클라이언트

 

 

예제 — React Hook Form과 결합한 폼 검증
import { useForm } from "react-hook-form";
import { zodResolver } from "@hookform/resolvers/zod";
import { z } from "zod";

const signupSchema = z.object({
  email: z.string().email("올바른 이메일 형식이 아닙니다"),
  password: z.string().min(8, "비밀번호는 8자 이상이어야 합니다"),
});

type SignupForm = z.infer<typeof signupSchema>;

function SignupPage() {
  const { register, handleSubmit, formState: { errors } } = useForm<SignupForm>({
    resolver: zodResolver(signupSchema),
  });

  const onSubmit = (data: SignupForm) => {
    submitSignup(data);
  };
  // ... 폼 렌더링
}

같은 스키마를 서버 API의 요청 바디 검증에도 그대로 재사용하면, 클라이언트와 서버의 검증 규칙이 어긋나는 문제도 함께 없어집니다.

 

실무 도입 시 이것만은 챙기세요
1. 클라이언트와 서버 검증에 같은 스키마를 재사용하세요 — 스키마를 공유 패키지로 분리해 두 곳에서 import하는 구조가 일관성을 보장합니다.
2. safeParse()를 기본으로 쓰세요 — 실패를 값으로 다루는 스타일이 에러 처리 흐름을 더 명시적으로 만듭니다.
3. 번들 크기가 실제로 문제인지 먼저 측정하세요 — Valibot 전환은 실제 번들 분석 결과로 확인한 뒤 결정하세요.

 

마무리 — 3줄 요약

① Zod·Valibot은 스키마 하나로 타입 추론과 런타임 검증을 동시에 얻어 타입과 검증 로직이 어긋나는 문제를 구조적으로 없앱니다.
② safeParse()는 타입 단언과 달리 실제로 값을 검사하고 성공한 값에만 타입을 보장합니다.
③ Zod는 성숙한 생태계가, Valibot은 작은 번들 크기가 강점이므로 번들 크기 민감도에 따라 선택하면 됩니다.
