번들러 전쟁 2막 — Rolldown, Turbopack, Rspack이 노리는 것

프론트엔드

한 줄 요약 — 러스트로 작성된 네이티브 번들러 Rolldown, Turbopack, Rspack은 모두 빠르지만 각각 노리는 생태계와 증분 빌드 전략이 달라, "가장 빠른 것"보다 "내 스택과 맞는 것"을 골라야 합니다.

 

번들러 경쟁이 다시 불붙었습니다

몇 년 전만 해도 프론트엔드 빌드 성능 이야기는 webpack이 느리니 esbuild나 SWC로 일부 단계를 대체하자는 수준이었습니다. 지금은 Vite 생태계의 차기 번들러로 예고된 Rolldown, Next.js가 자체 개발 중인 Turbopack, ByteDance가 만든 webpack 호환 러스트 번들러 Rspack까지, 네이티브 번들러들이 각자 다른 생태계의 기본값 자리를 노리고 있습니다.

이 셋을 그냥 빠른 번들러로 뭉뚱그리면 놓치는 게 많습니다. 셋은 각각 다른 문제를 풀려고 설계됐고, 그 목표가 API 호환성과 증분 빌드 전략에 그대로 반영돼 있습니다.

 

핵심 개념 1 — 같은 러스트, 다른 목표

Rolldown은 Vite 팀(VoidZero)이 만드는 Rollup 호환 번들러로, Vite의 개발 서버와 프로덕션 빌드 도구 이원화를 없애는 것이 목표입니다. Turbopack은 Vercel이 Next.js를 위해 만드는 번들러로 webpack 대체가 1차 목표이며, 함수 단위 캐싱에 특화된 증분 계산 엔진 위에서 동작합니다. Rspack은 ByteDance가 만든 webpack 호환 번들러로, 기존 설정과 플러그인을 거의 그대로 두고 속도만 얻는 이행 비용 최소화에 초점을 맞춥니다.

 

핵심 개념 2 — 증분 빌드 전략의 차이

세 번들러의 체감 속도 차이는 상당 부분 증분 빌드를 어떻게 구현했는가에서 나옵니다. Turbopack은 함수 호출과 인자를 캐시 키로 삼아 입력이 바뀌지 않은 결과를 재사용하는 범용 증분 계산 엔진(Turbo Engine)을 기반으로 합니다. Rspack과 Rolldown은 각각 webpack, Rollup의 기존 모듈 그래프 기반 증분 재컴파일 아키텍처를 러스트로 재작성하는 접근입니다.

구분 Rolldown Turbopack Rspack
호환 대상 Rollup / Vite 플러그인 webpack(부분) webpack 설정·플러그인
1차 목표 생태계 Vite Next.js 범용
개발 주체 VoidZero(Vite 팀) Vercel ByteDance

 

핵심 개념 3 — 실제로 바뀌는 개발 경험

세 도구가 공통으로 노리는 최종 효과는 콜드 스타트 시간과 HMR 반응 속도의 체감 개선입니다. 대형 모노레포에서 webpack 기반 개발 서버가 수십 초씩 걸리던 콜드 스타트가 Turbopack이나 Rspack에서 수 초 단위로 줄어드는 사례가 보고되지만, 이 이득은 프로젝트 규모와 의존성 그래프 복잡도에 따라 편차가 큽니다.

세 도구 모두 아직 각 생태계에서 완전한 기본값 자리를 확정 짓지는 않았고 빠르게 발전 중이므로, 도입 전 실제 프로젝트의 플러그인 목록으로 호환성을 검증하는 과정이 필요합니다.

 

예제 — 프로젝트별 마이그레이션 진입점
# Rspack - 기존 webpack 설정을 그대로 두고 실행기만 교체
npm install --save-dev @rspack/cli @rspack/core
npx rspack build --config webpack.config.js

# Vite + Rolldown - Rollup 대신 Rolldown을 프로덕션 번들러로 사용
npm install --save-dev rolldown-vite

# Next.js + Turbopack - 개발 서버에 우선 적용
next dev --turbopack

 

실무 도입 시 이것만은 챙기세요
1. 플러그인·로더 호환성부터 검증하세요 — "거의 호환"은 완전히 동일하지 않다는 뜻입니다. 실제 사용 플러그인 목록을 먼저 추리세요.
2. 벤치마크 수치보다 직접 측정하세요 — 공개 벤치마크는 특정 프로젝트 구조 기준이라 실제 개선폭은 편차가 큽니다.
3. 개발 서버부터 단계적으로 도입하세요 — 발전이 빠른 단계라 프로덕션 전면 적용보다 안전합니다.

 

마무리 — 3줄 요약

① Rolldown은 Vite 도구 이원화 해소, Turbopack은 함수 단위 캐싱으로 Next.js webpack 대체, Rspack은 webpack 설정 재사용을 각각 목표로 합니다.
② 셋 다 러스트 기반 네이티브 처리로 속도를 얻지만 증분 빌드 전략과 겨냥 생태계가 다릅니다.
③ 아직 발전 단계이므로 전체 프로덕션 전환보다 개발 서버 단계 검증이 안전합니다.
