로그 레벨이 뭔가요 — DEBUG, INFO, WARN, ERROR 제대로 쓰기

백엔드

한 줄 요약 — ERROR·WARN·INFO·DEBUG를 심각도와 상세함에 맞게 구분하고, 예외는 스택트레이스와 함께 남기며 민감정보는 절대 로그에 남기지 마세요.

 

왜 println 대신 로거를 쓰나

println은 출력을 끄고 켤 수 없고, 언제·어디서 찍혔는지 정보가 없으며, 파일 저장이나 중요도별 필터링도 어렵습니다. 로거는 이 모든 것을 관리 가능하게 해주며 핵심이 로그 레벨입니다.

 

로그 레벨과 그 의미
레벨 언제 예시
ERROR 즉시 대응 필요 결제 실패, DB 끊김
WARN 주의 필요 재시도, 임계치 근접
INFO 정상 주요 흐름 서버 시작, 주문 완료
DEBUG 개발 상세 추적 변수 값, 분기 진입

운영에서는 INFO 이상만, 개발에서는 DEBUG까지 보는 식으로 조절합니다.

 

코드 예제
log.debug("주문 생성 시작, 요청={}", order);
log.info("주문 생성 완료, orderId={}", order.getId());
log.error("결제 실패, orderId={}", order.getId(), e); // 예외는 스택트레이스와 함께

 

실무 포인트

운영에서 DEBUG로 켜두면 로그가 폭증해 디스크가 차거나 비용이 커집니다. 운영은 INFO 이상으로 유지하고 조사 시에만 낮추세요.

주의 — 비밀번호·카드번호·토큰 같은 민감정보는 절대 로그에 남기지 마세요. 로그 유출이 곧 정보 유출이 됩니다.
