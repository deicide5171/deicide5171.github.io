AI 에이전트도 기억이 필요하다 — 3계층 메모리 아키텍처

2026. 8. 15. · AI

한 줄 요약 — 세션이 끝나면 모든 걸 잊는 에이전트의 한계를 넘기 위해, 운영체제 메모리 계층에서 착안한 Core·Recall·Archival 3계층 구조와 최근 동향을 정리했습니다.

 

왜 지금 에이전트 메모리일까요

지금까지 에이전트 관련 논의는 주로 "어떤 모델을 쓸까", "도구를 어떻게 연결할까"에 집중돼 있었습니다. MCP나 A2A 같은 프로토콜이 에이전트와 도구, 에이전트끼리의 연결 문제를 풀었다면 남은 문제는 하나입니다. 대화가 끝나고 세션이 닫히면 에이전트는 사용자에 대해 아무것도 기억하지 못합니다.

몇 주에 걸쳐 프로젝트를 이어가는 코딩·리서치 에이전트가 늘면서, "지난주에 뭘 했는지"를 기억하는 능력이 제품 경쟁력으로 떠올랐습니다. 그래서 에이전트 메모리는 이제 단순한 RAG 응용을 넘어, 자체 벤치마크(LoCoMo, LongMemEval 등)와 전용 아키텍처 패턴을 가진 독립 연구·엔지니어링 영역이 됐습니다.

 

핵심 구조: OS에서 빌려온 3계층

가장 널리 참조되는 설계는 운영체제 메모리 계층을 그대로 빌려온 것입니다. RAM·캐시·디스크가 속도와 용량을 맞바꾸듯, 에이전트 메모리도 접근 속도와 저장 용량을 맞바꾸는 3단계로 나뉩니다.

계층 OS 비유 저장 위치 역할
Core Memory RAM 컨텍스트 윈도우 안 항상 참조되는 프로필·현재 대화
Recall Memory 디스크 캐시 검색 가능한 대화 이력 최근 세션 기록, 필요 시 주입
Archival Memory 콜드 스토리지 벡터 DB·구조화 저장소 명시적 쿼리로만 조회하는 장기 기억

 

Core Memory는 매 요청마다 토큰 비용을 지불하므로 용량이 가장 제한적입니다. Recall과 Archival은 벡터·키워드 검색으로 필요한 순간에만 끌어와 컨텍스트에 삽입하는 방식으로 동작합니다. 이 구조 덕분에 에이전트는 컨텍스트 윈도우 크기에 얽매이지 않고 사실상 무한한 기억 용량을 가진 것처럼 행동할 수 있습니다.

 

예제: 계층형 메모리 조회 흐름

매 요청마다 Archival까지 뒤지면 지연시간과 비용이 커지므로, "지금 이 질문이 장기 기억을 필요로 하는가"를 판단하는 라우팅 단계가 핵심입니다.

def build_context(user_id, user_message, core_budget=2000):
    core = load_core_memory(user_id)  # 항상 포함

    recall_hits = recall_store.search(
        query=user_message, user_id=user_id, top_k=5
    )

    archival_hits = []
    if needs_long_term_lookup(user_message):
        archival_hits = archival_store.query(
            query=user_message, user_id=user_id, top_k=3
        )

    return assemble(core, recall_hits, archival_hits, budget=core_budget)

 

도입할 때 이것만은 챙기세요
1. 원문을 그대로 쌓지 않기 — Recall Memory에 대화 원문을 그대로 저장하면 검색 품질이 떨어집니다. 요약·엔티티 추출 후 저장하세요
2. 출처(provenance) 남기기 — 언제, 어떤 대화에서 만들어진 기억인지 함께 저장해야 정보 충돌 시 우선순위를 판단할 수 있습니다
3. 신선도(staleness) 정책 — 사용자 선호나 프로젝트 상태는 시간이 지나면 바뀝니다. 오래된 기억을 자동으로 낮은 신뢰도로 처리하는 규칙이 필요합니다
4. 벤치마크로 검증 — LoCoMo, LongMemEval 같은 장기 기억 벤치마크로 정기적으로 품질을 측정하세요

 

마무리 — 3줄 요약

① 에이전트 메모리는 Core·Recall·Archival 3계층으로 나눠 속도와 용량을 맞바꾸는 것이 기본 설계입니다.
② 여러 기기·도구를 넘나드는 에이전트에는 메모리를 분산 시스템처럼 다루는 동기화 패턴이 필요합니다.
③ 저장 시 요약·출처·신선도 관리를 함께 설계해야 장기 기억이 실제로 신뢰할 수 있는 정보로 남습니다.
