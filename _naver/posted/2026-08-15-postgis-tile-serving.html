PostGIS 하나로 벡터 타일 서버 만들기 — pg_tileserv 실전 정리

2026. 8. 15. · GIS

한 줄 요약 — PostGIS 테이블을 별도 ETL 없이 바로 웹 지도 타일로 서빙하는 pg_tileserv의 원리와 설정, 성능 포인트를 정리했습니다.

 

왜 지금 PostGIS 타일 서빙인가

웹 지도에 대용량 공간 데이터를 올릴 때 흔한 방식은 "DB에서 데이터를 뽑아 → 배치로 타일을 미리 구워서 → 정적 파일로 서빙"하는 파이프라인이었습니다. 빠르긴 하지만 데이터가 바뀔 때마다 다시 구워야 해서, 배차 현황이나 실시간 신고 지도처럼 실시간성이 중요한 서비스에는 잘 맞지 않습니다.

PostGIS는 이미 많은 팀이 공간 데이터 저장소로 쓰고 있는 오픈소스 확장입니다. 여기에 pg_tileserv 같은 경량 타일 서버를 앞단에 붙이면, 지오메트리 컬럼이 있는 테이블을 별도 ETL 없이 그대로 벡터 타일(MVT) 레이어로 자동 노출할 수 있습니다. DB에 데이터가 바뀌는 즉시 지도에 반영되는 구조를 훨씬 적은 인프라로 만들 수 있는 거죠.

 

기존 방식 vs PostGIS 직접 서빙
항목 사전 타일링(배치) PostGIS + pg_tileserv
최신성 배치 주기만큼 지연 DB 반영 즉시
인프라 타일 생성 파이프라인 + 스토리지 DB + 경량 서버 하나
동적 쿼리 어려움 SQL 함수로 자유롭게 조건 추가

 

정적 지도(행정구역 경계, 국가 지도)는 사전 타일링이 여전히 유리합니다. 반면 자주 바뀌고 조회 조건이 다양한 데이터는 PostGIS 직접 서빙이 더 잘 맞습니다.

 

동작 원리

① 테이블에 geometry 컬럼과 공간 인덱스(GiST)가 있으면 pg_tileserv가 자동으로 타일 레이어로 등록합니다.
② 지도 클라이언트가 특정 타일 좌표(z/x/y)를 요청합니다.
③ pg_tileserv는 해당 타일의 경계 박스만 ST_AsMVT 함수로 SQL 조회합니다.
④ 결과를 MVT 바이너리로 인코딩해 응답하고, 클라이언트는 MapLibre 등으로 렌더링합니다.

핵심은 전체 지도를 미리 만들지 않고, 화면에 보이는 범위만 그때그때 SQL로 잘라 준다는 점입니다.

 

예제: 조건이 있는 커스텀 타일 만들기

단순 테이블 노출을 넘어, 조건이 있는 동적 레이어는 SQL 함수로 만듭니다.

CREATE OR REPLACE FUNCTION public.active_reports(
    z integer, x integer, y integer
) RETURNS bytea AS $$
    SELECT ST_AsMVT(tile, 'active_reports', 4096, 'geom') FROM (
        SELECT
            id,
            title,
            ST_AsMVTGeom(
                geom,
                ST_TileEnvelope(z, x, y),
                4096, 64, true
            ) AS geom
        FROM reports
        WHERE status = 'active'
          AND geom && ST_TileEnvelope(z, x, y)
    ) AS tile;
$$ LANGUAGE SQL STABLE;

geom && ST_TileEnvelope(z, x, y)는 GiST 공간 인덱스를 타는 bbox 필터로, 전체 테이블을 스캔하지 않고 해당 타일 범위와 겹치는 행만 빠르게 골라냅니다. pg_tileserv는 이 함수를 자동 감지해 활성 신고 데이터만 담은 레이어로 노출합니다.

 

실무 도입 시 이것만은 챙기세요
1. 공간 인덱스는 필수 — geom 컬럼에 GIST 인덱스가 없으면 타일 요청마다 전체 스캔이 발생해 응답이 급격히 느려짐
2. 저줌 레벨에서는 단순화 — 국가 단위 지도에서까지 원본 정밀도 폴리곤을 보낼 필요 없이 ST_Simplify로 톨러런스 조절
3. 캐싱을 앞단에 배치 — 자주 조회되는 저줌 타일은 CDN·리버스 프록시 캐시로 DB 부하 절감
4. 함수 파라미터 검증 — 사용자 입력을 SQL 함수 인자로 넘길 때 SQL 인젝션 방지를 위한 바인딩·화이트리스트 필수

 

마무리 — 3줄 요약

① PostGIS + pg_tileserv 조합은 별도 ETL 없이 DB 테이블을 실시간 벡터 타일로 노출할 수 있게 해줍니다.
② 요청받은 타일의 bbox만 ST_AsMVT로 잘라 SQL로 조회하는 방식이라, GiST 공간 인덱스가 성능을 좌우합니다.
③ 정적·대용량 지도는 사전 타일링이 유리하고, 자주 바뀌는 동적 데이터에는 PostGIS 직접 서빙이 현실적인 선택지입니다.
