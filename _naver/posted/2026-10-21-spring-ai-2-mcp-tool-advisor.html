Spring AI 2.0 GA — MCP 서버를 Spring Boot 서비스에 바로 얹는 설계

STACK

한 줄 요약 — AI 기능을 기존 Spring Boot 서비스에 붙여달라는 요구는 더 이상 별도 Python 서버를 세우는 일이 아닙니다. 2026년 6월 GA된 Spring AI 2.0의 @McpTool 어노테이션과 ToolCallingAdvisor가 기존 서비스 메서드를 MCP 도구로 바꾸는 방식과, 1.x에서 올라갈 때 무엇이 깨지는지 정리했습니다.

 

왜 지금 이 판단이 필요한가

"우리 재고 조회·주문 처리 로직을 에이전트가 직접 호출하게 해주세요. 근데 Python으로 따로 서버 하나 더 올리는 건 피하고 싶어요." Java·Spring 스택으로 백엔드를 운영해 온 팀이 AI 에이전트 연동을 검토할 때 흔히 부딪히는 벽입니다. MCP 서버 구현체 대부분이 Python·TypeScript 생태계에 몰려 있어서, 기존 Spring Boot 서비스 로직을 그대로 쓰려면 REST API로 한 번 감싸고 그 위에 별도 MCP 서버를 또 세우는 이중 구조가 되기 쉬웠습니다.

2026년 6월 12일 GA된 Spring AI 2.0은 이 문제를 정면으로 겨냥합니다. MCP Java SDK 2.0.0을 품고, 기존에 커뮤니티 프로젝트였던 mcp-annotations를 코어로 편입시켜 @McpTool 하나로 평범한 Spring 서비스 메서드를 MCP 도구로 노출할 수 있게 됐습니다. 동시에 도구 호출 루프를 어드바이저 체인 안으로 옮기면서 1.x의 도구 호출 방식과 완전히 같지는 않은 구조가 됐습니다. "그냥 AI 라이브러리 버전 올리기"로 받으면 안 되는 이유입니다.

 

전체 시스템에서의 위치

Spring AI 2.0을 기존 Spring Boot 아키텍처에 끼워 넣으면 어디에 무엇이 새로 들어오는지가 명확해집니다.

기존 서비스 레이어(@Service 빈)는 그대로 둡니다. 여기에 @McpTool 메서드 어노테이션만 추가하면 MCP 서버의 도구 목록에 자동 등록됩니다. ChatClient + Advisor 체인이 도구 호출 루프를 담당하며, 1.x에서 ToolCallback을 직접 등록하던 방식 대신 ToolCallingAdvisor가 체인 중간에서 호출을 가로채는 구조로 바뀌었습니다. 결과적으로 앞단 에이전트는 표준 MCP 클라이언트로 접속하고, 뒷단은 기존 DB·비즈니스 로직을 그대로 재사용합니다.

 

선택의 트레이드오프
접근 장점 단점
별도 Python MCP 서버 생태계 성숙 비즈니스 로직 이중 구현
Spring AI 2.0 @McpTool 로직 단일 소스, 기존 설정 재사용 Java MCP SDK 생태계 신생
1.x ToolCallback 유지 변경 비용 없음 신규 기능 못 받음
전면 마이그레이션 장기적 일관성 무중단 패치 아님

 

판단 기준은 "지금 AI 기능이 핵심 비즈니스 로직과 얼마나 가까이 있는가"입니다. 단순 챗봇 응답 생성처럼 거리가 있으면 별도 서버 유지도 나쁘지 않지만, 재고·주문처럼 기존 서비스 레이어의 트랜잭션·검증 로직을 그대로 써야 한다면 로직을 복제하지 않는 @McpTool 노출 쪽이 유지보수 비용을 크게 줄입니다.

 

실제 프로젝트 진행 순서

1. Spring Boot 4.0/4.1·Spring Framework 7·Jackson 3 요구사항부터 맞춥니다. Boot 3.x라면 AI 업그레이드보다 Boot 4 마이그레이션이 선행 과제입니다.
2. 에이전트가 호출해도 안전한 메서드(멱등하거나 명확한 권한 검사가 있는)만 먼저 추립니다.
3. 읽기 전용 조회 메서드부터 @McpTool로 노출하고 실제 호출을 확인합니다.
4. 주문 생성처럼 되돌리기 어려운 도구는 어드바이저 체인에 승인 단계를 끼워 넣습니다.
5. 1.x ToolCallback 코드는 전수 조사 후 모듈 단위로 단계적으로 옮깁니다.
6. 벡터 스토어 의존성을 분리된 레포지토리 좌표로 갱신합니다.

 

예제 코드:

@Service
public class InventoryService {

    @McpTool(name = "check_stock", description = "SKU로 현재 재고 수량을 조회한다")
    public StockInfo checkStock(@McpToolParam(description = "조회할 SKU") String sku) {
        return inventoryRepository.findBySku(sku)
            .map(StockInfo::from)
            .orElseThrow(() -> new SkuNotFoundException(sku));
    }
}

 

주의 — @McpTool 메서드는 기존 @Service 빈의 메서드이므로 @PreAuthorize 같은 권한 검사가 그대로 적용됩니다. 도구 설명은 짧게 쓰지 말고 호출 조건과 반환값 의미까지 구체적으로 적으세요. 2.0은 1.x의 드롭인 교체가 아니므로 업그레이드 PR은 기능 추가와 분리해 검토받으세요.

 

정리

Spring AI 2.0은 기존 Spring Boot 서비스 메서드를 별도 서버 없이 @McpTool로 바로 MCP 도구화할 수 있게 만든 전환점입니다. 도구 호출 루프가 어드바이저 체인으로 옮겨가면서 1.x 코드는 드롭인 교체가 아니라 단계적 이전 대상이 됩니다. 판단 기준은 AI 기능이 핵심 비즈니스 로직과 얼마나 가까운가이며, 가까울수록 기존 서비스 레이어를 그대로 노출하는 쪽이 유리합니다.
