로그가 서버마다 흩어져 있을 때 — 중앙 로그 수집 기초

인프라

한 줄 요약 — 중앙 로그 수집은 흩어진 로그를 한 곳에 모아 검색·분석하며, 구조화(JSON) 로그와 요청 추적 ID가 핵심입니다.

 

서버 10대에 일일이 들어가 볼 순 없다

서버가 여러 대로 늘면 어느 서버가 에러를 냈는지 모르니 다 들어가 grep을 돌려야 합니다. 로드밸런서 환경에선 한 사용자 요청이 여러 서버에 흩어져 추적이 거의 불가능합니다. 중앙 로그 수집이 이를 해결합니다.

 

기본 흐름
각 서버 -> 수집 에이전트 -> 중앙 저장소 -> 대시보드
(Filebeat)    (Elasticsearch)   (Kibana)

 

대표적인 조합
스택 구성
ELK Elasticsearch + Logstash + Kibana
Loki 스택 Loki + Promtail + Grafana(가볍고 저렴)

 

구조화가 핵심
비구조화: 2026-09-06 ERROR 결제 실패 user=123
구조화(JSON): {"level":"ERROR","msg":"결제 실패","user":"123"}
-> 필드로 조건 검색 가능

 

실무 포인트

로그에 요청 추적 ID(trace id)를 붙이면, 여러 서버를 거치는 한 요청을 하나의 흐름으로 이어 볼 수 있습니다.

주의 — 로그 양과 보관 기간이 곧 비용입니다. 여러 곳으로 흘러가므로 비밀번호·개인정보가 로그에 섞이지 않게 수집 단계에서 마스킹하세요.
