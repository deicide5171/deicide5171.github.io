메모리도 거리가 있다 — NUMA를 고려한 애플리케이션·DB 튜닝

2026. 8. 24. · 인프라

한 줄 요약 — 멀티소켓 서버에서 로컬/원격 메모리 접근의 지연 시간이 다른 NUMA 구조를 짚고, numactl과 애플리케이션·DB 설정으로 이를 고려하는 실무 튜닝법을 정리했습니다.

 

벤치마크가 재현되지 않는다면

같은 서버, 같은 RAM 용량인데 벤치마크 점수가 재현되지 않는다면 NUMA(Non-Uniform Memory Access) 배치를 의심해볼 시점입니다. 멀티소켓 서버에서는 각 CPU 소켓(NUMA 노드)이 자신에게 물리적으로 붙어 있는 로컬 메모리와, 다른 소켓에 붙은 원격 메모리를 모두 접근할 수 있지만, 두 접근의 지연 시간은 같지 않습니다.

커널 스케줄러나 메모리 할당자가 프로세스를 잘못된 노드에 배치하면, 논리적으로는 아무 문제가 없어 보이는 코드가 실제로는 매번 원격 메모리를 오가며 성능을 갉아먹습니다.

 

핵심 개념 1 — NUMA 노드와 로컬/원격 접근 지연

멀티소켓 서버는 각 CPU 소켓마다 자신의 메모리 컨트롤러에 직접 연결된 RAM 뱅크(로컬 메모리)를 갖고, 소켓 간은 QPI/UPI나 Infinity Fabric 같은 인터커넥트로 연결됩니다. 소켓 A의 코어가 소켓 B에 붙은 메모리에 접근하려면 이 인터커넥트를 거쳐야 하므로 지연 시간이 늘어납니다.

$ numactl --hardware
available: 2 nodes (0-1)
node 0 cpus: 0 1 2 3 4 5 6 7
node 0 size: 128932 MB
node distances:
node   0   1
  0:  10  21
  1:  21  10

distance 값이 클수록 원격 접근 비용이 크다는 뜻이며, 이 값이 애플리케이션 배치 결정의 기초 데이터가 됩니다.

 

핵심 개념 2 — 메모리 정책: bind, interleave, preferred
정책 동작 적합한 상황
cpunodebind + membind 특정 노드의 CPU·메모리만 사용 노드 크기에 맞는 단일 인스턴스
interleave 여러 노드에 라운드로빈 분산 노드보다 큰 메모리를 쓰는 프로세스
preferred 가능하면 지정 노드, 부족 시 허용 유연성이 필요한 경우

 

DB나 JVM처럼 하나의 프로세스가 서버 메모리 대부분을 차지하는 경우, 무정책 상태로 두면 커널의 기본 할당 정책(first-touch)에 의존하게 되는데, 스레드가 노드 간을 오가며 실행되면 원격 접근이 누적됩니다.

 

예제 — numactl로 PostgreSQL 프로세스 바인딩
# 노드 0의 CPU와 메모리만 사용하도록 시작
numactl --cpunodebind=0 --membind=0 \
  pg_ctl -D /var/lib/postgresql/16/main start

# 큰 메모리 영역은 여러 노드에 분산해 병목 완화
numactl --interleave=all \
  pg_ctl -D /var/lib/postgresql/16/main start

shared_buffers가 단일 노드 크기를 넘는 대형 인스턴스에서는 interleave=all이 한 노드에 몰리는 것보다 안정적인 경우가 많습니다. 인스턴스를 노드 크기에 맞춰 쪼갤 수 있다면 각 인스턴스를 노드에 고정하는 편이 더 예측 가능한 지연을 줍니다.

 

실무 도입 시 이것만은 챙기세요
1. JVM은 -XX:+UseNUMA 옵션을 확인하세요 — G1GC 등 일부 GC는 NUMA 인식 할당을 지원하지만, 애플리케이션 스레드가 노드를 오가면 이점이 상쇄되므로 CPU 어피니티와 함께 고려해야 합니다.
2. Transparent Huge Page와 NUMA의 상호작용을 주의하세요 — 압축 작업이 노드 경계를 넘나들며 예기치 않은 지연 스파이크를 유발할 수 있어 DB 워크로드에서는 madvise로 제한하는 경우가 많습니다.
3. 측정 없이 바인딩부터 하지 마세요 — numastat, perf stat으로 실제 원격 접근 비율을 먼저 측정해야 합니다.

 

마무리 — 3줄 요약

① 멀티소켓 서버에서는 로컬/원격 메모리 접근의 지연 시간이 다르며, numactl --hardware의 노드 거리로 그 정도를 확인할 수 있습니다.
② 워크로드가 노드 하나에 들어가면 cpunodebind/membind로 고정하고, 노드보다 크면 interleave로 분산하는 것이 기본 전략입니다.
③ JVM의 NUMA 인식 GC 옵션, THP와의 상호작용, 바인딩 전 실측이 실무 튜닝의 핵심입니다.
