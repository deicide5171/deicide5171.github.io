트랜잭션이 뭔가요 — ACID 개념부터 예제까지

데이터베이스

한 줄 요약 — 트랜잭션은 여러 작업을 전부 성공하거나 전부 실패하는 하나의 단위로 묶어 데이터 일관성을 지키는 개념입니다.

 

왜 이체 도중 서버가 죽으면 돈이 사라지면 안 되는가

계좌 이체는 "A에서 빼고 B에 더한다"는 두 작업으로 이뤄집니다. A에서 돈을 뺀 직후 서버가 죽으면 B는 못 받았는데 A만 사라지는 사고가 납니다. 트랜잭션은 이런 사고를 막는 개념입니다.

 

ACID란 무엇인가
속성 의미
원자성(A) 전부 성공하거나 전부 실패
일관성(C) 트랜잭션 전후 데이터 규칙 유지
고립성(I) 동시 트랜잭션끼리 간섭하지 않음
지속성(D) 커밋된 데이터는 장애가 나도 유지

 

예제 — 트랜잭션으로 묶은 이체
BEGIN;
UPDATE accounts SET balance = balance - 10000 WHERE id = 'A';
UPDATE accounts SET balance = balance + 10000 WHERE id = 'B';
COMMIT;
-- 중간에 오류가 나면 ROLLBACK으로 둘 다 취소

BEGIN과 COMMIT 사이의 두 UPDATE는 하나의 단위로 묶입니다. 두 번째에서 에러가 나면 첫 번째도 함께 취소해야 잔액 사고를 막을 수 있습니다.

 

애플리케이션 코드에서의 트랜잭션
@Transactional
public void transfer(String fromId, String toId, BigDecimal amount) {
    Account from = accountRepository.findById(fromId);
    Account to = accountRepository.findById(toId);
    from.withdraw(amount);
    to.deposit(amount);
}

 

실무 포인트

트랜잭션이 너무 길면 락을 오래 잡아 다른 요청이 대기합니다. 외부 API 호출 같은 느린 작업은 트랜잭션 안에 넣지 않는 것이 기본 원칙입니다.

주의 — 같은 클래스 내부에서 메서드를 직접 호출(self-invocation)하면 프록시를 거치지 않아 @Transactional이 적용되지 않는 흔한 함정이 있습니다.
