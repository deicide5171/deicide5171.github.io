Next.js 16.3 업데이트 — Turbopack 개선과 Rust 기반 React Compiler

2026. 8. 15. · 웹개발

한 줄 요약 — Next.js 16.3 계열 업데이트에서는 Turbopack 메모리 관리와 영속 빌드 캐시가 다듬어졌고, Rust 기반 React Compiler 지원과 Vite 호환 import.meta.glob이 추가되었습니다.

 

왜 지금 이 업데이트인가

Next.js는 몇 버전 전부터 Turbopack을 기본 번들러로 밀어붙이고 있습니다. 16번대에 들어서면서는 빌드 파이프라인 자체를 Rust 툴체인으로 옮기는 작업이 계속 진행되고 있는데요, 16.3 계열은 새 기능을 잔뜩 얹는 릴리스라기보다 그동안 쌓인 메모리·캐시·HMR 안정성 이슈를 다듬는 성격이 강합니다.

특히 대규모 프로젝트에서 dev 서버가 오래 켜져 있을수록 메모리를 계속 점유하는 문제, 재시작할 때마다 캐시가 날아가 처음부터 다시 컴파일하는 문제는 실무에서 체감이 컸던 부분입니다. 여기에 더해 Rust 네이티브 React Compiler 지원이 함께 다뤄지고 있어, 실무자 입장에서 짚어볼 가치가 있다고 판단했습니다.

 

16.3의 핵심 변화
영역 이전 방식 16.3 계열에서의 변화
Turbopack 메모리 장시간 구동 시 메모리 누적 경향 사용하지 않는 캐시 정리(eviction) 로직 강화
빌드 캐시 재시작 시 캐시 초기화가 잦음 디스크 기반 영속 캐시로 재사용 시도
React Compiler Babel 플러그인 경유 Rust 네이티브 구현 경로 지원
모듈 탐색 정적 import 위주 Vite 호환 import.meta.glob 지원
next/image 기존 최적화 파이프라인 캐시·리사이징 세부 개선 지속 반영

 

Rust 기반 React Compiler, 무엇이 달라지나

기존에는 React Compiler를 쓰려면 Babel 플러그인을 거쳐야 했습니다. Babel 기반 트랜스파일은 AST 순회와 변환 과정에서 빌드 시간에 영향을 주는데요, Turbopack이 Rust로 전환되면서 이 컴파일러 단계도 Rust 네이티브 경로로 처리할 수 있게 하는 방향이 함께 다뤄지고 있습니다.

설정 자체는 크게 복잡하지 않습니다. next.config에서 실험적 플래그로 컴파일러를 켜는 기존 방식은 그대로 유지되고, 내부적으로 Turbopack이 이를 처리하는 경로가 바뀌는 쪽에 가깝습니다.

// next.config.ts
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  experimental: {
    reactCompiler: true,
  },
};

export default nextConfig;

또 하나 눈에 띄는 변화는 Vite 호환 import.meta.glob 지원입니다. 여러 파일을 패턴으로 한 번에 불러오는 방식은 Vite 생태계에서 익숙한데, Turbopack이 이를 지원하면서 Vite와 Next.js 사이를 오가는 프로젝트의 마이그레이션 장벽이 다소 낮아질 것으로 보입니다.

// Vite 스타일 glob import 예시
const modules = import.meta.glob("./pages/**/*.tsx");

for (const path in modules) {
  console.log(path); // 예: "./pages/about.tsx"
}

 

실무 도입 시 이것만은 챙기세요
1. dev 서버로 먼저 검증 — Turbopack 메모리 개선은 로컬 개발 환경에서 체감 효과가 크므로 프로덕션 빌드보다 dev 워크플로에서 먼저 확인하세요
2. 캐시 디렉토리 용량 모니터링 — 영속 빌드 캐시가 디스크에 쌓이는 구조라 CI·컨테이너 빌드에서는 캐시 정리 정책을 함께 점검해야 합니다
3. React Compiler 회귀 테스트 우선 — Babel 경로에서 Rust 네이티브 경로로 처리 방식이 바뀌는 지점이므로 업그레이드 전후 렌더링 결과를 비교해보세요
4. 패치 버전 고정 후 단계적 업그레이드 — 16.3.x 패치가 이어지는 시기이므로 프로덕션은 특정 패치에 고정하고 개발 브랜치에서 먼저 검증하는 것이 안전합니다
5. 구체적 수치는 직접 측정 — 메모리 절감률이나 빌드 시간 단축 폭은 프로젝트 규모에 따라 달라질 수 있어 벤치마크는 각자 환경에서 재보는 것을 권장합니다

 

마무리 — 3줄 요약

① Next.js 16.3 계열은 Turbopack의 메모리 eviction과 영속 빌드 캐시로 dev 서버 안정성을 다듬는 데 초점을 둔 업데이트입니다.
② React Compiler를 Rust 네이티브 경로로 지원하고 Vite 호환 import.meta.glob을 도입해 빌드 성능과 생태계 호환성을 함께 넓히려 하고 있습니다.
③ 실무에서는 캐시 디렉토리 관리, 패치 버전 고정, React Compiler 회귀 테스트를 체크리스트 삼아 단계적으로 업그레이드하는 것이 안전합니다.
