위성영상 수천 장을 배열 하나처럼 — 시공간 래스터 데이터큐브(xarray/zarr)

GIS

한 줄 요약 — 시간·위도·경도·밴드 축이 모두 있는 위성영상 래스터 데이터를 파일 단위가 아니라 다차원 배열 하나로 다루는 데이터큐브 개념과, xarray·Zarr로 이를 구현하는 방법을 정리했습니다.

 

파일 천 개를 순회하는 코드, 언제까지 짜야 할까요

특정 지역의 3년치 위성영상에서 "여름철 평균 NDVI 변화"를 구하고 싶다고 해보겠습니다. 데이터가 하루 단위 GeoTIFF 파일 천 개로 흩어져 있다면, 이 질문에 답하기 위해 파일을 하나씩 열고 날짜를 파싱해 여름철만 골라내고 좌표계를 맞춰 픽셀 단위로 합산하는 코드를 직접 짜야 합니다. 파일 수가 수천~수만 개로 늘어나면 이 방식은 코드도 지저분해지고 I/O 병목도 심각해집니다.

시공간 데이터큐브는 이 문제를 "파일들의 모음"이 아니라 시간·위도·경도·밴드가 축인 하나의 다차원 배열로 재구성해서 풉니다. "여름철 평균"은 더 이상 파일을 순회하는 반복문이 아니라, 그 배열에서 시간 축을 조건으로 슬라이싱한 뒤 평균을 내는 배열 연산 한 줄이 됩니다.

 

핵심 개념 1 — 축이 있는 배열로 사고를 전환합니다

전통적인 래스터 처리는 파일 하나를 특정 시점·특정 밴드의 2차원 격자로 봅니다. 데이터큐브는 여기에 시간과 밴드를 추가 차원으로 붙여 전체를 (time, band, y, x) 4차원 배열 하나로 봅니다. "특정 시점 조회"는 time 축 인덱싱, "시계열 추세"는 좌표를 고정하고 time 축을 따라가는 것, "밴드 지수 계산"은 band 축 연산이 됩니다.

 

핵심 개념 2 — xarray는 축에 이름과 좌표를 붙입니다

NumPy 배열은 축이 그냥 정수 인덱스라서 어느 밴드, 어느 날짜인지 코드를 보는 사람이 따로 기억해야 합니다. xarray는 각 축의 이름(time, band, y, x)과 실제 좌표값을 붙인 DataArray/Dataset 구조를 제공해, cube.sel(time="2026-07-01", band="nir")처럼 실제 의미가 담긴 값으로 슬라이싱할 수 있게 합니다.

핵심 개념 3 — Zarr는 클라우드에서 청크 단위로 저장·조회합니다

데이터큐브 전체를 메모리에 올리는 것은 대부분 불가능합니다. Zarr는 대용량 배열을 청크(chunk) 단위로 나눠 저장하는 포맷으로, S3·GCS 같은 오브젝트 스토리지에 청크들을 흩어 저장해두고 필요한 청크만 부분적으로 읽어올 수 있게 합니다. xarray와 함께 쓰면 큐브를 열 때 실제 데이터는 즉시 읽지 않고 지연 평가 상태로 메타데이터만 로드합니다.

비교 GeoTIFF 파일 모음 Zarr + xarray 데이터큐브
시계열 조회 파일 목록 순회 + 수동 스태킹 축 슬라이싱 한 줄
병렬 처리 별도 구현 필요 Dask와 자연스럽게 결합

 

예제 — xarray + Zarr로 여름철 평균 NDVI 계산
import xarray as xr

# 클라우드에 저장된 Zarr 큐브를 지연 평가로 오픈
cube = xr.open_zarr("s3://example-bucket/sentinel2-cube.zarr", chunks="auto")

nir = cube["reflectance"].sel(band="nir")
red = cube["reflectance"].sel(band="red")
ndvi = (nir - red) / (nir + red)

# 6~8월만 골라 시간 축 평균
summer_ndvi = ndvi.sel(time=ndvi.time.dt.month.isin([6, 7, 8])).mean(dim="time")

summer_ndvi.rio.write_crs("EPSG:32652", inplace=True)
summer_ndvi.rio.to_raster("summer_ndvi_mean.tif")

chunks="auto"로 열면 xarray가 Dask 배열 위에서 동작해 mean(dim="time") 같은 연산도 청크 단위로 병렬 실행됩니다. 원본 수백GB 큐브 전체를 메모리에 올릴 필요가 없습니다.

 

실무 도입 시 이것만은 챙기세요
1. 청크 크기는 접근 패턴에 맞춰 설계하세요 — 시계열 분석이 주 용도라면 time 축은 작게, 공간 축은 크게 잡아야 합니다.
2. STAC 카탈로그와 결합해 큐브를 동적으로 구성하는 방식도 고려하세요 — stackstac, odc-stac은 미리 Zarr로 재적재하지 않고도 데이터큐브 인터페이스를 얻게 해줍니다.
3. 좌표계·리샘플링 정합성을 사전에 확인하세요 — 여러 위성의 영상은 투영법이나 해상도가 다를 수 있어 공통 격자로 리샘플링해둬야 합니다.

 

마무리 — 3줄 요약

① 시공간 데이터큐브는 파일들의 모음이 아니라 시간·밴드·위도·경도를 축으로 갖는 다차원 배열 하나로 래스터 시계열을 다루는 접근입니다.
② xarray는 축에 이름과 좌표값을 붙여 의미 있는 슬라이싱을 가능하게 하고, Zarr는 청크 단위 저장으로 클라우드에서 부분 조회를 가능하게 합니다.
③ 청크 크기를 접근 패턴에 맞추고 병합 전 좌표계·해상도 정합성을 맞춰야 데이터큐브의 이점을 제대로 살릴 수 있습니다.
