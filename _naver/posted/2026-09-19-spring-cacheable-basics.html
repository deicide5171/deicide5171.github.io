Spring @Cacheable 처음 써보기 — 캐싱을 애노테이션 한 줄로

백엔드

한 줄 요약 — @Cacheable은 메서드 결과를 캐시에 저장하며, 데이터 변경 시 @CacheEvict로 캐시를 지워야 오래된 데이터가 안 나옵니다.

 

같은 조회를 반복하는 게 아깝다면

자주 조회되지만 잘 안 바뀌는 데이터를 매번 DB에서 가져오는 것은 낭비입니다. @Cacheable은 애노테이션 한 줄로 메서드 결과를 캐시에 저장하고 다음부터 캐시에서 바로 반환합니다.

 

기본 사용법
@Cacheable("products")
public Product getProduct(Long id) {
    return productRepository.findById(id).orElseThrow();
}

처음 호출하면 DB를 조회해 캐시에 저장하고, 다음부터는 메서드를 실행하지 않고 캐시된 결과를 반환합니다. 인자(id)가 캐시 키가 됩니다.

 

캐시 관련 애노테이션
애노테이션 역할
@Cacheable 결과 캐시 저장(있으면 반환)
@CachePut 항상 실행 + 캐시 갱신
@CacheEvict 캐시 삭제(데이터 변경 시) 
@CacheEvict(value = "products", key = "#product.id")
public void updateProduct(Product product) { ... }

 

실무 포인트

캐시 무효화를 빠뜨리면 오래된 데이터가 계속 나옵니다. 수정·삭제 메서드에 @CacheEvict를 붙여야 합니다.

주의 — 기본 캐시는 애플리케이션 메모리라 서버가 여러 대면 공유가 안 됩니다. Redis 같은 공유 캐시를 연결하세요. self-invocation 함정도 주의하세요.
