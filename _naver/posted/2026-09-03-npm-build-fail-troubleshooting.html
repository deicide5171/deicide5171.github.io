로컬에선 되는데 빌드는 실패할 때 — npm run build 에러 잡기

프론트엔드

한 줄 요약 — dev는 관대하지만 build는 타입·최적화를 엄격히 검사하며, import 경로 대소문자 불일치가 리눅스 CI에서 깨지는 대표 함정입니다.

 

왜 dev는 되는데 build만 깨지나

개발 서버는 관대하게 동작하지만, 프로덕션 빌드는 타입 검사와 최적화를 더 엄격하게 수행합니다. 그래서 개발 중에는 넘어갔던 문제가 빌드에서 드러납니다.

 

흔한 원인 유형
유형 원인
타입 에러 dev는 건너뛰지만 build는 엄격히 검사
대소문자 파일명 리눅스 CI는 대소문자 구분
환경변수 누락 CI에 .env 값이 없음

 

가장 악명 높은 함정 — 대소문자
// 파일명은 Button.tsx인데
import Button from './components/button'; // 소문자!

// 맥/윈도우: 통과 (대소문자 무시)
// 리눅스 CI: Module not found 에러!

import 경로의 대소문자가 실제 파일명과 정확히 일치하는지 확인해야 합니다.

 

진단 순서
# 1. 로컬에서 프로덕션 빌드 직접 실행
npm run build

# 2. 에러의 파일·줄·유형 파악
# 3. CI에서만 나면 Node 버전·환경변수 비교
node -v

핵심은 dev가 아니라 npm run build를 직접 실행해 재현하는 것입니다.

 

실무 포인트

프론트엔드 빌드는 .env 값을 최종 번들에 박아넣습니다. CI에 환경변수를 등록하지 않으면 undefined가 그대로 빌드됩니다.

주의 — 큰 프로젝트는 CI 메모리 제한에 걸려 JavaScript heap out of memory로 실패할 수 있습니다. Node 메모리 할당량을 늘리는 옵션이 필요합니다.
