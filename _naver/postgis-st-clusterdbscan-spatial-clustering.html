PostGIS ST_ClusterDBSCAN으로 공간 밀집 지역 자동 탐지하기

GIS

한 줄 요약 — 화면 줌 기반 클러스터링과 달리 실제 좌표 거리와 밀도로 진짜 밀집 구역을 찾는 PostGIS ST_ClusterDBSCAN을 정리했습니다.

 

왜 지금 ST_ClusterDBSCAN을 다시 봐야 하는가

마커 클러스터링은 화면에 겹쳐 보이는 마커를 시각적으로 묶는 것일 뿐, 줌 레벨이 바뀌면 구성 자체가 매번 달라지는 임시 그룹핑입니다. 실무에서는 화면과 무관하게 데이터 자체의 공간적 밀집도를 분석해 영구적으로 저장해야 할 때가 많습니다. PostGIS는 이를 ST_ClusterDBSCAN 함수로 SQL 한 번에 제공합니다.

 

거리(eps)와 최소 개수(minpoints)로 정의되는 밀집

DBSCAN은 클러스터 개수를 미리 지정할 필요가 없습니다. eps(이웃 인정 최대 거리)와 minpoints(핵심점이 되기 위한 최소 이웃 수)로 밀집을 정의합니다. 핵심점들이 서로 eps 거리 안에서 연쇄적으로 이어지면 하나의 클러스터가 되고, 어디에도 속하지 못한 점은 노이즈로 분류됩니다.

 

윈도우 함수로 동작한다

ST_ClusterDBSCAN은 GROUP BY가 아니라 OVER() 절과 함께 윈도우 함수로 사용합니다. 각 행에 클러스터 번호를 새 컬럼으로 반환하고 원래 행 개수는 그대로 유지됩니다. 이후 GROUP BY로 클러스터별 통계를 뽑는 후속 쿼리와 자연스럽게 이어집니다.

항목 클라이언트 클러스터링 ST_ClusterDBSCAN
판단 기준 화면 픽셀 거리 실제 좌표 거리와 밀도
결과 영속성 렌더링마다 재계산 쿼리 결과 영구 저장 가능

 

배달 요청 밀집 구역 탐지 예제
SELECT
    id,
    geom,
    ST_ClusterDBSCAN(geom, eps := 500, minpoints := 5) OVER () AS cluster_id
FROM delivery_requests;

-- 클러스터별 통계
SELECT
    cluster_id,
    COUNT(*) AS point_count,
    ST_Centroid(ST_Collect(geom)) AS cluster_center
FROM clustered
WHERE cluster_id IS NOT NULL
GROUP BY cluster_id;

 

 

실무 포인트

eps 단위는 사용 중인 SRID의 단위를 그대로 따릅니다. EPSG:4326(위경도)로 계산하면 eps=500이 500도가 되어버리는 실수가 흔합니다. 미터 단위가 필요하면 EPSG:3857 같은 투영좌표계로 변환한 geometry를 써야 합니다.

minpoints를 너무 작게 잡으면 노이즈 필터링 효과가 거의 사라집니다. 도메인 지식에 맞춰 의미 있는 최소 개수를 정해야 합니다.

주의 — 대용량 테이블에서는 공간 인덱스(GiST)가 걸려 있어야 실행 계획이 합리적으로 나옵니다. 함수 자체가 인덱스를 직접 쓰진 않지만, WHERE 절과 함께 쓸 때 인덱스 유무가 전체 성능에 큰 영향을 줍니다.
