N+1 문제가 뭔가요 — 쿼리가 갑자기 수백 번 나가는 이유

데이터베이스

한 줄 요약 — 목록 조회 1번 + 각 항목의 연관 데이터 조회 N번이 따로 나가 쿼리가 폭증하는 현상이며, Fetch Join으로 한 번에 가져오는 것이 기본 해결책입니다.

 

리스트 하나 조회했을 뿐인데 쿼리가 수백 번

게시글 10개를 조회했는데 쿼리가 11번, 100개면 101번 나가는 경우가 있습니다. 이것이 N+1 문제입니다. 목록 쿼리 1번 + 각 항목의 연관 데이터 쿼리 N번이 따로 나가 데이터가 많아질수록 쿼리 수가 폭증합니다.

 

왜 발생하는가
List<Post> posts = postRepository.findAll(); // 쿼리 1번

for (Post post : posts) {
    post.getAuthor().getName();
    // -> 게시글마다 SELECT * FROM users WHERE id = ? 가 한 번씩!
}

ORM이 연관 데이터를 "실제로 쓸 때 가져오는(지연 로딩)" 특성 때문에 코드만 봐서는 눈치채기 어렵습니다.

 

해결의 기본 아이디어
@Query("SELECT p FROM Post p JOIN FETCH p.author")
List<Post> findAllWithAuthor();
// -> 쿼리 1번으로 끝난다

"필요한 연관 데이터를 처음부터 JOIN해서 한 번에 가져오는 것"이 핵심입니다. 프레임워크마다 이름은 다릅니다(Fetch Join, select_related, includes).

 

프레임워크별 해결 키워드
프레임워크 해결 방법
JPA/Hibernate Fetch Join, @EntityGraph
Django select_related, prefetch_related
Rails includes

 

실무 포인트

N+1은 개발 단계에선 데이터가 적어 안 보이다가 운영에서 갑자기 느려집니다. ORM이 날리는 SQL 로그를 켜두고 확인하는 습관이 중요합니다.

주의 — 무조건 다 JOIN하는 것도 답이 아닙니다. 그 데이터가 필요 없는 화면에서도 불필요한 JOIN이 생기므로 화면별로 필요한 만큼만 조절하세요.
