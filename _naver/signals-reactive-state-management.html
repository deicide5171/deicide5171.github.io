시그널(Signals) 기반 반응형 상태관리 — React가 아직 없는 것을 Vue·Solid는 어떻게 하는가

프론트엔드

한 줄 요약 — 컴포넌트 함수를 재실행하는 React와 달리, 시그널 기반 프레임워크는 값을 읽는 지점만 정밀하게 갱신합니다. 두 모델의 차이를 정리했습니다.

 

왜 지금 시그널을 다시 봐야 하는가

React에서 useState로 상태를 바꾸면 그 상태를 참조하는 컴포넌트와 하위 트리가 리렌더링됩니다. useMemo, memo로 제어할 수 있지만 결국 수동 보일러플레이트입니다. Vue, SolidJS, Preact Signals는 상태를 "읽는 지점만 정밀 갱신하는 반응형 원시 타입"으로 다뤄 이 문제를 근본적으로 다르게 풉니다.

 

Virtual DOM 리렌더링과 세밀한 반응성의 차이

React는 상태가 바뀌면 컴포넌트 함수를 처음부터 다시 실행하고 Virtual DOM diffing으로 변경을 적용합니다. 시그널 기반 시스템은 컴포넌트 함수를 한 번만 실행하고, 시그널 값이 바뀌면 그 값을 직접 읽던 최소한의 DOM 노드만 갱신합니다. 자식 리렌더링을 막아야 한다는 고민 자체가 발생하지 않습니다.

 

의존성 추적은 런타임에 자동으로 이뤄진다

시그널을 읽는 함수가 실행되는 동안 "지금 실행 중인 구독자"가 전역적으로 기록되고, 그 중 시그널 getter가 호출되면 자동으로 관계가 등록됩니다. useEffect의 의존성 배열을 명시할 필요가 없어, 배열 누락 버그가 구조적으로 발생하지 않습니다.

항목 React 시그널 기반
갱신 단위 컴포넌트 함수 재실행 읽는 지점만 정밀 갱신
의존성 추적 개발자가 배열 명시 런타임 자동 추적
자식 리렌더링 방지 memo 필요 구조적으로 불필요

 

예제 — SolidJS 시그널 기본 사용
function Counter() {
  const [count, setCount] = createSignal(0);

  createEffect(() => {
    console.log('현재 카운트:', count());
  });

  return (
    <div>
      <p>카운트: {count()}</p>
      <button onClick={() => setCount(count() + 1)}>증가</button>
    </div>
  );
}

count()를 호출하는 것이 곧 구독 등록입니다. Counter 함수는 최초 1회만 실행되고, 버튼 클릭 후에는 텍스트 노드만 직접 업데이트됩니다.

 

실무 포인트

React 생태계에서도 시그널 유사 라이브러리로 리렌더링 범위를 줄일 수 있습니다. Preact Signals, Jotai 등을 활용해 컴포넌트를 잘게 나누면 유사한 효과를 얻습니다.

대규모 리스트 렌더링처럼 비용이 큰 화면에서 효과가 가장 큽니다. 상태 변경이 드문 정적 페이지에서는 실질적 차이가 크지 않습니다.

주의 — 시그널 기반 프레임워크로 마이그레이션을 고려한다면 기존 React 멘탈 모델(상태 변경마다 컴포넌트 재실행)에 기반한 로직이 다르게 동작한다는 점을 미리 파악해야 합니다.
