React 19 use() 훅 제대로 쓰기 — Promise 언래핑과 useEffect의 차이

프론트엔드

한 줄 요약 — use()는 조건문 안에서 호출 가능하다는 점에서 다른 훅과 다릅니다. Promise를 넘기면 완료될 때까지 컴포넌트가 Suspense 경계까지 실행을 멈춥니다.

 

왜 useEffect로 매번 로딩 상태를 관리하는 게 번거로울까

컴포넌트 안에서 API를 호출할 때마다 useEffect로 fetch를 트리거하고, useState로 데이터·로딩·에러 상태를 따로따로 선언하는 패턴을 반복하게 됩니다. 컴포넌트마다 같은 보일러플레이트가 늘어나고, 의존성 배열을 잘못 적어 무한 재요청이 발생하는 실수가 반복됩니다.

React 19에서 정식 도입된 use()는 이 패턴을 대체하기 위한 훅입니다. 다만 이름과 형태가 기존 훅과 비슷해서 기존 규칙을 그대로 적용했다가 예상치 못한 동작을 마주치기 쉽습니다.

 

 

핵심 개념 1 — use()는 다른 훅들과 규칙이 다르다

일반 훅은 조건문 안에서 호출하면 안 된다는 규칙이 있지만, use()는 이 규칙에서 예외적으로 자유롭습니다. 조건문 안에서 호출하거나 if 문 뒤에서 조건부로 호출하는 것도 허용됩니다. Promise나 Context 값을 그 자리에서 즉시 꺼내오는 특수한 메커니즘이기 때문입니다.

 

핵심 개념 2 — Promise를 넘기면 컴포넌트가 정지한다

아직 완료되지 않은 Promise를 use()에 넘기면, 그 컴포넌트는 실행을 멈추고 가장 가까운 <Suspense> 경계의 폴백 UI를 보여줍니다. Promise가 resolve되면 다시 렌더링해 use()가 값을 즉시 반환합니다. 로딩 상태를 위한 분기를 컴포넌트 안에 쓸 필요가 없어지고, 그 책임이 Suspense 경계로 옮겨갑니다.

 

예제 — 두 방식 비교
// After: use() + Suspense + ErrorBoundary로 관심사 분리
function Profile({ userPromise }) {
  const user = use(userPromise);  // 로딩 중이면 자동으로 정지
  return <div>{user.name}</div>;
}

<ErrorBoundary fallback={<ErrorMessage />}>
  <Suspense fallback={<Spinner />}>
    <Profile userPromise={fetchUser(userId)} />
  </Suspense>
</ErrorBoundary>

로딩·에러 처리 코드가 컴포넌트 밖으로 옮겨가면서, Profile 컴포넌트는 데이터가 있을 때 무엇을 그릴지에만 집중할 수 있습니다.

 

흔한 실수
실수 결과
렌더링 중 매번 새 Promise 생성 렌더링마다 새 요청 → 무한 루프
ErrorBoundary 없이 사용 Promise reject 시 앱 전체 크래시

가장 치명적인 실수는 첫 번째입니다. use(fetchUser(userId))처럼 컴포넌트 함수 본문에서 매번 새 Promise를 만들어 넘기면 렌더링될 때마다 새 요청이 나가는 악순환에 빠질 수 있습니다.

 

실무 포인트

서버 컴포넌트와 함께 쓸 때 진가를 발휘합니다. Next.js App Router에서는 서버에서 만든 Promise를 클라이언트 컴포넌트로 넘기고 use()로 풀어내는 패턴이 자연스럽게 맞아떨어집니다.

기존 데이터 페칭 라이브러리를 완전히 대체하는 것은 아닙니다. 캐싱, 재시도 기능은 use() 자체에 없으므로 TanStack Query 같은 라이브러리와 조합하는 편이 현실적입니다.

주의 — Promise는 반드시 안정적인 참조로 컴포넌트 바깥(서버 컴포넌트, 캐싱 레이어, 상위 컴포넌트)에서 만들어 전달해야 무한 재요청을 피할 수 있습니다.
