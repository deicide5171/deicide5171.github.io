CSS 컨테이너 쿼리로 컴포넌트 기반 반응형 만들기

프론트엔드

한 줄 요약 — 미디어 쿼리는 뷰포트 기준, 컨테이너 쿼리는 부모 컨테이너 크기 기준으로 스타일을 분기해, 컴포넌트가 놓인 위치와 무관하게 스스로 적응하게 만듭니다.

 

왜 미디어 쿼리만으론 한계가 있나

같은 카드 컴포넌트를 메인 영역과 사이드바에 각각 배치하면, 카드의 실제 폭은 뷰포트 크기가 아니라 "어떤 부모 컨테이너 안에 놓였는가"에 따라 달라집니다. 뷰포트가 1920px여도 사이드바 안 카드는 300px일 수 있는데, 미디어 쿼리는 이 상황을 구분하지 못합니다.

 

잘못된 접근 vs 올바른 접근

위치별로 .sidebar .card 같은 오버라이드 클래스를 만드는 방식은 배치 위치가 늘어날 때마다 규칙을 계속 추가해야 해서, 컴포넌트 재사용이라는 목적과 어긋납니다.

.card-container {
  container-type: inline-size;
}

@container (min-width: 400px) {
  .card { flex-direction: row; }
}

부모 요소에 container-type: inline-size를 선언하면 그 요소가 쿼리 대상 컨테이너로 등록됩니다. 같은 카드 컴포넌트가 폭 400px 이상인 곳에 놓이면 가로 배치, 좁은 곳에 놓이면 세로 배치가 자동으로 적용됩니다.

항목 미디어 쿼리 컨테이너 쿼리
기준 뷰포트 크기 부모 컨테이너 크기
적합한 대상 페이지 전체 레이아웃 재사용 컴포넌트

 

주의 — container-type: inline-size는 레이아웃 격리(containment)도 함께 발생시킵니다. 내부 콘텐츠 크기가 외부로 영향을 주지 않게 격리되므로, 적용 전후 레이아웃을 반드시 비교 확인하세요.

 

실무 포인트

중첩된 컨테이너가 있다면 container-name으로 어떤 것을 기준으로 쿼리할지 명시하는 것이 안전합니다. cqw 같은 컨테이너 기준 상대 단위를 clamp()와 조합하면 카드 폭에 비례해 글자 크기를 키우는 것도 가능합니다. :has()와 조합하면 "이미지가 있고 폭이 400px 이상이면 가로 배치"처럼 여러 조건도 CSS만으로 처리할 수 있습니다.
