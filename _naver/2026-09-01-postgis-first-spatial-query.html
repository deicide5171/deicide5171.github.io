PostGIS 설치하고 첫 공간 쿼리 날려보기

GIS

한 줄 요약 — 실제 거리를 구할 때는 geometry가 아니라 ::geography로 형변환해야 지구 곡률을 반영한 정확한 미터 단위 값이 나옵니다.

 

왜 일반 SQL로는 공간 데이터를 다루기 어려운가

두 지점 사이 거리나 폴리곤 포함 여부 같은 질의는 일반 SQL 산술 연산만으로는 정확히 계산하기 어렵습니다. PostGIS는 PostgreSQL에 공간 데이터 타입과 연산을 추가하는 확장으로, GIS 분야의 표준입니다.

 

 

설치와 활성화
CREATE EXTENSION postgis;
SELECT PostGIS_Version();

우분투 계열이라면 postgis 패키지를 먼저 설치해야 합니다. 관리형 클라우드 DB는 대부분 옵션으로 이미 제공합니다.

 

첫 공간 쿼리 — 두 지점 사이 거리
CREATE TABLE places (
    id serial PRIMARY KEY,
    name text,
    geom geometry(Point, 4326)
);

INSERT INTO places (name, geom) VALUES
    ('서울 시청', ST_SetSRID(ST_MakePoint(126.978, 37.5665), 4326)),
    ('강남역', ST_SetSRID(ST_MakePoint(127.027, 37.4979), 4326));

SELECT ST_Distance(a.geom::geography, b.geom::geography) AS distance_meters
FROM places a, places b
WHERE a.name = '서울 시청' AND b.name = '강남역';

::geography로 형변환하는 것이 중요합니다. geometry 그대로 계산하면 평면 좌표 기준 거리가 나오지만, geography로 변환하면 실제 미터 단위 거리가 나옵니다.

 

실무 포인트

공간 인덱스(GiST)를 만들지 않으면 데이터가 많아질수록 공간 쿼리가 급격히 느려집니다. CREATE INDEX ... USING GIST (geom)을 반드시 함께 만드세요.

주의 — 좌표계(SRID)를 명시하지 않거나 다른 SRID를 섞어 계산하면 에러 없이 결과가 조용히 틀리게 나옵니다. 특히 주의해야 합니다.
