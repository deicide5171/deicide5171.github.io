"번들러·린터·테스트 러너 버전 맞추는 거 그만 지쳤어요" — Cloudflare가 인수한 Vite+ 1.0, 통합 툴체인으로 갈아탈 때인가

STACK

한 줄 요약 — Cloudflare에 인수된 VoidZero가 내놓은 Vite+ 1.0은 번들러·린터·테스트 러너·패키지 매니저를 하나로 묶지만, 번들러 엔진이 Rollup에서 Rolldown으로 바뀌는 심장부 교체를 동반합니다. 전면 전환 전에 반드시 격리 환경에서 호환성을 검증해야 하는 이유를 정리했습니다.

 

왜 지금 이 판단이 필요한가

"번들러는 Vite, 린트는 ESLint, 테스트는 Vitest, 패키지는 pnpm을 쓰는데, 메이저 업그레이드할 때마다 서로 호환되는 조합을 다시 맞추느라 하루씩 날아가요. 이거 하나로 묶어서 관리하게 해주세요"라는 요구는 프런트엔드 팀이 어느 정도 규모가 되면 반드시 나옵니다. 이 말을 그대로 받으면 올인원 프레임워크 하나 고르면 되겠지로 끝나기 쉽지만, 실제로는 도구 간 결합도를 어디까지 받아들일지를 정하는 아키텍처 판단입니다.

2026년 6월 4일 Cloudflare가 Vite를 만든 VoidZero를 인수했고, 그 VoidZero가 쌓아온 Vite·Vitest·Rolldown(러스트 기반 번들러)·Oxc(러스트 기반 린터·파서 툴체인)를 하나의 CLI로 묶은 Vite+ 1.0이 2026년 9월 28일 정식 출시됐습니다. Cloudflare는 Vite·Vitest·Rolldown·Oxc·Vite+ 전부를 MIT 라이선스로 유지하겠다고 공식 발표했습니다. 하지만 'MIT 라이선스니까 안전하다'와 '지금 당장 갈아타도 된다'는 전혀 다른 질문입니다.

 

전체 시스템에서의 위치

기존 빌드 파이프라인에서는 패키지 매니저, 번들러, 린터, 테스트 러너가 각각 독립된 패키지이자 독립된 설정 파일을 갖고 서로 다른 메이저 버전 주기로 움직입니다. Vite+는 이 네 역할을 vp 단일 CLI 아래로 모으고, 패키지 설치부터 린트·테스트·빌드까지 하나의 설정 체계로 묶습니다.

여기서 주목할 지점은 번들러 내부가 Rollup에서 러스트 기반 Rolldown으로 바뀐다는 사실입니다. 기존 Vite 플러그인 생태계는 수년간 Rollup의 JS 플러그인 API를 전제로 쌓였습니다. Rolldown이 Rollup API 호환을 목표로 하지만, 플러그인이 Rollup 내부 구현에 의존하는 경우는 전환 과정에서 조용히 깨질 수 있습니다.

 

선택의 트레이드오프
구조결합도벤더 종속 리스크적합한 상황
조합형(개별 도구)낮음낮음안정된 조합을 쓰며 전환 리스크를 피하려는 팀
Vite+ 1.0높음중간(MIT지만 로드맵 종속)신규 프로젝트, 정합 피로가 큰 팀
Vite+ 유료 플랜높음높음지원 SLA·로드맵 영향력이 필요한 조직

 

Cloudflare의 라이선스 약속과 100만 달러 독립 메인테이너 펀드는 '포크해도 생태계가 망하지 않는다'는 안전망을 제공하지만, 이는 최악의 경우를 완화하는 장치이지 전환 자체의 위험을 없애주지 않습니다. 커스텀 Vite 플러그인을 다수 쓰는 프로젝트일수록 신중해야 합니다.

 

실제 프로젝트 진행 순서

가장 먼저 할 일은 전면 전환이 아니라 격리된 환경에서의 호환성 검증입니다. 기존 프로젝트를 그대로 둔 채, 별도 브랜치나 샌드박스 저장소에서 먼저 깨지는 지점을 찾아야 합니다.

npm install -D vite-plus @voidzero-dev/vite-plus-core
# package.json overrides로 vite/vitest 의존 패키지를 vite-plus 버전으로 고정
# 기존 설정 그대로 둔 채 vp build, vp test 실행
# 커스텀 플러그인을 하나씩 비활성화하며 깨지는 지점 좁히기

호환성이 확인되면 CI 파이프라인에 기존 도구 체인과 Vite+ 체인을 병행으로 돌려 빌드 산출물 크기·빌드 시간·테스트 결과를 비교해야 합니다. 유의미한 개선이 확인된 뒤에야 테스트 환경 → 스테이징 → 프로덕션 순으로 전환 범위를 넓혀야 합니다.

 

주의 — '더 빠르다더라'는 소문만으로 전환하면, 실제 이득 없이 플러그인 호환성 문제만 떠안을 수 있습니다. 반드시 자신의 플러그인 목록으로 직접 비교 측정하십시오.
