여러 AI 코딩 에이전트에 지시서를 따로 써야 했던 문제 — AGENTS.md 표준과 레포 설정 전략

AI

한 줄 요약 — Claude Code엔 CLAUDE.md, Cursor엔 .cursorrules, Copilot엔 copilot-instructions.md를 따로 써야 했던 레포 지침 파편화를, OpenAI가 공개하고 이후 리눅스 재단 산하 Agentic AI Foundation으로 이관된 AGENTS.md 표준이 어떻게 줄이는지, 그리고 왜 완전히 하나로 합칠 수는 없는지 정리했습니다.

 

왜 지금 이 판단이 불거지는가

"우리 팀은 Claude Code로 기능 구현하고, 리뷰는 Copilot한테 시키고, 개인 작업은 Cursor를 쓰는데, 레포 지침을 세 번 따로 써야 하나요?" 요즘 팀이라면 한 번쯤 받아봤을 질문입니다. 처음엔 CLAUDE.md 하나만 관리하면 됐지만, 팀원마다 선호하는 도구가 다르고 CI에서는 Codex CLI를 돌리기 시작하면서 지침 파일이 `.cursorrules`, `.github/copilot-instructions.md`, `CLAUDE.md`로 늘어납니다. 코딩 컨벤션을 하나 바꾸면 서너 파일을 동시에 고쳐야 하고, 깜빡하고 하나만 수정하면 도구마다 다른 방식으로 동작하는 일이 생깁니다.

이 파편화를 줄이려는 움직임이 AGENTS.md입니다. OpenAI가 공개한 이 포맷은 이후 MCP, Block의 goose와 함께 리눅스 재단 산하의 새로운 Agentic AI Foundation으로 거버넌스가 이관됐고, Google·Cursor·Sourcegraph·JetBrains 등 여러 벤더가 공동으로 밀고 있습니다. 레포 루트에 두는 평범한 마크다운 파일이며 필수 필드도 특별한 문법도 없습니다. 공식 문서는 이를 "에이전트를 위한 README"라고 부릅니다. 2026년 기준 수만 개 저장소가 이 파일을 채택했고, Codex CLI·Cursor·Windsurf·Copilot·Gemini CLI·Aider·Devin 등 수십 개 도구가 네이티브로 읽습니다. 다만 Claude Code가 AGENTS.md를 직접 읽는지, 여전히 CLAUDE.md를 우선하는지는 출처마다 설명이 갈리므로 실제 적용 전에 공식 문서로 확인해야 합니다.

 

요구사항을 기술 문제로 번역하기

"지침을 한 곳에 모아주세요"는 사실 두 가지 서로 다른 요구가 섞여 있습니다. 하나는 "여러 도구가 같은 코딩 컨벤션·아키텍처 설명·테스트 실행법을 공유하게 해주세요"이고, 다른 하나는 "도구별로만 의미 있는 설정(권한 범위, MCP 서버 목록, 자동 승인 규칙)은 그 도구 안에 남겨주세요"입니다. 전자는 AGENTS.md 한 파일로 충분히 해결되지만, 후자는 AGENTS.md 스펙 자체에 없는 개념이라 도구별 파일로 남을 수밖에 없습니다. 그래서 실제 작업은 "모든 걸 한 파일로 합쳐주세요"가 아니라, 공유 가능한 지침과 도구 전용 설정을 구분하고, 전자는 단일 소스로, 후자는 그 단일 소스를 참조하는 얇은 어댑터로 설계하는 계층 설계 문제로 번역됩니다. 모노레포라면 하위 디렉터리마다 다른 지침이 필요할 때, 가장 가까운(디렉터리 트리상 최근접) 파일이 우선 적용되는 중첩 구조를 어디까지 활용할지도 설계에 포함해야 합니다.

 

전체 시스템에서의 위치

 

이 구조에서 AGENTS.md는 사람이 작성하는 설정과 에이전트가 소비하는 설정 사이의 공유 계층에 위치합니다. 앞단에는 팀의 코딩 컨벤션, 아키텍처 개요, 테스트·빌드 명령처럼 어떤 도구를 쓰든 똑같이 적용돼야 하는 지식이 있습니다. 이 지식이 AGENTS.md 하나로 들어갑니다. 뒷단에는 Claude Code·Cursor·Copilot·Codex CLI 같은 개별 도구가 있고, 이들은 각자의 포맷(심볼릭 링크, `@AGENTS.md` 임포트, 또는 네이티브 읽기)으로 AGENTS.md를 참조하면서 자기만의 추가 설정을 별도 파일에 보관합니다. AGENTS.md를 빼면 이 공유 지식이 도구 수만큼 복제되고, 하나를 고칠 때마다 나머지를 수동으로 동기화해야 하는 상태로 되돌아갑니다.

 

선택의 트레이드오프
접근 유지보수 비용 도구별 기능 활용 적합한 상황
도구별 파일 독립 관리 높음 높음 도구 하나만 표준으로 쓰는 팀
AGENTS.md 단일 파일만 사용 낮음 낮음 소규모 팀, 공유 지침만으로 충분
AGENTS.md + 도구별 어댑터(하이브리드) 중간 높음 여러 도구 혼용 팀, 모노레포
사내 자체 포맷 + 변환 스크립트 높음 매우 높음 사내 도구까지 세밀 제어 필요

 

단일 AGENTS.md만으로 끝내고 싶어지는 유혹이 있지만, 그 안에 권한 설정이나 MCP 서버 목록처럼 도구마다 의미가 다른 내용을 억지로 욱여넣으면 스펙 밖의 비표준 필드가 생기고, 그 도구가 스펙을 엄격히 따를수록 오히려 무시됩니다. 반대로 도구별 파일을 완전히 독립적으로 유지하면 처음에는 편하지만, 코딩 컨벤션 한 줄 바꿀 때마다 반복 작업이 선형으로 늘어납니다. 결국 "공유 지식은 하나, 도구 전용 설정은 각자"로 역할을 분리하는 하이브리드가 대부분의 멀티 도구 팀에 현실적인 지점입니다.

 

실제 프로젝트 진행 순서

1단계: 현재 흩어진 지침 파일을 전수 조사해 겹치는 부분과 도구 전용인 부분을 표로 구분합니다.

2단계: 겹치는 부분만 추출해 도구 중립적인 AGENTS.md를 새로 작성합니다.

3단계: 도구별 파일을 심볼릭 링크나 임포트 구문의 어댑터로 전환하고, 전용 설정만 남깁니다.

4단계: 모노레포라면 서브디렉터리별 중첩 AGENTS.md로 최근접 우선 규칙을 활용합니다.

5단계: CI에 참조 관계(심볼릭 링크 등)가 깨졌는지 검사하는 드리프트 체크를 추가합니다.

6단계: 한 레포에서 먼저 각 도구가 기대한 지침을 읽는지 검증한 뒤 점진적으로 확대합니다.

# CLAUDE.md는 AGENTS.md를 가리키는 심볼릭 링크로 전환
ln -sf AGENTS.md CLAUDE.md

# 도구 전용 설정(권한, MCP 서버 목록)은 별도 파일에만 둔다
# .claude/settings.json, .cursor/mcp.json 등

 

주의 — AGENTS.md를 권한·보안 설정의 저장소로 쓰지 마세요. 공개 저장소에 커밋되는 경우가 많고 특정 필드를 강제하지 않으므로, 자동 실행 허용 명령 목록이나 API 키 같은 민감한 설정은 반드시 도구별 설정 파일이나 환경 변수로 분리해야 합니다. 심볼릭 링크가 안 되는 CI 환경이나 Windows에서는 빌드 스크립트 단계에서 AGENTS.md 내용을 복사하는 전처리를 대안으로 준비하세요. 거버넌스가 리눅스 재단으로 넘어간 지 얼마 안 됐고 도구별 지원 수준도 계속 바뀌고 있으니, 분기마다 공식 문서를 다시 확인하는 루틴을 팀에 넣어두는 편이 안전합니다.

 

정리

"지침을 한 곳에 모아주세요"는 공유 가능한 지식과 도구 전용 설정을 구분하는 계층 설계 문제로 번역됩니다. AGENTS.md는 사람이 쓰는 지침과 각 AI 코딩 도구 사이의 공유 계층에 위치하며, 도구별 파일은 그 위에 얇은 어댑터로 남는 하이브리드 구조가 대부분의 멀티 도구 팀에 현실적입니다. 전환은 기존 지침 전수 조사 → 공유분 추출 → 도구별 어댑터화 → 모노레포 중첩 설계 → CI 드리프트 체크 순으로 점진적으로 진행하는 것이 안전합니다.
