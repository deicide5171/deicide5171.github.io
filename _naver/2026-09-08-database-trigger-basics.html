트리거가 뭔가요 — 데이터가 바뀔 때 자동으로 실행되는 동작

데이터베이스

한 줄 요약 — 트리거는 데이터 변경 시 자동 실행되는 DB 동작으로 이력·무결성에 유용하지만, 로직이 코드 밖에 숨어 추적이 어려울 수 있습니다.

 

데이터가 바뀔 때 자동으로 하고 싶다면

"주문 생성 시 재고 차감", "수정 시 이력 기록" 같은 작업을 DB가 알아서 하게 할 수 있습니다. 트리거는 INSERT·UPDATE·DELETE 발생 시 자동 실행되도록 등록해둔 동작입니다.

 

예제 — 변경 이력 남기기
CREATE TRIGGER log_user_update
AFTER UPDATE ON users
FOR EACH ROW
BEGIN
    INSERT INTO user_history (user_id, old_name, changed_at)
    VALUES (OLD.id, OLD.name, NOW());
END;

애플리케이션에서 이력 코드를 안 짜도 users 수정 시마다 DB가 알아서 기록합니다. OLD는 변경 전, NEW는 변경 후 값입니다.

 

유용한 경우와 위험한 경우
유용: 감사 로그, 무결성 강제, 집계 갱신
위험: 로직이 숨어 추적 어려움, 연쇄 트리거, 디버깅 악화

 

실무 포인트

트리거는 "숨은 로직"이 되기 쉽습니다. 코드 어디에도 없는데 데이터가 바뀌면 신입이 원인을 못 찾습니다. 쓴다면 문서화하고 팀이 알아야 합니다.

주의 — 트리거 실패가 원래 INSERT·UPDATE를 롤백시킬 수 있습니다. 복잡한 비즈니스 로직은 트리거보다 애플리케이션에 두세요.
