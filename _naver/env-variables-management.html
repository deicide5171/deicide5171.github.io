환경변수와 .env 파일 제대로 관리하기 — 초보자 실수 모음

2026. 9. 4. · 인프라

한 줄 요약 — 환경변수는 민감 설정을 코드 밖으로 분리하며, .env는 반드시 .gitignore에 넣고 프론트엔드 환경변수는 비밀이 아님을 기억하세요.

 

왜 API 키를 코드에 그냥 쓰면 안 되나

비밀번호나 API 키를 코드에 적으면 GitHub에 올리는 순간 공개됩니다. 공개 저장소의 키를 봇이 몇 분 만에 발견해 악용하는 사고가 흔합니다. 환경변수는 민감 설정값을 코드 밖으로 분리합니다.

 

.env 파일 기본 사용법
# .env (git에는 올리지 않는다)
DATABASE_URL=postgresql://user:pass@localhost:5432/mydb
API_KEY=sk-abc123

// Node.js
import 'dotenv/config';
const apiKey = process.env.API_KEY;

 

초보자가 자주 하는 실수
1. .env를 git에 커밋 -> 즉시 키 폐기·재발급
2. .env.example 안 만듦 -> 키 이름만 담아 커밋
3. 프론트엔드에 비밀 키 -> 브라우저에서 다 보인다
4. 배포 환경에 등록 빠뜨림 -> 서버·CI에 따로 등록

 

실무 포인트

.env는 한 번 커밋되면 git 히스토리에 영구히 남습니다. 뒤늦게 .gitignore에 추가해도 과거 커밋엔 남으므로, 실수로 올렸다면 파일 삭제로 끝내지 말고 키를 폐기·재발급하세요.

주의 — 프론트엔드 "환경변수"는 빌드 시점에 코드에 박혀 공개됩니다. 진짜 비밀이 필요한 작업은 반드시 백엔드를 거치도록 설계하세요.
