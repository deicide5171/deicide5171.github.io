PostgreSQL 전문 검색 — tsvector·tsquery와 GIN 인덱스 내부 동작

데이터베이스

한 줄 요약 — 텍스트를 정규화된 어휘소로 바꾸는 tsvector와 이를 역색인으로 저장하는 GIN 인덱스가 결합해 만드는 PostgreSQL 전문 검색의 내부 동작을 정리했습니다.

 

왜 지금 PostgreSQL 전문 검색을 다시 봐야 하는가

검색 기능이 필요하다는 요구사항이 나오면 반사적으로 Elasticsearch 도입을 검토하는 경우가 많습니다. 하지만 별도 검색 클러스터는 데이터 동기화 파이프라인, 별도 장애 도메인, 추가 인프라 비용을 함께 짊어진다는 뜻입니다. PostgreSQL은 LIKE보다 훨씬 정교한 자체 전문 검색을 내장하고 있어, 서비스 초기~중기 규모에서는 이것만으로 충분한 경우가 많습니다.

 

tsvector: 텍스트를 정규화된 어휘소 목록으로

to_tsvector를 실행하면 불용어가 제거되고, "running"과 "runners"가 모두 "run"이라는 어간(stem)으로 통합되며, 각 어휘소의 원문 위치까지 함께 저장됩니다. 이 어간 추출 덕분에 사용자가 "running"으로 검색해도 "runs", "ran"이 포함된 문서를 찾을 수 있습니다. 검색어 쪽도 to_tsquery로 같은 정규화를 거친 뒤 @@ 연산자로 매칭됩니다.

검색 방식 매칭 정확도 대용량 성능
LIKE '%keyword%' 어간 변화 무시 순차 스캔, 느림
tsvector + GIN 어간 정규화 역색인, 빠름

 

GIN 인덱스: 어휘소에서 문서로의 역색인

GIN(Generalized Inverted Index)은 일반 B-tree와 달리 "어휘소 → 그 어휘소를 포함하는 행 목록"이라는 역방향 색인을 구축합니다. 이는 검색 엔진의 역색인과 정확히 같은 구조입니다. 검색어가 여러 어휘소로 이루어져 있으면, GIN은 각 어휘소의 행 목록을 가져와 교집합·합집합 연산으로 빠르게 후보를 좁힙니다.

검색 컬럼 구성과 GIN 인덱스 생성 예제
ALTER TABLE articles
  ADD COLUMN search_vector tsvector
  GENERATED ALWAYS AS (
    setweight(to_tsvector('english', coalesce(title, '')), 'A') ||
    setweight(to_tsvector('english', coalesce(body, '')), 'B')
  ) STORED;

CREATE INDEX idx_articles_search ON articles USING GIN (search_vector);

SELECT id, title, ts_rank(search_vector, query) AS rank
FROM articles, to_tsquery('english', 'postgresql & index') AS query
WHERE search_vector @@ query
ORDER BY rank DESC LIMIT 20;

setweight로 제목(A)과 본문(B)에 다른 가중치를 부여하면, ts_rank가 제목에 검색어가 포함된 문서를 더 높은 순위로 올려줍니다.

 

실무 포인트

언어 설정을 실제 콘텐츠 언어와 맞춰야 합니다. 한국어는 PostgreSQL 기본 어간 추출기가 지원하지 않으므로, 형태소 분석 확장을 별도로 구성해야 의미 있는 결과가 나옵니다.

GIN 인덱스는 쓰기 비용이 B-tree보다 큽니다. 삽입·수정이 빈번한 테이블이라면 fastupdate 옵션으로 쓰기 성능과 검색 최신성 사이의 균형을 조정해야 합니다.

주의 — 오타 허용 검색, 다국어 형태소 분석 고도화, 대규모 벡터 유사도 검색이 필요해지는 시점이 별도 검색 엔진 도입을 재검토할 신호입니다.
