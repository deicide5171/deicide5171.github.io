Git 충돌(merge conflict) 났을 때 당황하지 않고 해결하기

2026. 9. 3. · 인프라

한 줄 요약 — 충돌은 에러가 아니라 사람이 판단해달라는 Git의 요청이며, <<<<·====·>>>> 표시를 읽고 정한 뒤 그 줄을 모두 지우면 됩니다.

 

충돌 메시지를 봐도 뭘 해야 할지 모르겠다면

CONFLICT 메시지가 뜨면 당황하기 쉽지만, 충돌은 에러가 아니라 Git이 "두 사람이 같은 부분을 다르게 고쳤으니 어느 쪽이 맞는지 정해달라"고 요청하는 상태입니다.

 

충돌 표시 기호 읽는 법
<<<<<<< HEAD
내 브랜치의 코드
=======
병합하려는 브랜치의 코드
>>>>>>> feature-branch

 

해결 단계
# 1. 충돌 파일 확인
git status

# 2. 파일을 열어 표시를 찾고 남길 코드를 결정
#    -> 결정 후 <<<<, ====, >>>> 표시 줄은 모두 삭제

# 3. 스테이징 후 커밋
git add file.js
git commit

핵심은 세 종류의 표시 줄을 반드시 모두 지워야 한다는 것입니다. 하나라도 남으면 문법 오류로 빌드가 깨집니다.

 

실무 포인트

무작정 한쪽을 통째로 덮어쓰면 상대방 작업이 사라질 수 있습니다. 두 변경의 의도를 이해하고 합치는 것이 원칙입니다.

꼬였다면 git merge --abort로 병합 전 상태로 안전하게 되돌릴 수 있습니다.

주의 — 오래된 브랜치를 뒤늦게 병합하면 충돌이 한꺼번에 몰립니다. 주기적으로 기본 브랜치를 병합해 두면 충돌이 크게 줄어듭니다.
