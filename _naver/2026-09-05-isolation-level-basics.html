트랜잭션 격리수준이 뭔가요 — 동시성 문제를 그림으로 이해하기

2026. 9. 5. · 데이터베이스

한 줄 요약 — 격리수준은 동시 트랜잭션이 서로를 얼마나 볼지 정하며, MySQL과 PostgreSQL의 기본값이 달라 DB 이전 시 주의해야 합니다.

 

동시에 같은 데이터를 건드리면

여러 사용자가 동시에 같은 데이터를 읽고 쓰면 예상치 못한 결과가 나옵니다. 격리수준은 "동시 트랜잭션들이 서로를 얼마나 볼 수 있게 할지"를 정합니다. 강하면 안전하지만 느리고, 약하면 빠르지만 이상 현상이 생깁니다.

 

동시성이 만드는 세 가지 문제
문제 상황
Dirty Read 커밋 안 된 데이터를 읽음
Non-Repeatable Read 두 번 읽었는데 값이 달라짐
Phantom Read 행 개수가 달라짐

 

격리수준 4단계
READ UNCOMMITTED - 가장 약함 (Dirty Read 발생)
READ COMMITTED   - 커밋된 것만 읽음
REPEATABLE READ  - 재조회 시 값 고정
SERIALIZABLE     - 가장 강함, 가장 느림

 

DB마다 기본값이 다르다
MySQL(InnoDB): REPEATABLE READ
PostgreSQL:    READ COMMITTED
-> DB를 바꾸면 동시성 동작이 달라질 수 있다

 

실무 포인트

무조건 SERIALIZABLE로 올리면 안전하지만 성능이 크게 떨어집니다. 대부분 READ COMMITTED/REPEATABLE READ로 충분하고, 엄격한 트랜잭션에만 선택적으로 높이세요.

주의 — "재고를 읽고→판단→차감" 같은 로직은 격리수준만으로 동시 판매를 못 막습니다. 별도의 락(비관/낙관적 락)이 필요합니다.
