MapLibre GL JS에서 커스텀 마커 아이콘 쓰기 — addImage 흔한 실수

GIS

한 줄 요약 — MapLibre GL JS는 addImage()로 이미지를 스프라이트에 먼저 등록해야만 icon-image에서 참조할 수 있으며, 이 등록 절차를 빠뜨리는 것이 가장 흔한 실수입니다.

 

왜 기본 마커로는 부족한가

원형 circle 레이어는 빠르고 간단하지만, 실제 서비스는 카테고리별로 다른 아이콘을 표시해야 하는 경우가 많습니다. DOM 기반 Marker는 포인트가 많아지면 성능 문제가 생기므로, 대량의 커스텀 아이콘은 GeoJSON 소스 + symbol 레이어 + 이미지 스프라이트 조합이 정석입니다.

 

 

잘못된 접근 vs 올바른 접근

이미지를 등록하지 않고 바로 icon-image에 이름을 넣으면 "Image could not be loaded" 경고가 뜨거나 아이콘이 조용히 안 보입니다. 핵심은 이미지 로딩이 비동기라는 점입니다.

map.loadImage('/assets/icons/restaurant.png', (error, image) => {
  if (error) throw error;
  if (!map.hasImage('restaurant-icon')) {
    map.addImage('restaurant-icon', image);
  }
  map.addLayer({
    id: 'poi', type: 'symbol', source: 'poi-source',
    layout: { 'icon-image': 'restaurant-icon' }
  });
});

loadImage() 콜백 안에서 addImage()를 호출하고, 그 이후에 레이어를 추가해야 합니다. 순서를 어기면 아직 등록되지 않은 이미지를 참조하는 순간이 생겨 렌더링이 실패합니다.

주의 — setStyle()로 스타일을 통째로 교체하면 등록된 이미지도 함께 사라집니다. 스타일 전환 기능이 있다면 style.load 이벤트에서 addImage()를 다시 호출해야 합니다.

 

SDF 아이콘으로 색상 동적 변경

sdf: true 옵션으로 등록한 단색 실루엣 이미지는 icon-color 속성으로 런타임에 색을 바꿀 수 있습니다. 카테고리별 이미지 파일을 여러 개 준비하지 않고도 색상만 데이터에 따라 다르게 표현할 수 있어 자산 관리가 단순해집니다.

실무 포인트

아이콘이 많다면 spritezero 같은 도구로 스프라이트 시트를 미리 빌드해 네트워크 요청 수를 줄이세요. addImage()의 pixelRatio 옵션을 지정하지 않으면 고해상도 화면에서 아이콘이 흐릿하게 보입니다. 밀집된 POI 지역에서 아이콘이 사라진다면 icon-allow-overlap 옵션부터 점검하세요.
