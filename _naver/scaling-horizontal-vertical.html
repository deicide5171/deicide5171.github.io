스케일 업 vs 스케일 아웃 — 서버를 키울까 늘릴까

2026. 9. 5. · 시스템설계

한 줄 요약 — 수직 확장은 서버 성능을 키우고 수평 확장은 서버 수를 늘리며, 수평 확장의 전제는 상태를 서버 밖으로 빼는 stateless 설계입니다.

 

트래픽이 늘면 무엇을 해야 하나

서버 한 대로 감당이 안 될 때 선택지는 둘입니다. 성능을 키우는 수직 확장(스케일 업), 서버 수를 늘리는 수평 확장(스케일 아웃)입니다.

 

두 방식 비교
항목 스케일 업 스케일 아웃
방법 성능 업그레이드 대수 늘리기
한계 물리적 상한 이론상 계속 확장
장애 영향 죽으면 전체 정지 한 대 죽어도 유지

 

수평 확장이 어려운 이유 — 상태
서버 A에서 로그인 -> 다음 요청이 서버 B로?
-> B는 세션을 모름 -> 로그아웃된 것처럼 보임

해결: 세션을 Redis 같은 공유 저장소에 두어
      어느 서버든 같은 세션을 참조하게 한다

"상태를 서버 밖으로 빼는(stateless)" 설계가 수평 확장의 전제 조건입니다.

 

실무 포인트

처음부터 무리하게 수평 확장을 설계할 필요는 없습니다. 감당 가능한 수준이면 수직 확장이 훨씬 간단하고 저렴합니다.

주의 — DB는 수평 확장이 특히 까다롭습니다. 애플리케이션 서버보다 복잡하므로 읽기 복제본이나 캐시부터 검토하세요.
