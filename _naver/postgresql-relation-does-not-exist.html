PostgreSQL 'relation does not exist' 에러 해결하기

2026. 9. 1. · 데이터베이스

한 줄 요약 — 대부분 테이블이 없는 게 아니라 다른 스키마에 있거나 search_path가 다른 문제입니다.

 

분명히 만든 테이블인데 왜 없다고 하는가

테이블이 분명히 존재하는데도 relation "users" does not exist 에러가 난다면, 대부분 테이블 이름 문제가 아니라 어느 스키마에서 찾고 있는지의 문제입니다. PostgreSQL은 하나의 DB 안에 여러 스키마를 가질 수 있습니다.

 

대소문자 문제, 가장 흔한 함정
CREATE TABLE "Users" (id serial primary key);

SELECT * FROM Users;   -- ERROR: relation "users" does not exist
SELECT * FROM "Users"; -- 성공

PostgreSQL은 큰따옴표 없이 쓴 식별자를 자동으로 소문자로 변환합니다. 실무에서는 테이블·컬럼명을 처음부터 소문자+언더스코어로 통일하는 것을 권장합니다.

 

스키마 문제 확인 및 해결
SHOW search_path;

SELECT schemaname, tablename FROM pg_tables WHERE tablename = 'users';

SELECT * FROM my_schema.users;  -- 스키마 명시

SET search_path TO my_schema, public;

 

실무 포인트

마이그레이션 도구(Flyway, Liquibase)가 다른 스키마에 테이블을 만들도록 설정된 경우가 있습니다. 로컬과 운영 환경 설정이 다르면 에러가 환경별로 다르게 나타납니다.

주의 — 커넥션 풀을 쓰면 세션마다 search_path가 다르게 설정될 수 있습니다. 애플리케이션 시작 시 명시적으로 고정하는 것이 안전합니다.
