롱 폴링이 뭔가요 — 실시간 흉내를 내는 오래된 요청

시스템 디자인

한 줄 요약 — 롱 폴링은 서버가 새 데이터가 생길 때까지 응답을 붙잡아 실시간에 가깝게 알림을 주며, 일반 폴링의 빈 응답 낭비를 줄입니다.

 

새 알림을 계속 물어보는 건 낭비다

1초마다 요청을 보내면(일반 폴링) 대부분 "없음" 응답이라 낭비가 큽니다. 롱 폴링은 서버가 요청을 받으면 바로 답하지 않고, 새 데이터가 생길 때까지(또는 타임아웃까지) 응답을 붙잡고 기다립니다.

 

일반 폴링 vs 롱 폴링
구분 일반 폴링 롱 폴링
응답 시점 즉시(없어도) 데이터 생기면
빈 응답 많음 거의 없음

 

동작 흐름
일반: 요청 -> "없음" -> 요청 -> "없음" ...
롱  : 요청 -> 서버가 붙잡고 대기 -> 데이터 생김 -> 응답
      응답받자마자 다시 요청(연결 유지)

 

실무 포인트

양방향 실시간엔 웹소켓이 낫지만, 서버→클라이언트 알림만 필요하면 롱 폴링이 간단한 대안입니다(요즘은 SSE도 많이 씀). 서버가 무한정 붙잡지 않게 타임아웃(예: 30초)을 두세요.

주의 — 롱 폴링은 각 클라이언트가 응답을 기다리며 연결을 점유합니다. 동시 사용자가 많으면 대기 연결이 자원을 잡아먹으니 규모를 고려하세요.
