CRDT로 오프라인 우선 동기화 설계하기 — 충돌 없는 분산 데이터 병합

아키텍처·시스템 설계

한 줄 요약 — CRDT는 병합 연산이 결합·교환·멱등법칙을 만족하도록 설계된 자료구조로, 수동 충돌 해결 없이 자동으로 병합됩니다.

 

왜 지금 CRDT를 다시 봐야 하는가

오프라인에서도 같은 데이터를 수정할 수 있어야 하는 협업 도구나 앱은 충돌 해결 문제에 부딪힙니다. Last-Write-Wins는 한쪽 변경을 통째로 날려버립니다. CRDT는 자료구조 자체를 "어떤 순서로 병합해도 같은 결과에 수렴"하도록 설계해 이 문제를 근본적으로 해결합니다.

 

병합 연산이 만족해야 할 대수적 성질

병합 연산은 결합법칙, 교환법칙, 멱등법칙을 만족해야 합니다. 결합·교환법칙은 순서·그룹과 무관하게 같은 결과를 보장하고, 멱등법칙은 같은 업데이트가 중복 도착해도 안전하게 만듭니다.

 

상태 기반(CvRDT)과 연산 기반(CmRDT)의 차이

상태 기반은 전체 상태를 주고받아 구현이 단순하지만 네트워크 비용이 큽니다. 연산 기반은 적용된 연산만 전파해 대역폭 효율적이지만 연산이 정확히 한 번 전달돼야 합니다.

CRDT 종류 예시 병합 방식
G-Counter 노드별 카운터 배열 각 노드 최댓값 후 합산
OR-Set 태그 붙은 추가/삭제 이력 최신 태그 기준 존재 판단
RGA/LSEQ 텍스트, 각 문자 위치 식별자 위치 순서로 병합

 

예제 — G-Counter로 분산 카운터 구현
class GCounter {
  constructor(nodeId, nodeIds) {
    this.nodeId = nodeId;
    this.counts = Object.fromEntries(nodeIds.map((id) => [id, 0]));
  }

  increment() {
    this.counts[this.nodeId] += 1;
  }

  value() {
    return Object.values(this.counts).reduce((a, b) => a + b, 0);
  }

  merge(other) {
    for (const id of Object.keys(this.counts)) {
      this.counts[id] = Math.max(this.counts[id], other.counts[id]);
    }
  }
}

각 노드가 자신의 슬롯만 증가시키고, 병합 시 슬롯별로 더 큰 값을 취하면 어떤 순서로 병합해도 항상 같은 결과에 수렴합니다.

 

실무 포인트

협업 텍스트 편집에는 Yjs, Automerge 같은 검증된 라이브러리를 먼저 검토하세요. 텍스트 CRDT는 이론은 단순해도 실제 구현에 미묘한 최적화가 많습니다.

모든 데이터를 CRDT로 모델링하려 하지 마세요. 은행 잔액처럼 강하게 일관돼야 하는 데이터는 CRDT의 결과적 일관성과 잘 맞지 않습니다.

주의 — 삭제된 데이터의 튬스톤이 계속 쌓이는 문제를 관리하세요. OR-Set 같은 구조는 삭제 이력을 완전히 지우지 못하므로 주기적인 가비지 컬렉션 전략이 필요합니다.
