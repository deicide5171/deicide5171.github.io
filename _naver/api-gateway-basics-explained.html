API Gateway가 뭔가요 — 처음 이해하는 개념과 역할

2026. 9. 2. · 시스템설계

한 줄 요약 — API Gateway는 클라이언트와 여러 백엔드 서비스 사이의 단일 진입점으로, 라우팅·인증·레이트 리밋을 한 곳에서 처리합니다.

 

왜 서비스마다 직접 호출하면 안 되는가

마이크로서비스로 나누면 주문·결제·회원 서비스처럼 독립된 서버가 생깁니다. 클라이언트가 이들을 직접 호출하면 주소가 바뀔 때마다 코드를 수정해야 하고 인증도 서비스마다 따로 구현해야 합니다. API Gateway가 이 문제를 해결합니다.

 

API Gateway가 하는 일
역할 설명
라우팅 경로에 따라 알맞은 서비스로 전달
인증/인가 토큰 검증을 한 곳에서 처리
레이트 리밋 서비스마다 반복 구현 없이 공통 적용

 

구조 차이
게이트웨이 없음: 클라이언트 -> 각 서비스 (인증 각각 구현)

게이트웨이 있음:
클라이언트 -> API Gateway (인증·라우팅 한 곳)
                 ├─> 주문 서비스
                 ├─> 결제 서비스
                 └─> 회원 서비스

 

예제 — 라우팅 설정
spring:
  cloud:
    gateway:
      routes:
        - id: order-service
          uri: http://order-service:8080
          predicates:
            - Path=/api/orders/**

클라이언트는 게이트웨이 주소 하나만 알면 되고, 뒤에서 서비스 주소가 바뀌어도 클라이언트 코드는 그대로입니다.

 

실무 포인트

게이트웨이 자체가 단일 장애점(SPOF)이 될 수 있으므로 반드시 여러 인스턴스로 이중화해야 합니다.

주의 — 서비스 메시와 혼동하지 마세요. API Gateway는 외부에서 들어오는 트래픽(North-South)을, 서비스 메시는 내부 서비스 간 통신(East-West)을 다룹니다.
