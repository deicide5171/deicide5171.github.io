블록 스토리지 vs 객체 스토리지 — 파일을 어디에 저장하나

시스템 디자인

한 줄 요약 — 블록 스토리지는 서버에 붙이는 디스크(DB·OS용), 객체 스토리지는 URL로 접근하는 파일 창고(이미지·백업)입니다.

 

이미지 업로드는 어디에 저장하나

사용자가 올린 사진을 서버 디스크에 두면 서버가 여러 대일 때 흩어지고 확장이 어렵습니다. 클라우드 스토리지엔 크게 블록 스토리지와 객체 스토리지가 있고 용도가 다릅니다.

 

두 스토리지 비교
구분 블록 객체
형태 디스크로 붙임 HTTP로 접근
예 AWS EBS AWS S3
적합 DB·OS 디스크 이미지·백업·정적

 

언제 무엇을
블록: "서버에 붙이는 하드디스크" -> DB, 앱 디스크
객체: "인터넷의 거대한 파일 창고" -> 이미지·백업·로그
      URL로 어디서나 접근, 사실상 무한 확장

 

실무 포인트

업로드 파일은 객체 스토리지(S3)에 두고 서버는 URL만 DB에 저장하세요(서버가 늘어도 공유 문제 없음). 앞에 CDN을 붙이면 빠르게 전송됩니다. DB 데이터는 낮은 지연이 필요해 블록 스토리지를 씁니다.

주의 — 객체 스토리지는 파일 단위 접근이라 DB용으로는 부적합합니다. DB엔 블록 스토리지를 쓰세요.
