"GeoServer에서 3D 건물도 표준 API로 내려주세요" — OGC API 3D GeoVolumes 모듈의 실체와 데이터 파이프라인 설계

GIS

한 줄 요약 — GeoServer에 OGC API 3D GeoVolumes 커뮤니티 모듈이 들어왔습니다. 하지만 이 모듈은 3D 데이터를 만들거나 변환하지 않고, 이미 만들어진 3D Tiles를 그대로 얹어 표준 API로 노출만 합니다. 이 차이를 모르고 도입하면 파이프라인의 진짜 병목을 놓칩니다.

 

왜 지금 이 판단이 중요해졌는가

"지도에 건물을 평면으로만 보여주지 말고, 3D로도 보여주면서 다른 OGC 클라이언트에서도 표준 방식으로 가져다 쓸 수 있게 해주세요." GIS 서비스를 운영하다 보면 이런 요구가 들어옵니다. 지금까지는 WMS·WFS로 2D 데이터를 내리던 GeoServer와, 3D 모델은 Cesium ion이나 별도 3D Tiles 서버가 처리하는 식으로 역할이 완전히 나뉘어 있었습니다. 이 간극을 메우려는 시도가 GeoServer의 OGC API 3D GeoVolumes 커뮤니티 모듈입니다.

그런데 이 모듈의 실제 설계를 들여다보면 기대와 다른 지점이 있습니다. 개발자가 공개한 설명에 따르면 이 모듈은 "매우 가벼운 구현"으로, 3D Tiles나 i3s 같은 콘텐츠를 외부에서 생성해 정적 파일로 제공받는 구조입니다. GeoServer 데이터 디렉토리 안의 geovolumes 서브디렉토리에 결과물을 넣어두면, 모듈은 그걸 OGC 표준 스펙에 맞춰 노출해줄 뿐입니다. 즉 GeoServer가 3D 변환·렌더링을 대신 해주는 게 아니라, 이미 완성된 결과물을 표준 API 껍데기로 감싸주는 역할만 합니다.

 

전체 시스템에서의 위치

이 구조에서 GeoServer가 서는 자리는 데이터 흐름의 맨 끝, "이미 만들어진 결과물을 어떤 프로토콜로 내보낼 것인가"의 자리입니다. 앞단에는 원본 3D 모델을 3D Tiles나 i3s로 변환하는 별도 파이프라인이 반드시 있어야 합니다. 이 변환 작업은 Cesium ion 같은 상용 서비스, 오픈소스 CLI, 혹은 자체 구축한 타일링 배치 작업이 맡습니다. GeoServer는 그 결과물이 떨어지는 디렉토리를 감시하다가, OGC API 표준 엔드포인트로 응답해주는 얇은 서빙 계층일 뿐입니다.

그래서 실제 설계에서 고민해야 할 지점은 GeoServer 쪽이 아니라 그 앞단입니다. 변환 파이프라인을 어떻게 트리거할 것인가, 변환된 파일을 geovolumes 디렉토리에 어떻게 배포할 것인가, 그리고 경로 규칙(상위 경로 접근이 보안상 차단됨)을 어떻게 지킬 것인가입니다.

기준GeoVolumes 모듈Cesium ion 호스팅자체 정적 서버(S3+CDN)자체 변환 파이프라인 구축
역할완성본을 OGC API로 노출만변환·호스팅 통합 제공호스팅만, 변환은 별도변환 자체를 직접 구현

성숙도커뮤니티 모듈, 나이틀리 전용상용 서비스로 안정적매우 안정적팀 역량에 의존
변환 작업 필요여전히 필요불필요여전히 필요직접 구현

 

표가 가리키는 결론은 GeoVolumes가 Cesium ion의 대체재가 아니라는 점입니다. 변환 파이프라인이 이미 있고, 그 결과물을 기존 GeoServer 운영 체계 안에서 OGC 표준으로 함께 관리하고 싶은 팀에게만 의미가 있습니다.

 

실제 프로젝트 진행 순서

1) "3D 데이터를 누가, 어떻게 3D Tiles로 만들 것인가"를 먼저 확정합니다.
2) 나이틀리 빌드로 테스트 환경에 모듈을 설치해 안정성을 확인합니다.
3) 샘플 3D Tiles를 geovolumes 디렉토리에 수동 배치해 API 응답을 직접 확인합니다.
4) 변환 파이프라인의 출력 경로를 geovolumes 디렉토리와 연결하는 배포 단계를 CI/CD에 추가합니다.
5) CesiumJS 등 클라이언트로 파일럿 레이어 하나부터 검증한 뒤 범위를 넓힙니다.

 

주의 — "GeoServer 3D 지원"이라는 말을 변환 기능까지 포함된 것으로 오해하지 마세요. 아직 core conformance class만 구현돼 있고 bbox 검색 클래스는 빠져 있습니다. geovolumes 디렉토리 밖을 가리키는 상대 경로는 보안상 차단되어 있으니 배포 자동화 전에 먼저 테스트하세요.

 

정리

GeoServer의 OGC API 3D GeoVolumes 모듈은 3D 데이터를 변환하거나 렌더링하지 않고, 외부에서 만들어진 정적 파일을 OGC 표준 API로 노출만 하는 가벼운 서빙 계층입니다. 진짜 설계 작업은 그 앞단의 3D Tiles 변환 파이프라인을 어떻게 구축하고 자동 배포할 것인가에 있습니다. 아직 커뮤니티 모듈·나이틀리 빌드 단계이므로 기존 2D 운영과 3D를 한 서버에서 통합 관리하려는 팀이 파일럿 레이어로 먼저 검증하는 것이 합리적입니다.
