DB 마이그레이션 도구를 왜 쓰나요 — 스키마 버전 관리 기초

데이터베이스

한 줄 요약 — 마이그레이션 도구는 스키마 변경을 번호 붙은 SQL 파일로 버전 관리해 모든 환경의 일관성을 보장합니다.

 

스키마 변경을 손으로 하면 생기는 문제

로컬·팀원·스테이징·운영 DB에 ALTER TABLE을 일일이 손으로 적용하면 어디에 적용했는지, 순서가 맞는지 관리가 안 되고 환경마다 스키마가 달라집니다. 마이그레이션 도구가 이를 버전 관리로 해결합니다.

 

핵심 아이디어
V1__create_users.sql
V2__add_email_to_users.sql
V3__create_orders.sql

도구가 "어디까지 적용됐는지" 기록하고
아직 안 된 파일만 순서대로 실행

 

Flyway 파일 예제
-- V2__add_email_to_users.sql
ALTER TABLE users ADD COLUMN email VARCHAR(255);
CREATE INDEX idx_users_email ON users(email);

V2가 버전, __ 뒤가 설명입니다. 개발자는 SQL 파일만 추가하면 되고 적용 여부는 도구가 관리합니다.

 

실무 포인트

이미 적용된 마이그레이션 파일은 절대 수정하지 마세요. 도구가 체크섬을 기록하므로 고치면 오류가 납니다. 변경이 필요하면 새 파일(V4, V5)을 추가하세요.

주의 — 컬럼 삭제·이름 변경 같은 파괴적 변경은 배포 중 옛 버전 코드와 충돌할 수 있으므로 여러 단계로 나누는 Expand-Contract 전략이 필요합니다.
