이 작업 몇 시간 걸리는데 중간에 끊겨도 처음부터 다시 하지 않게 해주세요 — 에이전트 체크포인트·압축 설계

System Design

한 줄 요약 — '이 리팩터링, 에이전트한테 몇 시간 맡길 테니 중간에 끊겨도 처음부터 다시 하지 않게 해주세요'라는 요구는 컨텍스트 윈도우가 꽉 찰 때마다 요약(compaction)으로 공간을 비우는 흔한 해법을 그대로 쓰면 깨집니다. 요약이 조용히 정보를 버리는 문제를, 압축 전에 구조화된 상태를 먼저 durable store에 쓰는 체크포인트 설계로 막는 방법을 정리했습니다.

 

왜 지금 이 문제가 불거지는가

"이 리팩터링 작업, 에이전트한테 몇 시간 동안 맡겨주세요. 중간에 끊겨도 처음부터 다시 하지 않게 해주세요." 에이전트가 짧은 단일 턴 작업을 넘어 수십 분~수 시간짜리 작업을 맡게 되면서 흔해진 요구입니다. 문제는 컨텍스트 윈도우가 아무리 넓어져도 결국 한계에 부딪힌다는 점입니다. 가장 널리 쓰이는 해법은 윈도우가 꽉 차기 전에 지금까지의 기록을 요약해 공간을 비우는 압축(compaction)인데, 여기에는 조용한 함정이 있습니다. 요약은 윈도우 안에만 존재했던 세부 정보를 돌이킬 수 없이 버립니다. 중간 단계에서만 유효했던 파일 경로, 특정 도구 호출의 정확한 인자, 사용자가 지나가며 던진 제약 조건 같은 것들이 요약 문장 한 줄로 뭉개지면 복구할 방법이 없습니다.

2026년 3월 공개된 한 연구(arXiv:2603.29231)는 짧은 작업에서 76.3%였던 평균 성공률이 매우 긴 작업에서는 52.1%까지 떨어졌고, 더 중요하게는 메모리 스캐폴드를 그냥 끼워 넣는 것만으로는 장기 작업 신뢰성이 개선되지 않았으며 오히려 모델 10개 중 6개에서 성능을 악화시켰다고 보고했습니다. 메모리를 추가하는 것 자체가 목적이 아니라, 무엇을 언제 어디에 남길지를 설계하는 것이 핵심이라는 뜻입니다.

 

전체 시스템에서의 위치

장기 실행 에이전트의 상태는 세 계층으로 나눠 생각하는 것이 안전합니다. 현재 스레드 안에서만 유효한 워킹 메모리(컨텍스트 윈도우 그 자체), 압축 직전에 구조화된 형태로 durable store에 써 두는 핫 체크포인트(진행 상황, 남은 작업, 생성된 아티팩트), 그리고 스레드를 넘어 장기적으로 참조할 정보를 담는 콜드 메모리입니다. 데이터 흐름은 한 방향이 고정돼야 합니다 — 압축이 워킹 메모리를 건드리기 전에 반드시 핫 체크포인트부터 기록합니다. 순서가 바뀌면 체크포인트 자체가 이미 손실된 상태를 받아 적게 됩니다.

 

선택의 트레이드오프
전략구현 난이도정보 손실 위험적합한 상황
압축 없이 윈도우만 키우기매우 낮음낮음(당장은)작업 길이가 짧고 예측 가능할 때
Naive 요약 후 압축만낮음높음 — 조용히 소실프로토타입, 재현 불필요
압축 전 체크포인트 선기록중간낮음수십 분~시간 단위 작업 대부분
Hot/Cold 계층 메모리 분리높음매우 낮음여러 세션에 걸친 장기 기억 필요 시

 

표에서 중요한 기준은 "이 작업이 정말로 긴 세션을 요구하는가"입니다. 몇 분 안에 끝나는 작업에 체크포인트·계층 메모리까지 설계하는 것은 과설계입니다. 메모리 스캐폴드를 도입한 뒤에는 반드시 도입 전후로 장기 작업 성공률을 비교 측정해, 실제로 개선되는지 확인해야 합니다.

 

실제 프로젝트 진행 순서

1) 작업이 실제로 긴 세션을 요구하는지부터 확인합니다.
2) 체크포인트의 구조(진행상황·남은작업·아티팩트)를 먼저 정의합니다.
3) 압축 트리거 직전에 체크포인트 기록이 선행되도록 코드 레벨에서 순서를 강제합니다.
4) 재개 로직에 체크포인트와 실제 상태 일치 여부를 확인하는 검증 단계를 추가합니다.
5) 메모리 스캐폴드 도입 전후로 장기 작업 성공률을 비교 측정합니다.

 

주의 — 콜드 메모리까지는 모든 프로젝트에 필요하지 않습니다. 단일 세션 안에서 끝나는 작업이라면 체크포인트만으로 충분하고, 세션을 넘나드는 장기 기억이 실제로 필요할 때만 벡터 스토어·파일 기반 계층을 추가하세요.

 

정리

컨텍스트 압축은 윈도우 안에만 있던 정보를 조용히 버릴 수 있고, 메모리 스캐폴드를 그냥 추가하는 것만으로는 장기 작업 신뢰성이 개선되지 않는다는 연구 결과도 있습니다. 압축이 워킹 메모리를 건드리기 전에 구조화된 체크포인트를 먼저 기록하는 순서를 지키고, 워킹 메모리·핫 체크포인트·콜드 장기 메모리를 필요한 만큼만 계층으로 나눠야 합니다.
