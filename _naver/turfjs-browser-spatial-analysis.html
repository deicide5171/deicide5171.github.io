Turf.js로 브라우저에서 공간 분석하기 — 서버 없이 버퍼·교차 계산

GIS

한 줄 요약 — 이미 브라우저에 로드된 GeoJSON 데이터라면, 서버 왕복 없이 Turf.js로 버퍼·교차 같은 공간 분석을 즉시 처리할 수 있습니다.

 

왜 모든 분석을 서버로 보낼 필요는 없나

"이 지점에서 반경 1km 안에 어떤 매장이 있는가" 같은 질문은 대부분 PostGIS 쿼리를 떠올리게 합니다. 대용량 데이터는 서버 처리가 맞지만, 이미 로드된 GeoJSON에서 사용자가 그린 도형과의 교차나 간단한 버퍼 계산 정도라면 매번 서버 왕복이 필요 없습니다. Turf.js는 이런 상황을 위한 순수 자바스크립트 공간 분석 라이브러리입니다.

 

 

잘못된 접근 vs 올바른 접근

사용자가 원을 그릴 때마다 서버에 폴리곤을 보내 PostGIS로 계산하고 결과를 받아오면, 슬라이더로 반경을 조정할 때마다 네트워크 왕복이 발생해 지도 조작이 버벅입니다.

const center = turf.point([126.978, 37.566]);
const circle = turf.circle(center, 1, { units: 'kilometers' });

const storesInRange = stores.features.filter(store =>
  turf.booleanPointInPolygon(store, circle)
);

이렇게 하면 이미 로드된 매장 데이터를 즉시 필터링해, 슬라이더를 움직이는 동안에도 지연 없이 결과가 갱신됩니다. 폴리곤 교차는 booleanIntersects(), 거리는 distance()로 계산합니다.

상황 적합한 방식
소량 데이터 즉각 필터링 Turf.js(클라이언트)
수백만 건 대용량 공간 조인 PostGIS(서버)

 

주의 — Turf.js는 평면 기하 근사를 쓰는 함수가 많아 넓은 범위나 극지방 근처에서는 오차가 커질 수 있습니다. 법적·통계적으로 중요한 최종 결과는 서버에서 재검증하세요.

 

실무 포인트

대용량 GeoJSON을 그대로 클라이언트에 올리지 마세요. 무거운 연산은 Web Worker로 분리해 메인 스레드가 멈추지 않게 하고, 좌표계는 항상 EPSG:4326(위경도)을 써야 합니다. 번들 크기를 줄이려면 @turf/turf 전체 대신 실제 쓰는 함수만 개별 패키지로 임포트하세요.
