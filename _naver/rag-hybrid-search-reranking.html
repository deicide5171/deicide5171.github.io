RAG 정확도를 끌어올리는 하이브리드 검색과 재순위(Reranking)

AI

한 줄 요약 — 벡터 검색만으로는 고유명사·코드 질의에서 놓치는 문서가 많습니다. BM25 + 벡터 검색 + 재순위로 정확도를 끌어올리는 구조를 정리했습니다.

 

왜 지금 하이브리드 검색을 다시 봐야 하는가

RAG를 처음 구축할 때는 임베딩과 코사인 유사도만으로 검색하는 경우가 많습니다. 문제는 실제 서비스에서 나타납니다 — 제품 코드명, 에러 코드, API 함수명처럼 정확한 문자열 일치가 중요한 질의에서 벡터 검색은 의미적으로 비슷한 다른 문서를 가져오고 정작 정확히 일치하는 문서는 놓치는 경우가 반복됩니다.

 

벡터 검색과 키워드 검색은 서로 다른 실패 모드를 가진다

BM25 같은 키워드 검색은 정확한 토큰 일치에 강하지만 동의어를 이해하지 못합니다. 벡터 검색은 의미적 유사성은 잘 잡지만 희귀 고유명사에서는 약합니다. 하이브리드 검색은 두 방식을 병렬 실행 후 병합해 실패 모드를 보완합니다.

검색 방식 강점 약점
BM25 (Sparse) 정확한 키워드 일치 동의어·문맥 이해 부족
벡터 검색 (Dense) 의미적 유사성 파악 희귀 고유명사에 약함
하이브리드 두 결과 결합 병합 로직 튜닝 필요

 

결과 병합과 재순위(Reranking)의 역할

BM25 점수와 코사인 유사도는 스케일이 다르므로 순위 기반으로 결합하는 RRF(Reciprocal Rank Fusion)를 흔히 씁니다. 병합된 후보군 상위 일부를 재순위 모델(cross-encoder)로 다시 정렬하는 것이 최근 RAG의 표준 구성입니다.

 

예제 — RRF로 두 검색 결과 병합하기
def reciprocal_rank_fusion(result_lists, k=60):
    scores = {}
    for results in result_lists:
        for rank, doc_id in enumerate(results):
            scores[doc_id] = scores.get(doc_id, 0) + 1 / (k + rank + 1)
    return sorted(scores.items(), key=lambda x: x[1], reverse=True)

bm25_results = bm25_search(query, top_k=50)
vector_results = vector_search(query, top_k=50)

fused = reciprocal_rank_fusion([bm25_results, vector_results])
candidates = [doc_id for doc_id, _ in fused[:30]]

reranked = cross_encoder_rerank(query, candidates, top_k=8)

RRF는 점수 스케일 차이를 신경 쓰지 않고 순위만으로 병합할 수 있어 구현이 단순하면서도 실무에서 꾸준히 좋은 성능을 보입니다.

 

실무 포인트

재순위 모델은 후보군 규모를 작게 유지하세요. cross-encoder는 벡터 검색보다 훨씬 느리므로, 1차 검색에서 상위 20~50개만 추려낸 뒤 적용해야 지연시간이 감당 가능한 수준을 유지합니다.

도메인 특화 재순위 모델을 우선 검토하세요. 코드 검색, 법률·의료 문서처럼 도메인 특화 모델이 있으면 정확도 차이가 크게 납니다.

주의 — 하이브리드 검색 도입 전에 실패 사례를 먼저 수집하세요. 벡터 검색만으로 실패하는 질의 유형(정확한 코드, 고유명사 등)을 로그에서 먼저 파악한 뒤 도입 효과를 정량적으로 검증하는 것이 순서에 맞습니다.
