한 줄 요약 — Vision API는 텍스트 API와 달리 인코딩 방식, 이미지 크기, 토큰 비용이라는 별도 제약이 있어, 프로토타입 단계부터 이를 고려해야 합니다.

 

첫 호출: 이미지를 요청에 넣는 방법

이미지를 base64로 인코딩해 요청 본문에 직접 담거나, 공개 URL을 전달하는 두 가지 방법이 있습니다. 처음 코드를 작성할 때 가장 흔한 실수는 media_type을 실제 파일 형식과 다르게 지정하는 것입니다. PNG 파일을 image/jpeg로 잘못 명시하면 400 에러가 나거나, 조용히 잘못된 결과가 나올 수 있습니다.

with open("receipt.jpg", "rb") as f:
    image_data = base64.b64encode(f.read()).decode("utf-8")

response = client.messages.create(
    model="claude-sonnet-4-5",
    messages=[{"role": "user", "content": [
        {"type": "image", "source": {"type": "base64",
            "media_type": "image/jpeg", "data": image_data}},
        {"type": "text", "text": "영수증 총액만 답해줘."}
    ]}]
)

 

 

흔한 에러 두 가지

이미지 크기 초과 — 대부분의 API는 이미지 하나당 크기 상한과 함께, 큰 이미지는 자동 리사이즈해 처리합니다. 이 과정에서 작은 글씨(영수증 항목 등)가 뭉개질 수 있으므로, 업로드 전에 서버에서 직접 리사이즈해 화질을 통제하는 편이 좋습니다.

토큰 비용 착각 — 이미지 한 장이 소비하는 토큰은 해상도에 비례하며, 텍스트 프롬프트보다 훨씬 많은 경우가 흔합니다. 여러 장을 배치 처리하는 파이프라인이라면 이 비용을 반드시 사전에 계산해야 합니다.

주의 — 신분증, 결제 정보 같은 민감한 이미지는 디버깅 로그에 그대로 남기지 마세요. 이미지 데이터 대신 메타데이터(크기, 처리 결과 요약)만 로깅하는 것이 안전합니다.

 

실무 포인트

한 요청에 이미지를 10장, 20장씩 한꺼번에 담으면 모델의 집중도가 흐려지고 응답 지연도 늘어납니다. 정말 여러 장을 동시에 봐야 하는 경우가 아니라면 이미지 단위로 요청을 쪼개는 편이 안정적입니다. 모델별 지원 포맷(JPEG, PNG, WebP, HEIC)도 API 버전마다 다르므로, 사용자가 올린 원본을 그대로 보내지 말고 지원 포맷으로 변환하는 단계를 항상 거치세요.
