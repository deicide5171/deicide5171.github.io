CHECK 제약이 뭔가요 — 잘못된 값을 DB가 거부하게 하기

2026. 9. 16. · 데이터베이스

한 줄 요약 — CHECK 제약은 컬럼 값이 조건을 만족할 때만 저장을 허용해 잘못된 데이터를 DB가 막습니다.

 

애플리케이션 검증만으로 충분할까

나이 음수·마이너스 가격·없는 상태값이 들어오면 안 됩니다. 앱에서 검증해도 버그·다른 경로로 잘못된 값이 저장될 수 있죠. CHECK 제약은 조건을 만족해야만 저장을 허용해 DB 차원에서 막습니다.

 

사용법
CREATE TABLE products (
  id BIGINT PRIMARY KEY,
  price INT CHECK (price >= 0),
  status VARCHAR(10) CHECK (status IN ('active','sold','hidden'))
);
-- price에 -100을 넣으면 오류로 거부

 

자주 쓰는 조건
조건 예
범위 age BETWEEN 0 AND 150
목록 status IN ('a','b','c')
관계 end_date >= start_date

 

실무 포인트

앱 검증(빠른 피드백)과 CHECK 제약(최종 보장)을 함께 쓰면 어떤 경로로 들어와도 안전합니다. 상태값엔 IN 목록으로 오타·없는 값을 원천 차단하세요.

주의 — CHECK 조건은 NULL을 "위반 아님"으로 취급하는 경우가 많습니다. NULL도 막으려면 NOT NULL을 함께 거세요.
