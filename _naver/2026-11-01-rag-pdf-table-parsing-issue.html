한 줄 요약 — PDF 표는 좌표 기반 텍스트 추출로는 행과 열 구조가 뭉개져 표 환각을 유발하므로, 표 전용 추출 도구로 구조를 보존해야 합니다.

 

왜 표가 있는 PDF가 골칫거리인가

RAG 파이프라인을 처음 만들 때는 순수 텍스트 문서로 테스트하지만, 운영에 들어가면 재무제표·스펙표처럼 표 형태의 정보가 담긴 PDF가 쏟아집니다. 대부분의 텍스트 추출 라이브러리는 표를 행과 열이 아니라 좌표상 흩어진 텍스트 조각으로 인식합니다.

이런 텍스트를 그대로 청킹해 임베딩하면 "노트북B의 재고는 몇 개인가?" 같은 질문에 LLM이 잘못된 행과 열을 짝지어 엉뚱한 답을 만들어냅니다. 이를 표 환각이라고 부릅니다.

 

도구별 비교
도구 인식 방식 한계
PyPDF2 / pdfminer 좌표 기반 텍스트 표 구조 정보 없음
pdfplumber 선 감지로 표 경계 추론 테두리 없는 표는 인식 실패
Camelot / Tabula 격자 기반 표 전용 추출 스캔 이미지 PDF엔 무력
레이아웃 인식 모델 시각적 레이아웃 학습 기반 처리 속도 느림, 비용 증가

 

잘못된 접근 vs 올바른 접근

흔한 실수는 라이브러리만 교체하면 해결될 거라 착각하는 것과, 표를 인식했어도 일반 문단처럼 고정 길이로 청킹하는 것입니다. 표는 행 하나가 의미 단위인 경우가 많아, 문자 수 기준으로 자르면 한 행이 두 청크로 쪼개져 검색 시 관련 정보를 통째로 놓치게 됩니다.

import pdfplumber

with pdfplumber.open("spec.pdf") as pdf:
    for page in pdf.pages:
        table = page.extract_table()
        if table:
            markdown_table = to_markdown(table)

표를 마크다운 형식으로 변환해 저장하면 행과 열 관계가 그대로 유지됩니다. 표는 행 단위 혹은 전체를 하나의 청크로 유지하고, 표가 크면 헤더 행을 각 청크에 반복 포함시켜 열의 의미를 잃지 않게 합니다.

주의 — 텍스트 레이어가 없는 스캔 이미지 PDF는 Camelot·pdfplumber가 아예 인식하지 못합니다. OCR로 먼저 텍스트를 뽑고 레이아웃 분석을 함께 쓰는 이중 처리가 필요합니다.

 

실무 포인트

표가 많은 도메인이라면 처음부터 레이아웃 인식 기반 파서를 기본값으로 검토하세요. 나중에 전환하면 청킹·인덱싱 파이프라인을 다시 손봐야 합니다. 표 추출 성공률은 반드시 자체적으로 측정하고, 표 제목·페이지 번호 같은 메타데이터를 함께 저장해 재랭킹 단계에서 활용하세요.
