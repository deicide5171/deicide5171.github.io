서브쿼리 지옥에서 벗어나기 — SQL 윈도우 함수 고급 패턴

2026. 8. 28. · 데이터베이스

한 줄 요약 — 순위, 이동평균, 전월 대비 증감처럼 상관 서브쿼리·자기 조인으로 억지로 풀던 문제를, SQL 윈도우 함수의 파티션과 프레임 개념으로 단순하고 빠르게 다시 쓰는 방법을 정리했습니다.

 

GROUP BY만으로는 안 되는 이유

"사용자별 최근 3개 주문의 평균 금액", "전월 대비 매출 증감률", "부서 내 급여 순위" 같은 요구사항을 GROUP BY만으로 풀려고 하면 곧바로 한계에 부딪힙니다. GROUP BY는 여러 행을 하나로 뭉개기 때문에, 뭉개지기 전 개별 행의 값을 그대로 유지하면서 동시에 그룹 단위 계산도 함께 보고 싶다는 요구를 표현할 수 없습니다.

그래서 흔히 상관 서브쿼리나 자기 조인으로 우회하는데, 이 방식은 코드가 급격히 복잡해지고 각 행마다 서브쿼리가 재실행되어 성능도 떨어집니다. 윈도우 함수는 이 문제를 정면으로 해결하기 위해 SQL 표준에 추가된 기능으로, GROUP BY처럼 행을 하나로 합치지 않으면서도 각 행에 그룹 단위 계산 결과를 붙여서 반환합니다.

 

핵심 개념 1 — PARTITION BY와 ORDER BY, GROUP BY와의 차이
구분 GROUP BY 윈도우 함수(OVER)
결과 행 수 그룹 수만큼 줄어듦 원본 행 수 그대로
개별 행 값 접근 불가능 가능
원본 컬럼+집계값 동시 사용 서브쿼리·조인 필요 바로 가능

 

핵심 개념 2 — 순위 함수 3형제, 동점 처리가 다릅니다

ROW_NUMBER()는 동점이어도 무조건 순차 번호(1,2,3,4...)를 매기고, RANK()는 동점에 같은 등수를 준 뒤 다음 등수를 건너뛰며(1,1,3,4...), DENSE_RANK()는 동점에 같은 등수를 주되 다음 등수를 건너뛰지 않습니다(1,1,2,3...). "정확히 N개 행"이 필요하면 ROW_NUMBER(), "동점자를 모두 포함한 상위 N위 그룹"이 필요하면 RANK()가 맞습니다.

핵심 개념 3 — 프레임, 이동평균과 누적합의 핵심

프레임은 ORDER BY로 정해진 순서 안에서 "현재 행 기준으로 어디부터 어디까지를 계산에 포함할지"를 지정합니다. 이동평균처럼 "최근 N개 행"이 필요하면 ROWS BETWEEN 2 PRECEDING AND CURRENT ROW처럼 물리적 행 개수 기준 프레임을 명시해야 합니다.

 

예제 — 상관 서브쿼리를 윈도우 함수로 바꾸기
-- Before: 사용자별 최근 3개 주문 평균을 상관 서브쿼리로
SELECT o.order_id, o.user_id, o.amount,
  (SELECT avg(o2.amount) FROM orders o2
   WHERE o2.user_id = o.user_id AND o2.ordered_at <= o.ordered_at
   ORDER BY o2.ordered_at DESC LIMIT 3) AS recent_avg
FROM orders o;

-- After: 윈도우 함수로 한 번의 스캔 + 정렬로 계산
SELECT order_id, user_id, amount, ordered_at,
  avg(amount) OVER (
    PARTITION BY user_id ORDER BY ordered_at
    ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
  ) AS recent_avg,
  amount - lag(amount) OVER (PARTITION BY user_id ORDER BY ordered_at) AS diff_from_prev,
  rank() OVER (PARTITION BY user_id ORDER BY amount DESC) AS amount_rank
FROM orders;

lag()는 파티션 내에서 현재 행 기준 이전 N번째 행의 값을 가져오는 함수로, 전월 대비 증감 패턴에 정확히 맞습니다. 상관 서브쿼리 버전은 행마다 계산을 반복하지만, 윈도우 함수 버전은 대부분 한 번의 정렬된 스캔으로 처리됩니다.

 

실무 도입 시 이것만은 챙기세요
1. 프레임을 생략하면 기본값 함정에 빠질 수 있습니다 — 누적 계산이 아니라면 ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING을 명시하는 습관을 들이세요.
2. 윈도우 함수는 WHERE 절에서 바로 못 씁니다 — SELECT/ORDER BY 단계에서 평가되므로 서브쿼리나 WITH 절로 감싼 뒤 바깥에서 필터링해야 합니다.
3. EXPLAIN으로 Sort 비용을 확인하세요 — 여러 윈도우 함수가 같은 PARTITION BY/ORDER BY를 공유하면 옵티마이저가 정렬을 재사용할 여지가 커집니다.

 

마무리 — 3줄 요약

① 윈도우 함수는 GROUP BY와 달리 행을 뭉개지 않고 원본 컬럼과 집계값을 한 쿼리에서 동시에 다룰 수 있게 합니다.
② ROW_NUMBER·RANK·DENSE_RANK는 동점 처리 방식이 다르므로 요구사항에 맞는 함수를 골라야 하고, 이동평균에는 프레임을 명시해야 합니다.
③ 상관 서브쿼리·자기 조인으로 짜던 순위·누적·전 행 비교 로직은 대부분 윈도우 함수로 더 짧고 빠르게 다시 쓸 수 있습니다.
