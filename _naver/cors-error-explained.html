CORS 에러는 왜 날까 — 원인과 해결법 총정리

2026. 8. 31. · 프론트엔드

한 줄 요약 — CORS는 브라우저가 강제하는 보안 정책이라 서버가 정상 응답해도 허용 헤더가 없으면 JS의 응답 접근이 차단됩니다.

 

왜 프론트엔드 개발자를 가장 많이 괴롭히나

콘솔에 Access-Control-Allow-Origin 관련 에러가 뜨면 프론트엔드 코드를 아무리 고쳐도 해결되지 않습니다. CORS는 브라우저가 강제하는 보안 정책이라 문제의 원인도 해결도 대부분 서버 쪽에 있기 때문입니다.

 

CORS가 발생하는 조건
요청 출처 대상 URL 교차 출처 여부
https://a.com http://a.com/api 예(프로토콜 다름)
https://a.com https://api.a.com 예(서브도메인도 다른 출처)
https://a.com:3000 https://a.com:8080 예(포트 다름)

 

왜 서버가 정상 응답해도 브라우저가 막는가

서버는 요청을 정상적으로 처리하고 응답까지 내려보냅니다. 문제는 브라우저가 그 응답을 자바스크립트에 넘겨주지 않고 차단한다는 점입니다. Network 탭에서 상태 코드가 200인데도 콘솔에 CORS 에러가 뜨는 이유입니다.

1. 브라우저가 OPTIONS로 preflight 요청을 먼저 보낸다
2. 서버가 Access-Control-Allow-Origin 등으로 허용 여부를 응답
3. 브라우저가 헤더를 확인해 실제 요청 진행 여부를 결정
4. 허용 헤더가 없으면 응답이 왔어도 JS 접근이 차단된다

 

서버 쪽 해결 코드 예제(Spring Boot)
@Configuration
public class CorsConfig implements WebMvcConfigurer {
    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/api/**")
                .allowedOrigins("https://my-frontend.com")
                .allowedMethods("GET", "POST", "PUT", "DELETE")
                .allowCredentials(true);
    }
}

allowedOrigins("*")로 전체 허용하면 편하지만, allowCredentials(true)와 와일드카드는 함께 쓸 수 없습니다.

 

실무 포인트

개발 환경에서 Vite의 server.proxy 같은 프록시 기능을 쓰면 CORS 문제를 우회할 수 있지만, 이는 개발 편의용이지 프로덕션 해결책은 아닙니다.

주의 — 인증 쿠키를 함께 보내야 한다면 프론트엔드에서 credentials: 'include', 서버에서 Access-Control-Allow-Credentials: true를 반드시 함께 설정해야 합니다.
