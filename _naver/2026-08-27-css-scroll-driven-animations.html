스크롤이 곧 타임라인이 된다 — CSS Scroll-driven Animations 실무

2026. 8. 27. · 프론트엔드

한 줄 요약 — 스크롤에 따라 진행률바를 채우거나 요소를 나타나게 하는 효과를 JS 스크롤 리스너로 만들면 자꾸 버벅입니다. CSS만으로 스크롤 위치를 애니메이션 타임라인으로 쓰는 법을 정리했습니다.

 

JS 스크롤 리스너의 한계

스크롤 진행률바, 스크롤에 맞춰 나타나는 리빌 애니메이션, 패럴랙스 효과 — 이런 것들을 만들 때 흔히 scroll 이벤트 리스너에 requestAnimationFrame을 조합해 매 프레임 스크롤 위치를 읽고 스타일을 직접 갱신합니다. 이 방식은 동작은 하지만 메인 스레드에서 스크롤 이벤트와 스타일 계산이 계속 오가면서 스크롤 중 프레임 드랍이 발생하기 쉽습니다.

CSS Scroll-driven Animations는 이 문제를 근본적으로 없앱니다. 스크롤 위치 자체를 애니메이션의 "시간"으로 취급해, 브라우저가 컴포지터 스레드에서 애니메이션 진행률을 스크롤 위치에 직접 묶어버립니다.

 

핵심 개념 1 — 두 가지 타임라인, scroll()과 view()

scroll()은 스크롤 컨테이너 전체의 스크롤 진행률(0~100%)을 타임라인으로 씁니다. 페이지를 처음부터 끝까지 스크롤하는 동안 진행률바를 채우는 것처럼 컨테이너 전체 기준 애니메이션에 적합합니다. view()는 특정 요소가 뷰포트에 들어오고 나가는 구간 자체를 타임라인으로 씁니다. 카드가 화면에 들어올 때 페이드인되는 것처럼 개별 요소의 가시성 기반 애니메이션에 적합하며, 내부적으로 IntersectionObserver가 하던 일을 브라우저 네이티브 타임라인으로 대체한 것에 가깝습니다.

 

핵심 개념 2 — JS 방식과의 비교
구분 JS (scroll + rAF) CSS Scroll-driven
실행 스레드 메인 스레드 컴포지터 스레드
메인 스레드 부하 영향 프레임 드랍 발생 가능 영향받지 않음
브라우저 지원 전 브라우저 최신 Chromium/Firefox, Safari 부분 지원

 

 

예제 — 읽기 진행률바와 카드 리빌 애니메이션
/* 1. 페이지 스크롤 진행률바 — scroll() 타임라인 */
@keyframes grow-progress {
  from { transform: scaleX(0); }
  to   { transform: scaleX(1); }
}

.progress-bar {
  transform-origin: left;
  animation: grow-progress auto linear;
  animation-timeline: scroll(root);
}

/* 2. 카드가 뷰포트에 들어올 때 페이드인 — view() 타임라인 */
@keyframes fade-in-up {
  from { opacity: 0; transform: translateY(24px); }
  to   { opacity: 1; transform: translateY(0); }
}

.reveal-card {
  animation: fade-in-up auto linear;
  animation-timeline: view();
  animation-range: entry 0% cover 40%;
}

animation-range로 타임라인 중 어느 구간에서 애니메이션이 진행될지 세밀하게 지정할 수 있습니다.

 

실무 도입 시 이것만은 챙기세요
1. @supports로 반드시 폴백을 챙기세요 — 미지원 브라우저에서는 요소가 시작 상태로 멈춰 보일 수 있습니다.
2. will-change는 필요할 때만 최소로 쓰세요 — Scroll-driven Animations 자체는 이미 컴포지터 처리를 전제하므로 대부분 추가 지정이 필요 없습니다.
3. animation-range로 튜닝하며 자연스러움을 조정하세요 — 기본값은 종종 너무 빠르거나 느리게 느껴집니다.

 

마무리 — 3줄 요약

① CSS Scroll-driven Animations는 스크롤 위치를 애니메이션 타임라인으로 삼아 컴포지터 스레드에서 실행되므로 JS 스크롤 리스너보다 매끄럽습니다.
② scroll()은 컨테이너 전체 진행률을, view()는 개별 요소의 가시성 구간을 타임라인으로 쓴다는 역할 차이가 있습니다.
③ 브라우저 지원이 아직 완전하지 않으므로 @supports 기반 폴백과 animation-range 튜닝이 실무 적용의 핵심입니다.
