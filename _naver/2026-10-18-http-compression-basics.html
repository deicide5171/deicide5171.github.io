HTTP 압축이 뭔가요 — gzip으로 응답을 작게 보내기

시스템 디자인

한 줄 요약 — HTTP 압축은 서버가 응답을 gzip·brotli로 압축해 전송량을 줄여 로딩을 빠르게 합니다(텍스트에 효과 큼).

 

응답을 그대로 보내면 무겁다

HTML·CSS·JS·JSON은 텍스트라 반복이 많아 잘 압축됩니다. 압축 없이 보내면 전송량이 커 느리죠. HTTP 압축은 서버가 응답을 압축해 보내고 브라우저가 풀어, 전송량을 크게 줄입니다.

 

어떻게 협상하나
1. 브라우저: Accept-Encoding: gzip, br
2. 서버: 압축 후 Content-Encoding: br
3. 브라우저: 받아서 압축을 풀어 표시

 

대표 방식
방식 특징
gzip 널리 지원, 무난
brotli 압축률 더 좋음

 

실무 포인트

텍스트는 60~80%까지 줄지만 JPG·MP4는 이미 압축돼 이득이 없으니 텍스트에만 켜세요. 정적 파일은 미리 압축(precompress)하면 부하가 줍니다. 보통 Nginx·프록시·CDN 설정으로 켭니다.

주의 — 이미지·동영상을 다시 압축하면 이득 없이 CPU만 씁니다. 압축 대상을 텍스트로 제한하세요.
