우리 팀 전용 패널을 채팅 옆에 띄워주세요 — Claude Code Mods로 확장점 고르는 기준

AI

한 줄 요약 — "배포 상태를 채팅 옆에 계속 띄워주세요"라는 요구는 Skill이나 MCP 도구로는 풀리지 않습니다. 2026년 10월 공개된 Claude Code Mods가 추가한 UI 렌더링 확장점이 Skill·MCP 도구와 어떻게 역할을 나누는지, 어디서는 아예 작동하지 않는지 정리했습니다.

 

왜 지금 이 문제가 불거지는가

"에이전트가 뭘 하고 있는지 매번 물어보기 귀찮으니, 배포 상태나 현재 작업 큐를 채팅 옆에 계속 떠 있게 해주세요." 이런 요구를 받으면 먼저 Skill을 떠올리게 됩니다. 그런데 Skill은 모델에게 "이렇게 행동하라"는 지시문 묶음일 뿐, 화면에 패널을 그리는 수단이 아닙니다. MCP 도구를 붙여도 마찬가지입니다. 도구는 모델이 호출해 데이터를 받아오는 통로이지, 그 결과를 상시 보이는 위젯으로 유지하는 장치가 아닙니다.

2026년 10월 1일 공개된 Claude Code Mods가 이 빈 자리를 채웁니다. Mod는 플러그인 형태로 배포되는 JavaScript·TypeScript 이벤트 핸들러로, 트랜스크립트 옆 패널이나 입력창 위 밴드 같은 렌더 사이트에 직접 UI를 그리고, 도구 호출 줄이나 스피너 같은 기존 요소의 스타일도 바꿀 수 있습니다. 확장점이 하나 늘었다는 건 반갑지만, 동시에 "이 요구는 Skill인가 MCP 도구인가 Mod인가"를 매번 새로 판단해야 하는 숙제도 함께 생겼습니다.

 

요구사항을 세 갈래로 번역하기

사용자의 말 한 줄은 보통 세 가지 중 하나, 혹은 그 조합으로 번역됩니다. "이럴 때는 이렇게 처리해주세요"는 행동 지시이므로 Skill의 영역이고, "저 시스템 데이터를 가져와서 판단에 써주세요"는 외부 연동이므로 MCP 도구의 영역입니다. "이 정보를 화면에 계속 보여주세요"는 렌더링이므로 이번에 추가된 Mod의 영역입니다. 실무에서 걸려 넘어지는 지점은 세 번째를 두 번째로 잘못 번역하는 경우입니다. MCP 도구는 모델이 필요할 때 한 번 호출해 결과를 컨텍스트에 넣는 구조라, 사람이 쳐다보고 있는 동안 계속 갱신되는 화면을 만드는 데는 애초에 맞지 않습니다.

 

전체 시스템에서의 위치

플러그인 하나 안에 Skill·MCP 서버·Mod가 함께 들어갈 수 있다는 점이 설계를 더 유연하게 만들지만, 동시에 실행 위치의 차이를 가립니다. Skill은 모델의 시스템 프롬프트에 얹히므로 어디서 실행되든 동일하게 작동하고, MCP 도구는 서버만 떠 있으면 클라이언트를 가리지 않습니다. 반면 Mod의 화면 렌더링은 터미널과 데스크톱 앱의 Code 탭에서만 그려집니다. VS Code 채팅 패널에서는 훅 코드는 실행되지만 커스텀 패널·밴드는 화면에 나타나지 않고, Agent SDK나 claude -p로 돌리는 무인 실행 환경에서도 마찬가지입니다. Mod로 설계한 UI를 CI 파이프라인이나 백그라운드 자동화에 그대로 가져가면 그 부분만 조용히 사라집니다.

 

선택의 트레이드오프
확장점바꾸는 것실행 위치 제약보안 범위적합한 요구
Skill모델의 행동·절차없음낮음"이런 상황엔 이렇게 하라"
MCP 도구모델이 쓰는 외부 기능서버 연결만 필요중간"저 데이터를 가져와 써라"
Mod(UI)화면 자체터미널·데스크톱 Code 탭만높음"이 정보를 상시 보여줘라"

 

Mod의 보안 범위가 높다고 표시한 이유는, Mod가 Claude Code 프로세스 안에서 실행되는 임의의 JS/TS 코드라 사실상 로컬 머신 전체에 접근할 수 있기 때문입니다. 외부 마켓플레이스에서 받은 Mod를 그대로 설치하는 것은 출처가 불분명한 VS Code 확장을 설치하는 것과 같은 수준의 신뢰 결정입니다. 권한 프롬프트 화면만큼은 Mod가 덮어쓸 수 없게 막아둔 것도 이 때문입니다.

 

실제 프로젝트 진행 순서

1) 요구를 셋 중 어디에 넣을지부터 가릅니다. "항상 이렇게 동작해라"면 Skill로 끝날 일을 Mod로 만들지 않습니다.
2) UI가 꼭 필요한지, 꼭 상시 노출이어야 하는지 다시 확인합니다.
3) 이 UI가 실제로 쓰일 환경을 먼저 적습니다 — 터미널·데스크톱 Code 탭뿐인지, VS Code나 CI 무인 실행도 섞여 있는지.
4) 렌더 사이트를 하나만 골라 최소 기능으로 먼저 만듭니다.
5) 배포 전 출처 검증 절차를 팀 규칙으로 먼저 정합니다.

 

주의 — Mod를 "더 강력한 Skill"로 오해하지 마세요. Mod는 화면을 그리는 수단이지 모델의 판단력을 바꾸는 수단이 아닙니다. VS Code·Agent SDK 사용자가 섞인 팀이면 핵심 정보를 Mod UI에만 의존시키지 말고 채팅 응답에도 남겨 이중화하세요. 설치 전에는 Mod의 권한 범위를 반드시 코드 리뷰 대상으로 삼으세요.

 

정리

Claude Code Mods는 "모델의 행동을 바꾼다"(Skill), "모델이 쓰는 기능을 늘린다"(MCP 도구)에 이어 "화면 자체를 바꾼다"는 세 번째 확장점을 추가했습니다. Mod가 그리는 UI는 터미널과 데스크톱 Code 탭에서만 보이고 VS Code 패널과 Agent SDK·claude -p 환경에서는 나타나지 않으므로, 사용 환경이 섞인 팀은 핵심 정보를 UI에만 의존시키면 안 됩니다. Mod는 로컬 머신에 접근하는 임의 코드이므로 보안 범위가 가장 넓고, 도입 전 출처 검증과 코드 리뷰 절차가 반드시 선행되어야 합니다.
