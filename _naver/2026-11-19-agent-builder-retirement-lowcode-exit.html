"워크플로우 먼저 비주얼로 빠르게 만들어주세요" — OpenAI Agent Builder 종료가 보여주는 로우코드 오케스트레이션의 수명

AI

한 줄 요약 — OpenAI가 비주얼 에이전트 빌더 Agent Builder를 종료하기로 하면서, 빌더 캔버스 위에만 존재하던 워크플로우 정의를 업무 지속 기간 안에 다른 형태로 옮겨야 하는 팀이 생겼습니다. 정의의 소유권을 벤더 포맷이 아니라 벤더 중립 표현에 두는 설계만이 이런 종료 공지에서 자유롭습니다.

 

왜 지금 이 판단이 필요한가

"이 업무, 일단 빠르게 비주얼로 만들어서 돌려보고 싶어요. 코드는 나중에 정리하면 되죠?"라는 요구는 요즘 흔합니다. 여러 로우코드 플랫폼이 "드래그앤드롭으로 에이전트 워크플로우를 짜라"고 등을 떠밀었고, 프로토타입 단계에서는 실제로 효과가 컸습니다. 그런데 OpenAI는 Agent Builder를 2026년 11월 30일부로 종료한다고 공지했습니다. 그 전까지 워크플로우를 export해 인벤토리를 만들고, 대체 아키텍처를 정하고, 재구현과 회귀 테스트까지 마치라는 것이 공지의 요지입니다.

이 사건이 중요한 이유는 Agent Builder 하나가 특별히 불안정해서가 아닙니다. 벤더가 내놓는 비주얼 오케스트레이션 제품은 대개 그 벤더의 모델·플랫폼 전략과 함께 움직이고, 전략이 바뀌면 제품도 접힙니다. "비주얼로 빠르게 만들어주세요"라는 요구를 받아들일 때, 그 결과물이 코드로 쉽게 빠져나올 수 있는 형태인지를 아무도 묻지 않는다는 데 진짜 문제가 있습니다.

 

전체 시스템에서의 위치

에이전트 오케스트레이션은 보통 워크플로우 정의, 그 정의를 실행하는 런타임, 모델·도구 호출 같은 실행 프리미티브로 나뉩니다. 비주얼 빌더는 이 세 층을 하나로 묶어 벤더의 캔버스 UI와 저장 포맷 안에 가둡니다. 정의가 벤더 JSON 스키마로만 존재하면, 런타임이 사라지는 순간 정의도 같이 못 쓰게 됩니다. 정의를 단계·조건·도구 호출 명세 같은 벤더 중립 표현으로 먼저 적어 두면, 그 표현을 비주얼 빌더든 자체 오케스트레이터든 여러 런타임이 해석할 수 있어 런타임 하나가 빠져도 정의는 남습니다.

 

선택의 트레이드오프
방식초기 속도탈출 비용적합한 상황
벤더 비주얼 빌더에 전부 위임매우 빠름매우 높음단명할 프로토타입, 검증용 PoC
빌더+문서 병행 기록빠름중간빌더 UI가 설계 합의에 도움되는 초기 단계
코드 기반 오케스트레이션느림낮음운영 지속성이 중요한 핵심 업무 흐름
하이브리드(코드 정의+비주얼 모니터링)중간낮음가시성과 장기 운영 둘 다 필요한 경우

 

빌더를 쓰지 말라는 결론이 아닙니다. 요구사항이 모호해서 "일단 눈으로 보면서 흐름을 맞춰보고 싶다"는 단계에서는 비주얼 빌더가 합의를 빠르게 만드는 데 유리합니다. 문제는 그 단계가 끝났는데도 정의의 소유권을 계속 벤더 포맷에 맡겨 두는 것입니다. 트레이드오프의 축은 "지금 얼마나 빠르냐"가 아니라 "이 워크플로우가 1년 뒤에도 돌아야 하는가"로 잡아야 합니다.

 

실제 프로젝트 진행 순서

가장 먼저 할 일은 지금 비주얼 빌더에 올라가 있는 워크플로우를 전수 조사하는 것입니다. 몇 개의 노드로 구성되고, 어떤 도구를 호출하며, 어디서 사람 승인을 기다리는지를 벤더 UI 바깥의 문서로 먼저 적습니다.

워크플로우 인벤토리 예시
- 이름: 주간 리포트 생성
- 트리거: 매주 월요일 09:00
- 단계: 데이터 수집 → 모델 요약 → 승인 대기 → 발송
- 외부 호출: 사내 API 2개, 이메일 발송 1개
- 상태 의존: 승인 대기 중 사람 입력

그다음 각 워크플로우를 "지금 당장 코드로 옮겨야 하는 것"과 "당분간 비주얼로 둬도 되는 것"으로 나눕니다. 기준은 운영 기간과 변경 빈도입니다. 몇 주 안에 폐기될 실험이라면 급하게 옮길 이유가 없고, 반대로 매주 돌며 회사 운영에 걸려 있는 흐름이라면 벤더의 종료 공지 유무와 무관하게 애초에 코드로 짰어야 한다는 신호로 받아들여야 합니다. 마지막으로 코드로 옮긴 뒤에는 반드시 같은 입력으로 비주얼 버전과 결과를 나란히 비교하는 회귀 테스트를 거친 뒤에만 비주얼 버전을 끕니다.

 

주의 — "일단 지금 잘 돌아간다"는 상태와 "정의가 벤더에 종속되어 있지 않다"는 상태는 전혀 다른 질문입니다. 전자만 확인하고 넘어가면, 벤더가 로드맵을 바꾸는 순간 재구현을 처음부터 다시 시작해야 합니다.
