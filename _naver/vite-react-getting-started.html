Vite로 React 프로젝트 시작하기 — CRA 대신 Vite를 쓰는 이유

2026. 8. 31. · 프론트엔드

한 줄 요약 — Vite는 개발 중 네이티브 ESM을 활용해 CRA보다 체감 속도가 훨씬 빠르며, 환경변수는 VITE_ 접두사와 import.meta.env로 접근합니다.

 

왜 지금 Vite인가

몇 년 전까지만 해도 React 프로젝트를 시작하면 create-react-app이 정석이었습니다. 하지만 CRA는 유지보수가 사실상 중단됐고, 프로젝트가 커질수록 개발 서버와 HMR 속도가 눈에 띄게 느려진다는 문제가 있었습니다. Vite는 개발 중 번들링 없이 브라우저의 네이티브 ES 모듈을 그대로 활용해 체감 속도 차이가 큽니다.

 

CRA와 Vite 핵심 차이
항목 CRA Vite
개발 서버 시작 프로젝트 클수록 느려짐 거의 즉시(ESM 기반)
유지보수 사실상 중단 활발히 개발 중
설정 커스터마이징 eject 필요(비가역적) vite.config.js로 간단히 확장

 

예제 — 프로젝트 생성부터 실행까지
# 1. 프로젝트 생성
npm create vite@latest my-app -- --template react-ts

# 2. 의존성 설치
cd my-app
npm install

# 3. 개발 서버 실행
npm run dev

npm run dev를 실행하면 몇 초 안에 로컬 서버가 뜹니다. App.tsx를 수정하고 저장하면 새로고침 없이 즉시 반영됩니다.

 

자주 막히는 설정 — 환경변수

CRA는 REACT_APP_ 접두사를 요구했지만, Vite는 VITE_ 접두사를 써야 하고 접근 방식도 다릅니다.

// .env
VITE_API_URL=https://api.example.com

// 코드에서 사용
const apiUrl = import.meta.env.VITE_API_URL;

process.env가 아니라 import.meta.env를 쓴다는 점을 놓치면 값이 undefined로 나와 한참 헤매게 됩니다.

 

실무 포인트

기존 CRA 프로젝트를 억지로 마이그레이션할 필요는 없습니다. 안정적으로 돌아가는 프로젝트라면 신규 프로젝트부터 Vite를 적용하는 것이 현실적입니다.

주의 — 절대경로 import(@/components/...)를 쓰려면 vite.config.js의 resolve.alias와 tsconfig.json의 paths를 함께 맞춰야 합니다. 하나만 설정하면 에디터에서는 되는데 빌드가 실패합니다.
