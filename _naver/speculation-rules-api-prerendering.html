Speculation Rules API로 다음 페이지 미리 가져오기(Prerendering)

프론트엔드

한 줄 요약 — 클릭 전에 다음 페이지를 완전히 렌더링해두는 prerender로 MPA에서도 SPA급 체감 속도를 얻는 방법과 안전장치를 정리했습니다.

 

왜 지금 Speculation Rules API를 다시 봐야 하는가

전통적인 MPA는 링크를 클릭할 때마다 새 페이지를 처음부터 요청해 느립니다. rel=prefetch는 파일만 미리 받을 뿐 렌더링해두지는 않아 한계가 있었습니다. Speculation Rules API는 클릭 전에 다음 페이지를 백그라운드에서 통째로 미리 렌더링해 클릭 즉시 완성된 페이지를 보여줍니다.

 

Prefetch와 Prerender는 완전히 다른 수준의 작업이다

prefetch는 HTML만 미리 다운로드합니다. prerender는 파싱·CSS 적용·JS 실행까지 완료해 완전히 렌더링된 페이지를 백그라운드에 만들어둡니다. 클릭 시 이미 완성된 결과를 스왑하듯 보여줍니다.

모드 수행 작업 체감 속도
prefetch HTML만 미리 다운로드 중간
prerender 파싱+렌더링+JS 실행 매우 큼

 

예측 규칙과 안전장치로 낭비되는 프리렌더를 줄인다

모든 링크를 프리렌더하면 낭비가 심하고, 로그아웃·결제 같은 부작용 페이지를 실수로 실행할 위험도 있습니다. CSS 선택자나 URL 패턴으로 규칙을 좁히고, document.prerendering으로 현재 프리렌더 상태인지 확인해 애플리케이션이 부작용을 막을 수 있습니다.

예제 — 문서 규칙과 조건부 실행 코드
<script type="speculationrules">
{
  "prerender": [
    { "where": { "selector_matches": ".product-card a" }, "eagerness": "moderate" }
  ],
  "prefetch": [
    { "urls": ["/help", "/faq"], "eagerness": "conservative" }
  ]
}
</script>

<script>
if (document.prerendering) {
  document.addEventListener('prerenderingchange', () => {
    sendAnalyticsPageView();
  }, { once: true });
} else {
  sendAnalyticsPageView();
}
</script>

 

실무 포인트

분석·로깅 코드는 반드시 document.prerendering으로 가드하세요. 빠뜨리면 보지도 않은 페이지가 페이지뷰로 잘못 집계됩니다.

부작용이 있는 URL은 프리렌더 규칙에서 명시적으로 제외하세요. GET 요청이 상태를 바꾸는 페이지가 있다면 이 기회에 먼저 고쳐야 합니다.

주의 — eagerness 설정을 트래픽과 서버 부하에 맞춰 조정하세요. 지나치게 적극적인 프리렌더링은 클릭되지 않는 페이지까지 서버 요청을 늘립니다.
