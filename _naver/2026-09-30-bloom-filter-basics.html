블룸 필터가 뭔가요 — '없는 건 확실히' 알려주는 자료구조

시스템 디자인

한 줄 요약 — 블룸 필터는 적은 메모리로 "이 값이 확실히 없다"를 판정해 DB 헛조회를 줄이며, "있다"는 불확실합니다.

 

"이 값이 있나?"를 매번 DB에 물으면 느리다

"이미 쓰는 아이디인가?"를 매번 DB에서 확인하면 부하가 큽니다. 특히 대부분이 "없는" 값이면 헛조회가 많죠. 블룸 필터는 적은 메모리로 "확실히 없다"를 빠르게 판정합니다. "없다"고 하면 진짜 없으니 DB를 안 봐도 됩니다.

 

핵심 특징
답 의미
"없다" 100% 확실 (조회 불필요)
"있다(아마)" 불확실 (DB 확인 필요)

 

어떻게 동작하나
값을 여러 해시로 돌려 비트 배열 여러 자리를 1로 켠다.
"apple" 추가 -> 3, 7, 11번 비트 ON
조회 "banana" -> 2, 7, 11번 확인
  하나라도 0 -> "확실히 없음"
  모두 1     -> "아마 있음"

 

실무 포인트

"DB에 없는 키"를 계속 조회하는 캐시 관통을 블룸 필터로 먼저 걸러 부하를 줄입니다(Redis 등). 삭제가 어려워 필요하면 카운팅 블룸 필터를 씁니다. 비트 배열 크기·해시 개수는 데이터 규모에 맞게 정합니다.

주의 — 비트 배열이 작으면 메모리는 아끼지만 "거짓 양성"(없는데 있다고 함)이 늘어납니다. 예상 데이터 수에 맞춰 크기를 정하세요.
