Next.js Hydration 에러 해결하기 — 서버와 클라이언트가 다를 때

2026. 9. 2. · 프론트엔드

한 줄 요약 — 서버가 만든 HTML과 브라우저의 첫 렌더링 결과가 다를 때 발생하며, 시간·랜덤 값·window 접근이 가장 흔한 원인입니다.

 

이 에러가 정확히 무엇을 말하는가

Next.js는 서버에서 HTML을 미리 만들어 보내고, 브라우저에서 React가 이벤트 핸들러를 붙이는 하이드레이션 과정을 거칩니다. 이때 두 결과가 다르면 React가 어느 쪽을 믿어야 할지 몰라 에러를 냅니다.

 

흔한 원인 4가지
원인 예시
시간 관련 값 new Date()를 렌더링에 직접 사용
랜덤 값 Math.random()으로 key 생성
브라우저 API 렌더링 중 window.innerWidth 읽기
localStorage 서버에는 없으므로 값이 다름

 

해결 방법
// 방법 1: useEffect로 클라이언트에서만 렌더링
useEffect(() => {
  setTime(new Date().toLocaleTimeString());
}, []);
if (!time) return <p>--:--:--</p>;

// 방법 2: dynamic import로 SSR 제외
const ClientOnlyClock = dynamic(() => import('./Clock'), { ssr: false });

ssr: false로 지정하면 그 컴포넌트는 서버에서 렌더링하지 않으므로 애초에 불일치가 발생하지 않습니다.

 

실무 포인트

로그인 상태를 localStorage에서 읽는 구조가 대표적 함정입니다. 서버는 항상 로그아웃 상태로 렌더링하므로 불일치가 생깁니다. 쿠키 기반 인증으로 바꾸면 해결됩니다.

주의 — suppressHydrationWarning으로 경고만 숨기는 것은 근본 해결이 아닙니다. 원인을 모른 채 남용하면 실제 UI 버그를 숨기게 됩니다.
