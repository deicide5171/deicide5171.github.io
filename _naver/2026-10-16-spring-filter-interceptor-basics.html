필터와 인터셉터 차이가 뭔가요 — 요청을 가로채는 두 지점

백엔드

한 줄 요약 — 필터는 스프링 바깥 넓은 범위, 인터셉터는 스프링 MVC 안 컨트롤러 근처에서 요청을 가로챕니다.

 

요청 전후에 공통 작업을 넣고 싶다

인증 확인·로깅·검증처럼 여러 요청에 공통 작업을 컨트롤러마다 넣지 않고 흐름의 한 지점에서 가로챕니다. 스프링엔 이런 지점이 둘, 필터와 인터셉터가 있습니다.

 

필터 vs 인터셉터
구분 필터 인터셉터
소속 서블릿(밖) 스프링 MVC
예 인코딩·CORS·보안 인증·로깅·권한

 

요청 흐름
요청 -> [필터] -> DispatcherServlet -> [인터셉터]
     -> 컨트롤러 -> [인터셉터] -> [필터] -> 응답
필터가 바깥, 인터셉터가 컨트롤러에 가까움

 

실무 포인트

어떤 핸들러가 실행될지 같은 스프링 정보가 필요하면 인터셉터, 인코딩·CORS·전체 로깅처럼 넓은 범위엔 필터를 씁니다(Spring Security도 필터 기반). 같은 작업을 양쪽에 중복하지 마세요.

주의 — 같은 로직을 필터·인터셉터 양쪽에 넣으면 실행 순서와 책임이 헷갈립니다. 성격에 맞는 한쪽에만 두세요.
