부모를 고르는 CSS가 왔다 — :has() 선택자 실전 활용 패턴

2026. 8. 30. · 프론트엔드

한 줄 요약 — :has() 선택자는 자손·형제·자기 자신의 상태를 조건으로 삼아 요소를 선택하는 관계 조건자로, 예전엔 JS가 필요했던 조건부 스타일링 상당수를 순수 CSS로 대체합니다.

 

부모를 고를 수 없었던 CSS

CSS는 오랫동안 부모를 고를 수 없는 언어였습니다. 카드가 에러 클래스를 가진 자식을 포함할 때 카드 자체의 테두리 색을 바꾸고 싶어도, CSS 선택자는 항상 자손·형제 방향으로만 뻗어나갈 수 있었고 위쪽(부모) 방향으로는 갈 수 없었습니다. 그래서 이런 요구가 생길 때마다 MutationObserver나 이벤트 리스너로 자바스크립트가 부모에 클래스를 붙이는 우회로를 써야 했습니다.

:has() 의사 클래스가 주요 브라우저에 전부 안착하면서 이 제약이 사라졌습니다. 흔히 "부모 선택자"라고 불리지만 실제로는 그보다 훨씬 일반적인, 조건부 매칭 도구입니다.

 

핵심 개념 1 — :has()는 "포함하면"이 아니라 "관계가 성립하면"입니다

:has()의 본질은 이 요소를 기준으로, 괄호 안 선택자가 매칭되는 무언가가 이 요소와 특정 관계에 있으면 선택한다는 관계 조건자입니다. 괄호 안에는 자손 결합자뿐 아니라 형제 결합자(~, +)도 쓸 수 있어서, "부모 선택자"라는 별명이 오히려 이 기능의 절반만 설명합니다.

/* 1) 자손 관계: 에러 메시지를 포함한 폼 그룹만 강조 */
.form-group:has(.error-message) {
  border-left: 3px solid #d0413b;
}

/* 2) 형제 관계: 체크된 체크박스 바로 다음에 오는 라벨 강조 */
.option:has(input:checked) + .option-label {
  font-weight: bold;
}

/* 3) 자기 자신 상태 결합: 포커스된 입력을 담은 필드셋 강조 */
fieldset:has(:focus-visible) {
  outline: 2px solid #2e9e63;
}

세 번째 예시가 특히 강력합니다 — :has(:focus-visible)처럼 다른 의사 클래스와 조합하면, 자바스크립트 없이 이 컨테이너 안 어딘가에 포커스가 있다는 상태 자체를 CSS가 직접 판정할 수 있습니다.

 

 

핵심 개념 2 — 실전 패턴: JS 없이 되던 것과 안 되던 것

:has() 이전에도 체크박스 해킹 같은 트릭으로 형제를 스타일링할 수 있었지만 항상 뒤에 오는 형제로만 가능했고, 부모나 앞쪽 형제를 건드리려면 JS가 필요했습니다. :has()는 이 방향 제약을 없앴습니다.

요구사항 :has() 이전 :has()로
자식에 이미지가 있는 카드만 다른 레이아웃 JS로 클래스 토글 .card:has(img)
폼 전체에 미입력 필수 필드 존재 여부 표시 JS 유효성 검사 form:has(:required:invalid)

특히 폼 유효성 검사 표시는 :has()가 가장 빛을 발하는 영역입니다. :invalid, :required 같은 상태 의사 클래스와 결합하면, 자바스크립트 유효성 검사 라이브러리 없이도 필수 항목 중 하나라도 비어 있으면 경고 테두리를 표시하는 것까지 순수 CSS로 표현할 수 있습니다.

 

핵심 개념 3 — 성능 특성과 남용 주의

:has()는 편리하지만 공짜가 아닙니다. 브라우저는 :has()가 포함된 규칙을 만나면 그 선택자가 매칭되는지 확인하기 위해 대상 요소의 하위 트리(또는 형제)를 탐색해야 합니다. 즉 일반적인 자손 선택자보다 계산 비용이 높고, DOM이 변경될 때마다 재평가 범위가 넓어질 수 있습니다. 대규모 리스트의 각 항목에 :has()를 거는 패턴은 스타일 재계산 비용이 눈에 띄게 늘어날 수 있어, 명확히 경계가 좁은 컨테이너 단위로 범위를 한정해 쓰는 것이 안전합니다.

 

예제 — 이미지 유무에 따른 카드 레이아웃 분기
.card {
  display: flex;
  flex-direction: column;
  padding: 16px;
}

.card:has(img) {
  display: grid;
  grid-template-columns: 120px 1fr;
  gap: 12px;
}

/* 자식 입력이 비어있지 않은 검색창에만 지우기 버튼 표시 */
.search-box:has(input:not(:placeholder-shown)) .clear-button {
  display: inline-flex;
}

 

실무 포인트

폴백을 완전히 생략하지 마세요. 최신 브라우저는 대부분 :has()를 지원하지만, 오래된 브라우저 지원이 필요하다면 @supports selector(:has(a))로 지원 여부를 감지해 JS 폴백을 조건부로 로드하는 편이 안전합니다.

선택자 범위를 좁게 유지하세요. 페이지 전체에 걸리는 넓은 선택자보다는 영향 범위가 국소적인 컨테이너 단위 선택자가 재계산 비용과 디버깅 난이도 양쪽에서 유리합니다.

주의 — :has()로 상태를 "읽을" 수는 있어도 상태를 "만들" 수는 없습니다. 상태 변경 자체는 여전히 사용자 상호작용이나 JS로 일어나야 하고, :has()는 그 상태가 이미 DOM에 반영된 뒤 조건으로 스타일을 분기하는 역할만 합니다.
