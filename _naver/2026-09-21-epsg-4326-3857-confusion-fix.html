웹지도 좌표가 어긋날 때 — EPSG:4326과 3857 혼동 잡는 법

GIS

한 줄 요약 — 마커가 지도 밖에 찍히는 문제의 대부분은 EPSG:4326(위경도)과 EPSG:3857(웹 메르카토르) 좌표계 혼동 때문입니다.

 

왜 거의 모두가 한 번은 겪는가

위경도 좌표를 정확히 입력했는데 마커가 저 멀리 찍히거나 지도가 회색 화면으로 렌더링되지 않는 증상은, 거의 항상 두 좌표계를 혼동해서 생깁니다. EPSG:4326은 위도·경도를 도 단위로 표현하며 GPS와 GeoJSON의 기본 좌표계입니다. EPSG:3857은 구면 지구를 평면으로 투영한 미터 단위 좌표계로, 대부분의 웹 지도 라이브러리 내부 렌더링에 쓰입니다.

 

서울시청은 EPSG:4326으로 [126.978, 37.566]이지만 EPSG:3857로 변환하면 [14135099, 4518234]처럼 훨씬 큰 숫자가 됩니다. 이 둘을 뒤섞으면 마커가 지도 밖으로 날아갑니다.

OpenLayers 명시적 지정 필요

OpenLayers는 다릅니다. View에 설정된 투영법을 그대로 따르므로, 명시적으로 변환하지 않으면 위경도 값을 그대로 미터 좌표로 착각해 렌더링합니다.

import { fromLonLat } from 'ol/proj';

const seoulCityHallLonLat = [126.978, 37.566];
const seoulCityHallMercator = fromLonLat(seoulCityHallLonLat);

fromLonLat()은 EPSG:4326 좌표를 View의 기본 투영법인 EPSG:3857로 변환해줍니다. GeoJSON을 불러올 때도 readFeatures()의 featureProjection 옵션을 지정해야 좌표가 어긋나지 않습니다.

주의 — 국내 공공데이터는 EPSG:5179, 5181 같은 국가 좌표계로 제공되는 경우가 많습니다. EPSG:4326으로 착각하고 바로 쓰면 좌표가 한반도 밖으로 튑니다. proj4로 변환 정의를 등록한 뒤 변환하세요.

 

실무 포인트

GeoJSON 표준은 [경도, 위도] 순서지만 국내 API는 [위도, 경도] 순서를 쓰는 경우가 많으니 순서를 반드시 확인하세요. 디버깅할 때는 좌표 자릿수부터 확인하면, 두 자리대 숫자는 EPSG:4326, 일곱 자리 이상 큰 숫자는 EPSG:3857일 가능성이 높습니다.
