웹사이트 다크모드 제대로 구현하기 — 깜빡임(FOUC) 없이 적용하는 법

프론트엔드

한 줄 요약 — 다크모드 깜빡임은 테마 스크립트가 첫 페인트보다 늦게 실행되기 때문입니다. head 최상단의 동기 인라인 스크립트로 렌더링 전에 테마를 미리 결정하면 해결됩니다.

 

왜 새로고침마다 하얗게 번쩍일까

다크모드 토글 버튼을 만들어 붙였더니 기능은 잘 동작하는데, 페이지를 새로고침할 때마다 순간적으로 흰 배경이 번쩍였다가 다크 테마로 바뀌는 현상을 겪게 됩니다. 원인은 대부분 테마를 적용하는 자바스크립트가 너무 늦게 실행되기 때문입니다.

일반적인 React나 Vue 앱에서는 컴포넌트가 마운트된 뒤에야 useEffect 안에서 localStorage를 읽어 테마를 적용합니다. 하지만 브라우저는 그보다 훨씬 먼저 기본(라이트) 스타일로 첫 페인트를 그려버립니다. 그 사이 짧은 순간이 "흰 화면 번쩍임"으로 보이는 것입니다.

 

 

핵심 개념 1 — 테마 결정은 렌더링보다 먼저 일어나야 한다

해법은 프레임워크 생명주기를 기다리지 않고, head 안에 인라인 스크립트를 넣어 첫 렌더링 전에 테마를 결정하는 것입니다. 브라우저는 head의 동기 스크립트를 만나면 실행이 끝날 때까지 이후 파싱과 렌더링을 멈춥니다. 이 짧은 시간을 이용해 테마 클래스를 미리 붙이면 첫 페인트부터 올바른 테마로 그려집니다.

<script>
  // 반드시 stylesheet보다 먼저, head 최상단에 위치
  (function () {
    const saved = localStorage.getItem('theme');
    const prefersDark = window.matchMedia('(prefers-color-scheme: dark)').matches;
    const theme = saved || (prefersDark ? 'dark' : 'light');
    document.documentElement.setAttribute('data-theme', theme);
  })();
</script>

 

핵심 개념 2 — 저장된 값과 시스템 설정을 구분한다

사용자가 직접 테마를 고른 적이 없다면 시스템 설정(prefers-color-scheme)을 따라야 하고, 한 번이라도 직접 선택했다면 그 선택을 시스템 설정보다 우선해야 합니다. 이 우선순위를 구분하지 않으면 사용자가 라이트모드를 골랐는데 OS 설정을 바꾸는 순간 사이트도 따라 바뀌는 예상 밖의 동작이 생깁니다.

 

예제 — CSS 변수와 토글 연결
:root { --bg: #ffffff; --text: #1a1a1a; }
[data-theme="dark"] { --bg: #121212; --text: #e8e8e8; }
body { background-color: var(--bg); color: var(--text); }

function toggleTheme() {
  const root = document.documentElement;
  const next = root.getAttribute('data-theme') === 'dark' ? 'light' : 'dark';
  root.setAttribute('data-theme', next);
  localStorage.setItem('theme', next);
}

 

흔한 실수
실수 결과
테마 스크립트를 body 하단에 둠 렌더링이 먼저 끝나 여전히 깜빡임
SSR에서 서버가 항상 라이트로 렌더링 하이드레이션 후 테마 바뀌며 깜빡임

 

실무 포인트

인라인 스크립트는 최소한으로 압축하세요. head에 들어가는 이 스크립트는 렌더링을 차단하므로 테마 결정 로직만 담아 실행 시간을 최소화해야 합니다.

CSS 변수 기반 설계가 클래스 기반보다 유지보수하기 쉽습니다. 커스텀 프로퍼티 값만 테마별로 바꾸면 컴포넌트 CSS는 그대로 재사용됩니다.

주의 — SSR 환경에서는 서버가 클라이언트의 localStorage를 알 수 없다는 근본적인 제약이 있습니다. 쿠키에 테마 값을 함께 저장해 서버 렌더링 시점에도 참조하는 절충이 필요합니다.
