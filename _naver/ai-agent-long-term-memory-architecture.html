AI 에이전트의 장기 기억 설계 — 대화 요약과 벡터 저장을 결합한 메모리 아키텍처

AI

한 줄 요약 — 모든 대화를 저장하는 대신 단기·중기·장기 세 계층으로 나눠 압축·조회하는 에이전트 메모리 아키텍처를 정리했습니다.

 

왜 지금 에이전트 메모리 설계를 다시 봐야 하는가

여러 세션에 걸쳐 관계를 이어가는 AI 에이전트는 이전 대화를 기억해야 합니다. 지난 대화 전체를 매번 프롬프트에 넣으면 컨텍스트 윈도우 한계와 토큰 비용 문제에 부딪힙니다. 게다가 모든 발화가 똑같이 중요하지 않습니다. 장기 기억 아키텍처는 무엇을 어떤 형태로 압축해 저장할지를 계층적으로 설계합니다.

 

단기 기억과 장기 기억을 분리하는 계층 구조

최근 대화는 원문 그대로 단기 기억(working memory)으로 유지합니다. 창을 벗어난 대화는 요약해 중기 기억(episodic summary)으로 보관하고, 추출된 구조화된 사실(선호도, 과거 결정 등)은 장기 기억(semantic memory)에 별도 저장합니다.

 

무엇을 요약하고 무엇을 그대로 남길지 결정하는 기준

롤링 요약은 오래된 대화 블록을 몇 문장으로 압축하고 원문은 버립니다. 명시적 사실 추출은 경량 모델로 "기억해야 할 구조화된 사실이 있는가"를 판단해 즉시 장기 기억에 저장합니다. 이렇게 하면 중요한 사실은 대화가 요약·삭제돼도 안전하게 남습니다.

계층 저장 형태 유지 기간
단기 기억 원문 대화 최근 N턴
중기 기억 요약 텍스트 세션~수 주
장기 기억 구조화된 사실 무기한

 

예제 — 사실 추출과 저장 스케치
def extract_and_store_facts(conversation_turn, memory_store, user_id):
    prompt = f"""
    다음 대화에서 사용자에 대해 장기적으로 기억해야 할 사실이 있으면
    JSON 배열로 추출하라. 없으면 빈 배열을 반환하라.
    대화: {'{conversation_turn}'}
    """
    facts = call_lightweight_model(prompt)

    for fact in facts:
        if fact["confidence"] >= 0.7:
            memory_store.upsert(
                user_id=user_id,
                key=fact["key"],
                value=fact["value"],
            )

저비용 모델로 사실 추출만 수행해 비용을 크게 늘리지 않고도 중요 정보를 놓치지 않습니다.

 

실무 포인트

사실 추출에는 저비용 모델을 쓰고 confidence 임계치로 잡음을 걸러내세요. 모든 발화에서 추출하면 저장소가 오염됩니다.

장기 기억에는 출처와 타임스탬프를 함께 저장하세요. 사용자 선호가 바뀔 수 있으므로 시점 추적이 필요합니다.

주의 — 모든 응답에 장기 기억 전체를 넣지 말고 질의에 관련된 것만 검색해 넣으세요. 저장소가 커질수록 무관한 기억까지 매번 주입하면 Lost in the Middle 문제와 토큰 낭비를 동시에 유발합니다.
