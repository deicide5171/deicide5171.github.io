Node.js CPU 집약적 작업 처리하기 — Worker Threads로 이벤트 루프 지키기

백엔드

한 줄 요약 — Node.js의 논블로킹 I/O는 CPU 연산에는 적용되지 않으므로, 무거운 계산은 worker_threads로 별도 스레드에 위임해야 이벤트 루프가 막히지 않습니다.

 

왜 API 하나가 서버 전체를 멈추게 하는가

Node.js는 I/O 작업을 논블로킹으로 처리해 다른 요청을 막지 않지만, 이미지 리사이징이나 대용량 JSON 파싱처럼 CPU를 실제로 소모하는 연산은 예외입니다. 이런 작업이 실행되는 동안 이벤트 루프를 통째로 점유해, 서버로 들어오는 다른 모든 요청이 대기 상태에 걸립니다.

 

잘못된 접근 vs 올바른 접근

async/await을 붙여도 연산이 저절로 다른 스레드에서 실행되지 않습니다. async/await은 비동기 I/O를 다루는 문법일 뿐, CPU 연산 자체를 병렬화해주지 않습니다.

const { Worker } = require('worker_threads');

function resizeImageInWorker(filePath) {
  return new Promise((resolve, reject) => {
    const worker = new Worker('./resize-worker.js', { workerData: { filePath } });
    worker.on('message', resolve);
    worker.on('error', reject);
  });
}

Worker 스레드는 메인 스레드와 메모리를 공유하지 않고 메시지로 통신합니다. 무거운 연산이 Worker 안에서 실행되는 동안 메인 스레드의 이벤트 루프는 계속 다른 요청을 처리할 수 있습니다.

방법 적합한 상황
Worker Threads 단발성 CPU 작업, 긴밀한 통신
Child Process 완전 격리, 크래시 영향 차단
외부 큐(BullMQ) 오래 걸리는 작업, 재시도 필요

 

주의 — 아주 짧은 연산마다 매번 새 Worker를 생성하면 스레드 생성 비용이 오버헤드가 됩니다. 반복적인 무거운 작업은 piscina 같은 Worker 풀 라이브러리로 재사용하세요.

 

실무 포인트

Worker 간 데이터는 구조화 복제 알고리즘으로 직렬화되므로, 매우 큰 데이터를 자주 주고받으면 그 자체가 병목이 될 수 있습니다. SharedArrayBuffer로 복사 비용을 줄일 수 있습니다. Worker 내부의 처리되지 않은 예외는 error 이벤트로 전달되니 반드시 처리하세요.
