CTE(WITH)가 뭔가요 — 복잡한 쿼리를 읽기 쉽게 나누기

데이터베이스

한 줄 요약 — CTE(WITH)는 중간 결과에 이름을 붙여 복잡한 쿼리를 단계별로 정리하며, 재귀 조회에도 씁니다.

 

서브쿼리가 겹겹이 쌓여 읽기 힘들다

서브쿼리가 중첩되면 SQL이 괄호 지옥이 됩니다. CTE는 WITH 절로 중간 결과에 이름을 붙여 쿼리를 단계별로 정리합니다. 긴 식을 변수로 나누는 것과 비슷하죠.

 

서브쿼리 vs CTE
WITH cat_avg AS (
  SELECT category, AVG(price) AS avg_p
  FROM products GROUP BY category
)
SELECT * FROM cat_avg WHERE avg_p > 1000;
-- WITH 이름 AS (쿼리) 후 이름을 테이블처럼 사용

 

장점
장점 설명
가독성 단계마다 이름
재귀 WITH RECURSIVE로 계층

 

실무 포인트

복잡한 쿼리를 "집계 → 필터 → 조인"처럼 CTE로 쪼개면 읽기·디버깅이 편합니다. WITH RECURSIVE로 조직도·카테고리 트리 같은 계층을 조회합니다.

주의 — CTE가 항상 빠른 건 아닙니다. DB에 따라 최적화 경계로 취급돼 느려질 수 있으니 EXPLAIN으로 확인하세요.
