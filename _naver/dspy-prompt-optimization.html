프롬프트를 손으로 짜지 않는다 — DSPy로 보는 프롬프트 자동 최적화

2026. 8. 29. · AI

한 줄 요약 — DSPy는 프롬프트 문자열을 직접 쓰는 대신 입출력 시그니처와 파이프라인만 선언하면, 실제 프롬프트와 예시는 옵티마이저가 학습 데이터로 자동 탐색해 컴파일해주는 프로그래밍 모델입니다.

 

프롬프트, 언제까지 손으로 고치실 건가요

LLM 애플리케이션을 만들다 보면 반드시 겪는 순간이 있습니다. 모델을 바꾸거나 시스템 프롬프트에 문장 하나를 추가했더니 다른 부분의 출력 품질이 흔들리는 경우입니다. 프롬프트는 코드처럼 버전 관리는 되지만 컴파일도 타입 체크도 없는 텍스트 뭉치이기 때문입니다.

DSPy(Declarative Self-improving Python)는 이 문제를 프롬프트 엔지니어링이 아니라 프로그래밍 문제로 바꿔서 접근합니다. 개발자는 입력과 출력 시그니처를 선언하고 평가 지표를 정의하면, 실제 프롬프트 문자열과 few-shot 예시는 DSPy의 옵티마이저가 학습 데이터를 돌려가며 자동으로 탐색해 채워 넣습니다.

 

핵심 개념 1 — 시그니처와 모듈

DSPy에서 가장 먼저 하는 일은 프롬프트 문장을 쓰는 것이 아니라 시그니처(Signature)를 정의하는 것입니다. "질문과 문맥을 받아 답변을 낸다"처럼 입력·출력 필드와 의미를 선언한 명세로, 함수 시그니처와 비슷한 역할을 합니다. 이를 Predict, ChainOfThought, ReAct 같은 모듈에 감싸면, 모듈이 시그니처에 맞는 실제 프롬프트를 내부적으로 생성해 LLM을 호출합니다.

핵심은 개발자가 "생각의 사슬을 유도하는 문장을 어떻게 쓸지" 고민할 필요가 없다는 점입니다. RAG 파이프라인이라면 검색·문맥 정리·답변 생성을 각각 시그니처를 가진 모듈로 선언하고 파이썬 코드로 연결하기만 하면 됩니다.

 

핵심 개념 2 — 옵티마이저가 프롬프트를 컴파일합니다

DSPy의 차별점은 옵티마이저에 있습니다. 학습용 입력 몇 개와 평가 지표 함수를 받아, 모듈이 사용할 지시문 문장과 few-shot 예시 조합을 자동으로 탐색해 점수가 가장 높은 조합을 찾아냅니다. BootstrapFewShot은 모델이 스스로 생성한 성공적 추론 과정을 예시로 재활용하고, MIPROv2는 지시문 후보와 예시 조합을 베이지안 탐색으로 함께 최적화합니다.

이 과정을 "컴파일"이라 부르는 이유는, 개발 중엔 구조만 신경 쓰다가 배포 직전 옵티마이저를 한 번 돌려 최적화된 프롬프트 세트를 산출물로 얻기 때문입니다. 모델을 교체해도 프롬프트를 손으로 다시 쓰는 대신 같은 데이터로 재컴파일하면 됩니다.

구분 수동 프롬프트 엔지니어링 DSPy
산출물 프롬프트 문자열 시그니처 + 파이프라인 코드
모델 교체 시 프롬프트 재작성 같은 데이터로 재컴파일
품질 검증 눈으로 비교 평가 지표 함수로 정량 비교

 

핵심 개념 3 — 평가 지표 설계가 성패를 가릅니다

옵티마이저가 아무리 정교해도 평가 지표(metric)가 부실하면 엉뚱한 방향으로 최적화됩니다. 지표는 예측 출력을 받아 점수를 반환하는 함수로, 단순 문자열 일치부터 LLM-as-judge까지 자유롭게 구현할 수 있습니다. 요약 태스크라면 유사도 지표만으로는 그럴듯하지만 사실과 다른 요약을 걸러내지 못하므로, 사실성 검증 로직을 지표에 넣어야 합니다.

지표가 실제 목표를 제대로 반영하지 못하면 옵티마이저는 그 지표에서만 높은 점수를 내는 프롬프트를 찾아내고, 실제 프로덕션 품질과는 괴리가 생깁니다.

 

예제 — 간단한 RAG 파이프라인 컴파일
import dspy

# 1. 시그니처 정의 - 입력/출력 필드만 선언
class GenerateAnswer(dspy.Signature):
    context = dspy.InputField(desc="검색된 관련 문서")
    question = dspy.InputField()
    answer = dspy.OutputField(desc="간결한 답변")

# 2. 모듈 파이프라인 정의
class RAG(dspy.Module):
    def __init__(self, retriever):
        super().__init__()
        self.retrieve = retriever
        self.generate = dspy.ChainOfThought(GenerateAnswer)

    def forward(self, question):
        context = self.retrieve(question).passages
        return self.generate(context=context, question=question)

# 3. 평가 지표 - 문맥 근거 없는 답변은 감점
def metric(example, pred, trace=None):
    grounded = pred.answer_supported_by(example.context)
    return 1.0 if grounded else 0.0

# 4. 옵티마이저로 컴파일
optimizer = dspy.MIPROv2(metric=metric, auto="medium")
compiled_rag = optimizer.compile(RAG(retriever=my_retriever), trainset=train_examples)

 

실무 도입 시 이것만은 챙기세요
1. 작은 학습 세트로 시작하세요 — 옵티마이저는 학습 예시 30~50개만으로도 효과를 냅니다. 수백 개를 모으려다 도입이 미뤄지는 것보다 작게 시작해 늘리는 편이 낫습니다.
2. 컴파일 결과물은 별도로 버전 관리하세요 — 최적화된 프롬프트·예시 조합은 JSON으로 저장되므로 모델 아티팩트처럼 버전을 매겨 배포 파이프라인에 태우세요.
3. 지표 함수부터 리뷰하세요 — 결과가 이상하면 먼저 의심할 곳은 프롬프트가 아니라 평가 지표입니다.

 

마무리 — 3줄 요약

① DSPy는 프롬프트 문자열 대신 입출력 시그니처와 파이프라인을 코드로 선언하고, 실제 프롬프트는 옵티마이저가 학습 데이터로 탐색해 컴파일합니다.
② BootstrapFewShot, MIPROv2 같은 옵티마이저는 지시문 문장과 few-shot 예시 조합을 평가 지표 점수 기준으로 자동 탐색합니다.
③ 옵티마이저의 품질은 결국 평가 지표 설계에 좌우되므로, 지표가 실제 목표를 반영하지 못하면 프로덕션 품질과 괴리가 생깁니다.
