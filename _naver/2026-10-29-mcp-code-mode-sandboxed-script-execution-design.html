"이 작업, 도구 호출 500번 말고 한 번에 처리해주세요" — MCP Code Mode가 바꾸는 에이전트 실행 모델

AI

한 줄 요약 — 표 500행을 도구 호출로 하나씩 처리하면 느리고 비싸다는 요구는, 모델이 직접 도구를 호출하는 방식 대신 코드를 짜서 샌드박스에서 실행하게 하는 MCP Code Mode로 이어집니다. 토큰 절감 주장과 실제 반론, 샌드박스·자격증명 재설계까지 정리했습니다.

 

왜 지금 이 문제가 불거지는가

"이 스프레드시트 500행을 하나씩 검토해서 CRM에 반영해주세요"라는 요구를 에이전트에게 맡기면, 보통 모델은 행 하나마다 도구 호출 턴을 하나씩 만듭니다. 도구를 부르고, 결과를 컨텍스트에 받고, 다음 행으로 넘어가는 과정을 500번 반복합니다. 턴마다 전체 도구 스키마가 컨텍스트에 다시 얹히고, 중간 결과도 전부 모델이 들고 있어야 하니 토큰 비용과 지연이 행 수에 비례해서 불어납니다.

Cloudflare의 Kenton Varda와 Sunil Pai가 2025년 9월 26일 공개한 "Code Mode: the better way to use MCP"는 이 문제를 다른 축에서 풀었습니다. 모델이 매 단계 JSON 도구 호출 턴을 주고받는 대신, 도구를 TypeScript 함수처럼 보여주고 전체 로직을 담은 스크립트 하나를 작성하게 한 뒤, 그 스크립트를 샌드박스에서 실행해 최종 결과만 모델 컨텍스트로 돌려주는 방식입니다. Cloudflare는 2026년 3월 26일 MCP Portal에 이 기능을 정식으로 올렸고, Anthropic도 비슷한 시기에 유사한 패턴을 공개했습니다.

 

전체 시스템에서의 위치

직접 호출 모델은 모델 → 도구 호출(JSON) → MCP 서버 → 결과 반환이라는 루프를 필요한 횟수만큼 반복합니다. Code Mode는 모델이 스크립트를 한 번 작성하면, 그 스크립트가 샌드박스 안에서 도구 함수들을 프로그램처럼 반복 호출하고, 최종 요약만 모델에게 1회 전달됩니다. 자격증명은 샌드박스 안에 둘 수 없으므로 별도의 HTTP 브릿지로 분리해, 스크립트는 브릿지에 요청만 보내고 다운스트림 인증은 브릿지가 전담합니다.

 

선택의 트레이드오프
기준 직접 도구 호출 Code Mode
반복 작업 비용 호출 횟수만큼 왕복·컨텍스트 적재 샌드박스 내부 루프, 왕복 1회
도구 스키마 노출 전체를 시스템 프롬프트에 상주 필요 시 타입 파일로 온디맨드 로드
실행 신뢰 경계 서버가 각 호출을 개별 검증 모델이 쓴 코드를 실행 — 진짜 샌드박스 필수
적합한 경우 단발성 호출(티켓 1건 생성 등) 대량 루프·조건 분기가 필요한 작업

 

Code Mode가 "항상 더 싸다"는 것은 아직 확정된 사실이 아닙니다. 여러 벤치마크가 65~98%의 토큰 절감을 보고했지만, 2026년 6월 한 내부 스파이크 테스트에서는 토큰 사용량은 뒤섞이고 턴 수는 오히려 순증가하는 결과가 나왔습니다. 작업의 성격에 따라 결과가 갈립니다.

 

예제 코드:

// 샌드박스 안에서 모델이 작성·실행하는 스크립트 예시
import { crm, sheet } from "./tools";

const rows = await sheet.read("Q4-leads");
for (const row of rows) {
  if (row.status === "미검토") {
    await crm.upsertContact({ email: row.email, stage: "검토중" });
  }
}
// 중간 500번의 호출 결과는 샌드박스 안에만 머물고,
// 모델 컨텍스트에는 이 스크립트의 최종 요약만 돌아온다.

 

주의 — 모델이 작성한 코드를 그대로 실행하는 구조이므로 인프로세스 실행은 위험합니다. Firecracker·gVisor 같은 microVM이나 Workers isolate 같은 실제 격리 환경이 전제 조건이며, 자격증명은 반드시 샌드박스 바깥의 브릿지로 분리해야 합니다. 전체 워크로드를 한 번에 전환하지 말고, 반복이 많은 배치 작업부터 토큰·턴 수를 실측하세요.

 

정리

Code Mode는 도구 개수 문제가 아니라 도구 호출 모델 자체를 직접 호출에서 코드 생성·샌드박스 실행으로 바꾸는 설계입니다. 토큰 절감 효과는 작업 성격에 따라 갈리므로 반복이 많은 워크로드부터 실측해야 하고, 모델이 쓴 코드를 실행하는 순간 진짜 샌드박스와 자격증명 분리가 전제 조건이 됩니다. 단발성 호출에는 여전히 직접 호출이 더 단순하고 저렴합니다.
