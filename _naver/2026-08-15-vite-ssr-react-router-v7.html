Vite 위에서 SSR 얻기 — React Router v7과 TanStack Start

2026. 8. 15. · 웹개발

한 줄 요약 — "Vite는 클라이언트 전용"이라는 인식이 옅어지고 있습니다. React Router v7의 프레임워크 모드와 TanStack Start가 Vite 위에서 SSR을 제공하기 시작하면서, Next.js 대신 선택할 수 있는 실용적인 대안이 생겼습니다.

 

왜 지금 이 이야기가 나올까요

몇 년 전까지는 "빠른 번들러가 필요하면 Vite, SSR이 필요하면 Next.js"라는 구분이 거의 상식처럼 통했습니다. 하지만 이 구분이 점점 흐려지고 있습니다. Remix 팀이 React Router에 합류하면서 나온 React Router v7의 프레임워크 모드는 Vite 위에서 SSR과 중첩 라우팅, 라우트 단위 데이터 로딩까지 제공합니다.

여기에 TanStack 진영의 TanStack Start까지 등장하면서, Vite 생태계 안에서도 풀스택 SSR 프레임워크를 선택할 수 있는 상황이 되었습니다. 이미 Vite 기반 SPA를 운영 중인 팀 입장에서는 전체 구조를 갈아엎지 않고도 서버 사이드 기능만 얹을 수 있다는 점이 큰 매력으로 다가옵니다.

 

핵심 개념 — 프레임워크 모드란 무엇인가요

React Router는 원래 클라이언트 라우팅 라이브러리였지만, v7부터는 프레임워크 모드를 함께 제공합니다. 이 모드를 켜면 Vite 플러그인이 라우트 구조를 읽어 서버 진입점과 클라이언트 번들을 함께 생성하고, 각 라우트의 데이터 로딩 함수를 서버에서 실행해 미리 채워줍니다. 사실상 Remix가 하던 역할을 React Router 본체가 흡수한 셈입니다.

TanStack Start는 접근 방식이 조금 다릅니다. TanStack Router의 타입 안전한 라우팅 위에 서버 함수와 SSR 진입점을 얹는 구조로, TanStack Query와의 결합을 전제로 설계되었습니다. 데이터 계층을 라우터에 통합할지, 별도 쿼리 라이브러리에 맡길지에서 두 프레임워크의 철학이 갈립니다.

 

Next.js와 비교하면 어떨까요
항목 Next.js React Router v7 / TanStack Start
번들러 Turbopack/Webpack 자체 Vite
데이터 로딩 서버 컴포넌트 중심 라우트 loader / 서버 함수
기존 SPA 이관 구조가 달라 부담 큼 라우트 단위 점진적 이관 가능
생태계 성숙도 매우 높음 성장 중(Remix 자산 계승)

 

정리하면 Next.js는 서버 컴포넌트를 중심에 둔 완결형 프레임워크로 기능이 풍부하지만 그만큼 학습 곡선과 락인도 큽니다. 반면 React Router v7과 TanStack Start는 이미 익숙한 Vite와 React 방식에 SSR만 얹는다는 실용주의적 접근에 가깝습니다.

 

설정 예제로 감을 잡아봅니다
// vite.config.ts
import { reactRouter } from "@react-router/dev/vite";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [reactRouter()],
});
// app/routes/products.$id.tsx
import type { LoaderFunctionArgs } from "react-router";
import { useLoaderData } from "react-router";

export async function loader({ params }: LoaderFunctionArgs) {
  const product = await getProduct(params.id);
  return { product };
}

export default function ProductPage() {
  const { product } = useLoaderData<typeof loader>();
  return <h1>{product.name}</h1>;
}

기존 라이브러리 모드 SPA에서 넘어온다면, 라우트 설정 파일을 추가하고 각 컴포넌트에 데이터 로딩 함수를 붙이는 순서로 단계적 이관이 가능하다는 점이 특징입니다.

 

도입 전 이것만은 챙기세요
1. 배포 타깃을 먼저 정하세요 — Node, Cloudflare Workers 등 어댑터별로 지원 범위와 성숙도가 다르니 실제 환경에서 먼저 검증하는 것이 안전합니다
2. 서버 컴포넌트는 없습니다 — 두 프레임워크 모두 React 서버 컴포넌트를 기본 전제로 하지 않으므로, RSC가 꼭 필요하다면 Next.js가 아직 유리합니다
3. 부가 기능은 직접 구성해야 합니다 — 미들웨어, 이미지 최적화, 캐싱 전략 등은 Next.js만큼 갖춰지지 않은 부분이 있습니다
4. 점진적 도입을 우선 검토하세요 — 완전 전환보다 기존 Vite SPA에 라우트 단위로 SSR을 붙여나가는 경로가 위험 부담이 적습니다

 

마무리 — 3줄 요약

① React Router v7의 프레임워크 모드와 TanStack Start는 Vite 위에서 SSR과 데이터 로딩을 제공하는 실용적 대안으로 떠오르고 있습니다.
② Next.js는 서버 컴포넌트 중심의 완결형 프레임워크로 기능은 풍부하지만 락인이 크고, 두 대안은 기존 Vite·React 자산을 살리며 점진적으로 SSR을 도입하기 좋습니다.
③ 배포 어댑터 성숙도와 서버 컴포넌트 필요 여부를 먼저 확인한 뒤, 라우트 단위로 점진적으로 도입하는 것을 추천드립니다.
