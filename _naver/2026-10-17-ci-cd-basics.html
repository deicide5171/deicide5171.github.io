CI/CD가 뭔가요 — 코드를 자동으로 빌드·테스트·배포하기

인프라

한 줄 요약 — CI/CD는 코드 변경을 자동으로 빌드·테스트(CI)하고 배포(CD)하는 자동화로, "푸시 → 검증 → 배포"가 흐르게 합니다.

 

배포를 손으로 하면 실수가 난다

코드를 고칠 때마다 사람이 직접 빌드·테스트·배포하면 느리고 실수가 잦죠. CI/CD는 이 과정을 자동화합니다. 코드를 올리면 자동으로 검증하고 배포까지 이어집니다.

 

CI와 CD
용어 의미
CI 자동 빌드·테스트로 통합
CD 검증된 코드 자동 배포

 

파이프라인 흐름
1. git push
2. CI: 빌드 -> 테스트 -> 통과 확인
3. CD: 통과하면 자동 배포
사람 개입 없이 흐른다

 

실무 포인트

CI의 핵심은 자동 테스트입니다(실패 시 배포 차단). 곧바로 운영 배포가 부담되면 마지막 배포만 사람이 승인(지속적 전달)하는 방식으로 시작하세요. GitHub Actions·GitLab CI가 널리 쓰입니다.

주의 — 테스트 없이 빌드만 하는 CI는 버그를 그대로 배포합니다. 파이프라인이 너무 느려도 개발자가 지치니 병렬화·캐시로 빠르게 유지하세요.
