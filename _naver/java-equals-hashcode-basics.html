자바 equals와 hashCode가 뭔가요 — 같음을 정의하는 규칙

2026. 9. 20. · 백엔드

한 줄 요약 — 값으로 같음을 판단하려면 equals를 재정의하고, hashCode도 반드시 함께 재정의합니다.

 

값이 같은데 다르다고 나온다

내용이 같은 두 객체를 ==나 기본 equals로 비교하면 false입니다. 기본 동작은 "같은 메모리 주소인가"를 보기 때문입니다. 값으로 비교하려면 equals를 재정의해야 합니다.

 

각자의 역할
메서드 역할
equals 논리적으로 같은지 판단
hashCode 정수 해시로 요약(HashMap 사용)

 

왜 함께 재정의하나
규칙: equals가 true면 hashCode도 같아야 함.

HashMap/Set은 hashCode로 버킷을 찾고
그 안에서 equals로 최종 비교.

equals만 재정의 → 같은 값이 다른 버킷 →
"못 찾는" 버그 발생

 

실무 포인트

equals에서 비교한 같은 필드로 hashCode도 계산합니다. Objects.equals·Objects.hash를 쓰면 간단합니다. record·롬복은 자동 생성해 실수를 줄여줍니다.

주의 — equals만 재정의하고 hashCode를 빼먹으면 HashSet·HashMap에서 객체를 못 찾는 버그가 납니다. 항상 세트로.
