시스템설계

한 줄 요약 — 멱등성은 같은 요청을 여러 번 보내도 결과가 한 번 처리한 것과 같은 성질이며, POST 작업에는 멱등성 키로 중복을 막습니다.

 

결제 버튼을 두 번 누르면 두 번 결제되나

응답이 늦어 다시 누르거나 네트워크 오류로 재시도되면 같은 요청이 두 번 도착해 결제가 두 번 될 수 있습니다. 멱등성이 보장되면 중복 요청이 와도 안전합니다.

 

HTTP 메서드의 멱등성
메서드 멱등한가
GET / PUT / DELETE 예
POST 아니오(호출마다 새로 생성)

POST는 멱등하지 않아 결제·주문 생성에 중복 방지가 특히 중요합니다.

 

멱등성 키로 중복 막기
1. 요청마다 고유 키 함께 보냄 (Idempotency-Key: abc-123)
2. 서버가 이미 처리한 키인지 확인
3. 처음이면 처리·저장, 이미 본 키면 저장된 결과 반환
-> 같은 키로 100번 와도 실제 처리는 한 번

 

실무 포인트

중복 요청은 "혹시 오는 것"이 아니라 "반드시 오는 것"으로 가정하고 설계해야 합니다. 결제·주문에는 멱등성 키가 거의 필수입니다.

주의 — 클라이언트가 재시도할 때 매번 새 키를 만들면 중복 방지가 안 됩니다. 같은 논리적 요청은 재시도해도 같은 키를 유지해야 합니다.
