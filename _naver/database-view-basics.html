뷰(View)가 뭔가요 — 복잡한 쿼리를 이름 하나로

2026. 9. 7. · 데이터베이스

한 줄 요약 — 뷰는 복잡한 조회 쿼리에 이름을 붙여 가상 테이블처럼 재사용하는 기능이며, 일반 뷰는 성능이 원본 쿼리에 달렸습니다.

 

같은 복잡한 쿼리를 반복한다면

여러 테이블을 JOIN하는 복잡한 쿼리를 여러 곳에서 반복하면, 쿼리가 바뀔 때 모든 곳을 고쳐야 합니다. 뷰는 이 쿼리에 이름을 붙여 가상 테이블처럼 저장해둡니다.

 

뷰의 기본
CREATE VIEW active_user_orders AS
SELECT u.name, o.item, o.price
FROM users u JOIN orders o ON u.id = o.user_id
WHERE u.status = 'ACTIVE';

SELECT * FROM active_user_orders WHERE price > 10000;

뷰는 데이터를 저장하는 게 아니라 조회할 때 안의 쿼리가 실행됩니다. "저장된 쿼리"에 가깝고, 원본이 바뀌면 결과도 자동으로 최신입니다.

 

일반 뷰 vs 구체화 뷰
일반 뷰: 조회할 때마다 쿼리 실행 (항상 최신, 무거우면 느림)
구체화 뷰: 결과를 저장 (빠름, 원본 바뀌면 갱신 필요)

 

실무 포인트

일반 뷰는 성능을 마법처럼 개선하지 않습니다. 원본 쿼리가 느리면 뷰도 느립니다. 뷰는 편의성·재사용을 위한 것입니다.

반복되고 무거운 집계는 결과를 저장하는 구체화 뷰를 검토하세요. 대신 갱신 전략이 필요합니다.

주의 — 급여 컬럼을 뺀 뷰를 만들어 일반 사용자에게는 뷰만 조회하게 하면, 민감한 컬럼을 노출하지 않고 접근 제어를 할 수 있습니다.
