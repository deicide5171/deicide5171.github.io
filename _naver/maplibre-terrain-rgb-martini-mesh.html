MapLibre GL JS Terrain-RGB와 Martini 메시 — 웹지도에서 지형을 3D로 세우는 원리

GIS

한 줄 요약 — 고도를 PNG 픽셀에 인코딩하는 Terrain-RGB와 지형 굴곡에 따라 삼각형 밀도를 자동 조절하는 Martini 알고리즘이 웹지도 3D 지형을 만드는 원리를 정리했습니다.

 

왜 지금 지형 렌더링 파이프라인을 다시 봐야 하는가

MapLibre GL JS의 setTerrain()을 켜면 평면 지도가 입체적인 산과 계곡으로 솟아오릅니다. 원시 표고 데이터를 그대로 타일로 잘라 보내면 파일 용량이 커질 뿐 아니라, 평평한 지역도 산악 지형과 똑같이 촘촘한 격자 해상도로 삼각형을 그려야 해서 GPU가 폴리곤을 낭비하게 됩니다. Terrain-RGB와 Martini는 이 문제를 각각 저장 방식과 메시화 방식에서 풉니다.

 

Terrain-RGB: 이미지 픽셀에 고도를 숨기기

각 픽셀의 R, G, B 8비트 값을 이어 붙이면 24비트 정수를 얻을 수 있고, 여기에 오프셋과 배율을 적용해 -10,000m부터 소수점 단위까지 고도를 표현합니다. 이 방식의 진짜 이점은 기존 타일 서버 인프라(HTTP 캐싱, CDN, 표준 이미지 디코더)를 고도 데이터에도 그대로 재사용할 수 있다는 것입니다.

 

Martini: 균일한 격자를 불균일한 삼각형으로

Martini는 RTIN(Right-Triangulated Irregular Network)이라는 계층적 삼각분할 구조를 이진 트리 형태로 미리 계산해두고, 각 삼각형의 근사 오차가 임계값을 넘을 때만 재귀적으로 두 개로 쪼갭니다. 평지는 큰 삼각형 몇 개로, 급경사 산악 지역은 정점이 밀집되도록 자동 조절되어, 같은 시각적 정확도를 훨씬 적은 정점 수로 달성합니다.

단계 입력 핵심 이점
Terrain-RGB 디코딩 PNG 타일 기존 이미지 인프라 재사용
Martini 삼각분할 균일 고도 그리드 정점 밀도 자동 조절

 

MapLibre GL JS 연결 예제
map.addSource('terrain-dem', {
  type: 'raster-dem',
  tiles: ['https://example.com/terrain-rgb/{z}/{x}/{y}.png'],
  tileSize: 256,
  encoding: 'mapbox'
});

map.setTerrain({
  source: 'terrain-dem',
  exaggeration: 1.5
});

raster-dem 소스는 타일을 받아오면 자동으로 Martini 기반 메시 생성 로직을 거쳐 지형을 렌더링하므로, 애플리케이션 코드에서 직접 삼각분할을 호출할 필요는 없습니다.

 

실무 포인트

encoding 옵션을 반드시 데이터 제공처와 맞춰야 합니다. Mapbox 방식과 Terrarium(AWS) 방식은 고도 복원 공식이 달라, 잘못 지정하면 지형이 뒤집히거나 극단적으로 솟아오르는 오류가 납니다.

exaggeration 값은 연출 도구이지 정확도 도구가 아닙니다. 실측 고도 분석이 필요한 애플리케이션에서는 이 값을 1로 고정해야 합니다.

주의 — 모바일 기기에서는 지형 최대 줌 레벨을 제한하는 것이 안전합니다. 고해상도 지형 타일을 계속 요청하면 저사양 GPU에서 메시 재계산 비용이 프레임 드랍으로 이어질 수 있습니다.
