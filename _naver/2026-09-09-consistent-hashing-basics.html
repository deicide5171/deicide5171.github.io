일관된 해싱이 뭔가요 — 서버를 늘려도 캐시가 안 깨지게

시스템 디자인

한 줄 요약 — 일관된 해싱은 키와 서버를 원형 링에 놓아, 서버가 늘거나 줄어도 인접 키만 이동하게 하는 분산 기법입니다.

 

서버를 늘렸더니 캐시가 다 날아갔다

데이터를 여러 서버에 나눌 때 흔히 해시값 % 서버수로 위치를 정합니다. 그런데 서버를 3대에서 4대로 늘리면 나누는 수가 바뀌어 거의 모든 키의 위치가 달라집니다. 캐시라면 전부 무효화되어 DB로 요청이 몰리죠. 일관된 해싱은 이 영향을 최소화합니다.

 

단순 나머지 방식의 문제
서버 수 key=100의 위치
3대 100 % 3 = 1번
4대 100 % 4 = 0번

 

링(ring)으로 생각하기
0 ~ 최대값을 원형(링)으로 배치한다.
서버들도 링 위 한 지점에 놓는다.
키는 시계방향으로 가장 가까운 서버에 저장된다.
서버 하나가 빠지면 -> 그 서버 키만 다음 서버로 이동
나머지 키는 그대로 유지

 

실무 포인트

서버 하나를 여러 가상 노드로 흩뿌리면 부하가 고르게 분산됩니다. Redis 클러스터·카산드라·DynamoDB·CDN 등이 내부적으로 이 기법을 씁니다. 직접 구현하기보다 이런 시스템이 해줍니다.

주의 — 가상 노드를 써도 완벽한 균등 분배는 아닙니다. 노드 수와 가상 노드 개수를 조절해 불균형을 허용 범위로 맞추세요.
