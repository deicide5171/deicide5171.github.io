WHERE에 함수 쓰면 인덱스가 안 탄다 — sargable 이해하기

데이터베이스

한 줄 요약 — WHERE에서 인덱스 컬럼을 함수로 감싸면(DATE(col)) 인덱스를 못 탑니다. 컬럼은 그대로, 값을 가공하세요.

 

인덱스를 걸었는데 왜 느릴까

인덱스를 걸어도 조회가 느린 원인은 종종 WHERE에서 인덱스 컬럼을 함수로 감싸기 때문입니다. 인덱스는 컬럼의 원래 값 순으로 정렬돼 있어, 컬럼을 가공하면 못 씁니다.

 

안 되는 경우 vs 되는 경우
-- 못 탐: 컬럼을 함수로 감쌈
WHERE DATE(created_at) = '2026-09-18'
-- 탈 수 있음: 컬럼 그대로, 범위 조건
WHERE created_at >= '2026-09-18'
  AND created_at < '2026-09-19'

 

왜 그런가 (sargable)
인덱스는 컬럼 원래 값으로 정렬
DATE(col) -> 원래 순서 깨져 모든 행 함수 적용 필요
-> 인덱스 무용
"인덱스 탈 수 있는 조건" = sargable

 

실무 포인트

함수는 컬럼이 아니라 비교 값 쪽에 적용하세요. 꼭 LOWER(email)를 써야 하면 함수 기반 인덱스를 만들면 됩니다. EXPLAIN에 "Seq Scan"이 뜨면 인덱스를 못 타는 것입니다.

주의 — price * 2 > 1000처럼 컬럼을 연산해도 인덱스를 못 탑니다. price > 500으로 바꾸세요.
