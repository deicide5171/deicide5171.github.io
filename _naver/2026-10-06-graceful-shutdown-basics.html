그레이스풀 셧다운이 뭔가요 — 서버를 안전하게 끄기

시스템 디자인

한 줄 요약 — 그레이스풀 셧다운은 종료 시 새 요청은 막고 처리 중인 요청은 마친 뒤 서버를 꺼, 배포 때 오류를 막습니다.

 

배포할 때마다 일부 요청이 실패한다

새 버전 배포로 서버를 재시작하면 처리 중이던 요청이 갑자기 끊겨 사용자가 에러를 봅니다. 그레이스풀 셧다운은 종료 신호를 받으면 새 요청은 그만 받되, 처리 중인 요청은 끝까지 마친 뒤 끕니다.

 

그냥 종료 vs 우아한 종료
구분 강제 종료 그레이스풀
처리 중 요청 끊김(에러) 끝까지 마침
사용자 영향 오류 거의 없음

 

종료 흐름
1. 종료 신호(SIGTERM) 수신
2. 로드밸런서에서 트래픽 대상 제외
3. 새 요청 거부, 처리 중인 요청은 완료
4. 모두 끝나면(또는 타임아웃) 종료

 

실무 포인트

앱이 SIGTERM을 받아 정리 후 종료하게 하세요(무시하면 SIGKILL로 끊김). 유예 시간(grace period)을 요청 처리 시간보다 넉넉히 주고, DB 커넥션 반납·작업 저장도 함께 하세요.

주의 — 갑자기 끊기면 커넥션 누수나 중복 처리가 생깁니다. 종료 시 정리 작업을 반드시 넣으세요.
