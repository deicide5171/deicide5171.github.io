Next.js 캐싱 전략 완전 정복

2026. 8. 15. · 웹 개발

한 줄 요약 — Next.js는 네 개의 캐시 레이어가 각각 다르게 동작해서, "분명히 지웠는데 화면이 안 바뀐다"는 문제가 자주 생깁니다.

 

왜 캐싱이 어렵게 느껴질까요

예전 Pages Router 시절에는 캐싱을 신경 쓸 부분이 많지 않았는데, App Router로 넘어오면서 요청 메모이제이션, 데이터 캐시, 풀 라우트 캐시, 라우터 캐시 네 개 레이어가 각각 다른 방식으로 동작하게 되었습니다. 그래서 "revalidate를 호출했는데 화면이 안 바뀐다"는 질문이 개발자 커뮤니티에서 반복적으로 나오고 있습니다.

 

네 가지 캐시 레이어 한눈에 보기
레이어위치무효화 방법
요청 메모이제이션서버(렌더 트리)자동 소멸
데이터 캐시서버revalidatePath / revalidateTag
라우터 캐시클라이언트router.refresh() 또는 자동 만료

 

코드로 보는 무효화 예시
"use server";
import { revalidateTag } from "next/cache";

export async function updatePost(slug) {
  await fetch(`https://api.example.com/posts/${slug}`, { method: "PUT" });
  revalidateTag(`post-${slug}`);
}

 

"캐시가 안 지워진다" 흔한 원인

서버 캐시는 지웠지만 클라이언트 라우터 캐시가 이전 화면을 그대로 들고 있는 경우가 가장 흔합니다. 또한 fetch에 태그를 아예 붙이지 않고 revalidateTag만 호출하면 무효화할 대상 자체가 없어서 아무 일도 일어나지 않습니다. 개발 모드와 배포 환경에서 캐시 동작이 다르게 보일 수 있다는 점도 자주 놓치는 부분입니다.

 

실무 도입 시 이것만은 챙기세요
1. 태그는 데이터 단위로 설계 — 경로 무효화와 태그 무효화의 역할을 구분해두세요.
2. 재검증 주기와 온디맨드 무효화 우선순위 — 팀 내에서 미리 합의해두세요.
3. 정적/동적 콘텐츠 분리 — 캐시 가능한 부분만 정적으로 남기세요.
4. 프리뷰 환경에서 검증 — 로컬에서는 재현이 안 되는 캐시 버그가 많습니다.

 

마무리 — 3줄 요약

① Next.js는 네 개의 캐시 레이어가 각각 다른 생명주기로 동작합니다.
② revalidatePath는 경로 단위, revalidateTag는 태그 단위 무효화입니다.
③ 서버 캐시를 지워도 클라이언트 라우터 캐시가 남아있으면 화면이 안 바뀔 수 있습니다.
