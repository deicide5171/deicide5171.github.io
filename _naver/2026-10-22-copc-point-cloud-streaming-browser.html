포인트클라우드도 변환 없이 스트리밍한다 — COPC 포맷과 브라우저 디코딩 설계

GIS

한 줄 요약 — '드론으로 찍은 LiDAR 스캔을 바로 지도에 올려 보여주세요'라는 요구는 그동안 Potree용 전용 포맷으로 변환하는 전처리 파이프라인을 의미했습니다. LAZ 파일을 그대로 HTTP Range Request로 스트리밍하는 COPC 포맷이 이 전처리 단계를 어떻게 없애는지, Potree 방식과의 트레이드오프와 도입 순서를 정리했습니다.

 

왜 지금 이 판단이 필요한가

"드론으로 찍은 LiDAR 스캔 데이터, 변환 없이 바로 지도에 올려서 보여주세요." 측량·건설 현장 담당자가 한 번쯤 던지는 요구입니다. 문제는 LiDAR 스캔 결과물이 보통 수억 개 점으로 이뤄진 LAS·LAZ 파일 한 덩어리라는 데 있습니다. 이 파일을 브라우저에 그대로 던지면 로딩만 몇 분이 걸리거나 아예 멈춥니다. 그래서 지금까지 표준 해법은 Potree였습니다 — 원본을 옥트리 구조로 쪼개 전용 포맷으로 미리 변환해두고, 뷰어가 필요한 LOD만 요청해 스트리밍하는 방식입니다. 효과는 확실했지만 서버 한쪽에 전처리 파이프라인을 또 하나 세워야 했습니다.

COPC(Cloud Optimized Point Cloud)는 이 전제를 바꿉니다. 일반 LAZ 압축 파일 안에 점들을 옥트리 순서로 재배치하고 그 계층 구조를 설명하는 VLR을 끼워 넣은 것뿐입니다. 확장자도 그대로 .laz입니다. COPC를 이해하는 클라이언트는 같은 파일에서 HTTP Range Request만으로 필요한 영역·해상도의 점만 뽑아 씁니다. PMTiles가 벡터 타일에서 했던 일을 포인트클라우드에서 해내는 셈입니다. 2026년 가을 GeoLibre가 v3.x에서 COPC 디코딩을 브라우저 엔진에 직접 넣으면서 이 흐름이 빨라지고 있습니다.

 

전체 시스템에서의 위치

Potree 경로는 PotreeConverter로 전용 옥트리 포맷을 생성합니다 — 상시 또는 배치 전처리 서버가 필요하고, 결과물은 Potree 뷰어 전용입니다. COPC 경로는 PDAL writers.copc 또는 untwine으로 원본을 COPC로 한 번만 변환합니다. 출력물이 표준 LAZ이므로 변환 후에는 S3·R2 같은 정적 스토리지에 올려두고 서버 프로세스 없이 서빙합니다. Cesium·copc.js·GeoLibre 같은 클라이언트가 VLR의 옥트리 계층 정보를 읽어 화면에 보이는 영역만 선택적으로 내려받습니다. "전처리가 아예 없어지는" 건 아니지만, COPC는 업계 표준 LAZ 포맷의 내부 배치만 바꿔 서버 운영 부담을 치워냅니다.

 

선택의 트레이드오프
접근 장점 단점
Potree 성숙한 생태계, 세밀한 LOD 튜닝 전용 포맷, 다른 도구와 비호환
COPC 표준 LAZ 호환, 서버 없이 정적 서빙 뷰어 생태계가 아직 얇음
원본 그대로 서빙 변환 작업 없음 대용량에서 사실상 불가
3D Tiles 변환 Cesium 생태계 완전 통합 변환 비용이 COPC보다 큼

 

판단 기준은 "이 포인트클라우드를 어떤 뷰어 생태계 안에서 소비할 것인가"입니다. 이미 Potree 워크플로가 자리 잡았다면 바꿀 이유가 적지만, 2D 지도 위에 포인트클라우드를 얹거나 서버 운영 부담을 PMTiles 수준으로 낮추고 싶다면 COPC가 자연스러운 선택입니다.

 

실제 프로젝트 진행 순서

1. 원본 포맷부터 확인합니다. COPC는 LAS 1.4 PDRF 6·7·8만 지원하므로 오래된 장비 출력물은 먼저 승급합니다.
2. untwine 또는 PDAL writers.copc로 변환합니다.
3. 정적 스토리지에 올리고 Range Request 지원을 확인합니다.
4. 뷰어를 고릅니다. viewer.copc.io로 먼저 검증한 뒤 Cesium·GeoLibre·copc.js로 실제 레이어를 짭니다.
5. 지도 위 다른 레이어와 좌표계·LOD 동기화를 맞춥니다.
6. 전면 배포 전 일부 타일로 Range Request 패턴과 캐시 적중률을 먼저 측정합니다.

 

예제 코드:

# LAS/LAZ 원본을 COPC로 변환 (PDAL)
pdal translate input.laz output.copc.laz \
  --writers.copc.forward=all

# 변환 결과가 COPC 스펙을 지키는지 확인
pdal info output.copc.laz --metadata | grep -i copc

 

주의 — COPC 파일의 info VLR은 파일 시작 375바이트 지점에서 시작하는 고정 160바이트 구조입니다. 커스텀 파서를 직접 짠다면 이 오프셋을 벗어나면 안 됩니다. CDN 캐시 설정 시 Range Request를 그대로 전달하는지도 꼭 확인하세요 — 일부 설정은 전체 파일을 캐싱하려다 Range 헤더를 무시해 스트리밍 이점을 무력화합니다.

 

정리

COPC는 포인트클라우드를 전용 포맷으로 갈아엎지 않고, 표준 LAZ 파일 내부를 옥트리 순서로 재배치해 HTTP Range Request 스트리밍을 가능하게 합니다. Potree는 세밀한 LOD 제어가 강점이고, COPC는 서버 없는 정적 스토리지 서빙과 PDAL 생태계 호환성이 강점입니다. 변환은 untwine이나 PDAL로 한 번만 거치면 되고, 이후 운영 부담은 PMTiles 수준으로 가벼워집니다.
