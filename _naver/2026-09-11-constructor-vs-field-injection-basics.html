생성자 주입 vs 필드 주입 — 스프링에서 뭘 써야 하나

백엔드

한 줄 요약 — 의존성 주입은 필드 주입과 생성자 주입이 있고, 생성자 주입이 final·테스트 용이·순환 참조 조기 발견으로 권장됩니다.

 

@Autowired를 필드에 붙이면 안 되나

다른 빈을 가져다 쓰는 것이 의존성 주입(DI)입니다. 방식은 필드 주입(@Autowired 필드)과 생성자 주입(생성자로 받기)이 있죠. 둘 다 동작하지만 실무에선 생성자 주입을 권장합니다.

 

두 방식 비교
구분 필드 주입 생성자 주입
final 불가 가능(불변)
테스트 프레임워크 필요 new로 쉽게

 

코드로 비교
// 생성자 주입 (권장)
@Service
public class OrderService {
    private final PaymentClient payment;
    public OrderService(PaymentClient payment) {
        this.payment = payment;
    }
}

 

실무 포인트

생성자 주입은 final로 불변을 보장하고, 테스트에서 new OrderService(mock)로 쉽게 주입합니다. 롬복 @RequiredArgsConstructor로 생성자 코드를 줄일 수 있습니다.

주의 — 필드 주입은 순환 참조를 런타임에야 발견하지만, 생성자 주입은 시작 시 바로 드러나 안전합니다.
