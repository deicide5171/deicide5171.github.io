커넥션 풀이 뭔가요 — DB 연결을 재사용하는 이유

2026. 9. 6. · 데이터베이스

한 줄 요약 — 커넥션 풀은 연결을 미리 만들어두고 빌려 쓰고 반납해 연결 생성 비용을 없애며, 풀 크기는 클수록 좋은 게 아닙니다.

 

DB 연결은 생각보다 비싼 작업이다

DB 연결을 맺는 과정(인증, 네트워크 핸드셰이크)은 오래 걸립니다. 매 요청마다 연결을 맺고 끊으면 쿼리보다 연결에 더 많은 시간이 듭니다. 커넥션 풀은 연결을 재사용해 이 낭비를 없앱니다.

 

풀이 없을 때와 있을 때
[풀 없음] 매 요청: 연결 생성 -> 쿼리 -> 종료
[풀 있음] 미리 N개 생성 -> 빌림 -> 쿼리 -> 반납

 

핵심 설정값
설정 의미
최대 풀 크기 동시에 빌려줄 최대 연결 수
커넥션 타임아웃 연결 대기 최대 시간
최대 수명 오래된 연결 교체 주기

 

풀 크기는 클수록 좋은가
너무 크면: DB max_connections 초과, 컨텍스트 스위칭 증가
너무 작으면: 요청들이 대기하다 타임아웃
-> 실측으로 적정값 조정

 

실무 포인트

커넥션을 빌린 뒤 반드시 반납해야 합니다. 반납하지 않으면 풀이 고갈되어 새 요청이 멈춥니다. 커넥션 누수가 가장 흔한 장애 원인입니다.

주의 — 애플리케이션 인스턴스 수 × 풀 크기가 DB의 max_connections를 넘지 않게 해야 합니다.
