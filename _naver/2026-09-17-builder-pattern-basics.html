빌더 패턴이 뭔가요 — 생성자 인자 지옥 벗어나기

백엔드

한 줄 요약 — 빌더 패턴은 인자가 많은 객체를 이름과 함께 하나씩 지정해 만들어 가독성과 안전성을 높입니다.

 

생성자 인자가 많아 헷갈린다

인자가 많으면 new User("철수", 20, "서울", true, null)처럼 무슨 값인지 알기 어렵고 순서를 헷갈립니다. 빌더 패턴은 값을 이름과 함께 하나씩 지정한 뒤 마지막에 객체를 만듭니다.

 

생성자 vs 빌더
// 생성자: 헷갈림
new User("철수", 20, "서울", true, null);
// 빌더: 명확
User.builder().name("철수").age(20)
    .city("서울").active(true).build();

 

장점
장점 설명
가독성 이름으로 명확
선택적 값 필요한 것만, 순서 자유

 

실무 포인트

자바에선 롬복 @Builder로 빌더 코드를 자동 생성합니다. 필드가 2~3개뿐이면 빌더가 오히려 과하니 생성자가 낫습니다. 인자가 많을 때 빌더가 빛납니다.

주의 — 빌더는 값을 자유롭게 빼먹을 수 있어 필수 값 없이 build될 수 있습니다. build()에서 필수 값을 검증하세요.
