CSS Cascade Layers(@layer) 딥다이브 — 명시도 전쟁을 구조적으로 끝내는 법

프론트엔드

한 줄 요약 — Cascade Layers는 명시도보다 먼저 개입하는 레이어 순서를 도입해, 셀렉터 구체성 경쟁 없이도 어떤 스타일이 이길지 명시적으로 통제합니다.

 

왜 명시도만으로 한계가 오는가

디자인 시스템, 서드파티 라이브러리, 유틸리티 클래스, 팀 커스텀 스타일이 뒤섞이면 필연적으로 명시도 전쟁이 벌어집니다. 라이브러리 기본 스타일을 덮어쓰려고 셀렉터를 더 구체적으로 쓰거나 !important를 붙이는 악순환은 CSS 유지보수를 불가능에 가깝게 만듭니다.

 

캐스케이드 알고리즘에서 레이어가 개입하는 위치

우선순위는 origin/importance → 레이어 순서 → 명시도 → 소스 순서로 매겨집니다. 나중에 선언된 레이어 안의 규칙은 셀렉터 명시도가 낮아도, 먼저 선언된 레이어의 매우 구체적인 셀렉터보다 항상 이깁니다. 명시도 비교는 같은 레이어 안에서만 의미를 갖습니다.

레이어 없는 스타일은 항상 가장 강하다

@layer로 감싸지 않은 일반 규칙(unlayered)은 모든 레이어보다 우선합니다. 실무 패턴은 서드파티 라이브러리와 리셋을 낮은 레이어에, 팀 컴포넌트 스타일을 높은 레이어에 두는 것입니다.

우선순위 대상
낮음 서드파티, 리셋
중간 팀 컴포넌트
최고 unlayered 규칙

 

레이어 선언과 순서 제어 예제
@layer reset, library, components, utilities;

@layer reset {
  * { margin: 0; padding: 0; box-sizing: border-box; }
}

@layer library {
  .btn { background: gray; padding: 8px 16px; }
}

@layer components {
  .btn { background: var(--brand-color); border-radius: 8px; }
}

@import url("third-party.css") layer(library);

components 레이어의 .btn은 명시도가 같아도 더 높은 레이어이므로 항상 이깁니다.

 

실무 포인트

레이어 순서는 첫 등장 순서로 고정됩니다. 이름만 먼저 나열해 순서를 명시적으로 확정해두면 내용이 파일 어디에 흩어져 있든 순서가 안전하게 유지됩니다.

!important와 결합하면 순서가 역전됩니다. 레이어 안에서 !important를 쓰면 먼저 선언된 레이어가 나중 레이어보다 우선하므로 가급적 피하세요.

주의 — 레거시 브라우저 지원이 필요하다면 통째로 마이그레이션하지 말고, 새로 작성하는 컴포넌트부터 점진적으로 레이어를 적용하는 것이 현실적입니다.
