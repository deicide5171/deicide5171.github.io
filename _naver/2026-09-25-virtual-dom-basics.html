가상 DOM이 뭔가요 — React가 화면을 빠르게 바꾸는 원리

프론트엔드

한 줄 요약 — 가상 DOM은 실제 DOM을 흉내 낸 가벼운 JS 복사본으로, 비교 후 달라진 곳만 실제 DOM에 반영해 효율을 높입니다.

 

화면을 다시 그리는 건 비싸다

브라우저의 실제 DOM 조작은 느립니다. 데이터가 바뀔 때마다 화면 전체를 다시 그리면 성능이 나빠지죠. 가상 DOM은 실제 DOM을 자바스크립트 객체로 흉내 낸 가벼운 복사본입니다. React는 여기서 바뀐 부분을 먼저 계산한 뒤, 실제로 달라진 곳만 진짜 DOM에 반영합니다.

 

실제 DOM vs 가상 DOM
구분 실제 DOM 가상 DOM
정체 브라우저가 그리는 화면 JS 객체 복사본
조작 비용 비쌈 쌈

 

어떻게 동작하나
1. 데이터 변경 -> 새 가상 DOM 트리 생성
2. 이전 가상 DOM과 비교 (diffing)
3. 실제로 달라진 부분만 찾음
4. 그 부분만 진짜 DOM에 반영 (최소한의 조작)

 

실무 포인트

가상 DOM이 무조건 빠른 건 아닙니다(비교에도 비용). 진짜 장점은 복잡한 UI를 편하게 관리하면서 성능을 지켜주는 것입니다. 목록엔 고유 key를 줘야 정확히 갱신됩니다. Svelte처럼 가상 DOM 없는 접근도 있습니다.

주의 — 목록 렌더링에서 key를 빼먹으면 불필요한 갱신과 버그가 생깁니다. 각 항목에 고유 key를 꼭 주세요.
