"이 조사, 서브에이전트 다섯 개한테 동시에 맡겨주세요" — fork가 기본값이 되며 다시 그어야 하는 동시성 경계

AI

한 줄 요약 — Claude Code v2.1.302부터 fork 서브에이전트가 claude -p·Agent SDK·데스크톱 앱에서 기본값이 됐습니다. 포크와 신규 서브에이전트, 포그라운드와 백그라운드 실행을 가르는 설계 기준과, 기본값이 조용히 바뀔 때 생기는 리스크를 정리했습니다.

 

왜 지금 이 판단이 필요한가

"이 리서치, 서브에이전트 다섯 개한테 나눠서 동시에 맡기고 결과만 모아주세요." AI 코딩 에이전트를 쓰다 보면 자연스럽게 나오는 요구입니다. 그런데 매번 두 가지 결정이 따라붙습니다. 그 서브에이전트가 부모의 대화 맥락을 그대로 물려받을 것인가(fork), 아니면 백지 상태에서 시작할 것인가. 그리고 그 작업을 화면 앞에서 돌릴 것인가, 뒤에서 돌릴 것인가입니다.

2026년 10월 16일 출시된 Claude Code v2.1.302는 이 두 결정의 기본값을 한 번에 바꿨습니다. fork 서브에이전트가 터미널뿐 아니라 claude -p, Agent SDK, 데스크톱 앱, VS Code 확장에서도 기본으로 켜졌고, 신선 설치본에서는 SDK 세션의 권한 모드 자체가 조용히 바뀌는 경우도 생겼습니다.

 

전체 시스템에서의 위치

부모 세션이 작업을 서브에이전트에 넘기는 순간, 요청은 두 갈래 경로 중 하나를 탑니다. fork는 부모의 대화 맥락과 프롬프트 캐시를 그대로 이어받아 연속해서 작업하는 모양이고, 신규 서브에이전트는 새 지시문만 가지고 독립적으로 시작합니다.

두 경로 모두 백그라운드로 돌 수 있습니다. 기본값에서는 결과가 바로 필요하지 않은 작업이 백그라운드로 빠지고, 권한 확인이 필요한 순간에만 화면에 프롬프트가 올라옵니다. 동시성에는 상한도 있습니다 — 동시 서브에이전트 약 20개, 중첩 깊이 3단계입니다.

 

선택의 트레이드오프
기준 fork 신규 서브에이전트
컨텍스트 부모 대화 전체 상속 백지 상태, 지정한 프롬프트만
비용 캐시 재사용으로 저렴 새 캐시를 처음부터 쌓음
적합한 상황 같은 대화의 연장 독립된 검증·다른 관점 리뷰
위험 민감한 맥락까지 그대로 전파 배경을 다시 설명해 프롬프트가 길어짐

 

판단 기준은 단순합니다. 같은 대화의 연장이면 fork, 독립된 새 임무면 신규 서브에이전트. 그리고 다음 행동이 결과를 기다려야만 하면 포그라운드, 아니면 백그라운드입니다. 이 두 축을 매번 의식적으로 정하지 않으면 기본값이 알아서 정해버립니다.

 

실제 프로젝트 진행 순서

1. 병렬화하려는 작업의 성격부터 분류합니다(맥락 공유 필요 → fork, 독립 임무 → 신규).
2. 기본값이 바뀌었다는 전제로 subagent_type을 명시적으로 지정합니다.
3. 동시성 상한(약 20개, 중첩 3단계)을 설계에 반영합니다.
4. 권한 모드 기본값을 조직 정책에 맞게 설정 파일에 고정합니다.
5. 지출 상한이 기본 제공되지 않으므로 비용 가드레일을 직접 세웁니다.
6. 환경변수로 팀 전체에 일관된 기본값을 강제합니다.

 

예제 코드:

# CI 파이프라인에서 서브에이전트 기본값을 조직 표준으로 고정
export CLAUDE_CODE_FORK_SUBAGENT=0
export CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1

# 호출부에서는 작업 성격에 따라 명시적으로 타입을 지정
claude -p "PR을 버그·성능·보안 세 관점에서 각각 서브에이전트로 검토해줘" \
  --subagent-type fork --max-concurrent-subagents 3

 

주의 — 서브에이전트 정의에서 tools 필드를 비워두면 부모가 가진 도구를 그대로 상속합니다. 민감한 도구(결제·삭제·배포)를 쓰는 서브에이전트는 tools를 명시적으로 좁혀야 합니다. 이번 변화는 third-party 블로그 재구성에 의존한 보고가 섞여 있으니, 프로덕션 반영 전 공식 체인지로그와 실제 버전 동작을 반드시 재현해 확인하세요.

 

정리

fork는 컨텍스트·캐시를 상속하는 대화의 연장, 신규 서브에이전트는 독립된 임무라는 축으로 먼저 나눕니다. 포그라운드·백그라운드는 다음 행동이 결과를 기다려야 하는지로 정하고, 동시성 상한을 설계에 미리 반영합니다. 기본값이 바뀌는 시점에는 CI·자동화 스크립트에서 타입과 권한 모드를 환경변수로 명시적으로 고정해 리스크를 차단하는 것이 핵심입니다.
