낙관적 락 vs 비관적 락 — 동시 수정 충돌을 막는 두 방법

시스템 디자인

한 줄 요약 — 비관적 락은 먼저 잠그고 작업(대기), 낙관적 락은 저장 시 버전을 검사(실패 시 재시도)하며, 충돌 빈도로 선택합니다.

 

두 사람이 같은 데이터를 동시에 고치면

재고 1개인데 두 명이 동시에 주문하면, 각자 "재고 1 확인 → 주문 → 0으로" 해서 둘 다 성공해 재고가 -1이 되는 사고가 납니다. 이런 동시 수정 충돌을 막는 것이 낙관적 락과 비관적 락입니다.

 

두 방식의 차이
구분 비관적 락 낙관적 락
방식 먼저 잠그고 작업 저장 시 검사
충돌 시 대기 실패 → 재시도
적합 충돌 잦음 충돌 드묾

 

동작 방식
[비관적] A가 행 잠금 -> B 대기 -> A 완료 후 B
        (SELECT ... FOR UPDATE)
[낙관적] version 컬럼 사용
        읽을 때 v=5 -> 저장 시 "아직 5인가?" 확인
        누가 먼저 바꿔 v=6이면 실패 -> 재시도

 

실무 포인트

충돌이 드물면 낙관적(대기 없음), 잦으면 비관적이 낫습니다. 낙관적 락은 실패 시 재시도 로직이 필요하고, 사용자에겐 "다른 사람이 먼저 수정했습니다"를 안내하는 게 좋습니다.

주의 — 비관적 락은 여러 행을 잠그다 서로 기다리면 데드락에 빠집니다. 잠그는 순서를 통일하고 범위·시간을 최소화하세요.
