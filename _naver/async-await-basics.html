async/await 기초 — 콜백 지옥에서 벗어나기

2026. 9. 5. · 프론트엔드

한 줄 요약 — async/await는 비동기 코드를 위에서 아래로 읽히게 만들며, 순서가 상관없는 작업은 Promise.all로 병렬 실행해야 빠릅니다.

 

왜 비동기 처리가 헷갈리나

서버 요청 같은 작업은 결과가 즉시 오지 않습니다(비동기). "결과가 오면 처리하라"를 콜백으로 중첩하다 보면 코드가 오른쪽으로 밀려나는 콜백 지옥에 빠집니다.

 

콜백 지옥 vs async/await
// 콜백 지옥
getUser(1, (user) => {
  getOrders(user.id, (orders) => { ... });
});

// async/await
async function show() {
  const user = await getUser(1);
  const orders = await getOrders(user.id);
  console.log(orders); // 평평하게!
}

await는 "작업이 끝날 때까지 기다렸다 결과를 받아라"는 뜻이며, await를 쓰는 함수는 async로 선언해야 합니다.

 

에러 처리는 try/catch로
try {
  const user = await getUser(1);
  const orders = await getOrders(user.id);
} catch (error) {
  console.error("실패:", error);
}

 

실무 포인트 — 병렬 처리
// 느림: 순차 (총 3초)
const a = await fetchA(); const b = await fetchB();

// 빠름: 병렬 (총 1초)
const [a, b, c] = await Promise.all([fetchA(), fetchB(), fetchC()]);

순서가 상관없는 독립적인 작업은 Promise.all로 묶어 동시에 실행하세요.

주의 — 처리 안 된 에러(unhandled rejection)는 조용히 사라지거나 예상치 못한 곳에서 터집니다. try/catch나 .catch()로 반드시 처리하세요.
