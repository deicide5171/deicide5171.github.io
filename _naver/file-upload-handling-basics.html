파일 업로드 처리 기초 — 서버는 어디에 어떻게 저장할까

2026. 9. 4. · 백엔드

한 줄 요약 — 파일은 multipart/form-data로 전송되며, 서버가 여러 대라면 로컬 대신 S3 같은 오브젝트 스토리지에 저장하는 것이 표준입니다.

 

파일 업로드는 왜 텍스트와 다른가

이미지·PDF 같은 파일은 크기가 크고 이진 데이터라 다르게 처리해야 합니다. 그래서 multipart/form-data 형식으로 전송되며, 파일과 텍스트 필드를 함께 담을 수 있습니다.

 

서버가 파일을 받는 흐름
@PostMapping("/upload")
public String upload(@RequestParam("file") MultipartFile file) {
    if (file.isEmpty()) return "파일이 없습니다";
    file.transferTo(new File("/uploads/" + safeName));
    return "업로드 완료";
}

 

어디에 저장할 것인가
저장 위치 특징
로컬 디스크 간단하나 서버 여러 대면 흩어짐
S3 등 오브젝트 스토리지 확장성 좋음, 실무 표준
DB에 직접(BLOB) 대용량엔 비효율, 권장 안 함

 

보안·안정성 주의점
1. 파일 크기 제한 (무제한이면 디스크 고갈 공격)
2. 확장자·타입 검증 (.exe, .sh 차단)
3. 파일명 그대로 쓰지 않기 (../ 경로 조작 공격 -> UUID로 새로 지정)

 

실무 포인트

업로드 파일은 웹 서버가 실행할 수 없는 위치에 저장해야 합니다. 스크립트 파일이 실행 가능한 경로에 있으면 심각한 사고로 이어집니다.

주의 — 대용량 파일은 Presigned URL로 클라이언트가 S3에 직접 업로드하게 하면 서버 부하가 크게 줄어듭니다.
