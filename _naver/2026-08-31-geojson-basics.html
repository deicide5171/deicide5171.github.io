GeoJSON이 뭔가요 — 웹 지도에서 가장 많이 쓰는 공간 데이터 포맷 입문

GIS

한 줄 요약 — GeoJSON은 순수 JSON 구조라서 별도 파서 없이 웹에서 바로 다룰 수 있는 공간 데이터 포맷이며, 좌표 순서는 항상 [경도, 위도]입니다.

 

왜 하필 GeoJSON인가

지리 정보를 담는 포맷은 Shapefile, KML, GML 등 여러 가지가 있지만, 웹 지도 개발에서는 GeoJSON이 사실상 표준입니다. 그냥 JSON이라서 별도 파서 없이 JSON.parse()만으로 바로 다룰 수 있고, 거의 모든 웹 지도 라이브러리가 기본 지원합니다.

 

 

GeoJSON 도형 타입
타입 표현하는 것 좌표 구조
Point 하나의 점 [경도, 위도]
LineString 선(도로, 경로) [[경도,위도], ...]
Polygon 면(행정구역 경계) [[[경도,위도], ...]] (첫점=끝점)

 

예제 — 기본 구조
{
  "type": "Feature",
  "geometry": {
    "type": "Point",
    "coordinates": [126.978, 37.5665]
  },
  "properties": { "name": "서울 시청" }
}

Feature는 지오메트리와 속성 정보를 함께 담는 기본 단위입니다. 여러 Feature를 모으면 FeatureCollection이 됩니다.

 

실무 포인트

좌표 순서는 [경도, 위도]입니다. 위도·경도 순서로 저장하는 다른 포맷과 혼동하면 지도에 엉뚱한 위치가 찍힙니다. RFC 7946에 명시된 규칙이라 예외가 없습니다.

Polygon의 좌표 배열은 첫 점과 마지막 점이 같아야 닫힌 도형으로 인식됩니다.

주의 — 대용량 GeoJSON(수만 개 이상의 Feature)을 브라우저에 그대로 로드하면 성능이 급격히 나빠집니다. 이 경우 벡터 타일(PBF)로 변환해서 서빙하는 것이 실무 표준입니다.
