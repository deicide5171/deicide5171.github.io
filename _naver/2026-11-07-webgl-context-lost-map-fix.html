지도가 갑자기 하얗게 변할 때 — WebGL Context Lost 에러 원인과 복구 방법

GIS

한 줄 요약 — WebGL Context Lost는 자바스크립트 예외가 아니라 별도 이벤트로 통지되며, GPU 자원 관리 때문에 버그 없이도 발생합니다. preventDefault() 호출이 복구의 핵심입니다.

 

왜 잘 쓰던 지도가 갑자기 하얗게 변할까

MapLibre GL JS나 Cesium으로 만든 3D 지도를 오래 켜두거나, 노트북을 절전 모드에 뒀다 다시 켜거나, GPU를 많이 쓰는 다른 탭을 여러 개 열어두면 지도가 갑자기 새하얀 캔버스로 변하고 이후 어떤 조작에도 반응하지 않는 현상을 겪게 됩니다. 콘솔에 에러 메시지 하나 없이 조용히 멈춰 있는 경우가 많습니다.

이 현상은 코드 버그가 아니라 브라우저와 운영체제가 GPU 자원을 관리하는 방식 때문에 발생합니다. 시스템이 메모리 압박을 받거나 GPU 드라이버가 크래시하면 브라우저는 특정 탭의 WebGL 컨텍스트를 강제로 회수해버릴 수 있습니다.

 

 

핵심 개념 1 — 예외가 아니라 이벤트로 알려진다

WebGL 컨텍스트 유실은 try/catch로 잡히는 에러가 아니라, canvas 엘리먼트의 webglcontextlost 이벤트로 통지됩니다. 이 이벤트를 리스닝하고 있지 않으면 애플리케이션은 아무 알림도 받지 못한 채 렌더링이 멈춰버립니다. 컨텍스트가 유실되면 텍스처·셰이더·버퍼가 전부 사라지므로 처음부터 다시 만들어 올려야 합니다.

 

핵심 개념 2 — 복구는 명시적으로 허가해야 한다

브라우저는 상황이 되면 webglcontextrestored 이벤트로 재생성 기회를 주지만, 기본 동작은 "복구하지 않음"입니다. webglcontextlost 핸들러 안에서 event.preventDefault()를 호출해야만 브라우저가 복구를 시도합니다. 이 한 줄을 빠뜨리면 컨텍스트는 영영 복구되지 않습니다.

 

예제 — MapLibre GL JS 감지 및 복구
const canvas = map.getCanvas();

canvas.addEventListener('webglcontextlost', (event) => {
  event.preventDefault();  // 빠뜨리면 복구 시도 자체가 안 됨
  console.warn('WebGL 컨텍스트 유실 — 복구 대기 중');
  showReloadBanner();
});

canvas.addEventListener('webglcontextrestored', () => {
  console.info('WebGL 컨텍스트 복구됨');
  map.setStyle(map.getStyle());  // 리소스 강제 재생성
  hideReloadBanner();
});

Cesium을 쓰는 경우도 원리는 같습니다. 다만 내부 상태가 훨씬 복잡해 완전 자동 복구가 보장되지 않는 경우가 많으므로, 복구를 시도하는 대신 아예 새로고침을 유도하는 편이 안전할 때도 있습니다.

 

발생 원인과 대응
원인 대응
GPU 메모리 압박 텍스처 해상도 최적화, 안 쓰는 레이어 제거
노트북 절전/GPU 전환 contextrestored 핸들러로 재초기화
GPU 드라이버 크래시 사용자에게 새로고침 안내

 

실무 포인트

이벤트 리스너는 지도 생성 직후 반드시 등록하세요. Context Lost는 언제 발생할지 예측할 수 없으므로 지도 초기화 코드와 한 세트로 등록해야 합니다.

복구 실패 시 사용자에게 명확한 안내를 제공하세요. 일정 시간 안에 webglcontextrestored가 발생하지 않으면 새로고침 안내로 전환하는 타임아웃 로직이 필요합니다.

주의 — 모바일 브라우저는 데스크톱보다 GPU 메모리 여유가 훨씬 적어 여러 앱을 오가는 것만으로도 컨텍스트가 회수될 수 있으므로, 모바일 대상 서비스라면 복구 로직을 실제 기기에서 반드시 테스트해야 합니다.
