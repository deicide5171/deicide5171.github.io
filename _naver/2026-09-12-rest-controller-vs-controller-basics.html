@RestController와 @Controller 차이 — 뷰냐 데이터냐

백엔드

한 줄 요약 — @Controller는 뷰(HTML) 이름을, @RestController는 데이터(JSON)를 반환하며, @RestController = @Controller + @ResponseBody입니다.

 

둘 다 컨트롤러인데 뭐가 다른가

핵심 차이는 반환값을 어떻게 다루느냐입니다. @Controller는 뷰(HTML 화면) 이름을 반환하고, @RestController는 데이터(JSON) 자체를 반환합니다.

 

두 애너테이션 비교
구분 @Controller @RestController
반환값 뷰(HTML) 이름 데이터(JSON)
용도 서버가 화면 렌더 REST API

 

예시
@Controller
public class PageController {
    @GetMapping("/home")
    public String home() { return "home"; } // home.html 렌더
}
@RestController
public class UserApi {
    @GetMapping("/api/users/1")
    public User get() { return new User(1L,"철수"); } // JSON
}

 

실무 포인트

프론트와 JSON으로 통신하는 API 서버는 @RestController, 타임리프 등 서버 렌더링이면 @Controller를 씁니다. 하나에서 섞기보다 클래스를 나누는 게 깔끔합니다.

주의 — @Controller에서 JSON을 주려면 메서드에 @ResponseBody가 필요합니다. 빼먹으면 반환 문자열이 "뷰 이름"으로 해석됩니다.
