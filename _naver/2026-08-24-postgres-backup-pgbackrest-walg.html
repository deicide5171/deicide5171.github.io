pg_dump로는 안 된다 — pgBackRest·WAL-G로 하는 PostgreSQL 물리 백업 실전

2026. 8. 24. · 데이터베이스

한 줄 요약 — 수백 GB급 운영 PostgreSQL에서는 pg_dump 논리 백업 대신 데이터 파일을 통째로 복사하는 물리 백업 + WAL 아카이빙이 필요합니다. pgBackRest와 WAL-G 두 도구를 비교했습니다.

 

왜 pg_dump만으로는 부족할까요

수십 GB짜리 개발 DB라면 pg_dump 한 줄로 충분합니다. 그러나 수백 GB, 수 TB급 운영 DB에서 논리 백업은 백업 자체에 몇 시간이 걸리고, 복원은 그보다 더 오래 걸리며, 백업 도중 벌어진 트랜잭션의 일관성 보장도 까다로워집니다. 이 규모에서는 데이터 파일을 통째로 복사하는 물리 백업과, 그 사이의 변경분을 놓치지 않는 WAL 아카이빙의 조합이 사실상 유일한 선택지입니다.

문제는 물리 백업을 직접 구현하려면 pg_basebackup만으로는 부족한 기능 — 증분/차등 백업, 병렬 처리, 원격 스토리지 업로드, 보관 주기 관리 — 이 많다는 것입니다. 이 공백을 메우는 두 대표 도구가 pgBackRest와 WAL-G입니다.

 

핵심 개념 1 — 논리 백업과 물리 백업은 다른 문제를 풉니다

pg_dump는 SQL 문 또는 커스텀 포맷으로 데이터를 논리적으로 덤프합니다. 스키마 변경에 유연하지만 덤프·복원 모두 데이터 규모에 비례해 느려집니다. 반면 물리 백업은 디스크의 데이터 파일 자체를 바이트 단위로 복사합니다. 복원 시 SQL 재실행이 없으므로 훨씬 빠르지만, 같은 메이저 버전 간에만 호환됩니다.

운영 환경의 RTO(복구 목표 시간)를 짧게 가져가야 한다면 물리 백업이 기본 선택지이고, pg_basebackup이 그 표준 도구입니다. 하지만 증분 백업이 없고 병렬 압축·업로드가 제한적이며 보관 정책 관리 기능이 없습니다. pgBackRest와 WAL-G는 이 위에서 실무에 필요한 기능을 채웁니다.

 

핵심 개념 2 — pgBackRest vs WAL-G
구분 pgBackRest WAL-G
구현 언어 C/Perl Go
백업 유형 풀/증분/차등 풀 + 델타(증분)
페이지 체크섬 검증 지원 제한적
대표 채택 사례 대규모 온프레미스/하이브리드 Postgres Operator, Patroni 연동

 

pgBackRest는 기능이 풍부한 대신 설정 항목도 많아 학습 곡선이 있고, WAL-G는 Kubernetes 오퍼레이터 생태계에서 가볍게 붙이기 좋은 선택으로 자주 쓰입니다. 둘 다 핵심 원리는 같습니다 — 주기적인 베이스 백업과 연속적인 WAL 아카이빙의 조합입니다.

 

예제 — pgBackRest 설정과 백업 명령
[global]
repo1-path=/var/lib/pgbackrest
repo1-retention-full=2
repo1-type=s3
repo1-s3-bucket=my-pg-backups
process-max=4
compress-type=zst

[main]
pg1-path=/var/lib/postgresql/16/main

# 최초 스탠자 생성 및 풀 백업
pgbackrest --stanza=main stanza-create
pgbackrest --stanza=main --type=full backup

# 이후 증분 백업 (변경분만)
pgbackrest --stanza=main --type=incr backup

WAL-G는 환경 변수 기반 설정과 wal-g backup-push, wal-g backup-fetch 명령 조합으로 유사한 흐름을 구현합니다.

 

실무 도입 시 이것만은 챙기세요
1. 백업은 복원 테스트 전까지 백업이 아닙니다 — 별도 인스턴스에 정기적으로 복원해 실제로 서비스가 뜨는지 검증해야, 장애 시점에 백업 파일이 손상돼 있었다는 사실을 미리 발견할 수 있습니다.
2. WAL 아카이빙 지연을 반드시 모니터링하세요 — archive_command가 실패하거나 업로드가 밀리면 WAL이 쌓여 디스크가 가득 차고 DB가 정지할 수 있습니다.
3. 증분 백업 체인이 길어질수록 복원 시간이 늘어납니다 — 정기적으로 풀 백업을 다시 잡아 체인을 리셋하는 보관 정책이 필요합니다.

 

마무리 — 3줄 요약

① 대용량 PostgreSQL 운영 환경에서는 pg_dump 논리 백업 대신 물리 백업과 WAL 아카이빙의 조합이 필요합니다.
② pgBackRest는 기능이 풍부하고 검증이 강력한 대신 설정이 복잡하고, WAL-G는 가볍고 오퍼레이터 생태계와 궁합이 좋습니다.
③ 백업은 정기적인 복원 리허설과 WAL 아카이빙 랙 모니터링, 증분 체인 관리 없이는 신뢰할 수 없습니다.
