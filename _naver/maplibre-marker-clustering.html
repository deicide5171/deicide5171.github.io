MapLibre GL JS 마커가 너무 많을 때 — Supercluster로 클러스터링하기

GIS

한 줄 요약 — 포인트가 수천 개를 넘으면 개별 마커 대신 GeoJSON 소스에 cluster: true만 지정해 Supercluster 기반 클러스터링을 쓰면 성능과 가독성을 동시에 해결할 수 있습니다.

 

왜 마커가 많으면 문제가 되는가

매장 위치나 매물처럼 포인트가 수천 개를 넘어가면 두 가지 문제가 생깁니다. 개별 DOM 마커를 그만큼 찍으면 팬·줌마다 브라우저가 버벅이고, 마커가 겹치면 화면이 점으로 뒤덮여 정작 필요한 정보를 읽을 수 없게 됩니다. 이를 해결하는 표준 방법이 마커 클러스터링입니다.

 

 

잘못된 접근 vs 올바른 접근

처음 구현할 때 흔히 화면의 모든 포인트 쌍 거리를 직접 계산해 묶으려 하지만, 포인트가 늘어나면 팬·줌마다 재계산되어 프레임 드랍이 눈에 띄게 발생합니다. MapLibre GL JS는 GeoJSON 소스에 cluster: true만 지정하면 내부적으로 Supercluster 라이브러리가 이 작업을 대신 처리해줍니다.

map.addSource('points', {
  type: 'geojson',
  data: 'points.geojson',
  cluster: true,
  clusterMaxZoom: 14,
  clusterRadius: 50
});

point_count 속성이 있는 피처는 클러스터(원+숫자), 없는 피처는 개별 포인트로 필터링해 서로 다른 레이어로 나눠 그립니다. Supercluster는 내부적으로 공간 인덱스를 미리 구축해두기 때문에 줌 레벨이 바뀔 때마다 빠르게 다시 계산합니다.

방식 동작 특징
직접 거리 계산 모든 쌍을 비교 데이터 늘면 급격히 느려짐
Supercluster 공간 인덱스 기반 줌 변경 시에도 빠름

 

주의 — 클러스터 원을 클릭했을 때 자동으로 확대되는 처리(getClusterExpansionZoom)를 빠뜨리면, 사용자가 클러스터를 눌러도 반응이 없어 답답함을 느낄 수 있습니다.

 

실무 포인트

데이터가 수만 개를 넘으면 클라이언트 클러스터링만으로는 부족합니다. 이 경우 Tippecanoe로 PMTiles를 만들어 줌 레벨별로 필요한 데이터만 내려주는 구조를 검토해야 합니다. 또한 clusterProperties 옵션으로 클러스터 안의 평균값·합계를 계산해 "평균 가격" 같은 정보도 함께 표시할 수 있습니다.
