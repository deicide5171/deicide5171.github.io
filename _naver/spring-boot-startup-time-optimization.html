Spring Boot 애플리케이션 시작이 느릴 때 — 부트 타임 줄이는 법

백엔드

한 줄 요약 — Spring Boot 부트 타임 개선은 짐작이 아니라 ApplicationStartup API로 실측한 뒤, 지연 초기화와 불필요한 오토컨피규레이션 제외부터 시작해야 합니다.

 

왜 부트 타임이 문제가 되는가

프로젝트 초반엔 3~4초에 뜨던 애플리케이션이 빈이 늘면서 20~30초씩 걸리기 시작합니다. 로컬 개발에서는 재시작할 때마다 이 시간이 낭비되고, 쿠버네티스 환경에서는 롤링 업데이트와 오토스케일링 반응 속도가 느려집니다.

Spring Boot 시작 시간은 JVM 기동, 클래스패스 스캔, 빈 초기화 세 구간으로 나뉩니다. 어느 구간이 느린지 먼저 구분해야 정확한 최적화가 가능합니다.

 

어디가 느린지부터 측정하라
SpringApplication app = new SpringApplication(Application.class);
app.setApplicationStartup(new BufferingApplicationStartup(2048));
app.run(args);

이렇게 하면 어떤 빈, 어떤 오토컨피규레이션 클래스가 시간을 많이 쓰는지 실측할 수 있습니다. 짐작으로 최적화를 시작하면 엉뚱한 곳을 손대고 시간만 낭비하기 쉽습니다.

 

잘못된 접근 vs 올바른 접근

흔한 실수는 컴포넌트 스캔 범위부터 좁히는 것이지만, 실제 병목은 대개 오토컨피규레이션 조건 평가와 외부 연결(DB 커넥션 풀, 메시지 브로커) 초기화에서 발생합니다. 스캔 범위만 좁히면 체감 개선이 거의 없습니다.

spring:
  main:
    lazy-initialization: true

지연 초기화를 켜면 빈을 실제로 필요할 때까지 생성하지 않습니다. 다만 첫 요청 지연이 민감한 서비스라면 헬스체크로 워밍업을 별도로 태워야 합니다. 여기에 더해 HikariCP의 minimum-idle을 필요 이상으로 크게 잡지 않는 것도 시작 시간을 줄이는 데 도움이 됩니다.

주의 — 콜드 스타트 자체가 병목이라면 AppCDS(Class Data Sharing)나 GraalVM Native Image 같은 JVM 레벨 해법까지 검토해야 합니다.

 

실무 포인트

로컬 개발과 운영 환경의 최적화 목표를 구분하세요. 로컬은 반복 재시작 체감을, 운영은 오토스케일링 반응성을 줄이는 데 집중해야 합니다. 또한 지연 초기화는 순환 참조나 초기화 순서에 의존하는 코드에서 예상치 못한 버그를 드러낼 수 있으므로, 도입 전 통합 테스트로 부작용을 확인하세요.
