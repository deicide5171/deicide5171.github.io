DB 백업 기초 — 논리 백업과 물리 백업, 무엇을 언제 쓸까

2026. 9. 4. · 데이터베이스

한 줄 요약 — 논리 백업은 이식성이 좋고 물리 백업은 대용량에 빠르며, 복구 테스트를 안 한 백업은 신뢰할 수 없습니다.

 

백업이 있다고 안심하면 안 되는 이유

"백업을 돌리고 있으니 괜찮다"는 절반만 맞습니다. 그 백업으로 실제 복구가 되는지 확인한 적이 없다면 데이터를 못 살릴 수 있습니다. 어떻게 백업하는가와 어떻게 복구하는가를 함께 봐야 합니다.

 

논리 백업 vs 물리 백업
항목 논리 백업 물리 백업
방식 SQL로 추출 DB 파일 통째로 복사
도구 mysqldump, pg_dump 스냅샷, pg_basebackup
이식성 좋음 제한적(같은 버전 권장)

 

논리 백업 예제
pg_dump -U user mydb > backup.sql   # 백업
psql -U user mydb < backup.sql      # 복구

 

백업 전략의 핵심 개념
RPO: 데이터를 얼마나 잃어도 되는가 -> 백업 주기 결정
RTO: 얼마나 빨리 복구해야 하는가 -> 백업·복구 방식 결정

 

실무 포인트

복구 테스트를 안 한 백업은 백업이 아닙니다. 정기적으로 실제 복구가 되는지 검증해야 진짜 대비가 됩니다.

주의 — 백업을 원본과 같은 서버·디스크에만 두면 서버가 망가질 때 함께 사라집니다. 반드시 별도 위치(다른 서버, 클라우드 스토리지)에 보관하세요.
