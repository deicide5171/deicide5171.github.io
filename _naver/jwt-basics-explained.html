JWT가 뭔가요 — 토큰 구조와 세션과의 차이

2026. 9. 2. · 백엔드

한 줄 요약 — JWT는 사용자 정보를 토큰 자체에 담아 서버가 세션을 저장하지 않아도 되게 만들지만, 즉시 무효화가 어렵다는 근본적 한계가 있습니다.

 

왜 서버가 로그인 상태를 기억하지 않아도 되는가

전통적인 세션 방식은 서버가 세션 정보를 저장하고 클라이언트에게 세션 ID만 줍니다. JWT는 이 저장 단계를 없애고, 사용자 정보 자체를 토큰에 담아 클라이언트에게 주며 서버는 위조되지 않았는지만 검증합니다.

 

JWT의 세 부분 구조
부분 담는 내용
Header 서명 알고리즘 정보
Payload 사용자 정보(claims)
Signature 위조 검증용 서명

중요: Payload는 암호화가 아니라 단순 Base64 인코딩입니다. 누구나 디코딩해 읽을 수 있으므로 비밀번호나 개인정보를 담으면 안 됩니다.

 

세션 방식과의 비교
항목 세션 JWT
서버 저장 필요 불필요
즉시 무효화 쉬움 어려움

 

예제 — JWT 생성과 검증
String token = Jwts.builder()
        .subject("user123")
        .expiration(new Date(System.currentTimeMillis() + 3600_000))
        .signWith(secretKey)
        .compact();

Claims claims = Jwts.parser()
        .verifyWith(secretKey)
        .build()
        .parseSignedClaims(token)
        .getPayload();

 

실무 포인트

액세스 토큰은 짧게(수 분~1시간), 리프레시 토큰은 길게 발급하는 패턴이 표준입니다. 탈취되더라도 피해 시간이 짧아집니다.

주의 — JWT를 localStorage에 저장하면 XSS에 노출됩니다. HttpOnly 쿠키가 더 안전하지만 CSRF 방어를 함께 고려해야 합니다.
