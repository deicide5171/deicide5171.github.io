헬스 체크가 뭔가요 — 서버가 살아있는지 확인하는 법

시스템 디자인

한 줄 요약 — 헬스 체크는 서버가 정상인지 주기적으로 확인해 죽은 서버로 트래픽이 가지 않게 하며, liveness/readiness로 나뉩니다.

 

죽은 서버로 트래픽을 보내면 안 된다

로드 밸런서가 여러 서버에 트래픽을 나눠줍니다. 서버 하나가 죽었는데 계속 요청을 보내면 사용자는 에러를 받죠. 이를 막으려면 각 서버가 정상인지 주기적으로 확인해야 합니다. 이 절차가 헬스 체크이며, 보통 /health로 요청해 응답을 봅니다.

 

어떻게 동작하나
LB -> 각 서버의 /health 로 주기적 요청
  서버A: 200 OK    -> 정상, 트래픽 보냄
  서버B: 응답 없음  -> 비정상, 트래픽 제외
  (다시 정상이면 트래픽 재개)

 

Liveness와 Readiness
구분 질문 실패 시
Liveness 살아있나? 재시작
Readiness 준비됐나? 트래픽만 뺌

 

실무 포인트

단순 200만 반환하면 DB가 끊겨도 "정상"으로 보입니다. 필요한 의존성까지 점검하되 너무 무겁지 않게 하세요. "몇 번 연속 실패 시 제외" 같은 임계값으로 일시적 흔들림에 과민 반응하지 않게 합니다.

주의 — liveness에 DB 점검까지 넣으면, DB 일시 장애로 멀쩡한 앱들이 줄줄이 재시작됩니다. liveness는 가볍게 "프로세스가 응답하나"만 보세요.
