시간까지 지도에 담다 — Cesium CZML로 만드는 시계열 동적 엔티티

2026. 8. 24. · GIS

한 줄 요약 — 위성 궤도나 차량 이동처럼 시간에 따라 위치가 바뀌는 데이터를 GeoJSON으로는 표현할 수 없는 이유를 짚고, Cesium의 CZML 포맷으로 시계열 동적 엔티티를 만드는 법을 정리했습니다.

 

GeoJSON으로는 왜 부족할까요

위성이 지구를 도는 궤적, 배송 차량의 실시간 이동 경로, 태풍의 시간별 진로 — 이런 데이터는 "지금 여기 있다"는 정적인 좌표 하나로는 표현이 안 됩니다. GeoJSON은 애초에 시간 축이라는 개념이 없어서, 시간대별 스냅샷을 여러 Feature로 쪼개 넣거나 매 프레임 애플리케이션 코드로 좌표를 다시 계산해 넣어야 하는 번거로움이 생깁니다.

Cesium의 CZML(Cesium Language)은 이 문제를 포맷 레벨에서 해결합니다. 하나의 엔티티에 여러 시각의 좌표 샘플을 담고, Cesium 뷰어가 타임라인(Clock)이 흐르는 대로 그 사이를 보간해 부드럽게 움직이는 것까지 자동으로 처리합니다.

 

핵심 개념 1 — CZML의 패킷 구조

CZML은 JSON 배열이며, 배열의 각 원소를 "패킷(packet)"이라 부릅니다. cartographicDegrees는 [초, 경도, 위도, 고도]가 반복되는 시퀀스입니다. Cesium은 clock.currentTime이 두 샘플 사이를 지날 때 interpolationAlgorithm(LINEAR, LAGRANGE, HERMITE)에 따라 중간 위치를 계산합니다.

{
  "id": "satellite-1",
  "position": {
    "epoch": "2026-08-24T09:00:00Z",
    "cartographicDegrees": [
      0,    127.0, 37.5, 700000,
      3600, 135.2, 40.1, 705000,
      7200, 142.8, 35.3, 698000
    ],
    "interpolationAlgorithm": "LAGRANGE",
    "interpolationDegree": 2
  }
}

 

 

핵심 개념 2 — GeoJSON·KML과 시간 지원 비교
구분 GeoJSON KML CZML
시간 축 지원 없음 gx:Track 제한적 네이티브
보간 방식 직접 구현 선형만 LINEAR/LAGRANGE/HERMITE
주 사용처 정적 벡터 데이터 Google Earth 경로 Cesium 3D 시계열

 

예제 — CZML 로드와 Clock 바인딩
const viewer = new Cesium.Viewer("cesiumContainer");

const dataSource = await Cesium.CzmlDataSource.load("satellite-track.czml");
viewer.dataSources.add(dataSource);

viewer.clock.shouldAnimate = true;
viewer.timeline.zoomTo(dataSource.clock.startTime, dataSource.clock.stopTime);
viewer.trackedEntity = dataSource.entities.getById("satellite-1");

 

실무 도입 시 이것만은 챙기세요
1. 샘플 간격과 보간 알고리즘을 데이터 특성에 맞추세요 — 잘못된 보간 알고리즘 선택은 실제로 존재하지 않는 경로로 엔티티가 미끄러지는 시각적 오류를 만듭니다.
2. 대량 엔티티는 availability 기반으로 로드를 줄이세요 — availability 구간을 짧게 나눠 필요한 시간대의 패킷만 스트리밍으로 추가하는 방식이 실무에서 쓰입니다.
3. 좌표 정밀도와 고도 처리를 미리 검증하세요 — 고도 값을 빠뜨리면 지형 위에 파묻히거나 붕 뜨는 렌더링 오류가 흔히 발생합니다.

 

마무리 — 3줄 요약

① CZML은 하나의 엔티티에 여러 시각의 좌표 샘플을 담고 Cesium이 Clock 진행에 맞춰 자동 보간하는 포맷입니다.
② GeoJSON/KML은 시간 축을 네이티브로 지원하지 않지만, CZML은 이 책임을 포맷과 렌더러로 옮깁니다.
③ 데이터 특성에 맞는 보간 알고리즘 선택과 대량 엔티티에서의 스트리밍 로드가 실무 적용의 핵심입니다.
