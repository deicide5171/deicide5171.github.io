## localhost:8080의 8080은 뭔가

로컬에서 서버를 띄우면 `localhost:8080` 같은 주소로 접속한다. IP 주소가 "건물 주소"라면 **포트(port)는 그 건물 안의 방 번호**다. 한 서버(IP)에서 여러 프로그램이 동시에 돌 때, 어느 프로그램으로 연결할지를 **포트 번호**로 구분한다. 웹 서버는 보통 방 번호 80(HTTP)·443(HTTPS)을 쓴다.

## 자주 쓰는 포트

| 포트 | 용도 |
|---|---|
| 80 | HTTP(웹) |
| 443 | HTTPS(보안 웹) |
| 22 | SSH(서버 접속) |
| 3306 / 5432 | MySQL / PostgreSQL |

## 포트 포워딩

```text
포트 포워딩: 한 포트로 온 요청을 다른 곳/포트로 넘기는 것

예1) 공유기 외부 8080 -> 내부 PC의 80으로 전달
예2) docker run -p 8080:80
     내 PC 8080 -> 컨테이너 안 80으로 연결
접속: localhost:8080 -> 컨테이너의 웹서버(80)에 도달
```

## 실무 포인트

- **`-p 호스트:컨테이너` 순서를 헷갈리지 마라.** 도커의 `-p 8080:80`은 "내 PC의 8080을 컨테이너의 80에 연결"이다. 왼쪽이 밖(호스트), 오른쪽이 안(컨테이너)이다. 순서를 바꾸면 접속이 안 된다.
- **1024 미만 포트는 권한이 필요하다.** 80·443 같은 낮은 번호는 관리자 권한이 있어야 열 수 있다. 개발 중엔 8080·3000처럼 높은 번호를 쓰고, 실제 배포에선 리버스 프록시가 80·443을 받는 경우가 많다.
- **방화벽에서 포트를 열어야 외부 접속이 된다.** 서버 안에서 포트를 열어도, 방화벽/보안 그룹에서 해당 포트를 허용하지 않으면 외부에서 접속되지 않는다. 접속이 안 되면 방화벽 규칙부터 확인한다.

## 마무리 요약

- 포트는 한 IP(서버)에서 여러 프로그램을 구분하는 "방 번호"다(웹 80/443, SSH 22 등).
- 포트 포워딩은 한 포트로 온 요청을 다른 포트/대상으로 넘기는 것(도커 `-p 8080:80` 등)이다.
- `호스트:컨테이너` 순서, 낮은 포트 권한, 방화벽 허용을 확인해야 접속이 정상 동작한다.
