## 왜 지금 :has()를 알아야 하나

"체크박스가 체크되면 부모 카드에 테두리를 넣고 싶다", "이미지가 없는 카드는 레이아웃을 다르게 하고 싶다" — 이런 요구사항은 프론트엔드 개발에서 계속 반복된다. CSS는 오랫동안 부모나 형제 요소를 "자식의 상태를 보고" 선택하는 방법이 없었다. `.parent .child`처럼 아래 방향 선택은 되지만, 그 반대인 "자식 조건에 맞는 부모 찾기"는 불가능했다. 그래서 이런 상황이 오면 대부분 자바스크립트로 클래스를 토글하거나, 상태 관리 라이브러리에 로직을 추가하는 식으로 우회했다.

주요 브라우저(Chrome, Safari, Firefox)가 모두 `:has()`를 지원하면서 이 제약이 실제로 풀렸다. `:has()`는 "관계 선택자를 위한 선택자(relational pseudo-class)"로, 괄호 안 조건에 맞는 자식·형제를 포함하는 요소 자체를 선택할 수 있다.

## 기본 문법과 동작 방식

```css
/* 이미지를 포함한 카드에만 특별한 패딩 적용 */
.card:has(img) {
  padding: 0;
}

/* 체크된 체크박스를 포함한 라벨의 배경색 변경 */
label:has(input:checked) {
  background-color: #e8f5e9;
}

/* 다음 형제로 h2가 있는 경우 (형제 결합자와 조합) */
h1:has(+ h2) {
  margin-bottom: 4px;
}
```

기존 셀렉터와 결합자를 `:has()` 괄호 안에 그대로 쓸 수 있다는 점이 핵심이다. 자손 결합자, 형제 결합자, 속성 선택자, 심지어 다른 가상 클래스까지 조합할 수 있어 표현력이 매우 넓다.

## 잘못된 접근: 자바스크립트로만 해결하던 시절의 습관

`:has()` 이전에는 폼 유효성 표시 같은 것도 대부분 이런 식이었다.

```javascript
input.addEventListener('input', () => {
  const parent = input.closest('.form-group');
  if (input.validity.valid) {
    parent.classList.add('is-valid');
  } else {
    parent.classList.remove('is-valid');
  }
});
```

이 방식은 동작은 하지만, 스타일링 로직이 CSS와 JS 두 곳에 흩어진다. 상태가 바뀌는 모든 지점마다 이벤트 리스너를 달아야 하고, 컴포넌트가 많아질수록 리스너 등록·해제 관리가 번거로워진다. 특히 서버 사이드 렌더링 환경에서는 하이드레이션이 끝나기 전까지 스타일이 적용되지 않아 화면이 잠깐 깨져 보이는 현상(FOUC와 유사한 문제)도 생긴다.

## 올바른 접근

```css
.form-group:has(input:invalid:not(:placeholder-shown)) {
  border-color: #d32f2f;
}
.form-group:has(input:valid) {
  border-color: #2e7d32;
}
```

이렇게 하면 자바스크립트 이벤트 리스너 없이, 브라우저의 네이티브 유효성 검사 상태(`:valid`, `:invalid`)만으로 스타일이 즉시 반영된다. 렌더링 전에 스타일이 이미 결정되므로 하이드레이션 지연으로 인한 깜빡임도 없다.

레이아웃 조건 분기에도 유용하다. "라디오 그룹에서 특정 옵션이 선택되면 관련 섹션을 표시"하는 패턴도 `display: none`과 `:has()` 조합만으로 자바스크립트 없이 구현할 수 있다.

## 실무 포인트

- **`:has()`는 상위 방향으로만이 아니라 조건 필터로도 쓸 수 있다.** `body:has(.modal-open)`처럼 최상위 요소에 걸어서, 모달이 열렸을 때 배경 스크롤을 막는 패턴도 클래스 토글 자바스크립트 없이 구현 가능하다.
- **성능은 대체로 괜찮지만 무분별한 남용은 피하라.** `:has()`는 내부적으로 매칭 비용이 다른 선택자보다 높다. 큰 DOM 트리에서 매우 넓은 범위(`html:has(...)` 같은)로 걸면 리플로우 비용이 늘 수 있으니, 가능한 한 범위를 좁혀서 사용한다.
- **구형 브라우저 지원이 필요하면 폴백을 준비하라.** 사내 관리자 도구처럼 특정 구형 브라우저를 반드시 지원해야 하는 프로젝트라면 `@supports selector(:has(a))`로 지원 여부를 감지하고 자바스크립트 폴백을 병행한다.
- **CSS 안에서 상태 로직이 너무 복잡해지면 오히려 가독성이 떨어진다.** 조건이 3단계 이상 중첩되면 자바스크립트로 클래스를 명시적으로 다는 편이 유지보수에 유리할 수 있다는 점도 함께 고려한다.

- **`:has()` 안에 `:has()`를 중첩하거나 `,`로 여러 조건을 나열할 수도 있다.** `.card:has(img, video)`처럼 쉼표로 여러 자식 유형을 한 번에 검사하거나, `.list:has(li:nth-child(5))`처럼 특정 개수 이상의 항목이 있을 때만 스타일을 바꾸는 것도 가능하다. 이런 표현력 덕분에 "항목이 5개 이상이면 스크롤 컨테이너로 전환" 같은 조건부 레이아웃도 CSS만으로 처리할 수 있다.

## 마무리 요약

- `:has()`는 자식·형제 조건으로 부모를 선택할 수 있게 해주는 관계 선택자로, 주요 브라우저에서 이미 사용 가능하다.
- 폼 유효성 표시, 모달 배경 제어 같은 패턴을 자바스크립트 없이 순수 CSS로 옮길 수 있다.
- 매칭 비용과 가독성을 고려해 범위를 좁혀 쓰고, 필요하면 `@supports`로 폴백을 준비한다.
