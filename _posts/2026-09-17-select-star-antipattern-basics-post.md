## SELECT * 는 편하지만 대가가 있다

`SELECT *`는 모든 컬럼을 가져오라는 뜻이라 타이핑이 편하다. 하지만 실무에서는 **필요한 컬럼만 명시**하는 것이 권장된다. `SELECT *`가 여러 문제를 일으킬 수 있기 때문이다.

## SELECT * 의 문제

| 문제 | 설명 |
|---|---|
| 불필요한 전송 | 안 쓰는 컬럼까지 다 읽고 전송 |
| 커버링 인덱스 무력화 | 인덱스만으로 못 끝내고 테이블 접근 |
| 스키마 변경에 취약 | 컬럼 추가/변경 시 예상 밖 동작 |
| 큰 컬럼까지 로드 | TEXT·BLOB 같은 무거운 값도 함께 |

## 대신 이렇게

```sql
-- 지양
SELECT * FROM users WHERE id = 1;

-- 권장: 필요한 것만
SELECT id, name, email FROM users WHERE id = 1;
```

## 실무 포인트

- **네트워크·메모리를 아낀다.** 화면에 이름만 보여줄 건데 `SELECT *`로 프로필 사진·긴 소개글까지 다 가져오면 낭비다. 필요한 컬럼만 고르면 전송량과 메모리가 준다.
- **커버링 인덱스를 살린다.** 조회하는 컬럼이 모두 인덱스에 있으면 테이블을 안 봐도 돼(커버링 인덱스) 빠르다. `SELECT *`는 모든 컬럼을 요구해 이 최적화를 못 쓴다.
- **스키마 변경에 안전.** `SELECT *` 결과의 컬럼 순서·개수에 코드가 의존하면, 나중에 컬럼이 추가되며 깨질 수 있다. 필요한 컬럼을 명시하면 이런 위험이 없다.

## 마무리 요약

- `SELECT *`는 편하지만 불필요한 전송, 커버링 인덱스 무력화, 스키마 변경 취약 등의 문제가 있다.
- 필요한 컬럼만 명시(`SELECT id, name`)하면 성능·안정성이 좋아진다.
- 특히 큰 컬럼(TEXT·BLOB)이 있거나 인덱스를 활용하려면 컬럼을 골라 조회한다.
