도심 지하에는 상수도관, 하수관, 통신관, 전력구, 가스관이 서로 다른 기관에 의해 서로 다른 시기에 매설된다. 각 기관이 자기 관로만 2D 평면도로 관리하면, 그 도면들을 겹쳐 봤을 때 실제로 깊이(z값)까지 충돌하는지, 아니면 단순히 평면상 위치만 겹치는지 알 수 없다. 굴착 공사 중 통신관을 절단하거나 가스관을 훼손하는 사고의 상당수가 이 "평면도만으로는 안 보이는 깊이 충돌"에서 비롯된다. **지하 시설물 3D 모델링**은 이 문제를 각 시설물에 정확한 깊이·형상 정보를 부여해 3차원 공간에서 실제 간섭 여부를 검토할 수 있게 만드는 작업이다.

이 글은 지하 시설물을 3D로 다룰 때 부딪히는 세 가지 실무 문제 — 좌표계와 깊이 기준의 정합, 데이터 표준의 파편화, 지상 건축(BIM)과 지하 시설물(GIS) 데이터를 하나의 좌표 공간에서 다루는 연계 — 를 정리한다.

## 핵심 개념 1: 깊이(z값) 기준의 정합이 가장 먼저 무너지는 지점

지하 시설물의 3D 모델링에서 가장 먼저 부딪히는 문제는 의외로 좌표계의 xy축이 아니라 **z값(깊이/표고)의 기준**이다. 어떤 기관은 지표면 기준 상대 깊이("지표하 1.2m")로 기록하고, 어떤 기관은 특정 수준점을 기준으로 한 절대 표고(EL. 23.4m)로 기록한다. 지표면 자체가 도로 재포장이나 지반 침하로 시간에 따라 변하기 때문에, 상대 깊이로만 기록된 오래된 데이터는 현재 지표 기준으로 정확히 몇 m인지 재계산이 필요하다. 여러 기관의 시설물을 하나의 3D 공간에 통합하려면 이 z값들을 반드시 같은 수직 기준면(vertical datum)으로 통일하는 좌표 변환 단계가 선행돼야 하고, 이 단계를 건너뛰면 실제로는 안전한 이격 거리를 확보한 두 시설물이 모델 상에서는 충돌하는 것처럼 나타나거나, 반대로 실제 충돌을 놓치는 결과가 나온다.

## 핵심 개념 2: 데이터 표준의 파편화 — CityGML Utility Network ADE와 각국 표준

지상 건물의 3D 표준화는 CityGML이 상당히 자리를 잡았지만, 지하 시설물은 표준화가 더 파편화돼 있다. CityGML은 **Utility Network ADE(Application Domain Extension)**라는 확장 모듈로 상수·하수·전력·통신 같은 네트워크형 시설물을 노드(맨홀, 밸브 등)와 링크(관로 구간)의 그래프 구조로 표현하는 방법을 정의하지만, 실제 현장에서는 국가·지자체별 지하시설물 관리 표준(국내는 국토교통부의 지하공간통합지도 구축 지침 등)이 별도로 존재해서, 데이터를 주고받으려면 그 사이의 스키마 매핑이 필요하다.

| 표준/체계 | 초점 | 표현 방식 |
|---|---|---|
| CityGML Utility Network ADE | 국제 표준, 지상 3D와 통합 지향 | 노드-링크 그래프 + LOD별 형상 |
| 국내 지하공간통합지도 | 국내 지하시설물 통합 관리 | 시설물 종류별 속성·형상 스키마 |
| IFC(건축 BIM 표준) | 건축·구조 부재 단위 | 부재 객체 + 속성 세트 |

노드-링크 그래프 구조가 중요한 이유는, 지하 시설물의 실제 관심사가 "관이 어디 있는가"를 넘어 "이 관이 막히면 어느 구간이 단수되는가" 같은 네트워크 위상 분석이기 때문이다. 형상(geometry)만 저장하고 연결 관계(topology)를 저장하지 않으면 이런 분석 자체가 불가능해진다.

## 핵심 개념 3: BIM-GIS 연계 — 서로 다른 세계의 좌표를 맞춘다

지상 건축물은 BIM(Building Information Modeling, 대표 포맷 IFC)으로, 지하 시설물과 지형은 GIS(대표 포맷 CityGML, 3D Tiles)로 따로 발전해 왔다. 문제는 지하 주차장, 지하철역, 공동구처럼 지상 건축물과 지하 시설물이 실제로 맞닿거나 교차하는 프로젝트에서 발생한다. BIM은 보통 건물 자체를 원점으로 하는 **로컬 좌표계**를 쓰고, GIS는 지리 좌표계(위경도나 투영좌표계)를 쓰기 때문에, 두 데이터를 겹쳐 보려면 로컬 좌표계를 지리 좌표계로 정확히 변환하는 **지오레퍼런싱(georeferencing)** 작업이 필요하다.

이 변환에서 흔히 놓치는 것이 수평 좌표뿐 아니라 수직 기준면까지 맞춰야 한다는 점이다. BIM 모델의 0m는 대개 그 건물의 기준층 바닥이고, GIS의 표고는 앞서 언급한 수직 기준면(예: 인천만 평균해수면 기준 등)을 따른다. 이 둘을 연결하는 정확한 오프셋 값이 없으면, 지하 주차장 모델을 지하 시설물 지도 위에 올렸을 때 실제로는 안 겹치는 두 구조물이 겹쳐 보이거나 그 반대의 착시가 생긴다.

## 예제: 지하 시설물 충돌 검토 쿼리 (PostGIS 3D)

```sql
-- 두 시설물 레이어를 동일 수직 기준면으로 정규화한 뒤 3D 버퍼 충돌 검토
-- (사전 조건: depth_offset 컬럼에 각 데이터셋의 수직 기준면 보정값을 미리 반영)

WITH normalized_pipes AS (
  SELECT
    id,
    facility_type,
    ST_Translate(geom, 0, 0, depth_offset) AS geom_3d  -- z값을 통일 기준면으로 이동
  FROM underground_facilities
)
SELECT
  a.id   AS facility_a,
  a.facility_type AS type_a,
  b.id   AS facility_b,
  b.facility_type AS type_b,
  ST_3DDistance(a.geom_3d, b.geom_3d) AS clearance_m
FROM normalized_pipes a
JOIN normalized_pipes b
  ON a.id < b.id
 AND ST_3DDWithin(a.geom_3d, b.geom_3d, 1.0)  -- 1m 이내로 근접한 쌍만 검토 대상
WHERE ST_3DDistance(a.geom_3d, b.geom_3d) < 0.3  -- 최소 이격거리 30cm 미만 = 위험
ORDER BY clearance_m ASC;
```

이 쿼리는 모든 시설물 쌍을 무차별 비교하지 않고 `ST_3DDWithin`으로 1차 후보를 좁힌 뒤 정확한 3D 거리(`ST_3DDistance`)를 계산하는 구조라, 데이터 규모가 커져도 계산량을 억제한다. 실무에서는 이 결과를 굴착 공사 계획 단계의 사전 검토 리포트로 자동 생성하는 파이프라인에 연결하는 경우가 많다.

## 실무 포인트

- **오래된 지하시설물 도면의 z값은 그 자체로 신뢰하지 마라.** 특히 상대 깊이로만 기록된 옛 도면은 지표면 변화를 반영하지 못했을 가능성이 높다. 실제 굴착·공사 이력이 있는 구간은 최신 실측(GPR 탐사, 시험굴착) 데이터로 z값을 갱신하는 절차를 거쳐야 3D 모델의 신뢰도가 의미를 갖는다.
- **네트워크 위상 없이 형상만 모델링하면 절반의 가치만 얻는다.** "이 관이 어디 있는가"만 보여주는 3D 모델은 시각화 자료로는 유용하지만, 실제 운영에 필요한 "이 구간을 차단하면 어디까지 영향을 받는가" 같은 분석에는 노드-링크 위상 데이터가 반드시 필요하다.
- **BIM-GIS 연계 프로젝트는 좌표 변환 검증을 프로젝트 초기에 별도 태스크로 분리하라.** 좌표계 불일치는 나중에 발견될수록 되돌리는 비용이 기하급수적으로 커진다. 두 데이터셋을 실제로 합치기 전에, 알려진 기준점(측량 기준점, 맨홀 위치 등) 몇 곳을 골라 변환 후 좌표가 실측치와 일치하는지 먼저 검증해야 한다.

## 3줄 요약

- 지하 시설물의 3D 모델링에서 가장 먼저 무너지는 것은 xy 좌표가 아니라 z값(깊이/표고)의 기준 정합이며, 여러 기관 데이터를 통합하려면 반드시 동일한 수직 기준면으로 변환해야 한다.
- CityGML Utility Network ADE 같은 국제 표준과 각국 고유 표준이 병존해 데이터 표준이 파편화돼 있고, 형상뿐 아니라 노드-링크 위상 정보를 함께 저장해야 실질적인 네트워크 분석이 가능하다.
- 지상 BIM과 지하 GIS 데이터를 겹쳐야 하는 프로젝트는 로컬 좌표계와 지리 좌표계 사이의 지오레퍼런싱, 특히 수직 기준면 오프셋을 프로젝트 초기에 별도로 검증해야 나중에 큰 비용을 치르지 않는다.
