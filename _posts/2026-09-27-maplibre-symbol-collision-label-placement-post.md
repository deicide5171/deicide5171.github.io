## 왜 라벨 배치가 지도 렌더링에서 가장 까다로운 문제인가

벡터 타일에는 도시명, 도로명, POI(관심 지점) 라벨이 수만 개씩 들어있는데, 이걸 그냥 다 그리면 화면이 텍스트로 뒤덮여 아무것도 읽을 수 없다. 문제를 더 어렵게 만드는 것은 이 계산이 정적으로 한 번 끝나는 게 아니라 사용자가 지도를 확대·축소·회전·이동할 때마다 실시간으로 다시 계산되어야 한다는 점이다. 게다가 라벨이 프레임마다 갑자기 나타났다 사라지면 눈에 거슬리므로 부드러운 전환까지 신경 써야 한다. MapLibre GL JS(그리고 그 조상인 Mapbox GL JS)는 이 문제를 심볼 배치와 충돌 감지를 매 프레임 GPU와 CPU가 나눠 처리하는 파이프라인으로 해결한다.

## 핵심 개념 1 — 우선순위 정렬과 그리드 기반 공간 인덱스

첫 단계는 화면에 그려질 후보 심볼들을 **배치 우선순위**로 정렬하는 것이다. 우선순위는 줌 레벨(작은 도시보다 대도시가 먼저), 스타일 레이어에 명시한 `symbol-sort-key`, 소스 데이터의 등장 순서 같은 여러 기준의 조합으로 결정된다. 그다음 화면 공간을 격자(grid)로 나누고, 각 심볼의 텍스트 바운딩 박스가 어느 셀들에 걸치는지 계산해 공간 인덱스에 등록한다. 이렇게 그리드로 미리 나눠두면, 새로운 심볼을 배치할 때 화면 전체의 다른 모든 심볼과 일일이 비교하는 대신 겹치는 셀에 이미 등록된 심볼만 확인하면 되므로 연산량이 크게 줄어든다.

## 핵심 개념 2 — 우선순위 순서대로 겹침을 확정하고 숨기기

우선순위가 높은 심볼부터 순서대로 그리드에 등록을 시도한다. 어떤 심볼의 바운딩 박스가 이미 등록된(즉 더 높은 우선순위로 확정된) 다른 심볼과 겹치면, 그 심볼은 이번 프레임에서 표시하지 않기로 결정된다. 이 과정을 모든 후보에 대해 반복하면, 최종적으로 서로 겹치지 않는 심볼 집합만 남는다. 텍스트 라벨과 아이콘은 별도의 충돌 판정 그룹으로 처리될 수 있어(`icon-allow-overlap`, `text-allow-overlap` 등의 스타일 속성으로 제어), 아이콘은 겹쳐도 되지만 텍스트는 겹치면 안 되는 것 같은 세밀한 제어가 가능하다. 카메라가 움직이면 이 전체 계산이 매 프레임 다시 수행되는데, 이때 새로 나타나거나 사라지는 라벨은 즉시 튀어나오지 않고 opacity 트랜지션으로 페이드 인/아웃되어 시각적으로 부드럽게 처리된다.

| 단계 | 처리 내용 |
|---|---|
| 1. 우선순위 정렬 | 줌 레벨, sort-key, 데이터 등장 순서로 심볼 순서 결정 |
| 2. 그리드 인덱싱 | 화면을 격자로 나눠 심볼 바운딩 박스를 셀에 등록 |
| 3. 충돌 판정 | 우선순위 순서대로 겹치는 셀 확인, 겹치면 숨김 |
| 4. 부드러운 전환 | 표시/숨김 전환 시 opacity 트랜지션으로 페이드 처리 |

## 코드 예제 — sort-key와 충돌 허용 옵션 제어

```javascript
map.addLayer({
  id: 'city-labels',
  type: 'symbol',
  source: 'places',
  layout: {
    'text-field': ['get', 'name'],
    'text-size': 14,
    // 인구가 많은 도시일수록 먼저 배치되어 충돌 시 우선권을 갖는다
    'symbol-sort-key': ['-', 0, ['get', 'population']],
    'text-allow-overlap': false,   // 텍스트끼리는 겹치면 숨김
    'icon-allow-overlap': true,    // 아이콘은 겹쳐도 항상 표시
    'text-optional': true,         // 아이콘은 남기고 텍스트만 숨기는 것을 허용
  },
  paint: { 'text-color': '#222' },
});
```

## 실무 포인트

- **`symbol-sort-key`를 명시적으로 설정하지 않으면 데이터 순서에 의존한다.** 중요한 지명이 우연히 데이터 뒤쪽에 있으면 덜 중요한 라벨에 밀려 숨겨질 수 있으므로, 인구·중요도 같은 명확한 기준으로 정렬 키를 지정하는 것이 안전하다.
- **`text-optional: true`로 정보 손실을 최소화할 수 있다.** 텍스트와 아이콘을 하나의 심볼로 묶었을 때, 공간이 부족하면 아이콘만 남기고 텍스트를 숨기는 것을 허용하면 완전히 사라지는 것보다 사용자에게 더 많은 정보를 남길 수 있다.
- **회전·틸트된 지도에서는 충돌 판정이 더 비싸진다.** 3D 틸트 상태에서는 화면상 심볼의 투영된 바운딩 박스가 매 프레임 다르게 계산되므로, 라벨이 많은 스타일에서는 이 재계산 비용이 프레임 드랍의 원인이 될 수 있다. 필요 이상으로 많은 라벨 레이어를 동시에 켜두지 않는 것이 성능에 도움이 된다.

## 마무리 요약

- MapLibre는 매 프레임 우선순위 정렬과 그리드 기반 공간 인덱스로 심볼 간 충돌을 판정해, 화면 전체를 일일이 비교하지 않고도 효율적으로 겹치는 라벨을 걸러낸다.
- `symbol-sort-key`, `text-allow-overlap`, `icon-allow-overlap`, `text-optional` 같은 스타일 속성으로 어떤 라벨이 우선권을 갖고 어떻게 겹침을 처리할지 세밀하게 제어할 수 있다.
- 표시/숨김 전환은 즉시가 아니라 opacity 페이드로 부드럽게 처리되며, 3D 틸트 상태에서는 재계산 비용이 커지므로 라벨 레이어 수를 신중히 관리해야 한다.
