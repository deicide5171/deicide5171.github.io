## 왜 모른다고 하지 않고 지어내는가

LLM에게 존재하지 않는 논문이나 API 함수를 물으면, "모릅니다"가 아니라 그럴듯한 제목과 설명을 만들어 답하는 경우가 있다. 이를 **환각(hallucination)**이라 부른다. 이 현상이 생기는 근본 원인은 LLM의 동작 방식 자체에 있다. LLM은 사실을 저장했다가 꺼내오는 검색엔진이 아니라, **다음에 올 확률이 가장 높은 단어를 예측**해서 문장을 생성하는 모델이다. "모른다"라는 답보다 그럴듯한 답을 만드는 패턴이 학습 데이터에 더 많으면, 모델은 자신 있게 틀린 답을 내놓는다.

## 환각이 잘 발생하는 상황

| 상황 | 이유 |
|---|---|
| 최신 정보 질문 | 학습 데이터에 없는 시점의 사실을 추측해서 답함 |
| 구체적인 수치·통계 | 대략적인 패턴은 알아도 정확한 숫자는 그럴듯하게 지어냄 |
| 존재하지 않는 API/함수 이름 | 비슷한 이름의 실제 API 패턴을 따라 그럴듯한 이름을 생성 |
| 출처가 필요한 인용 | 논문·기사 제목과 저자를 실제처럼 조합해서 만들어냄 |

## 환각을 줄이는 실무 기법

```text
1. RAG(검색 증강 생성) 적용
   - 실제 문서를 검색해 프롬프트에 근거로 넣으면 지어낼 필요가 줄어든다

2. "모르면 모른다고 답해"를 명시적으로 지시
   - 프롬프트에 이 지시가 없으면 모델은 기본적으로 답을 만들어내려는 경향이 있다

3. 출처 요구하기
   - "이 정보의 출처를 함께 알려줘"라고 요청하면, 출처를 댈 수 없는 지어낸 정보인지
     스스로 드러나는 경우가 있다 (다만 출처 자체도 지어낼 수 있어 완벽하지 않다)

4. 중요한 사실은 반드시 별도로 검증
   - 코드 실행, 공식 문서 대조, 다른 소스와 교차 검증
```

## 코드 예제: "모른다"를 유도하는 프롬프트

```python
prompt = """다음 문서를 참고해서 질문에 답해줘.
문서에 명시적으로 나와 있지 않은 내용은 절대 추측하지 말고
"제공된 문서에서 확인할 수 없습니다"라고 답해.

문서: {context}
질문: {question}"""
```

이렇게 명시적으로 "추측 금지"를 지시하는 것만으로도 환각 발생 빈도가 눈에 띄게 줄어든다는 것이 실무에서 널리 확인된 방법이다.

## 실무 포인트

- **환각을 100% 없앨 수는 없다.** 현재 LLM 기술의 근본적인 한계이므로, "환각이 아예 없는 시스템"을 목표로 하기보다 "환각이 발견됐을 때 사용자가 알아챌 수 있는 구조"를 설계하는 것이 현실적이다.
- **중요도가 높은 도메인(의료, 법률, 금융)일수록 사람의 최종 검토 단계를 반드시 둬야 한다.** LLM의 답을 그대로 자동화 파이프라인에 흘려보내는 것은 위험하다.
- **모델이 확신에 찬 어조로 답한다고 해서 그것이 정확하다는 뜻은 아니다.** 오히려 환각일 때도 자신감 있는 어조로 답하는 경우가 많아, 어조로 신뢰도를 판단하면 안 된다.

## 마무리 요약

- 환각은 LLM이 사실을 검색하는 것이 아니라 확률적으로 그럴듯한 다음 단어를 예측하기 때문에 생기는 근본적인 현상이다.
- RAG 적용과 "모르면 모른다고 답해"라는 명시적 지시가 실무에서 가장 효과적인 완화 방법이다.
- 환각을 완전히 없애기보다, 중요한 정보는 별도로 검증하는 구조를 갖추는 것이 현실적인 대응이다.
