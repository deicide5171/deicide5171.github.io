## 공공 지도 데이터를 받다 보면 만나는 약어

국토정보플랫폼이나 공공 GIS 포털에서 지도 데이터를 가져오려 하면 WMS, WMTS, WFS 같은 약어가 나온다. 이들은 **OGC(개방형 공간정보 컨소시엄)**가 정한 지도 서비스 표준이다. 어떤 서비스를 쓰는지에 따라 데이터를 받는 방식과 성능이 달라지므로 차이를 알아야 한다.

## WMS vs WMTS vs WFS

| 서비스 | 받는 것 | 특징 |
|---|---|---|
| WMS | 지도 이미지(그려진 그림) | 요청 영역마다 서버가 실시간 렌더링 |
| WMTS | 미리 잘라둔 타일 이미지 | 캐싱 가능, 빠름 |
| WFS | 벡터 데이터(좌표 그 자체) | 클라이언트에서 직접 스타일·분석 가능 |

## WMS와 WMTS의 핵심 차이

```text
WMS(Web Map Service):
- 클라이언트가 "이 영역의 지도를 그려줘"라고 요청
- 서버가 그때그때 이미지를 렌더링해서 보냄
- 영역·스타일이 자유롭지만, 매번 그리므로 느리고 캐싱 어려움

WMTS(Web Map Tile Service):
- 미리 정해진 격자(타일)로 잘라둔 이미지를 그대로 제공
- 같은 타일은 캐시 재사용 -> 빠르고 서버 부담 적음
- 대신 스타일·영역이 미리 정한 것으로 고정
```

## 실무 포인트

- **빠른 배경 지도가 필요하면 WMTS가 유리하다.** 미리 만들어둔 타일을 캐싱해 재사용하므로, 배경 지도처럼 자주 보는 데이터는 WMTS가 성능이 훨씬 좋다. WMS는 매 요청마다 렌더링해 느리다.
- **데이터를 직접 분석·스타일링하려면 WFS를 써야 한다.** WMS·WMTS는 완성된 이미지라 클라이언트에서 색을 바꾸거나 특정 조건으로 필터링할 수 없다. 벡터 좌표 자체가 필요하면 WFS(또는 최근의 OGC API Features)를 쓴다.
- **공공 데이터의 좌표계를 확인하라.** 국내 공공 WMS/WMTS는 EPSG:5179 같은 국내 좌표계로 제공되는 경우가 많아, 웹 지도(EPSG:3857)와 맞추려면 좌표계 설정을 확인해야 한다.

## 마무리 요약

- WMS·WMTS·WFS는 OGC가 정한 지도 서비스 표준으로, 받는 데이터의 형태가 다르다.
- WMS는 실시간 렌더링 이미지, WMTS는 미리 잘라둔 타일 이미지, WFS는 벡터 좌표 데이터를 제공한다.
- 빠른 배경 지도는 WMTS, 직접 분석·스타일링이 필요하면 WFS가 적합하다.
