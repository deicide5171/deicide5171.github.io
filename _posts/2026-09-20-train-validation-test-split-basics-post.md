## "모델이 잘 맞힌다는데 실제로는 왜 틀릴까?"

가진 데이터 전부로 학습하고 그 데이터로 성능을 재면, 모델이 답을 외웠는지 진짜 잘하는지 알 수 없다. 그래서 데이터를 **학습(train)·검증(validation)·테스트(test)**로 나눠, 본 적 없는 데이터로 성능을 확인한다.

## 세 덩어리의 역할

| 세트 | 역할 |
|---|---|
| train | 모델이 학습하는 데이터 |
| validation | 학습 중 튜닝·모델 선택 기준 |
| test | 마지막에 딱 한 번, 최종 성능 측정 |

```text
전체 데이터
 ├─ train      (예: 60~70%) → 학습에 사용
 ├─ validation (예: 15~20%) → 하이퍼파라미터 조정
 └─ test       (예: 15~20%) → 최종 평가(건드리지 않음)
```

## 왜 나누나

학습 데이터로 성능을 재면 "외운 것"까지 점수에 포함돼 실제보다 좋게 나온다(과대평가). 본 적 없는 test로 재야 새 데이터에서의 진짜 성능(일반화)을 알 수 있다.

## 실무 포인트

- **test는 마지막까지 아껴라.** test를 보며 튜닝하면 test에도 맞춰버려 의미가 사라진다. 튜닝은 validation으로만.
- **데이터가 적으면 교차검증(k-fold).** 검증셋을 따로 떼기 아까울 만큼 데이터가 적으면, 데이터를 k등분해 돌아가며 검증하는 교차검증을 쓴다.
- **분할은 무작위·대표성 있게.** 클래스 비율이 치우치지 않도록(층화 분할) 나눠야 각 세트가 전체를 대표한다.

## 마무리 요약

- 데이터를 train·validation·test로 나눠 본 적 없는 데이터로 성능을 확인한다.
- train은 학습, validation은 튜닝, test는 최종 평가용이다.
- test는 마지막에 한 번만 쓰고, 데이터가 적으면 교차검증을 활용한다.
