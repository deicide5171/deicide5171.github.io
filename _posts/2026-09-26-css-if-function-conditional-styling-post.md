## 왜 지금 CSS 조건문을 다시 봐야 하는가

CSS에서 "조건에 따라 다른 값을 쓰고 싶다"는 요구는 지금까지 미디어 쿼리, 컨테이너 쿼리, `:has()` 같은 개별 기능들을 조합해 우회적으로 해결해왔다. 문제는 이 방식이 조건 하나가 늘어날 때마다 규칙 블록 전체를 복제해야 한다는 것이다. 버튼의 패딩을 컨테이너 너비에 따라 세 단계로 바꾸고 싶다면, `@container` 쿼리 블록을 세 개 만들고 각각 안에서 같은 선택자를 다시 써야 했다. 다른 프로그래밍 언어라면 삼항 연산자나 `switch` 문 하나로 끝날 일이 CSS에서는 선택자 중복으로 이어졌던 것이다. CSS Values and Units Level 5에 포함된 `if()` 함수는 이 문제를 값 레벨의 조건문으로 직접 해결하려는 시도다.

## 핵심 개념 1 — 선언 안에서 조건과 값을 함께 쓰기

`if()` 함수는 CSS 커스텀 속성(변수)이나 미디어·컨테이너·기능 조건을 값으로 직접 평가해, 조건이 참이면 첫 번째 값을, 거짓이면 대체 값을 반환한다. 기존에는 조건마다 별도의 규칙 블록이 필요했다면, `if()`를 쓰면 하나의 선언 안에서 여러 조건-값 쌍을 나열할 수 있다. 문법은 `if(조건1: 값1; 조건2: 값2; else: 기본값)` 형태로, 위에서부터 순서대로 평가해 처음 참이 되는 조건의 값을 채택한다. 이는 스타일 쿼리(style query, `style()` 함수로 커스텀 속성 값을 조건으로 쓰는 기능)와 결합하면 특히 강력해진다 — 부모 요소의 커스텀 속성 값에 따라 자식 요소의 스타일을 완전히 다르게 분기할 수 있다.

## 핵심 개념 2 — 왜 아직 미디어 쿼리를 완전히 대체하지 못하는가

`if()`가 미디어 쿼리, 컨테이너 쿼리, 기능 쿼리(feature query, `@supports`가 하던 역할)를 조건으로 모두 받아들일 수 있다는 점은 이 함수를 단순한 문법 설탕 이상으로 만든다. 하지만 2026년 기준으로 브라우저 지원이 아직 제한적이라 Baseline에 오르지 못했다. 실무에서는 `if()`를 단독으로 신뢰하기보다, 옛 방식(미디어 쿼리 중첩)을 폴백으로 유지하면서 `@supports` 검사로 점진적으로 도입하는 전략이 필요하다. 또한 조건이 많아질수록 하나의 선언 안에 조건-값 쌍이 길게 나열되어 오히려 가독성이 떨어질 수 있다는 점도 실무에서 반드시 고려해야 할 트레이드오프다.

| 방식 | 조건 표현 위치 | 규칙 블록 중복 | 브라우저 지원(2026 기준) |
|---|---|---|---|
| 미디어 쿼리 중첩 | 블록 단위 | 조건 수만큼 중복 | 전체 지원 |
| 컨테이너 쿼리 | 블록 단위 | 조건 수만큼 중복 | 폭넓게 지원 |
| CSS if() 함수 | 값 단위(선언 내부) | 중복 없음 | 제한적, Baseline 미도달 |

## 코드 예제 — 컨테이너 크기에 따른 패딩 분기

```css
.card {
  /* 기존 방식: 조건마다 블록을 중복 작성 */
  padding: 8px;
}
@container (min-width: 400px) {
  .card { padding: 16px; }
}
@container (min-width: 700px) {
  .card { padding: 24px; }
}

/* if() 함수 방식: 하나의 선언으로 표현 */
.card-modern {
  padding: if(
    container(min-width: 700px): 24px;
    container(min-width: 400px): 16px;
    else: 8px
  );
}
```

지원 브라우저가 아닌 환경을 위해 `if()` 선언 앞에 폴백 값을 먼저 적어두면, 미지원 브라우저는 폴백 선언을만 적용하고 지원 브라우저는 뒤에 나온 `if()` 선언으로 값을 덮어쓴다.

## 실무 포인트

- **`@supports (background: if(true: red; else: blue))` 같은 기능 감지 패턴으로 지원 여부를 먼저 확인해야 한다.** 폴리필이 없는 순수 CSS 기능이므로, 미지원 브라우저에서는 조용히 무시되거나 선언 자체가 무효화될 수 있다.
- **디자인 토큰과 결합할 때 진가를 발휘한다.** 커스텀 속성으로 정의한 디자인 토큰 값을 조건으로 사용하면, 다크모드·밀도(density) 설정 같은 다차원 테마 분기를 자바스크립트 없이 CSS 레벨에서 해결할 수 있다.
- **조건-값 쌍이 4개를 넘어가면 가독성을 위해 분리를 고려해야 한다.** 지나치게 긴 `if()` 체인은 오히려 기존 미디어 쿼리 블록보다 읽기 어려워질 수 있다.

## 마무리 요약

- CSS `if()` 함수는 미디어·컨테이너·기능 쿼리를 값 레벨의 조건으로 평가해, 조건마다 규칙 블록을 중복 작성하지 않고 하나의 선언 안에서 조건부 스타일링을 표현한다.
- 스타일 쿼리와 결합하면 부모 요소의 커스텀 속성 값에 따라 자식 스타일을 분기하는 것까지 가능해, 자바스크립트 개입 없이 처리할 수 있는 조건 분기의 범위가 넓어진다.
- 2026년 기준 브라우저 지원이 제한적이므로 폴백 선언과 `@supports` 검사를 함께 쓰는 점진적 도입 전략이 필요하다.
