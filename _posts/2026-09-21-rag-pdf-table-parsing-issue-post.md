## 왜 표가 있는 PDF가 RAG의 골칫거리인가

RAG(검색 증강 생성) 파이프라인을 처음 구축할 때는 대부분 순수 텍스트 문서로 테스트한다. 실제 운영 단계에 들어가면 재무제표, 제품 스펙, 요금제 비교표처럼 **표 형태의 정보**가 담긴 PDF가 쏟아져 들어온다. 문제는 대부분의 PDF 텍스트 추출 라이브러리가 표를 "행과 열의 구조"가 아니라 "좌표상 흩어진 텍스트 조각들"로 인식한다는 점이다.

예를 들어 아래와 같은 표가 있다고 하자.

```
제품명    가격      재고
노트북A   1,200,000  15
노트북B   980,000    3
```

단순 텍스트 추출기는 이걸 `제품명 가격 재고 노트북A 1,200,000 15 노트북B 980,000 3`처럼 한 줄로 뭉개버리거나, PDF 내부 렌더링 좌표 순서에 따라 `제품명 노트북A 노트북B 가격 1,200,000 980,000 재고 15 3`처럼 열 단위로 흩어놓기도 한다. 이런 텍스트를 그대로 청킹해 임베딩하면, "노트북B의 재고는 몇 개인가?"라는 질문에 LLM이 잘못된 행과 열을 짝지어 엉뚱한 답을 만들어낸다. 이게 이른바 **표 환각(table hallucination)** 문제다.

## 잘못된 접근: 텍스트 추출기만 바꾸면 해결될 거라는 착각

흔한 첫 시도는 "PyPDF2가 별로니 pdfplumber로 바꿔보자"처럼 라이브러리만 교체하는 것이다. 실제로는 각 라이브러리가 표를 인식하는 방식과 한계가 다르기 때문에, 무작정 교체한다고 문제가 사라지지 않는다.

| 도구 | 표 인식 방식 | 한계 |
|---|---|---|
| PyPDF2 / pdfminer | 좌표 기반 순수 텍스트 추출 | 표 구조 정보 없음, 열이 섞임 |
| pdfplumber | 선(line) 감지로 표 경계 추론 | 테두리 없는 표는 인식 실패율 높음 |
| Camelot / Tabula | 격자 기반 표 전용 추출 | 스캔 이미지 PDF에는 무력 |
| 레이아웃 인식 모델(LayoutLM, Docling 등) | 시각적 레이아웃까지 학습한 모델 기반 | 처리 속도 느림, 인프라 비용 증가 |

또 다른 흔한 실수는 표를 인식했더라도 이를 일반 문단과 똑같이 고정 길이로 청킹하는 것이다. 표는 행 하나가 의미 단위인 경우가 많은데, 문자 수 기준으로 자르면 표 중간이 잘려 한 행이 두 청크로 쪼개지고, 검색 시 관련 행 전체를 가져오지 못하는 문제가 생긴다.

## 올바른 접근

**1) 표를 별도 구조로 추출해 마크다운이나 구조화된 텍스트로 변환한다.**

```python
import pdfplumber

with pdfplumber.open("spec.pdf") as pdf:
    for page in pdf.pages:
        table = page.extract_table()
        if table:
            markdown_table = to_markdown(table)  # 행/열 유지한 마크다운 변환
```

표를 마크다운 형식(`| 제품명 | 가격 | 재고 |`)으로 변환해 저장하면, 텍스트 조각으로 흩어지지 않고 행과 열 관계가 그대로 유지된다. 많은 임베딩 모델과 LLM이 마크다운 표 구조를 비교적 잘 이해한다.

**2) 표는 행 단위 혹은 표 전체를 하나의 청크로 유지한다.** 표가 크면 헤더 행을 각 청크에 반복해서 포함시켜, 어떤 청크를 검색해 가져오든 열의 의미를 잃지 않게 한다.

**3) 스캔 이미지 PDF는 OCR과 레이아웃 인식을 함께 쓴다.** 텍스트 레이어가 없는 스캔본은 Camelot·pdfplumber가 아예 인식하지 못하므로, OCR(Tesseract, 또는 비전 모델 기반 OCR)로 먼저 텍스트를 뽑고 레이아웃 분석 모델로 표 경계를 잡는 이중 처리가 필요하다.

## 실무 포인트

- **표가 많은 도메인(재무, 제조 스펙)이라면 처음부터 레이아웃 인식 기반 파서를 기본값으로 검토하라.** 규칙 기반 도구로 시작했다가 나중에 전환하면 이미 만들어둔 청킹·인덱싱 파이프라인을 다시 손봐야 한다.
- **표 추출 성공률을 반드시 자체적으로 측정하라.** "표를 몇 % 정확히 추출했는가"를 검증 없이 넘어가면, 운영 중 특정 포맷의 표에서만 조용히 실패하는 경우를 놓친다.
- **표 데이터는 검색 시 메타데이터로도 활용하라.** 표 제목, 페이지 번호, 컬럼명을 메타데이터로 함께 저장해두면 재랭킹(reranking) 단계에서 표 관련 질의를 더 정확히 우선순위화할 수 있다.

## 마무리 요약

- PDF 표는 좌표 기반 텍스트 추출로는 행과 열 구조가 뭉개져 RAG 검색 품질을 크게 떨어뜨린다.
- 표 전용 추출 도구로 구조를 보존한 뒤 마크다운 등으로 변환하고, 청킹 시 표의 행 단위 의미를 유지해야 한다.
- 스캔 이미지 PDF는 OCR과 레이아웃 인식을 함께 써야 하며, 표 추출 성공률은 반드시 별도로 검증해야 한다.
