## Nginx랑 톰캣은 뭐가 다른가

서버 구성에서 자주 나오는 Nginx(웹서버)와 톰캣(WAS)은 역할이 다르다. **웹서버(web server)**는 HTML·이미지 같은 **정적 파일을 그대로 전달**한다. **WAS(Web Application Server)**는 **코드를 실행해 동적 결과를 만든다**(DB 조회, 로그인 처리 등).

## 웹서버 vs WAS

| 구분 | 웹서버 | WAS |
|---|---|---|
| 예 | Nginx, Apache | 톰캣, 스프링 부트 내장 |
| 처리 | 정적 파일 전달 | 코드 실행(동적) |
| 예시 | 이미지·CSS·JS | 로그인·주문 처리 |

## 왜 함께 쓰나

```text
클라이언트 -> 웹서버(Nginx) -> WAS(톰캣)
  Nginx: 정적 파일은 직접 응답(빠름)
         동적 요청은 WAS로 전달(리버스 프록시)
  WAS: 코드를 실행해 동적 결과 생성

역할을 나눠 성능·보안·유연성을 얻는다
```

## 실무 포인트

- **정적은 웹서버가 처리해 부담을 던다.** 이미지·CSS 같은 정적 파일까지 WAS가 처리하면 무겁다. 웹서버가 정적 파일을 맡고, 동적 요청만 WAS로 넘기면 WAS 부담이 준다.
- **웹서버가 앞단 방어·분산.** 웹서버(리버스 프록시)가 앞에서 SSL 종료, 로드 밸런싱, 요청 필터링을 처리하면 WAS를 직접 노출하지 않아 보안·확장에 유리하다.
- **요즘은 내장 서버도 흔하다.** 스프링 부트는 톰캣을 내장해 WAS를 따로 안 띄워도 된다. 그래도 운영에선 앞에 Nginx를 두는 구성이 여전히 흔하다.

## 마무리 요약

- 웹서버(Nginx)는 정적 파일을 전달하고, WAS(톰캣)는 코드를 실행해 동적 결과를 만든다.
- 보통 웹서버를 앞에 두고 동적 요청만 WAS로 넘겨(리버스 프록시) 역할을 나눈다.
- 정적 처리 분담, 앞단 방어·분산의 이점이 있으며, 내장 서버를 써도 앞에 Nginx를 두는 경우가 많다.
