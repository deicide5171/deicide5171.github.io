## 왜 지금 컨텍스트 구조화를 다시 봐야 하는가

컨텍스트 윈도우가 10만 토큰을 넘어 100만 토큰대까지 확장되면서, 많은 팀이 "이제 청킹이나 검색 최적화 없이 문서를 통째로 넣으면 되지 않을까"라는 기대를 갖는다. 실제로 긴 컨텍스트를 지원하는 모델이 늘어나면서 RAG 파이프라인을 단순화하려는 시도가 늘었다. 하지만 컨텍스트 윈도우의 '수용 가능한 길이'와 '실제로 그 안의 정보를 균일하게 활용하는 능력'은 별개의 문제라는 점이 여러 벤치마크에서 반복적으로 드러난다.

이 현상을 흔히 Lost in the Middle이라 부른다. 프롬프트 맨 앞과 맨 뒤에 배치된 정보는 모델이 잘 찾아내지만, 중간 어딘가에 묻힌 핵심 정보는 정답률이 눈에 띄게 떨어진다. 컨텍스트를 길게 넣을수록 이 U자형 성능 곡선이 더 뚜렷해지는 경향도 보고된다. 즉 "넣을 수 있다"와 "쓸 수 있다" 사이의 간극을 이해하지 못하면, 컨텍스트를 늘렸는데도 답변 품질이 오히려 나빠지는 상황을 마주하게 된다.

## 핵심 개념 1 — 위치 편향은 어디서 오는가

트랜스포머 기반 모델은 어텐션 메커니즘으로 토큰 간 관계를 계산하지만, 학습 데이터의 분포와 위치 인코딩 방식의 특성상 시퀀스의 시작부와 끝부에 더 강하게 주의를 기울이는 경향이 학습 과정에서 굳어진다. 문서 요약이나 지시문이 보통 앞이나 뒤에 오는 학습 데이터 패턴, 그리고 긴 시퀀스에서 상대적 위치 정보가 희석되는 구조적 특성이 겹치면서 중간 구간의 정보 회수율이 낮아진다. 이는 특정 모델만의 결함이 아니라 현재 세대 아키텍처 전반에서 관찰되는 구조적 경향에 가깝다.

## 핵심 개념 2 — 컨텍스트 배치 전략

이 문제를 완화하는 가장 직접적인 방법은 검색된 문서를 컨텍스트에 넣는 순서를 관련도 순서 그대로 두지 않는 것이다. 가장 중요한 문서를 맨 앞과 맨 끝에 배치하고, 상대적으로 덜 중요한 문서를 중간에 두는 방식이 실무에서 자주 쓰인다. 아래 표는 컨텍스트 구조화 전략을 정리한 것이다.

| 전략 | 방법 | 언제 유효한가 |
|---|---|---|
| 양끝 배치 | 최상위 관련 문서를 처음·끝에 중복 배치 | 문서 수가 적고 순위 신뢰도가 높을 때 |
| 요약 압축 | 저관련 문서는 요약해 토큰 수 자체를 줄임 | 문서 수가 많아 위치 조정만으론 부족할 때 |
| 구조화 마킹 | 문서마다 ID·출처를 명시해 참조를 강제 | 인용·근거 제시가 중요한 답변일 때 |
| 재순위 후 절단 | 재순위(rerank) 후 상위 N개만 사용 | 검색 recall은 넉넉하지만 노이즈가 많을 때 |

## 예제 — 프롬프트 조립 시 문서 순서 재배치

```python
def build_context(ranked_docs, top_k=8):
    # ranked_docs: 관련도 내림차순으로 정렬된 문서 리스트
    docs = ranked_docs[:top_k]
    # 중요도가 높은 절반을 양끝으로, 낮은 절반을 중간으로 재배치
    front = docs[0::2]
    back = docs[1::2]
    reordered = front + list(reversed(back))
    return "\n\n".join(
        f"[문서 {i+1} | 출처: {d['source']}]\n{d['text']}"
        for i, d in enumerate(reordered)
    )
```

단순히 문서를 이어붙이는 대신, 순서를 재배치하고 각 문서에 명시적 식별자를 부여하면 모델이 인용 근거를 추적하기도 쉬워지고 중간 배치로 인한 손실도 어느 정도 줄일 수 있다.

## 실무 포인트

- **긴 컨텍스트를 지원한다고 청킹·재순위 단계를 통째로 걷어내지 마라.** 컨텍스트 윈도우가 커진 것은 "더 많이 넣어도 에러가 안 난다"는 뜻이지 "다 활용한다"는 보장이 아니다.
- **정답이 컨텍스트의 어느 위치에 있는지 직접 실험하라.** 같은 질문을 답이 앞/중간/뒤에 오도록 배치를 바꿔가며 테스트하면, 사용 중인 모델의 실제 위치 편향 곡선을 파악할 수 있다.
- **컨텍스트가 길어질수록 재순위(rerank) 단계의 가치가 커진다.** 검색 recall만 높이고 재순위 없이 넣으면 노이즈가 늘어 위치 편향의 악영향이 더 커진다.

## 마무리 요약

- 컨텍스트 윈도우 확장은 정보를 담을 수 있는 용량이 늘어난 것이지, 모델이 그 안의 모든 정보를 균일하게 활용하게 됐다는 뜻은 아니다.
- Lost in the Middle은 시퀀스 위치에 따른 구조적 편향이며, 중요 정보를 컨텍스트 양끝에 배치하거나 저관련 정보를 압축하는 방식으로 완화할 수 있다.
- 긴 컨텍스트 시대일수록 청킹·재순위 같은 컨텍스트 엔지니어링 단계를 없애기보다 오히려 정교하게 재설계해야 한다.
