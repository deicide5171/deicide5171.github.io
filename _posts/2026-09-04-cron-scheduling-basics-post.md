## 매일 새벽 백업을 자동으로

"매일 새벽 3시에 백업 스크립트를 돌려라", "10분마다 상태를 점검하라" 같은 반복 작업을 사람이 매번 실행할 수는 없다. **cron**은 리눅스에서 정해진 시각·주기에 명령을 자동 실행해주는 스케줄러다. 핵심은 "언제 실행할지"를 나타내는 **크론 표현식**을 읽고 쓸 줄 아는 것이다.

## 크론 표현식 5칸

```text
* * * * *  실행할_명령
│ │ │ │ │
│ │ │ │ └─ 요일 (0-7, 0과 7은 일요일)
│ │ │ └─── 월 (1-12)
│ │ └───── 일 (1-31)
│ └─────── 시 (0-23)
└───────── 분 (0-59)
```

각 칸은 왼쪽부터 분, 시, 일, 월, 요일이다. `*`는 "매번(모든 값)"을 뜻한다.

## 예시로 익히기

| 표현식 | 의미 |
|---|---|
| `0 3 * * *` | 매일 새벽 3시 0분 |
| `*/10 * * * *` | 10분마다 |
| `0 9 * * 1` | 매주 월요일 오전 9시 |
| `0 0 1 * *` | 매월 1일 자정 |
| `30 2 * * 1-5` | 평일(월~금) 새벽 2시 30분 |

`*/10`은 "10마다", `1-5`는 "1부터 5까지", `,`로 여러 값(예: `0,30`)을 지정할 수 있다.

## 등록과 확인

```bash
# 크론탭 편집 (내 사용자 계정의 스케줄)
crontab -e

# 아래 한 줄을 추가하면 매일 새벽 3시에 백업 스크립트 실행
0 3 * * * /home/user/backup.sh

# 등록된 크론 목록 확인
crontab -l
```

## 실무 포인트

- **cron은 실행 환경이 로그인 셸과 다르다.** 터미널에서는 되는 명령이 cron에서는 안 되는 흔한 이유가 PATH 등 환경변수 차이다. 스크립트 안에서 명령의 절대 경로를 쓰거나 필요한 환경변수를 명시적으로 설정하는 것이 안전하다.
- **표준 cron의 최소 주기는 1분이다.** "1초마다" 같은 초 단위 작업은 cron으로 안 되므로, 그런 경우 다른 방식(상주 프로세스, 전용 스케줄러)을 써야 한다.
- **실행 결과와 오류를 로그로 남겨라.** cron 작업은 조용히 실패하면 알아채기 어렵다. 명령 끝에 `>> /var/log/mytask.log 2>&1`을 붙여 출력과 에러를 파일에 남기면 나중에 실패 원인을 추적할 수 있다.
- **여러 서버에서 같은 cron이 돌면 작업이 중복 실행된다.** 서버를 여러 대로 확장했다면, 한 대에서만 실행되도록 분산 락(ShedLock 등)이나 전용 스케줄러를 고려해야 한다.

## 마무리 요약

- cron은 리눅스에서 정해진 시각·주기에 명령을 자동 실행하는 스케줄러다.
- 크론 표현식은 분·시·일·월·요일 5칸으로, `*`(매번)·`*/N`(N마다)·`1-5`(범위) 등을 조합한다.
- cron은 환경변수가 로그인 셸과 다르므로 절대 경로를 쓰고, 실행 결과를 로그로 남기는 것이 안전하다.
