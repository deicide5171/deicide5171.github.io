## 왜 지금 이 이야기인가

몇 년 전까지만 해도 "폰에서 LLM을 돌린다"는 이야기는 데모 영상 수준이었다. 그런데 최근 플래그십 스마트폰들이 앞다퉈 자체 NPU 성능을 강조하고, 제조사들이 "온디바이스 AI"를 마케팅 전면에 내세우면서 상황이 달라지고 있다. 파라미터 수를 극단적으로 줄인 경량 모델과 양자화 기법이 발전하면서, 수십억 파라미터급 모델을 클라우드 없이 폰 안에서 실행하는 사례가 실제로 늘어나는 것으로 보인다.

배경에는 세 가지 압력이 동시에 작용한다. 첫째는 지연시간이다. 네트워크 왕복이 없으면 응답이 즉각적이다. 둘째는 프라이버시로, 민감한 입력(메시지, 사진, 건강 데이터)이 기기 밖으로 나가지 않아도 된다는 점이 규제 환경에서 점점 더 중요해지고 있다. 셋째는 비용으로, 추론을 사용자 기기에서 수행하면 서버 측 GPU 비용을 사용자 단말로 분산시킬 수 있다. 이 세 축이 겹치면서 온디바이스 AI는 단순한 기술 트렌드를 넘어 제품 설계의 기본 축 중 하나로 자리잡는 흐름이다.

## 온디바이스 추론이 주는 이점과 대가

| 항목 | 클라우드 추론 | 온디바이스 추론 |
|---|---|---|
| 지연시간 | 네트워크 왕복 포함 | 로컬 연산만, 왕복 없음 |
| 오프라인 동작 | 불가 | 가능 |
| 프라이버시 | 서버로 데이터 전송 필요 | 기기 내부에서 처리 완결 |
| 모델 크기/성능 | 대형 모델 사용 가능 | 메모리·발열·배터리 제약 |
| 비용 구조 | 추론당 서버 비용 발생 | 초기 개발·최적화 비용 위주 |

핵심은 트레이드오프다. 온디바이스는 지연시간과 프라이버시를 얻는 대신, 모델 크기와 정확도에서 손해를 감수해야 한다. 그래서 실무에서는 온디바이스와 클라우드를 하이브리드로 조합하는 설계(간단한 요청은 로컬, 복잡한 요청은 클라우드로 라우팅)가 자주 언급된다.

## 모델을 작게 만드는 기법들

| 기법 | 핵심 아이디어 | 대표적 트레이드오프 |
|---|---|---|
| 양자화(Quantization) | 가중치를 FP16/INT8/INT4 등 낮은 비트로 표현 | 메모리·연산량 감소, 정밀도 손실 가능 |
| 지식 증류(Distillation) | 큰 교사 모델의 출력을 작은 학생 모델이 모방 학습 | 추론 비용 대폭 감소, 교사 모델 성능 상한 존재 |
| 프루닝(Pruning) | 기여도가 낮은 가중치/뉴런을 제거 | 모델 크기 감소, 구조적 재학습 필요할 수 있음 |

세 기법은 독립적이라기보다 함께 적용되는 경우가 많다. 예를 들어 증류로 작은 아키텍처를 얻은 뒤 다시 양자화를 적용해 최종 배포 크기를 줄이는 식이다. 실제 배포 시에는 정확도 저하 폭을 벤치마크로 확인하고, 목표 하드웨어(NPU/GPU/CPU)에 맞는 연산 그래프로 변환하는 과정이 뒤따른다.

## NPU 활용

최근 스마트폰 SoC는 대부분 신경망 연산 전용 가속기(NPU)를 탑재하고 있다. Apple의 Neural Engine, Qualcomm의 Hexagon NPU, Google Tensor 계열 칩 등이 대표적이다. NPU는 행렬 곱셈 같은 텐서 연산에 특화되어 있어 CPU 대비 전력 효율이 훨씬 높은 것으로 알려져 있다. 다만 모델이 NPU가 지원하는 연산자(operator) 집합 안에 들어와야 하며, 지원하지 않는 연산이 섞이면 일부 레이어가 CPU로 폴백되어 기대만큼 속도가 나지 않는 경우가 있다. 그래서 온디바이스 배포 파이프라인에서는 변환 후 "실제로 NPU에서 도는지"를 프로파일링으로 검증하는 단계가 중요하게 다뤄진다.

## 예제

```yaml
# MediaPipe LLM Inference 태스크 설정 예시 (개념적 형태)
task: llm_inference
model_path: "./gemma-2b-it-int4.tflite"
max_tokens: 512
backend: "gpu"   # 또는 cpu, npu 지원 여부는 기기별 상이
temperature: 0.7
```

```python
# 간단한 post-training 양자화 개념 예시 (의사코드 성격)
import onnx
from onnxruntime.quantization import quantize_dynamic, QuantType

quantize_dynamic(
    model_input="model_fp32.onnx",
    model_output="model_int8.onnx",
    weight_type=QuantType.QInt8,
)
# 변환 후에는 반드시 검증 데이터셋으로 정확도 저하 폭을 측정해야 한다
```

## 실무 포인트와 주의사항

- 목표 기기군(저가형~플래그십)에 따라 지원 가능한 모델 크기 편차가 크므로, 최소 사양 기기를 기준으로 벤치마크할 것
- 양자화 비트 수를 낮출수록 속도는 빨라지지만 특정 태스크(수치 추론, 긴 컨텍스트)에서 품질 저하가 더 크게 나타날 수 있음
- 배터리 소모와 발열은 실제 사용자 경험에 직접 영향을 주므로 장시간 연속 추론 시나리오를 별도로 테스트할 것
- 완전한 오프라인 모델과 하이브리드(로컬+클라우드 폴백) 모델 중 제품 요구사항에 맞는 전략을 초기에 결정할 것

## 3줄 요약

- 온디바이스 AI는 지연시간·프라이버시·비용 구조를 개선하지만 모델 크기와 정확도를 희생한다
- 양자화, 지식 증류, 프루닝은 함께 조합되어 실제 배포 가능한 크기로 모델을 압축한다
- NPU 활용 여부와 연산자 지원 범위를 반드시 프로파일링으로 검증해야 기대한 성능이 나온다
