## 왜 국내 서비스라면 국내 지도 API부터 검토해야 하나

웹 지도를 붙인다고 하면 자연스럽게 OpenLayers, Mapbox GL JS, Leaflet 같은 국제 라이브러리 튜토리얼부터 찾아보게 된다. 이 라이브러리들은 훌륭하지만, 정작 한국 주소 체계(도로명주소, 지번주소, 건물명 검색)에 대한 지오코딩 정확도는 OpenStreetMap 기반 지오코더보다 국내 사업자가 직접 제공하는 API가 훨씬 앞선다. "우리 매장 찾기", "배달 주소 입력" 같은 기능을 만드는 국내 서비스라면, 카카오맵과 네이버 지도 API를 먼저 검토하는 것이 합리적이다.

문제는 두 API가 이름도 비슷하고 기능도 겹치는 부분이 많아, 프로젝트 초기에 어느 쪽을 선택할지 고민하다 시간을 허비하기 쉽다는 점이다. 이 글은 처음 국내 지도 API를 검토하는 사람이 빠르게 방향을 잡을 수 있도록 핵심 차이를 정리한다.

## 첫 설정: SDK 로드 방식 비교

두 API 모두 JavaScript SDK를 `<script>` 태그로 불러오는 방식이지만, 키 발급 절차와 로딩 방식에 미묘한 차이가 있다.

```html
<!-- 카카오맵: appkey를 쿼리스트링에 직접 명시 -->
<script src="//dapi.kakao.com/v2/maps/sdk.js?appkey=YOUR_APP_KEY&autoload=false"></script>
<script>
  kakao.maps.load(function () {
    const map = new kakao.maps.Map(document.getElementById('map'), {
      center: new kakao.maps.LatLng(37.5665, 126.9780),
      level: 3,
    });
  });
</script>
```

```html
<!-- 네이버 지도: ncpClientId 파라미터로 인증 -->
<script src="https://oapi.map.naver.com/openapi/v3/maps.js?ncpClientId=YOUR_CLIENT_ID"></script>
<script>
  const map = new naver.maps.Map('map', {
    center: new naver.maps.LatLng(37.5665, 126.9780),
    zoom: 15,
  });
</script>
```

카카오맵은 `autoload=false`와 `kakao.maps.load()` 콜백을 함께 써야 스크립트 로딩 완료 시점을 안전하게 제어할 수 있다는 점을 처음 쓸 때 놓치기 쉽다. 이 콜백 없이 바로 `kakao.maps.Map`을 생성하면 SDK가 완전히 로드되기 전에 실행되어 오류가 날 수 있다. 네이버 지도는 스크립트가 로드되면 `naver.maps` 네임스페이스가 곧바로 사용 가능한 구조라 상대적으로 초기 설정이 단순하다.

## 핵심 차이: 지오코딩과 검색 API

지도를 띄우는 것 자체보다 실무에서 더 중요한 것은 주소를 좌표로 바꾸는 지오코딩과 장소 검색 품질이다.

| 항목 | 카카오맵 | 네이버 지도 |
|---|---|---|
| 주소 검색 API | 카카오 로컬 API (주소 검색, 좌표-주소 변환) | 네이버 클라우드 플랫폼 Geocoding/Reverse Geocoding |
| 장소·POI 검색 | 카카오맵 장소 검색(음식점, 카페 등 카테고리 검색 강점) | 검색 API가 별도 상품으로 분리, 설정이 한 단계 더 필요 |
| 인증 방식 | JavaScript 키(appkey)와 REST API 키가 분리 | 네이버 클라우드 플랫폼 콘솔에서 발급하는 Client ID 기반 |
| 무료 사용량 | 일 단위 호출 한도 제공 | 네이버 클라우드 플랫폼 종량 요금제 기준 무료 크레딧 |

카카오는 JavaScript SDK에서 쓰는 키와 서버 사이드에서 REST API를 호출할 때 쓰는 키가 따로 발급된다는 점을 놓치면, 서버에서 지오코딩 API를 호출할 때 "인증 실패" 에러를 마주하게 된다. 두 키를 혼동하지 않는 것이 첫 설정 단계에서 가장 흔한 실수다.

## 언제 무엇을 선택해야 할까

일반 소비자 대상 서비스에서 매장 찾기, 배달 주소, 부동산 매물처럼 **주소 검색 정확도**가 핵심이라면 카카오맵과 네이버 지도 둘 다 국내 주소 체계에 강하므로 큰 차이는 없다. 다만 이미 카카오 로그인, 카카오톡 공유 같은 카카오 생태계 기능을 쓰고 있다면 카카오맵으로 통일하는 편이 SDK 스타일이나 문서 참조 측면에서 일관성이 있다. 반대로 이미 네이버 클라우드 플랫폼(NCP)의 다른 서비스(서버, 스토리지)를 인프라로 쓰고 있다면 네이버 지도가 같은 콘솔에서 키를 관리할 수 있어 운영 편의성이 높다.

글로벌 확장 계획이 있는 서비스라면 처음부터 OpenLayers나 MapLibre 같은 국제 표준 라이브러리 위에 지도 엔진을 두고, 국내 주소 검색 기능만 카카오·네이버의 지오코딩 API로 보완하는 하이브리드 구조도 실무에서 자주 쓰이는 선택지다.

## 실무 포인트

- **약관과 이용 범위를 반드시 확인하라.** 두 API 모두 상업적 이용, 트래픽 규모에 따라 요금제와 이용 약관이 다르므로, 서비스 규모가 커지기 전에 요금 정책을 미리 확인해야 한다.
- **지도 스타일 커스터마이징 범위가 다르다.** Mapbox GL JS나 MapLibre처럼 벡터 타일 스타일을 세밀하게 커스터마이징하는 자유도는 국내 API보다 제한적인 경우가 많다. 브랜드에 맞춘 정교한 지도 디자인이 필요하다면 이 제약을 미리 확인해야 한다.
- **API 키는 반드시 도메인 제한을 걸어라.** 두 서비스 모두 콘솔에서 특정 도메인에서만 키가 동작하도록 제한하는 기능을 제공한다. 이를 설정하지 않으면 키가 노출됐을 때 무단 사용될 위험이 있다.

## 마무리 요약

- 국내 주소 체계를 다루는 서비스라면 국제 지도 라이브러리보다 카카오맵·네이버 지도의 지오코딩 정확도가 실무적으로 유리하다.
- 카카오맵은 `kakao.maps.load()` 콜백과 JavaScript 키·REST 키 구분을, 네이버 지도는 NCP 콘솔 기반 Client ID 발급을 첫 설정에서 놓치기 쉽다.
- 기존에 쓰는 생태계(카카오 로그인 vs 네이버 클라우드 플랫폼)와의 연계성을 기준으로 선택하면 운영 편의성 측면에서 자연스러운 결론에 도달한다.
