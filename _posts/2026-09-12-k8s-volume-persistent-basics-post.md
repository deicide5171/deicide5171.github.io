## 파드가 죽으면 안에 쓴 파일이 사라진다

쿠버네티스 파드는 언제든 죽고 다시 만들어진다. 컨테이너 안에 저장한 파일은 파드가 사라지면 **함께 없어진다.** DB 데이터나 업로드 파일처럼 유지해야 할 데이터는 이러면 안 된다. **볼륨(Volume)**은 **파드 바깥의 저장 공간을 컨테이너에 연결**해, 파드가 죽어도 데이터를 보존하게 한다.

## PV와 PVC

| 개념 | 설명 |
|---|---|
| PV(PersistentVolume) | 실제 저장 공간(디스크) |
| PVC(PersistentVolumeClaim) | "이만큼의 저장 공간을 달라"는 요청 |
| StorageClass | 저장소를 자동 생성하는 템플릿 |

파드는 PVC로 "10Gi 스토리지 주세요"라고 요청하고, 쿠버네티스가 실제 PV를 연결해준다. 앱은 어떤 디스크인지 몰라도 된다.

## 흐름

```text
파드 -> PVC("10Gi 필요") -> PV(실제 디스크) 연결
데이터는 파드가 아니라 PV에 저장된다.
파드가 죽어도 -> 새 파드가 같은 PVC로 -> 같은 데이터 사용
```

## 실무 포인트

- **상태 있는 앱엔 볼륨이 필수.** DB, 파일 저장소처럼 데이터를 유지해야 하는 앱은 반드시 영속 볼륨을 써야 한다. 반대로 상태 없는(stateless) 앱은 볼륨 없이 여러 파드로 자유롭게 확장하는 것이 좋다.
- **접근 모드를 확인하라.** 볼륨은 하나의 파드만 쓸 수 있는지(ReadWriteOnce), 여러 파드가 동시에 쓸 수 있는지(ReadWriteMany) 모드가 다르다. 여러 파드가 같은 볼륨에 쓰려면 지원하는 스토리지가 필요하다.
- **StatefulSet과 함께 쓴다.** DB처럼 각 파드가 고유한 저장소를 가져야 하면, Deployment 대신 StatefulSet을 쓴다. StatefulSet은 각 파드에 안정적인 이름과 전용 PVC를 붙여준다.

## 마무리 요약

- 쿠버네티스 볼륨은 파드 바깥 저장 공간을 연결해, 파드가 죽어도 데이터를 보존한다.
- 파드는 PVC로 스토리지를 요청하고, 쿠버네티스가 실제 PV를 연결한다.
- 상태 있는 앱엔 필수이며, 접근 모드 확인과 StatefulSet 사용을 함께 고려한다.
