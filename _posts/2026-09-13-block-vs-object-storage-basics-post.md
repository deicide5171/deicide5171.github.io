## 이미지 업로드는 어디에 저장하나

사용자가 올린 사진을 서버 디스크에 저장하면, 서버가 여러 대일 때 파일이 흩어지고 확장이 어렵다. 클라우드 스토리지에는 크게 **블록 스토리지**와 **객체 스토리지**가 있고, 용도가 다르다.

## 두 스토리지 비교

| 구분 | 블록 스토리지 | 객체 스토리지 |
|---|---|---|
| 형태 | 디스크(볼륨)처럼 붙임 | HTTP로 접근하는 저장소 |
| 예 | AWS EBS | AWS S3 |
| 접근 | 파일 시스템 마운트 | URL/API로 get/put |
| 적합 | DB, OS 디스크 | 이미지·백업·정적 파일 |

## 언제 무엇을 쓰나

```text
블록 스토리지: "서버에 붙이는 하드디스크"
  -> DB 데이터, 애플리케이션 디스크
  -> 한 서버에 붙어 빠른 읽기/쓰기

객체 스토리지: "인터넷의 거대한 파일 창고"
  -> 업로드 이미지, 로그, 백업, 정적 웹 파일
  -> URL로 어디서나 접근, 사실상 무한 확장
```

## 실무 포인트

- **업로드 파일은 객체 스토리지에.** 사용자 업로드 이미지·문서는 S3 같은 객체 스토리지에 두고, 서버는 그 URL만 DB에 저장하는 것이 일반적이다. 서버가 늘어나도 파일 공유 문제가 없다.
- **정적 파일은 CDN과 함께.** 객체 스토리지 앞에 CDN을 붙이면 이미지·정적 파일을 사용자 가까이서 빠르게 전송한다. 웹사이트 정적 호스팅에도 자주 쓴다.
- **DB 데이터는 블록 스토리지에.** DB는 빠르고 낮은 지연의 디스크가 필요해 블록 스토리지(EBS 등)를 쓴다. 객체 스토리지는 파일 단위 접근이라 DB용으로는 부적합하다.

## 마무리 요약

- 블록 스토리지는 서버에 붙이는 디스크(DB·OS용), 객체 스토리지는 URL로 접근하는 파일 창고다.
- 업로드 이미지·백업·정적 파일은 객체 스토리지(S3), DB 데이터는 블록 스토리지가 적합하다.
- 객체 스토리지는 사실상 무한 확장되고 CDN과 잘 어울린다.
