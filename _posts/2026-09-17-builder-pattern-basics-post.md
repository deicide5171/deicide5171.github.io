## 생성자 인자가 많아 헷갈린다

객체를 만들 때 인자가 많으면 `new User("철수", 20, "서울", true, null, ...)`처럼 무엇이 무슨 값인지 알기 어렵고, 순서를 헷갈리기 쉽다. **빌더 패턴(builder pattern)**은 **필요한 값을 이름과 함께 하나씩 지정한 뒤 마지막에 객체를 만드는** 방식으로 이 문제를 푼다.

## 생성자 vs 빌더

```java
// 생성자: 인자가 뭔지 헷갈림
new User("철수", 20, "서울", true, null);

// 빌더: 이름을 붙여 명확
User user = User.builder()
    .name("철수")
    .age(20)
    .city("서울")
    .active(true)
    .build();
```

## 장점

| 장점 | 설명 |
|---|---|
| 가독성 | 어떤 값이 무엇인지 이름으로 명확 |
| 선택적 값 | 필요한 것만 지정, 순서 자유 |
| 불변 객체 | build 후 바꿀 수 없게 만들기 쉬움 |

## 실무 포인트

- **롬복 `@Builder`로 간단히.** 자바에서는 빌더 코드를 직접 짜지 않고 롬복 `@Builder` 애너테이션으로 자동 생성하는 것이 흔하다. 클래스에 붙이면 `.builder()...build()`를 쓸 수 있다.
- **인자가 적으면 오히려 과함.** 필드가 2~3개뿐이면 빌더가 오히려 코드를 늘린다. 생성자로 충분하다. 인자가 많거나 선택적 값이 많을 때 빌더가 빛난다.
- **필수 값 검증을 넣어라.** 빌더는 값을 자유롭게 빼먹을 수 있어, 필수 값이 없는 채로 `build()`될 수 있다. `build()`에서 필수 값을 검증해 잘못된 객체 생성을 막는다.

## 마무리 요약

- 빌더 패턴은 인자가 많은 객체를 이름과 함께 하나씩 지정해 만드는 방식이다.
- 가독성이 좋고 선택적 값·불변 객체를 다루기 쉽다.
- 롬복 `@Builder`로 간단히 쓰되, 인자가 적으면 생성자가 낫고 `build()`에서 필수 값을 검증한다.
