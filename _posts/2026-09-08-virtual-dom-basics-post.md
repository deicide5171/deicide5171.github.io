## 화면을 다시 그리는 건 비싸다

브라우저의 실제 DOM을 직접 조작하는 것은 느리다. 데이터가 바뀔 때마다 화면 전체를 다시 그리면 성능이 나빠진다. **가상 DOM(Virtual DOM)**은 실제 DOM을 **자바스크립트 객체로 흉내 낸 가벼운 복사본**이다. React는 이 가상 DOM에서 먼저 바뀐 부분을 계산한 뒤, **실제로 달라진 곳만** 진짜 DOM에 반영한다.

## 실제 DOM vs 가상 DOM

| 구분 | 실제 DOM | 가상 DOM |
|---|---|---|
| 정체 | 브라우저가 그리는 실제 화면 | JS 객체로 만든 복사본 |
| 조작 비용 | 비쌈(느림) | 쌈(빠름) |
| 갱신 방식 | 직접 수정 | 비교 후 달라진 곳만 실제 반영 |

## 어떻게 동작하나

```text
1. 데이터가 바뀌면 새 가상 DOM 트리를 만든다.
2. 이전 가상 DOM과 새 가상 DOM을 비교한다. (diffing)
3. 실제로 달라진 부분만 찾아낸다.
4. 그 부분만 진짜 DOM에 반영한다. (최소한의 실제 조작)
```

핵심은 **비교 후 최소한만 바꾸기**다. 화면 전체가 아니라 실제로 변한 곳만 건드리므로 빠르다.

## 실무 포인트

- **가상 DOM이 무조건 더 빠른 것은 아니다.** 비교(diffing) 자체에도 비용이 든다. 단순한 페이지라면 직접 DOM 조작이 더 빠를 수도 있다. 가상 DOM의 진짜 장점은 **복잡한 UI를 편하게 관리하면서도 성능을 지켜준다**는 점이다.
- **`key`를 잘 줘야 한다.** 목록을 렌더링할 때 각 항목에 고유한 `key`를 주면, React가 어떤 항목이 바뀌었는지 정확히 판단해 불필요한 갱신을 줄인다. `key`를 빼먹으면 성능·버그 문제가 생긴다.
- **최신 접근은 다양하다.** Svelte는 가상 DOM 없이 컴파일 단계에서 갱신 코드를 만들고, React도 최적화 기법이 계속 발전한다. 가상 DOM은 만능이 아니라 하나의 해법임을 알아두면 좋다.

## 마무리 요약

- 가상 DOM은 실제 DOM을 흉내 낸 가벼운 JS 객체 복사본이다.
- 데이터가 바뀌면 가상 DOM끼리 비교해 달라진 곳만 실제 DOM에 반영해 효율을 높인다.
- 무조건 빠른 건 아니며, 복잡한 UI를 편하게 관리하려는 것이 핵심 목적이다.
