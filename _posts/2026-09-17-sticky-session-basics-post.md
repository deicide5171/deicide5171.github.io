## 로그인했는데 갑자기 로그아웃된다

서버가 여러 대이고 로드 밸런서가 요청을 나눠줄 때, 로그인 정보를 특정 서버의 메모리에만 저장하면 문제가 생긴다. 다음 요청이 다른 서버로 가면 그 서버는 로그인 정보를 몰라 "로그아웃" 상태가 된다. **스티키 세션(sticky session)**은 **같은 사용자의 요청을 항상 같은 서버로 보내** 이를 막는다.

## 어떻게 붙이나

```text
로드 밸런서가 사용자를 식별해 같은 서버로 고정:
- 쿠키 기반: LB가 심은 쿠키로 어느 서버였는지 기억
- IP 해시: 같은 IP는 같은 서버로

같은 사용자 -> 항상 서버 A -> 세션 정보 유지
```

## 스티키 세션 vs 세션 외부화

| 방식 | 설명 |
|---|---|
| 스티키 세션 | 같은 서버로 고정(세션은 서버 메모리에) |
| 세션 외부화 | 세션을 Redis 등 공유 저장소에 |

## 실무 포인트

- **스티키 세션은 확장에 불리하다.** 특정 서버에 사용자가 묶이므로, 그 서버가 죽으면 그 사용자들의 세션이 날아간다. 부하도 고르게 안 퍼질 수 있다. 임시방편으로는 쓰지만 근본 해법은 아니다.
- **근본 해법은 세션 외부화.** 세션을 서버 메모리가 아니라 Redis 같은 공유 저장소에 두면, 어느 서버로 가도 세션을 조회할 수 있다. 스티키 세션이 필요 없어지고 서버를 자유롭게 늘리고 줄일 수 있다.
- **JWT로 무상태화도.** 세션을 서버에 저장하지 않고 토큰(JWT)에 담아 클라이언트가 들고 다니게 하면, 서버는 상태를 안 가져 스티키 세션이 불필요하다. 다만 토큰 무효화 등 다른 고려가 생긴다.

## 마무리 요약

- 스티키 세션은 같은 사용자의 요청을 항상 같은 서버로 보내 서버 메모리의 세션을 유지한다.
- 쿠키·IP 해시로 사용자를 특정 서버에 고정한다.
- 확장·장애에 불리하므로, 근본 해법은 세션 외부화(Redis)나 무상태 토큰(JWT)이다.
