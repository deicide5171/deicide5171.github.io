## 왜 지금 이 비교가 필요한가

2024~2025년을 거치며 AI 코딩 도구는 "탭 자동완성을 도와주는 보조 도구"에서 "레포지토리 전체를 이해하고 멀티 파일 리팩터링까지 수행하는 에이전트"로 빠르게 진화했다. GitHub Copilot, Cursor, Claude Code는 모두 "AI가 코드를 짜준다"는 표면적 목표는 같지만, 내부적으로 서로 다른 철학과 아키텍처를 갖고 있다. 어떤 도구를 선택하느냐에 따라 개발 워크플로우 자체가 달라지기 때문에, 세 도구의 차이를 명확히 이해하는 것이 실무에서 점점 더 중요해지고 있다.

특히 최근에는 "에디터에 내장된 자동완성형" 도구와 "터미널/CLI에서 독립적으로 동작하는 에이전트형" 도구가 명확히 갈라지는 흐름이 보인다. 이 글에서는 세 도구를 작동 방식, 컨텍스트 활용, 사용 시나리오라는 세 축으로 나눠 비교한다.

## 작동 방식의 근본적 차이

| 도구 | 기본 인터랙션 모델 | 실행 환경 |
|---|---|---|
| GitHub Copilot | 인라인 자동완성 + Chat 패널 | 에디터 확장(VS Code, JetBrains 등) |
| Cursor | 인라인 자동완성 + 에이전트형 멀티파일 편집 | Cursor 자체 에디터(VS Code 포크) |
| Claude Code | 대화형 에이전트, 터미널/CLI 기반 | CLI, 특정 에디터에 종속되지 않음 |

Copilot은 원래 "다음 줄을 예측해서 보여주는" 인라인 자동완성에서 출발했고, 지금도 이 부분이 가장 강력한 정체성으로 남아 있는 것으로 보인다. Chat 기능이 추가되면서 대화형 상호작용도 가능해졌지만, 여전히 에디터에 종속된 확장 프로그램의 형태를 취한다.

Cursor는 VS Code를 포크해 만든 독립 에디터로, 자동완성과 에이전트형 멀티파일 편집을 한 제품 안에 통합한 것이 특징이다. "빠른 자동완성"과 "에이전틱 작업"을 하나의 UI 안에서 전환하며 쓸 수 있다는 점이 강점으로 자주 언급된다.

Claude Code는 접근 자체가 다르다. 에디터 확장이 아니라 터미널에서 실행되는 CLI 에이전트로, 파일 읽기/쓰기, 셸 명령 실행, 테스트 실행, git 조작 등을 스스로 계획하고 수행한다. 에디터에 종속되지 않기 때문에 CI 파이프라인이나 스크립트 안에서도 호출할 수 있다는 점이 구조적으로 다르다.

## 컨텍스트 활용 방식

세 도구 모두 "레포지토리를 이해한다"고 표현하지만 방식은 다르다.

- **Copilot**: 열려 있는 파일, 최근 편집 이력, 일부 워크스페이스 정보를 조합해 컨텍스트를 구성하는 것으로 알려져 있다. Chat/Workspace 기능에서는 레포 일부를 참조할 수 있지만, 기본 자동완성은 로컬 컨텍스트 위주로 동작하는 경향이 있다.
- **Cursor**: 코드베이스 인덱싱(임베딩 기반 검색)을 적극적으로 활용해 "이 프로젝트에서 비슷한 패턴이 어디 있는지" 찾아 참조하는 데 강점이 있다고 알려져 있다.
- **Claude Code**: 대화 세션 안에서 필요할 때마다 파일을 직접 열어 읽고, 검색 도구를 사용해 컨텍스트를 능동적으로 수집하는 방식에 가깝다. 사전 인덱싱보다는 에이전트가 스스로 탐색하는 루프에 의존하는 구조다.

## 예제

Cursor 프로젝트 규칙 설정 예시:

```yaml
# .cursor/rules/style.mdc
description: 프로젝트 코딩 컨벤션
globs: ["src/**/*.ts"]
---
- 모든 비동기 함수는 반드시 에러 핸들링을 포함할 것
- 컴포넌트는 함수형으로만 작성
```

Claude Code를 CLI에서 호출해 멀티파일 리팩터링을 지시하는 예시:

```bash
claude "src/api 아래 모든 핸들러에서 콜백 기반 코드를 \
async/await로 변환하고, 관련 테스트를 실행해서 통과 여부를 알려줘"
```

## 사용 시나리오별 추천

- 빠른 자동완성, 이미 짜고 있는 코드의 다음 줄 예측이 주 목적이라면 **Copilot**이 무난하다. 다양한 에디터 지원 등 생태계도 넓은 편이다.
- 에디터 안에서 자동완성과 에이전틱 편집을 자연스럽게 넘나들고 싶다면 **Cursor**가 적합하다. 코드베이스 검색/인덱싱 기반 제안이 강점으로 자주 언급된다.
- 여러 파일에 걸친 큰 리팩터링, 테스트 실행-수정 반복, 셸 명령이 필요한 자동화 작업에는 **Claude Code**와 같은 CLI 에이전트형 도구가 유리하다. 에디터를 열지 않고도 파이프라인에 넣을 수 있다는 점도 차별점이다.

## 실무 포인트와 주의사항

- 도구별 과금 모델(구독형, 사용량 기반 등)이 다르므로 팀 규모와 사용 패턴에 맞춰 비교해야 한다.
- 에이전트형 도구는 셸 명령이나 파일 삭제 등 파괴적 작업을 수행할 수 있으므로 권한 범위와 확인 절차를 반드시 설정해야 한다.
- 사내 코드가 외부로 전송되는지, 학습에 사용되는지 등 보안/데이터 정책은 도구마다 다를 수 있으므로 도입 전 확인이 필요하다.
- 여러 도구를 동시에 쓰는 팀도 늘고 있는 것으로 보인다 — 자동완성은 Copilot, 큰 리팩터링은 CLI 에이전트로 역할을 분리하는 조합도 실무에서 관찰된다.

## 3줄 요약

- Copilot은 인라인 자동완성 중심의 에디터 확장, Cursor는 자동완성+에이전트를 통합한 독립 에디터, Claude Code는 에디터에 종속되지 않는 CLI 에이전트다.
- 컨텍스트 확보 방식도 로컬 컨텍스트, 코드베이스 인덱싱, 능동적 탐색 루프로 서로 다르다.
- 작업 성격(빠른 자동완성 vs 멀티파일 리팩터링/자동화)에 따라 적합한 도구가 갈린다.
