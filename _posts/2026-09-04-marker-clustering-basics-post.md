## 마커 하나하나가 다 부담이다

전국 매장 5,000곳을 지도에 마커로 찍으면, 지도가 버벅이고 화면은 겹친 핀으로 뒤덮여 알아보기도 어렵다. 마커 하나하나가 DOM 요소이거나 그려야 할 대상이라, 개수가 많아질수록 렌더링 부담이 커지기 때문이다. **마커 클러스터링(marker clustering)**은 가까이 모여 있는 마커들을 하나의 "묶음 마커"로 합쳐 보여주는 기법이다.

<img src="/assets/images/posts/2026-09-04-marker-clustering-basics-1.svg" alt="여러 개의 개별 마커가 줌 레벨에 따라 하나의 숫자가 적힌 클러스터 마커로 묶이고, 확대하면 다시 개별 마커로 펼쳐지는 클러스터링 동작을 보여주는 다이어그램" style="width:100%;">

## 클러스터링의 동작

```text
- 줌아웃 상태: 가까운 마커들을 묶어 "127" 같은 숫자 원으로 표시
- 확대하면: 묶음이 점점 작은 묶음으로 나뉘고
- 충분히 확대: 개별 마커가 하나씩 보인다

즉, 화면에 실제로 그리는 요소 수를 줌 레벨에 따라 확 줄인다
```

## Leaflet 예제

```javascript
// Leaflet.markercluster 플러그인 사용
const markers = L.markerClusterGroup();

for (const store of stores) { // 5000개
  const marker = L.marker([store.lat, store.lng]);
  markers.addLayer(marker);
}
map.addLayer(markers);
// -> 5000개를 그대로 찍지 않고 화면에 보이는 묶음만 렌더링
```

플러그인이 알아서 가까운 마커를 묶고, 사용자가 확대·이동할 때마다 다시 계산해 보여준다. 개발자는 마커를 클러스터 그룹에 넣기만 하면 된다.

## 클러스터링 외의 대안

| 기법 | 언제 |
|---|---|
| 마커 클러스터링 | 개별 위치가 중요하고 클릭 상호작용이 필요할 때 |
| 히트맵 | 밀집도·분포만 보여주면 될 때(개별 마커 불필요) |
| 서버 사이드 집계 | 데이터가 수십만 이상이라 클라이언트가 감당 못 할 때 |
| 벡터 타일 | 초대용량 포인트를 타일로 미리 렌더링 |

## 실무 포인트

- **데이터가 수만 개를 넘으면 클라이언트 클러스터링도 한계가 있다.** 모든 좌표를 브라우저로 내려받는 것 자체가 부담이므로, 이 경우 서버에서 현재 보이는 영역과 줌 레벨에 맞게 미리 집계해 내려주는 방식을 검토해야 한다.
- **클러스터를 클릭했을 때 동작을 정해두어야 한다.** 보통 클러스터를 클릭하면 그 영역으로 자동 확대(zoom in)되게 하는데, 이 상호작용이 없으면 사용자가 묶인 마커를 펼칠 방법이 없어 답답해한다.
- **개별 위치의 정확성이 중요하지 않다면 히트맵이 더 나을 수 있다.** "어디에 많이 모여 있나"만 보여주면 되는 분석용 지도라면, 마커 대신 히트맵으로 밀집도를 색으로 표현하는 것이 더 직관적이다.

## 마무리 요약

- 마커가 많아질수록 렌더링 부담과 화면 혼잡이 커지는데, 클러스터링은 가까운 마커를 묶어 이를 해결한다.
- 줌 레벨에 따라 묶음이 나뉘고 펼쳐지며, 화면에 실제로 그리는 요소 수를 크게 줄인다.
- 데이터가 수만 개를 넘으면 서버 집계나 벡터 타일을, 분포만 보면 되면 히트맵을 검토하는 것이 좋다.
