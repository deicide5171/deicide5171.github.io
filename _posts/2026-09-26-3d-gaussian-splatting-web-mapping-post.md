## 왜 지금 3D 재구성 방식을 다시 봐야 하는가

디지털 트윈, 부동산 가상 투어, 문화재 디지털 아카이빙처럼 실제 공간을 3D로 담아 웹에서 보여줘야 하는 수요는 꾸준히 늘어왔고, 그 표준 접근은 포토그래메트리로 사진을 겹쳐 폴리곤 메시를 만드는 것이었다. 문제는 이 방식이 근본적으로 "표면은 매끈한 폴리곤으로 나타낼 수 있다"는 가정 위에 서 있다는 점이다. 나뭇잎, 전선, 유리창, 반사되는 수면처럼 실제 세계에 흔한 대상들은 이 가정을 깨뜨려서, 메시로 재구성하면 구멍이 나거나 뭉개진 덩어리로 표현된다. NeRF(Neural Radiance Fields)는 신경망으로 이 문제를 풀었지만 학습과 렌더링 모두 무거워 실시간 웹 렌더링에는 부적합했다. 2023년 발표된 3D Gaussian Splatting(3DGS)은 NeRF 수준의 사실감을 유지하면서도 일반 GPU에서 실시간 렌더링이 가능한 표현 방식으로 빠르게 주목받았고, 최근 Cesium·deck.gl 생태계로도 통합이 진행되며 웹 지도의 새로운 렌더링 축으로 떠오르고 있다.

## 핵심 개념 1 — 폴리곤 대신 수백만 개의 반투명 타원체

3DGS의 핵심 아이디어는 장면을 매끈한 표면이 아니라, 공간에 흩뿌려진 수십만~수백만 개의 3차원 가우시안(타원체)의 집합으로 표현하는 것이다. 각 가우시안은 위치, 크기와 방향(공분산 행렬), 색상, 불투명도라는 몇 가지 파라미터만 갖는다. 여러 사진에서 SfM(Structure from Motion)으로 초기 포인트 클라우드를 얻은 뒤, 각 점을 초기 가우시안으로 삼아 학습을 시작한다. 학습 과정에서 렌더링된 이미지와 실제 사진을 비교해 오차가 큰 영역은 가우시안을 더 잘게 쪼개고, 불필요한 가우시안은 가지치기하는 적응적 밀도 제어(adaptive density control)를 반복한다. 최종적으로 반투명한 타원체들이 겹겹이 쌓여 사람 눈에는 매끄러운 표면처럼 보이는 결과를 만들어낸다.

## 핵심 개념 2 — 래스터화 기반 실시간 렌더링

NeRF가 광선마다 신경망을 여러 번 통과시키는 무거운 볼륨 렌더링에 의존했다면, 3DGS는 전통적인 그래픽스 파이프라인에 가까운 래스터화(rasterization) 방식으로 렌더링한다. 카메라 시점이 정해지면 각 가우시안을 화면 공간에 투영(splat)하고, 깊이 순서대로 정렬한 뒤 알파 블렌딩으로 겹쳐 그린다. 이 과정이 전통적인 삼각형 래스터화와 유사한 병렬 구조를 갖기 때문에 GPU에서 초당 수백 프레임까지 렌더링이 가능하며, 이것이 3DGS가 웹 브라우저 안에서도 실시간으로 동작할 수 있는 근본 이유다.

| 방식 | 표현 단위 | 얇은 구조물 처리 | 렌더링 방식 | 실시간성 |
|---|---|---|---|---|
| 폴리곤 메시(포토그래메트리) | 삼각형 표면 | 구멍·뭉개짐 발생 | 삼각형 래스터화 | 매우 빠름 |
| NeRF | 신경망 볼륨 함수 | 우수 | 광선별 볼륨 렌더링 | 느림(실시간 어려움) |
| 3D Gaussian Splatting | 타원체 집합 | 우수 | 타원체 래스터화(splat) | 빠름(실시간 가능) |

## 코드 예제 — 웹에서 .splat 파일 로딩 (개념 의사코드)

```javascript
// Cesium/deck.gl 생태계의 Gaussian Splatting 확장은
// 표준 3D Tiles/타일링 구조 위에 .splat/.ply 포맷을 얹는 방향으로 발전 중이다
import { GaussianSplatViewer } from "gaussian-splat-web-viewer"; // 예시 패키지명

const viewer = new GaussianSplatViewer({
  canvas: document.getElementById("scene"),
  splatUrl: "/models/site-scan.splat",
  cameraControls: "orbit",
});

viewer.on("load", () => {
  // 각 가우시안의 위치·공분산·색상·불투명도가
  // GPU 버퍼로 업로드되어 뷰 변경 시마다 재정렬·블렌딩된다
  console.log(`가우시안 개수: ${viewer.splatCount}`);
});
```

## 실무 포인트

- **아직 표준 배포 포맷이 완전히 정착하지 않았다.** `.splat`, `.ply` 기반 여러 변형 포맷이 경쟁 중이며, 3D Tiles나 PMTiles처럼 확립된 웹 지도 표준과의 통합은 현재진행형이라 도구 선택 시 유지보수 리스크를 감안해야 한다.
- **파일 크기와 GPU 메모리 사용량이 상당하다.** 수백만 개의 가우시안 하나하나가 위치·공분산·색상 파라미터를 가지므로, 대규모 야외 장면은 압축·LOD 전략 없이는 모바일 기기에서 감당하기 어렵다.
- **편집이나 시맨틱 정보 부여가 폴리곤 메시보다 까다롭다.** "이 건물은 몇 층인가" 같은 구조화된 속성을 가우시안 하나하나에 붙이는 표준 방법이 아직 3D Tiles 메타데이터 확장만큼 성숙하지 않았다.

## 마무리 요약

- 3D Gaussian Splatting은 장면을 폴리곤 표면이 아니라 위치·공분산·색상·불투명도를 가진 수백만 개의 반투명 타원체 집합으로 표현해, 나뭇잎이나 전선 같은 얇은 구조물도 자연스럽게 재구성한다.
- 렌더링이 신경망 볼륨 함수가 아니라 GPU 래스터화에 가까운 splat 방식이기 때문에 NeRF와 달리 실시간 렌더링이 가능해, 웹 브라우저에서의 실사 3D 뷰어가 현실적인 선택지가 됐다.
- 표준 배포 포맷과 시맨틱 메타데이터 체계가 아직 3D Tiles만큼 성숙하지 않았으므로, 도입 전 파일 크기·플랫폼별 렌더링 성능을 반드시 검증해야 한다.
