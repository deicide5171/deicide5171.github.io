## div로 다 만들 수 있는데 왜 안 그러나

`<div>`에 스타일과 클릭 이벤트를 붙이면 버튼처럼 보이게 만들 수 있다. 그런데 실제 `<button>` 대신 `<div>`로 버튼을 만들면, 화면에는 똑같아 보여도 스크린 리더 사용자나 키보드 사용자에게는 "버튼"으로 인식되지 않는다. **시맨틱 HTML**은 요소의 의미에 맞는 태그를 쓰는 것으로, 접근성과 SEO의 기본이 된다.

## 시맨틱 태그 예시

| 의미 | 시맨틱 태그 | div로 하면 |
|---|---|---|
| 페이지 머리말 | `<header>` | 의미 정보 없음 |
| 내비게이션 | `<nav>` | 스크린리더가 메뉴로 인식 못 함 |
| 본문 주요 영역 | `<main>` | "본문으로 건너뛰기" 불가 |
| 클릭 동작 | `<button>` | 키보드 포커스·Enter 동작 없음 |
| 목록 | `<ul>`, `<li>` | 항목 개수 안내 안 됨 |

## div 버튼 vs 진짜 button

```html
<!-- 나쁨: 겉보기만 버튼 -->
<div class="btn" onclick="submit()">전송</div>
<!-- 키보드 Tab으로 포커스 안 됨, Enter/Space로 실행 안 됨,
     스크린리더가 "버튼"이라고 안 읽음 -->

<!-- 좋음: 진짜 버튼 -->
<button onclick="submit()">전송</button>
<!-- 키보드 접근, Enter/Space 실행, "전송 버튼"으로 읽힘 — 다 공짜로 -->
```

`<button>`을 쓰면 키보드 접근성, 포커스, 스크린리더 인식이 브라우저에 의해 자동으로 처리된다. `<div>`로 만들면 이 모든 것을 직접 구현해야 하고, 대부분 빠뜨린다.

## 왜 접근성이 중요한가

```text
- 시각장애인은 스크린리더로 웹을 "듣는다" -> 의미 있는 태그가 안내 기준
- 손을 못 쓰는 사용자는 키보드만으로 조작 -> button/link가 기본 지원
- 접근성은 법적 의무이기도 하다 (공공·대기업 사이트)
- 검색엔진도 시맨틱 태그로 페이지 구조를 이해 -> SEO에도 유리
```

## 실무 포인트

- **먼저 시맨틱 태그로 안 되는지 확인하고, 안 될 때만 ARIA를 쓰라.** ARIA 속성으로 `<div>`에 버튼 역할을 부여할 수도 있지만, 처음부터 `<button>`을 쓰는 것이 훨씬 간단하고 안전하다. "No ARIA is better than bad ARIA"라는 말이 있다.
- **이미지에는 `alt`, 폼 입력에는 `label`을 반드시 붙여라.** 이 둘은 접근성의 가장 기본이면서 가장 자주 빠뜨리는 부분이다. `alt`는 이미지를 못 보는 사용자에게 설명을, `label`은 입력칸이 무엇을 위한 것인지 알려준다.
- **키보드만으로 전체 기능을 쓸 수 있는지 테스트하라.** 마우스 없이 Tab·Enter만으로 모든 버튼·링크·폼을 조작할 수 있어야 접근성의 최소 기준을 만족한다.

## 마무리 요약

- 시맨틱 HTML은 요소의 의미에 맞는 태그(header·nav·button 등)를 쓰는 것으로, 접근성과 SEO의 기본이다.
- `<div>` 버튼은 겉보기만 같고 키보드·스크린리더 지원이 없어, 진짜 `<button>`을 쓰는 것이 안전하다.
- 이미지의 `alt`, 폼의 `label`, 키보드 조작 가능성이 접근성의 가장 기본적인 체크 항목이다.
