## 왜 지금 멀티모달인가

지금까지 이미지를 다루는 AI 파이프라인은 보통 OCR로 텍스트를 뽑고, 별도의 이미지 분류 모델을 돌리고, 그 결과를 다시 LLM 프롬프트에 이어붙이는 식이었다. 단계마다 모델이 다르고 오류가 누적되며, 표나 손글씨처럼 애매한 입력에서는 OCR 단계부터 무너지기 쉬웠다. **멀티모달 모델(Vision-Language Model)** 은 이 파이프라인을 하나의 요청으로 압축한다. 이미지와 텍스트를 같은 컨텍스트에 넣고, "이 영수증에서 합계 금액만 뽑아줘" 같은 지시를 자연어로 그대로 던질 수 있다.

최신 멀티모달 모델들은 이미지 안의 텍스트 인식뿐 아니라 표의 구조, 차트의 추세, 다이어그램의 관계까지 함께 이해하는 방향으로 계속 발전하고 있다. 그만큼 "이미지를 이해하는 기능"과 "텍스트를 추론하는 기능"을 별도 서비스로 나눠 운영하던 아키텍처를, 하나의 API 호출로 대체할 여지가 커졌다는 뜻이다. 다만 모델이 이미지를 어떻게 처리하는지 구조를 모르고 붙이면 비용·지연시간·정확도 모두에서 예상 밖의 문제를 만나기 쉽다.

## 핵심 개념 1: 모델은 이미지를 어떻게 "보는가"

멀티모달 모델의 기본 구조는 이미지 인코더가 이미지를 일정 개수의 벡터(이미지 토큰)로 변환하고, 이를 텍스트 토큰과 같은 시퀀스 공간에 배치해 트랜스포머가 함께 처리하는 방식이다. 즉 모델 입장에서 이미지는 "픽셀"이 아니라 텍스트 토큰과 동일하게 취급되는 토큰 묶음이며, 이 때문에 이미지 한 장도 텍스트처럼 토큰 사용량과 비용에 반영된다.

| 구성 요소 | 역할 | 애플리케이션에 미치는 영향 |
|---|---|---|
| 이미지 인코더 | 픽셀을 이미지 토큰 시퀀스로 변환 | 해상도·이미지 크기가 토큰 수(= 비용)에 직결 |
| 토큰 통합(Fusion) | 이미지 토큰과 텍스트 토큰을 하나의 시퀀스로 결합 | 프롬프트에서 이미지·텍스트 순서 배치가 결과에 영향 |
| 언어 모델 본체 | 통합된 시퀀스를 바탕으로 추론·생성 | 동일한 프롬프트 엔지니어링 기법(예시 제공, 단계별 지시)이 그대로 적용 |

<img src="/assets/images/posts/2026-08-19-multimodal-model-practice-1.svg" alt="멀티모달 모델의 이미지+텍스트 처리 흐름 - 이미지·텍스트 입력이 인코더와 토큰 통합을 거쳐 언어 모델 본체에서 응답 또는 구조화 데이터로 나오는 과정" style="width:100%;">

이 구조 때문에 "이미지 하나 = 고정 비용"이 아니다. 같은 이미지라도 해상도를 어떻게 전달하느냐에 따라 토큰 수가 달라질 수 있으므로, 프로덕션에서는 반드시 사용 중인 모델의 공식 문서에서 이미지 크기별 토큰 계산 방식을 확인하고 설계해야 한다.

## 핵심 개념 2: 대표적인 활용 패턴

| 패턴 | 입력 형태 | 대표 활용 | 주의점 |
|---|---|---|---|
| 이미지 캡셔닝·설명 | 이미지 1장 | 접근성 대체 텍스트, 콘텐츠 태깅 | 세부 오브젝트 누락 가능 — 검수 필요 |
| VQA(시각 질의응답) | 이미지 + 질문 텍스트 | 상품 이미지 기반 CS 응대, 리뷰 이미지 분석 | 질문이 모호하면 답변도 모호해짐 |
| 문서·표·차트 이해 | 스캔 이미지/스크린샷 | 영수증·계약서 항목 추출, 대시보드 요약 | 저해상도·회전된 이미지는 정확도 저하 |
| 다중 이미지 비교 | 이미지 여러 장 + 텍스트 | 상품 사진 A/B 비교, 시계열 스크린샷 변화 감지 | 이미지 순서·라벨을 프롬프트에 명시해야 혼동 방지 |

핵심은 "이미지를 텍스트로 먼저 변환해서 LLM에 넣는" 기존 방식 대신, 이미지와 지시문을 같은 요청에 그대로 넣고 모델이 직접 추론하게 하는 것이다. 다만 표·차트처럼 구조가 중요한 입력은 여전히 결과를 구조화된 스키마로 강제하는 것이 안전하다.

## 예제 1: 이미지 + 텍스트를 함께 전달하기 (Python)

```python
import base64
import anthropic

client = anthropic.Anthropic()

with open("receipt.jpg", "rb") as f:
    image_b64 = base64.b64encode(f.read()).decode("utf-8")

response = client.messages.create(
    model="claude-opus-5",
    max_tokens=1024,
    messages=[{
        "role": "user",
        "content": [
            {
                "type": "image",
                "source": {
                    "type": "base64",
                    "media_type": "image/jpeg",
                    "data": image_b64,
                },
            },
            {
                "type": "text",
                "text": "이 영수증 이미지에서 상호명, 결제일자, 합계 금액만 뽑아줘.",
            },
        ],
    }],
)

print(response.content[0].text)
```

## 예제 2: 결과를 구조화된 스키마로 강제하기 (Python)

이미지에서 뽑은 정보를 바로 데이터베이스에 저장하려면 자유 텍스트 응답보다 스키마 검증이 안전하다. Tool Use 또는 구조화 출력 기능을 함께 쓰면 파싱 실패 걱정 없이 이미지 분석 결과를 그대로 데이터로 받을 수 있다.

```python
response = client.messages.create(
    model="claude-opus-5",
    max_tokens=1024,
    output_config={
        "format": {
            "type": "json_schema",
            "schema": {
                "type": "object",
                "properties": {
                    "merchant": {"type": "string"},
                    "date": {"type": "string"},
                    "total_amount": {"type": "number"},
                },
                "required": ["merchant", "date", "total_amount"],
                "additionalProperties": False,
            },
        }
    },
    messages=[{
        "role": "user",
        "content": [
            {"type": "image", "source": {"type": "base64", "media_type": "image/jpeg", "data": image_b64}},
            {"type": "text", "text": "영수증에서 상호명, 결제일자, 합계 금액을 추출해줘."},
        ],
    }],
)
```

## 실무 포인트

- **이미지 해상도를 무작정 올리지 않는다**: 해상도가 높을수록 인식 정확도가 오를 수 있지만 토큰 수도 함께 늘어난다. 텍스트 인식이 목적이면 실제로 읽을 수 있는 최소 해상도로 리사이즈해 비용을 관리하는 편이 낫다.
- **여러 장을 비교시킬 때는 순서와 라벨을 명시한다**: "첫 번째 이미지는 이전 버전, 두 번째는 변경 후"처럼 프롬프트에 이미지 순서를 명확히 알려줘야 모델이 어느 이미지를 가리키는지 혼동하지 않는다.
- **중요한 수치는 반드시 재검증 절차를 둔다**: 표나 손글씨처럼 애매한 영역은 모델이 그럴듯하지만 틀린 값을 낼 수 있으므로, 금액·날짜처럼 사업적으로 중요한 필드는 사람 검수나 이중 검증 로직을 함께 설계한다.
- **이미지 저장·전송 시 개인정보를 고려한다**: 신분증, 영수증 등 민감 정보가 담긴 이미지를 외부 API로 보낼 때는 사내 데이터 정책과 모델 제공사의 데이터 처리 방침을 함께 확인해야 한다.

## 3줄 요약

- 멀티모달 모델은 이미지를 텍스트와 동일한 토큰 시퀀스로 처리해, OCR·이미지 분류·LLM으로 나뉘어 있던 파이프라인을 하나의 요청으로 통합할 수 있게 해준다.
- 이미지 캡셔닝, VQA, 문서·차트 이해, 다중 이미지 비교 등 패턴마다 입력 설계가 다르며, 구조화된 결과가 필요하면 Tool Use나 구조화 출력과 함께 쓰는 것이 안전하다.
- 실전에서는 해상도·토큰 비용 균형, 다중 이미지 순서 명시, 중요 수치의 재검증 절차, 민감 이미지의 데이터 처리 방침까지 함께 설계해야 안정적으로 운영할 수 있다.
