## 한 클러스터에 여러 팀·환경이 섞인다

하나의 쿠버네티스 클러스터에 여러 팀의 앱, 또는 개발/스테이징 환경이 함께 돌면 리소스가 뒤섞여 관리가 어렵다. 같은 이름의 리소스가 충돌하기도 한다. **네임스페이스(Namespace)**는 **하나의 클러스터를 논리적으로 여러 공간으로 나눠** 이 문제를 푼다. 큰 사무실을 팀별 구역으로 나누는 것과 비슷하다.

## 무엇을 주나

| 기능 | 설명 |
|---|---|
| 이름 격리 | 다른 네임스페이스면 같은 이름 리소스 가능 |
| 리소스 쿼터 | 네임스페이스별 CPU·메모리 상한 |
| 접근 제어 | 네임스페이스 단위로 권한(RBAC) 부여 |

## 사용 예

```text
kubectl create namespace dev
kubectl create namespace prod

# 특정 네임스페이스에 배포/조회
kubectl apply -f app.yaml -n dev
kubectl get pods -n prod

기본 네임스페이스는 'default'
```

## 실무 포인트

- **환경·팀 분리에 쓴다.** `dev`·`staging`·`prod`로 나누거나, 팀별로 네임스페이스를 두면 리소스가 섞이지 않고 권한도 분리할 수 있다. 단, 완전한 보안 격리는 아니므로 강한 격리가 필요하면 클러스터를 분리한다.
- **리소스 쿼터로 폭주를 막는다.** 한 네임스페이스가 클러스터 자원을 다 쓰지 못하게 CPU·메모리 상한(ResourceQuota)을 건다. 개발 환경이 운영 자원을 잠식하는 사고를 예방한다.
- **네임스페이스를 지우면 안의 것도 지워진다.** 네임스페이스 삭제는 그 안의 모든 리소스를 함께 지운다. 운영 네임스페이스 삭제는 매우 위험하니 신중해야 한다.

## 마무리 요약

- 네임스페이스는 하나의 클러스터를 논리적으로 나눠 팀·환경별로 격리하는 공간이다.
- 이름 격리, 리소스 쿼터, 접근 제어를 네임스페이스 단위로 줄 수 있다.
- 환경·팀 분리에 쓰되 완전한 보안 격리는 아니며, 삭제 시 내부 리소스가 함께 지워진다.
