## 왜 지금 공간 인덱스 그리드인가

"내 위치 반경 3km 안의 매장 찾기", "인근 배차 가능 차량 조회" 같은 기능은 위경도 좌표 그대로 비교하면 성능이 나오지 않는다. 그래서 지도를 일정한 규칙의 격자(그리드)로 나누고, 각 셀에 고유 문자열/정수 ID를 부여해 인덱싱하는 방식이 널리 쓰인다. 오랫동안 표준처럼 쓰인 **Geohash**에 이어, Uber가 만든 **H3**가 배차·물류·공간 분석 도구에서 채택 사례를 늘리고 있다.

두 방식 모두 "좌표를 문자열/정수 하나로 바꿔서 빠르게 검색하고 근접도를 계산한다"는 목적은 같지만, 그리드의 모양과 성질이 달라 적합한 상황이 갈린다. PostGIS 같은 공간 DB를 쓰더라도, 애플리케이션 계층에서 이런 그리드 인덱스를 함께 쓰는 경우가 많아 두 방식의 차이를 알아둘 필요가 있다.

## Geohash와 H3 비교

| 항목 | Geohash | H3 |
|---|---|---|
| 셀 모양 | 사각형(위경도 비트 인터리빙) | 육각형(일부 오각형 포함) |
| 이웃 셀 개수 | 8개(모서리 인접 왜곡 있음) | 6개(균일한 인접 거리) |
| 접두어 관계 | 문자열 접두어 = 상위 영역(정렬·범위 쿼리 용이) | 계층 인덱스 있으나 문자열 접두어와 다름 |
| 면적 왜곡 | 위도에 따라 셀 폭이 크게 달라짐 | 상대적으로 균일(완전히 동일하진 않음) |
| 대표 용도 | DB 정렬/범위 쿼리, 간단한 근접 검색 | 배차, 밀도 분석, 육각 격자 집계 |

Geohash는 문자열 접두어만으로 상위 영역을 알 수 있어 DB 인덱스와 궁합이 좋고, H3는 육각형 특유의 균일한 인접 구조 덕분에 "주변 셀 확장 탐색"이 더 자연스럽다.

## 핵심 개념: 왜 육각형인가

사각 그리드는 인접 셀이 "변으로 붙은 4개"와 "꼭짓점으로만 닿은 4개"로 나뉘어, 이웃 간 거리가 방향에 따라 달라진다(대각선 이웃이 더 멀다). 이 때문에 "반경 검색"을 사각 그리드로 근사하면 방향에 따라 오차가 들쭉날쭉해진다.

육각 그리드는 모든 이웃 6개가 중심으로부터 거의 동일한 거리에 있어, 밀도 추정이나 반경 근사가 더 균일하다. H3는 이 성질을 살려 지구 전체를 육각형(정확히는 20면체 기반이라 12개 오각형 포함)으로 덮고, 여러 해상도 레벨(0~15)을 계층적으로 제공한다.

## 예제: H3로 좌표를 셀로 변환 (Python)

```python
import h3

lat, lng = 37.5665, 126.9780  # 서울시청
resolution = 9  # 약 174m 육각형 셀

cell = h3.latlng_to_cell(lat, lng, resolution)
neighbors = h3.grid_disk(cell, 1)  # 자신 + 인접 6개

print(cell)        # 예: '891f2c4d2a7ffff' 형태의 H3 인덱스
print(len(neighbors))  # 7
```

`grid_disk`로 반경 k셀 이내 이웃을 한 번에 구할 수 있어, "내 셀과 인접 셀들"을 조건으로 하는 근접 검색 쿼리를 단순하게 짤 수 있다.

## 실무 포인트

- **정렬·범위 쿼리가 중심이면 Geohash**: RDBMS 인덱스에 문자열로 저장해 접두어 범위 검색(`LIKE 'wydm%'`)만으로 근사 영역 조회가 가능하다.
- **균일한 반경 근사·집계가 중심이면 H3**: 배차 앱의 "주변 기사 찾기", 밀도 히트맵 같은 용도에는 육각 그리드의 균일성이 유리하다.
- **해상도(정밀도) 선택이 성능을 좌우한다**: 해상도가 너무 세밀하면 인덱스 크기와 쿼리 수가 폭증하고, 너무 성기면 근사 오차가 커진다. 서비스의 실제 검색 반경에 맞춰 실험적으로 정한다.
- **PostGIS와 병행 가능하다**: 정밀한 폴리곤 연산은 PostGIS(`ST_DWithin` 등)에 맡기고, 대량 후보군을 빠르게 좁히는 1차 필터로 Geohash/H3를 쓰는 조합이 흔하다.

## 3줄 요약

- Geohash는 사각 그리드와 문자열 접두어 구조 덕분에 DB 정렬·범위 쿼리에 강하다.
- H3는 육각 그리드의 균일한 인접 거리 덕분에 반경 근사와 밀도 집계에 유리하다.
- 두 방식은 대체재가 아니라 상황별 도구이며, PostGIS 정밀 연산과 함께 1차 필터로 병행하는 것이 실무에서 흔한 패턴이다.
