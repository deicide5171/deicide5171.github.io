## `0 == "0"`은 참인데 `0 === "0"`은 거짓

자바스크립트에는 비교 연산자가 둘 있다. **`==`(느슨한 동등)**과 **`===`(엄격한 동등)**이다. 둘의 차이는 **타입이 다를 때 자동 변환을 하느냐**다. `==`는 타입을 맞춰 비교하고, `===`는 타입까지 같아야 참이다.

## == vs ===

| 비교 | 결과 | 이유 |
|---|---|---|
| `0 == "0"` | true | 타입 변환 후 비교 |
| `0 === "0"` | false | 타입(숫자 vs 문자열)이 다름 |
| `null == undefined` | true | ==에선 같다고 봄 |
| `null === undefined` | false | 타입이 다름 |

## == 의 함정

```javascript
0 == ""        // true  (둘 다 0으로 변환)
0 == "0"       // true
"" == "0"      // false (문자열끼리는 변환 안 함)
false == "0"   // true
```

`==`는 이렇게 직관과 어긋나는 결과를 낸다. 규칙이 복잡해 버그의 원인이 되기 쉽다.

## 실무 포인트

- **기본적으로 `===`를 써라.** 대부분의 스타일 가이드가 `===`를 권장한다. 타입 변환으로 인한 예상 밖 결과를 막고, 코드 의도가 분명해진다. `!=` 대신 `!==`도 마찬가지다.
- **`null`·`undefined` 체크는 예외적으로 `==` 활용.** `value == null`은 `value`가 `null` 또는 `undefined`일 때 참이다. 이 하나만은 `==`가 편리해 의도적으로 쓰기도 한다.
- **타입을 먼저 맞춰라.** 사용자 입력은 대부분 문자열이다. 숫자와 비교하려면 `Number(input) === 5`처럼 명시적으로 변환한 뒤 `===`로 비교하는 것이 안전하다.

## 마무리 요약

- `==`는 타입을 자동 변환해 비교하고, `===`는 타입까지 같아야 참이다.
- `==`는 `0 == "0"`처럼 직관과 어긋나는 결과를 내 버그의 원인이 된다.
- 기본적으로 `===`를 쓰고, 값 타입을 명시적으로 맞춰 비교하는 것이 안전하다.
