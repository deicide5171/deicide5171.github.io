## LLM은 시키는 대로 하지 않을 때가 있다

LLM은 때로 욕설·개인정보를 뱉거나, JSON을 달라 했는데 설명을 붙이거나, 주제를 벗어난 답을 한다. 실제 서비스에 그대로 쓰면 위험하다. **가드레일(guardrails)**은 **LLM의 입력과 출력을 검사·차단·교정**해, 정해진 범위 안에서만 동작하게 하는 안전장치다.

## 어디에 두나

| 위치 | 하는 일 |
|---|---|
| 입력 가드레일 | 위험한 질문·프롬프트 주입 차단 |
| 출력 가드레일 | 유해 내용·형식 위반·개인정보 필터 |

## 흐름

```text
사용자 입력 -> [입력 가드레일] -> LLM -> [출력 가드레일] -> 사용자
  입력: 금지 주제·공격 프롬프트 걸러냄
  출력: 욕설·개인정보·형식 위반 검사, 위반 시 차단/재생성
```

## 실무 포인트

- **형식 강제는 가드레일의 흔한 용도다.** "반드시 JSON으로"를 프롬프트로만 부탁하면 가끔 어긴다. 출력이 정해진 스키마에 맞는지 검사하고, 어기면 재요청하거나 고쳐서 안정적인 형식을 보장한다.
- **입력 검사로 프롬프트 주입을 막는다.** "이전 지시를 무시하고..." 같은 공격(프롬프트 인젝션)을 입력 단계에서 탐지·차단한다. 사용자 입력을 그대로 믿지 않는 것이 핵심이다.
- **완벽하지 않으니 여러 겹으로.** 가드레일 하나로 모든 위험을 막을 수는 없다. 입력·출력 검사, 로깅, 사람 검토(민감한 작업) 등을 겹겹이 두는 것이 안전하다.

## 마무리 요약

- 가드레일은 LLM의 입력·출력을 검사·차단·교정해 정해진 범위 안에서만 동작하게 한다.
- 입력 가드레일은 위험 질문·프롬프트 주입을, 출력 가드레일은 유해 내용·형식 위반을 막는다.
- 형식 강제·주입 방어에 유용하며, 완벽하지 않으니 여러 겹의 안전장치로 설계한다.
