## 로그 파일이 디스크를 다 먹어버렸다

애플리케이션은 계속 로그를 남긴다. 하나의 로그 파일에 무한정 쌓이면, 결국 디스크가 꽉 차 서버 전체가 멈추는 사고로 이어진다. **로그 로테이션(log rotation)**은 **로그 파일을 주기적으로(또는 크기 기준으로) 잘라 새 파일로 넘기고, 오래된 파일은 압축·삭제**해 디스크를 지켜준다.

## 무엇을 하나

| 동작 | 설명 |
|---|---|
| 자르기(rotate) | `app.log` → `app.log.1`로 넘기고 새 `app.log` 시작 |
| 압축(compress) | 오래된 로그를 gzip으로 용량 줄임 |
| 보관 기간(retention) | 일정 개수/기간 넘은 로그는 삭제 |

## logrotate 설정 예시

```text
# /etc/logrotate.d/myapp
/var/log/myapp/*.log {
    daily            # 매일 자른다
    rotate 14        # 14개(=14일치)만 보관
    compress         # 오래된 건 압축
    missingok        # 로그 파일 없어도 에러 안 냄
    notifempty       # 비어 있으면 안 자름
}
```

리눅스에서는 `logrotate`가 대표적이다. 이 설정이면 매일 로그를 잘라 14일치만 남기고 나머지는 지운다.

## 실무 포인트

- **로테이션 후 앱이 새 파일에 쓰게 하라.** 파일을 옮겨도 앱이 옛 파일 핸들을 붙잡고 있으면 새 로그가 사라진 파일에 쓰인다. `copytruncate` 옵션을 쓰거나, 로테이션 후 앱에 시그널을 보내 파일을 다시 열게 한다.
- **컨테이너 환경은 방식이 다르다.** 도커/쿠버네티스는 보통 로그를 표준출력(stdout)으로 내보내고, 플랫폼이 로테이션·수집을 담당한다. 컨테이너 안에서 직접 파일 로테이션을 하기보다 이 방식을 따르는 것이 좋다.
- **크기와 시간 기준을 함께 고려하라.** 트래픽이 몰리면 하루 만에 로그가 폭증할 수 있다. `daily`뿐 아니라 `maxsize`로 크기 기준도 걸어두면 급증에도 안전하다.

## 마무리 요약

- 로그 로테이션은 로그 파일을 잘라 새 파일로 넘기고, 오래된 것은 압축·삭제해 디스크가 차는 것을 막는다.
- 리눅스에선 `logrotate`로 주기·보관 개수·압축 등을 설정한다.
- 로테이션 후 앱이 새 파일에 쓰게 하고, 컨테이너 환경은 stdout+플랫폼 수집 방식을 따르는 것이 좋다.
