## Permission denied는 왜 뜨나

리눅스에서 스크립트를 실행하거나 파일을 열려는데 "Permission denied"가 뜨는 것은 **파일 권한** 때문이다. 리눅스는 각 파일에 "누가 무엇을 할 수 있는지"를 정해둔다. `ls -l`로 보면 `rwxr-xr-x` 같은 표시가 이 권한이다.

## rwx와 대상

```text
-rwxr-xr-x  로 예를 들면
 ├── rwx : 소유자(user)  = 읽기·쓰기·실행
 ├── r-x : 그룹(group)   = 읽기·실행
 └── r-x : 기타(others)  = 읽기·실행

r=읽기(4), w=쓰기(2), x=실행(1)
```

## 숫자 표기 (chmod 755)

| 숫자 | 권한 | 뜻 |
|---|---|---|
| 7 | rwx | 읽기+쓰기+실행 (4+2+1) |
| 5 | r-x | 읽기+실행 (4+1) |
| 6 | rw- | 읽기+쓰기 (4+2) |
| 0 | --- | 없음 |

`chmod 755 file` = 소유자 rwx, 그룹·기타 r-x

## 실무 포인트

- **스크립트는 실행 권한(x)이 필요.** `./deploy.sh`가 "Permission denied"면 실행 권한이 없는 것이다. `chmod +x deploy.sh`로 실행 권한을 준다.
- **민감 파일은 권한을 좁혀라.** SSH 개인키·설정 파일은 소유자만 읽게 `chmod 600`으로 좁힌다. 권한이 너무 열려 있으면 SSH가 키 사용을 거부하기도 한다.
- **777은 피하라.** `chmod 777`은 누구나 읽고 쓰고 실행할 수 있게 열어버려 보안에 매우 위험하다. "권한 문제니 777로"는 나쁜 습관이다. 꼭 필요한 권한만 준다.

## 마무리 요약

- 리눅스 파일 권한은 소유자·그룹·기타에 대해 읽기(r)·쓰기(w)·실행(x)을 정한다.
- `rwxr-xr-x`는 chmod 숫자로 755(4+2+1 / 4+1 / 4+1)에 해당한다.
- 스크립트엔 실행 권한(+x), 민감 파일엔 좁은 권한(600)을 주고 777은 피한다.
