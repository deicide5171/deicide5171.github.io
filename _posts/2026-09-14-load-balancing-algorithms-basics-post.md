## 요청을 서버들에 어떻게 나누나

로드 밸런서는 들어온 요청을 여러 서버에 나눠준다. 그런데 "어느 서버로 보낼지"를 정하는 규칙이 여럿이다. 이 규칙이 **부하 분산 알고리즘(load balancing algorithm)**이다. 상황에 맞는 방식을 골라야 서버 부하가 고르게 퍼진다.

## 대표 알고리즘

| 알고리즘 | 방식 |
|---|---|
| 라운드 로빈 | 순서대로 돌아가며 배정 |
| 가중 라운드 로빈 | 성능 좋은 서버에 더 많이 |
| 최소 연결 | 연결이 가장 적은 서버로 |
| IP 해시 | 같은 IP는 항상 같은 서버로 |

## 언제 무엇을 쓰나

```text
라운드 로빈: 서버 성능이 비슷하고 요청이 균일할 때
최소 연결:   요청 처리 시간이 제각각일 때(긴 요청 대비)
IP 해시:     같은 사용자를 같은 서버로(세션 유지) 보낼 때
```

## 실무 포인트

- **라운드 로빈이 기본이자 무난.** 서버 성능이 비슷하면 라운드 로빈만으로 충분히 고르게 분산된다. 가장 간단해 기본값으로 많이 쓴다.
- **처리 시간이 들쭉날쭉하면 최소 연결.** 어떤 요청은 금방, 어떤 요청은 오래 걸리면 라운드 로빈은 특정 서버에 긴 작업이 몰릴 수 있다. 이럴 땐 현재 연결이 적은 서버로 보내는 최소 연결이 낫다.
- **세션이 필요하면 스티키 세션.** 로그인 상태를 특정 서버 메모리에 두면, 매번 다른 서버로 가면 세션이 끊긴다. IP 해시나 스티키 세션으로 같은 사용자를 같은 서버에 붙인다. 단, 세션을 외부(Redis 등)에 두면 이 제약이 사라진다.

## 마무리 요약

- 부하 분산 알고리즘은 로드 밸런서가 요청을 어느 서버로 보낼지 정하는 규칙이다.
- 라운드 로빈(순서)·가중(성능 반영)·최소 연결(적은 곳으로)·IP 해시(세션 유지)가 대표적이다.
- 서버가 비슷하면 라운드 로빈, 처리 시간이 다르면 최소 연결, 세션 유지엔 IP 해시를 쓴다.
