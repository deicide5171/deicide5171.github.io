## 챗봇과 에이전트는 뭐가 다른가

일반 챗봇은 질문을 받으면 텍스트로 답만 한다. 반면 **AI 에이전트(agent)**는 목표를 받으면 스스로 계획을 세우고, **도구를 써서 실제 행동을 하고, 결과를 보고 다시 판단하는 과정을 반복**해 목표를 달성한다. "파리 항공권 알아봐줘"라고 하면, 챗봇은 방법을 설명하지만 에이전트는 검색 도구를 호출해 실제로 항공권을 찾아온다.

## 에이전트의 핵심 요소

| 요소 | 설명 |
|---|---|
| LLM(두뇌) | 무엇을 할지 판단하고 계획을 세운다 |
| 도구(tools) | 검색·API 호출·코드 실행 등 실제 행동 수단 |
| 반복 루프 | 행동 → 결과 관찰 → 다음 행동 결정을 반복 |
| 메모리 | 지금까지의 진행 상황·맥락을 기억 |

챗봇은 "LLM 하나"만 있지만, 에이전트는 여기에 **도구 사용**과 **반복 루프**가 더해진 것이라고 보면 이해하기 쉽다.

## 동작 흐름

```text
목표: "이번 주 서울 날씨 정리해줘"

1. LLM: "날씨 API를 호출해야겠다" (판단)
2. 도구 실행: 날씨 API 호출 -> 데이터 받음 (행동)
3. LLM: 데이터를 보고 "충분한가?" 판단 (관찰)
4. 부족하면 다시 도구 호출, 충분하면 정리해 답변 (반복/종료)
```

이 "판단 → 행동 → 관찰 → 반복" 루프가 에이전트의 본질이다.

## 실무 포인트

- **에이전트는 강력하지만 예측하기 어렵다.** 스스로 여러 단계를 결정하므로, 의도치 않은 행동을 할 수 있다. 실제 시스템에 영향을 주는 도구(결제, 삭제 등)는 사람이 확인하는 단계(human-in-the-loop)를 두는 것이 안전하다.
- **모든 문제에 에이전트가 필요하진 않다.** 단순 질의응답이나 정해진 흐름은 일반 LLM 호출이나 규칙 기반으로 충분하다. 여러 도구를 오가며 여러 단계 판단이 필요할 때 에이전트가 빛을 발한다.
- **비용과 시간을 고려하라.** 에이전트는 루프를 돌 때마다 LLM을 여러 번 호출하므로, 한 번의 챗봇 응답보다 비용과 지연이 크다. 루프 횟수 제한 등 안전장치가 필요하다.

## 마무리 요약

- AI 에이전트는 목표를 받아 스스로 도구를 쓰고 결과를 보며 반복 판단해 일을 처리한다.
- 챗봇(LLM 하나)에 도구 사용과 반복 루프가 더해진 것이 에이전트다.
- 강력하지만 예측이 어렵고 비용이 크므로, 위험한 행동엔 사람 확인을 두고 필요할 때만 써야 한다.
