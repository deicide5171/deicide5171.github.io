## 왜 "SQL을 안 쓴다"는 이름이 붙었나

NoSQL은 원래 "No SQL(SQL을 안 쓴다)"이라는 뜻으로 시작했지만, 지금은 대부분 "Not Only SQL(SQL만 쓰지 않는다)"로 이해된다. 즉 관계형 DB처럼 고정된 테이블·행·열 구조와 SQL 질의어에 얽매이지 않고, 데이터 성격에 맞는 다양한 저장 구조를 쓰는 데이터베이스들을 통칭하는 말이다.

## 관계형 DB와 NoSQL의 근본적인 차이

| 항목 | 관계형 DB(SQL) | NoSQL |
|---|---|---|
| 스키마 | 미리 정의된 고정 스키마 | 스키마가 유연하거나 없음 |
| 데이터 모델 | 테이블(행과 열) | 문서, 키-값, 그래프, 와이드컬럼 등 다양 |
| 관계 표현 | JOIN으로 여러 테이블 연결 | 보통 하나의 문서/구조에 관련 데이터를 함께 저장 |
| 확장 방식 | 수직 확장(서버 성능 업그레이드) 위주 | 수평 확장(서버 대수를 늘리는 것)에 강점 |
| 대표 예시 | MySQL, PostgreSQL | MongoDB(문서), Redis(키-값), Cassandra(와이드컬럼) |

## 같은 데이터, 다른 표현 방식

```sql
-- 관계형 DB: 사용자와 주문을 별도 테이블로 나누고 JOIN으로 연결
SELECT u.name, o.item, o.price
FROM users u
JOIN orders o ON u.id = o.user_id
WHERE u.id = 1;
```

```json
// NoSQL(문서형): 사용자 문서 안에 주문 정보를 함께 내장
{
  "_id": 1,
  "name": "김철수",
  "orders": [
    { "item": "노트북", "price": 1500000 },
    { "item": "마우스", "price": 30000 }
  ]
}
```

관계형 DB는 데이터를 중복 없이 나누고 필요할 때 JOIN으로 합치는 것을 지향하지만(정규화), NoSQL 문서형은 자주 함께 조회하는 데이터를 아예 하나의 구조에 미리 합쳐 넣는(비정규화) 경향이 있다.

## 실무 포인트

- **NoSQL이 관계형 DB보다 무조건 빠르거나 뛰어난 것은 아니다.** 각각 다른 트레이드오프를 갖고 있을 뿐이며, 강한 일관성과 복잡한 JOIN이 필요한 데이터라면 여전히 관계형 DB가 적합하다.
- **NoSQL은 세부 종류에 따라 성격이 완전히 다르다.** 문서형(MongoDB), 키-값형(Redis), 와이드컬럼형(Cassandra), 그래프형(Neo4j)은 각각 다른 문제를 풀기 위해 설계됐으므로 "NoSQL 하나"로 뭉뚱그려 비교하는 것은 의미가 없다.
- **비정규화된 구조는 조회는 빠르지만 데이터 일관성을 애플리케이션이 직접 관리해야 하는 부담이 생긴다.** 주문 정보가 사용자 문서에 중복 저장되면, 나중에 데이터 수정 시 여러 곳을 함께 갱신해야 할 수 있다.

## 마무리 요약

- NoSQL은 SQL을 아예 안 쓴다는 뜻이 아니라, 고정된 테이블 구조에 얽매이지 않는 다양한 데이터베이스를 통칭하는 말이다.
- 관계형 DB는 정규화와 JOIN을 지향하고, NoSQL 문서형은 자주 함께 쓰는 데이터를 미리 합쳐두는 경향이 있다.
- NoSQL 세부 종류마다 성격이 크게 다르므로, 데이터 성격과 조회 패턴에 맞는 종류를 골라야 한다.
