## 파일 업로드는 왜 텍스트 데이터와 다른가

일반 폼 데이터는 JSON으로 주고받으면 되지만, 이미지·PDF 같은 파일은 크기가 크고 이진 데이터라 다르게 처리해야 한다. 그래서 파일 업로드는 보통 **multipart/form-data**라는 형식으로 전송된다. 이 형식은 하나의 요청에 파일과 다른 텍스트 필드를 함께 담을 수 있다.

## 서버가 파일을 받는 흐름

```java
// Spring Boot 파일 업로드 예제
@PostMapping("/upload")
public String upload(@RequestParam("file") MultipartFile file) {
    if (file.isEmpty()) {
        return "파일이 없습니다";
    }
    String filename = file.getOriginalFilename();
    // 서버 디스크나 클라우드 스토리지에 저장
    file.transferTo(new File("/uploads/" + filename));
    return "업로드 완료: " + filename;
}
```

## 어디에 저장할 것인가

| 저장 위치 | 특징 |
|---|---|
| 서버 로컬 디스크 | 간단하지만 서버가 여러 대면 파일이 서버마다 흩어짐 |
| 클라우드 오브젝트 스토리지(S3 등) | 확장성·내구성 좋음, 사실상 실무 표준 |
| DB에 직접 저장(BLOB) | 작은 파일엔 가능하나 대용량엔 비효율적, 권장하지 않음 |

서버가 한 대일 때는 로컬 디스크도 괜찮지만, 여러 대로 확장하면 A 서버에 올린 파일을 B 서버가 못 찾는 문제가 생긴다. 그래서 실무에서는 S3 같은 별도 스토리지에 저장하는 것이 표준이다.

## 보안·안정성 주의점

```text
1. 파일 크기 제한
   -> 무제한이면 거대한 파일로 디스크·메모리를 고갈시키는 공격 가능

2. 파일 확장자·타입 검증
   -> 이미지만 받는다면서 실행 파일(.exe, .sh)이 올라오면 위험

3. 파일명 그대로 쓰지 않기
   -> 사용자가 준 파일명에 ../ 같은 경로가 들어가면
      의도치 않은 위치에 저장될 수 있다(경로 조작 공격)
   -> 서버에서 안전한 이름(UUID 등)으로 새로 지정하는 것이 안전
```

## 실무 포인트

- **업로드 파일은 웹 서버가 실행할 수 없는 위치에 저장해야 한다.** 업로드 폴더에 올라온 스크립트 파일이 그대로 실행 가능한 경로에 있으면 심각한 보안 사고로 이어진다.
- **대용량 파일은 서버를 거치지 않는 방식(Presigned URL)을 검토하라.** 클라이언트가 S3에 직접 업로드하도록 임시 서명 URL을 발급하면, 큰 파일이 서버 메모리를 거치지 않아 서버 부하가 크게 줄어든다.
- **이미지라면 원본 그대로 두지 말고 리사이징·최적화를 고려하라.** 사용자가 올린 고해상도 원본을 그대로 서비스하면 트래픽과 저장 비용이 커지므로, 용도에 맞는 크기로 변환해 두는 것이 좋다.

## 마무리 요약

- 파일 업로드는 크기가 크고 이진 데이터라 multipart/form-data 형식으로 전송된다.
- 서버가 여러 대라면 로컬 디스크 대신 S3 같은 오브젝트 스토리지에 저장하는 것이 표준이다.
- 크기 제한·타입 검증·안전한 파일명 지정은 보안을 위해 반드시 갖춰야 할 기본이다.
