## 배포를 사람이 손으로 하면 실수가 난다

코드를 고칠 때마다 사람이 직접 빌드하고 테스트하고 서버에 올리면, 느리고 실수가 잦다. **CI/CD**는 **이 과정을 자동화**한다. 코드를 올리면 자동으로 검증하고 배포까지 이어지게 하는 것이다.

## CI와 CD

| 용어 | 의미 |
|---|---|
| CI(지속적 통합) | 코드 변경을 자동으로 빌드·테스트해 통합 |
| CD(지속적 배포/전달) | 검증된 코드를 자동으로 배포 |

## 파이프라인 흐름

```text
1. 개발자가 코드를 푸시(git push)
2. CI: 자동 빌드 -> 테스트 실행 -> 통과 확인
3. CD: 통과하면 스테이징/운영에 자동 배포

-> 사람 개입 없이 "푸시 -> 검증 -> 배포"가 흐른다
```

## 실무 포인트

- **테스트가 CI의 핵심.** CI가 의미 있으려면 자동 테스트가 있어야 한다. 테스트 없이 빌드만 하면 버그가 그대로 배포된다. 테스트가 실패하면 배포를 막아 나쁜 코드가 운영에 못 가게 한다.
- **CD는 단계적으로.** 곧바로 운영에 자동 배포(지속적 배포)하는 것이 부담되면, 운영 직전까지만 자동화하고 마지막 배포는 사람이 승인(지속적 전달)하는 방식으로 시작한다.
- **빠르고 안정적인 파이프라인.** 파이프라인이 너무 느리면 개발자가 기다리다 지친다. 테스트를 병렬화하고 캐시를 활용해 빠르게 유지하며, 실패 시 원인을 바로 알 수 있게 한다. GitHub Actions, GitLab CI 등이 널리 쓰인다.

## 마무리 요약

- CI/CD는 코드 변경을 자동으로 빌드·테스트(CI)하고 배포(CD)하는 자동화다.
- "푸시 → 자동 검증 → 자동 배포" 파이프라인으로 실수를 줄이고 배포를 빠르게 한다.
- 자동 테스트가 핵심이며, CD는 단계적으로 도입하고 파이프라인을 빠르게 유지한다.
