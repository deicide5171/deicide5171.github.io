## 상태 코드의 첫 자리 숫자가 곧 분류다

HTTP 응답에는 항상 상태 코드가 붙는다. 이 세 자리 숫자는 무작위가 아니라 **첫 자리 숫자로 큰 분류가 정해진다**. 이 규칙만 알아도 처음 보는 코드의 대략적인 의미를 짐작할 수 있다.

| 첫 자리 | 분류 | 의미 |
|---|---|---|
| 2xx | 성공 | 요청이 정상 처리됨 |
| 3xx | 리다이렉션 | 다른 곳으로 이동하라 |
| 4xx | 클라이언트 오류 | 요청하는 쪽이 잘못함 |
| 5xx | 서버 오류 | 서버 쪽에서 문제 발생 |

## 자주 만나지만 헷갈리는 코드들

```text
[성공 2xx]
200 OK        - 일반적인 성공
201 Created   - 새 자원 생성 성공 (POST 후)
204 No Content - 성공했지만 응답 본문 없음 (삭제 후 등)

[클라이언트 오류 4xx]
400 Bad Request  - 요청 형식이 잘못됨
401 Unauthorized - 인증 안 됨 (로그인 필요)
403 Forbidden    - 인증은 됐지만 권한 없음
404 Not Found    - 자원이 없음
429 Too Many Requests - 요청이 너무 많음(레이트 리밋)

[서버 오류 5xx]
500 Internal Server Error - 서버 내부 오류(가장 흔함)
502 Bad Gateway   - 게이트웨이가 뒷단에서 잘못된 응답 받음
503 Service Unavailable - 서버가 일시적으로 처리 불가(과부하·점검)
504 Gateway Timeout - 게이트웨이가 뒷단 응답을 기다리다 타임아웃
```

## 헷갈리기 쉬운 구분

- **401 vs 403**: 401은 "누구인지 모르겠다(로그인 안 함)", 403은 "누군지는 아는데 권한이 없다"이다.
- **400 vs 422**: 400은 요청 형식 자체가 잘못됨, 422는 형식은 맞는데 내용이 검증에 실패함(예: 이메일 형식 오류)이다.
- **502 vs 503 vs 504**: 502는 뒷단이 이상한 응답을 줌, 503은 서버가 아예 처리 불가 상태, 504는 뒷단이 시간 안에 응답을 안 줌이다.

## 실무 포인트

- **상태 코드를 정확히 쓰면 클라이언트가 로직으로 분기하기 쉬워진다.** 모든 오류를 200으로 주고 본문에 에러를 담는 방식은, 클라이언트가 매번 본문을 뜯어봐야 해서 좋지 않다. 인증 실패는 401, 자원 없음은 404처럼 코드로 명확히 알려주는 것이 표준이다.
- **500번대는 사용자 잘못이 아니라 서버 문제라는 신호다.** 로그와 모니터링에서 5xx가 늘어나면 서버 쪽을 즉시 점검해야 한다. 반대로 4xx는 잘못된 요청이 많다는 뜻이라 클라이언트나 API 사용법을 살펴봐야 한다.
- **429를 받으면 무작정 재시도하지 말고 대기해야 한다.** 응답의 `Retry-After` 헤더가 알려주는 시간만큼 기다렸다 재시도하는 것이 올바른 대응이다.

## 마무리 요약

- HTTP 상태 코드는 첫 자리 숫자로 성공(2xx)·리다이렉션(3xx)·클라이언트 오류(4xx)·서버 오류(5xx)로 분류된다.
- 401(인증)과 403(권한), 502/503/504의 차이를 구분하면 문제 원인을 빠르게 좁힐 수 있다.
- 상태 코드를 정확히 쓰면 클라이언트가 응답을 코드로 분기할 수 있어 API 사용성이 좋아진다.
