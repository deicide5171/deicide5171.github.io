## 서버에 아무나 접속하면 안 된다

서버를 인터넷에 열어두면 전 세계 누구나 접근을 시도할 수 있다. 실제로 공개 IP를 가진 서버는 몇 분 안에 자동 스캔 봇의 접속 시도를 받는다. **방화벽(firewall)**은 어떤 트래픽을 허용하고 차단할지 규칙으로 정해 서버를 보호한다. 클라우드에서는 이를 **보안 그룹(Security Group)**이라는 형태로 제공한다.

## 방화벽 규칙의 기본 요소

| 요소 | 설명 |
|---|---|
| 방향 | 인바운드(들어옴) / 아웃바운드(나감) |
| 포트 | 어떤 포트를 열지 (80, 443, 22 등) |
| 소스/대상 | 어느 IP 대역에서 오는 것을 허용할지 |
| 프로토콜 | TCP, UDP 등 |

## 흔히 여는 포트

```text
22   : SSH (서버 원격 접속)
80   : HTTP
443  : HTTPS
3306 : MySQL (외부에 열면 매우 위험!)
5432 : PostgreSQL (외부에 열면 매우 위험!)

원칙: 꼭 필요한 포트만, 꼭 필요한 대상에게만 연다 (최소 권한)
```

## 보안 그룹 설정 예시(개념)

```text
인바운드 규칙:
- 443(HTTPS): 모든 IP 허용 (웹 서비스니까)
- 22(SSH): 우리 사무실 IP만 허용 (아무나 접속 못 하게)
- 3306(DB): 애플리케이션 서버의 보안 그룹만 허용 (외부 차단)

-> DB 포트를 "모든 IP"에 열면 전 세계에서 접근 시도가 들어온다
```

## 실무 포인트

- **DB 포트를 절대 인터넷 전체에 열지 마라.** 3306(MySQL), 5432(PostgreSQL) 같은 DB 포트를 `0.0.0.0/0`(모든 IP)에 열어두면 무차별 공격의 표적이 된다. DB는 애플리케이션 서버에서만 접근 가능하게 제한해야 한다.
- **클라우드 보안 그룹과 서버 내부 방화벽이 이중으로 걸릴 수 있다.** 포트가 안 열리는 문제를 서버 안에서만 찾다가, 정작 클라우드 콘솔의 보안 그룹에서 막혀 있던 경우가 흔하다. 둘 다 확인해야 한다.
- **아웃바운드도 필요하면 제한하라.** 대부분 인바운드에 집중하지만, 보안이 중요한 환경에서는 서버가 외부로 나가는 트래픽(아웃바운드)도 제한해 데이터 유출·악성코드 통신을 막는다.

## 마무리 요약

- 방화벽·보안 그룹은 서버로 드나드는 트래픽을 규칙으로 통제해 보호한다.
- 방향·포트·소스·프로토콜로 규칙을 정하며, "꼭 필요한 포트만 필요한 대상에게" 여는 최소 권한이 원칙이다.
- DB 포트를 모든 IP에 여는 것은 절대 금물이고, 클라우드 보안 그룹과 서버 방화벽을 함께 확인해야 한다.
