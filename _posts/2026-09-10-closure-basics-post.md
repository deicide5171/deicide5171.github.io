## 함수가 끝났는데 변수가 살아있다?

보통 함수가 끝나면 그 안의 변수는 사라진다. 그런데 자바스크립트에서는 함수 안에서 만든 함수가 **바깥 함수의 변수를 계속 기억**하는 경우가 있다. 이렇게 **함수가 자신이 선언된 곳의 변수(환경)를 기억하는 것**을 **클로저(closure)**라 한다.

## 예시로 보기

```javascript
function makeCounter() {
  let count = 0;              // 바깥 함수의 변수
  return function() {         // 안쪽 함수(클로저)
    count += 1;
    return count;
  };
}

const counter = makeCounter();
counter(); // 1
counter(); // 2  (count가 살아서 유지됨!)
```

`makeCounter`는 끝났지만, 반환된 함수가 `count`를 계속 기억한다. 그래서 호출할 때마다 값이 누적된다.

## 무엇에 쓰나

| 활용 | 설명 |
|---|---|
| 상태 유지 | 위 카운터처럼 값을 기억 |
| 데이터 은닉 | `count`를 밖에서 직접 못 건드림 |
| 콜백/이벤트 | 이벤트 핸들러가 만들어질 때의 변수 사용 |

## 실무 포인트

- **데이터 은닉에 쓸 수 있다.** 클로저 안의 변수는 밖에서 직접 접근할 수 없다. `makeCounter`의 `count`는 반환된 함수를 통해서만 바뀌므로, 외부의 무분별한 수정을 막는 "비공개 변수" 효과를 낸다.
- **반복문 속 클로저를 조심하라.** 예전 `var`로 반복문을 돌며 클로저를 만들면, 모든 클로저가 같은 변수를 공유해 마지막 값만 참조하는 함정이 있었다. `let`을 쓰면 반복마다 새 변수가 생겨 해결된다.
- **메모리 누수에 주의하라.** 클로저가 큰 데이터를 계속 참조하면 그 데이터가 메모리에서 안 지워진다. 더 이상 필요 없으면 참조를 끊어 가비지 컬렉션이 되게 한다.

## 마무리 요약

- 클로저는 함수가 자신이 선언된 곳의 변수(환경)를 기억하는 현상이다.
- 바깥 함수가 끝나도 안쪽 함수가 그 변수를 유지해, 상태 유지·데이터 은닉에 쓴다.
- 반복문 속 `var` 함정은 `let`으로 해결하고, 큰 데이터 참조로 인한 메모리 누수를 조심한다.
