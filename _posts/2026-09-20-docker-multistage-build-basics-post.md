## "이미지가 1GB나 되는데 실행 파일은 몇 MB다"

빌드에 쓴 컴파일러·의존성이 최종 이미지에 그대로 남으면 이미지가 무거워진다. **멀티스테이지 빌드**는 빌드 단계와 실행 단계를 분리해, **실행에 꼭 필요한 것만** 최종 이미지에 담는 방법이다.

## 예시: 빌드와 실행 분리

```dockerfile
# 1단계: 빌드 (무거운 도구 포함)
FROM node:20 AS builder
WORKDIR /app
COPY . .
RUN npm ci && npm run build

# 2단계: 실행 (결과물만 복사)
FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html
```

`AS builder`로 빌드 단계에 이름을 붙이고, `--from=builder`로 그 결과물만 가져온다. 컴파일러·node_modules는 최종 이미지에 남지 않는다.

## 무엇이 좋아지나

| 항목 | 효과 |
|---|---|
| 이미지 크기 | 빌드 도구 제외로 대폭 감소 |
| 보안 | 불필요한 도구가 없어 공격면 축소 |
| 배포 속도 | 작은 이미지가 빠르게 전송·기동 |

## 실무 포인트

- **실행에 필요한 것만 마지막 단계로.** 산출물(빌드 결과, 바이너리)만 복사하고 소스·빌드 도구는 버린다.
- **경량 베이스 이미지를 실행 단계에.** `alpine`·`distroless` 같은 작은 이미지를 최종 단계 베이스로 쓰면 더 가벼워진다.
- **캐시를 활용해 빌드 시간 단축.** 자주 바뀌지 않는 의존성 설치를 앞쪽 레이어에 두면 코드만 바뀔 때 캐시가 재사용된다.

## 마무리 요약

- 멀티스테이지 빌드는 빌드 단계와 실행 단계를 나눠 필요한 산출물만 최종 이미지에 담는다.
- 이미지 크기와 공격면이 줄고 배포가 빨라진다.
- 실행 단계엔 경량 베이스를 쓰고, 레이어 순서로 캐시를 활용한다.
