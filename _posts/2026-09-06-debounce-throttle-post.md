## 이벤트가 너무 자주 발생하는 문제

검색창에 타이핑할 때마다 서버에 검색 요청을 보내면, "안녕하세요"를 치는 동안 5번의 요청이 나간다. 스크롤 이벤트는 초당 수십 번 발생한다. 이 모든 이벤트에 무거운 작업(API 호출, 계산)을 붙이면 성능이 크게 나빠진다. **디바운스(debounce)**와 **스로틀(throttle)**은 이벤트 실행 횟수를 줄이는 두 가지 기법이다.

## 디바운스 vs 스로틀

| 기법 | 동작 | 비유 |
|---|---|---|
| 디바운스 | 이벤트가 멈추고 일정 시간 지난 뒤 한 번 실행 | "입력이 끝나면 그때 실행" |
| 스로틀 | 일정 시간마다 최대 한 번만 실행 | "N초에 한 번씩만 실행" |

```text
타이핑: ㅇ ㅏ ㄴ ㄴ ㅕ ㅇ (빠르게 연속)

디바운스(300ms): 마지막 입력 후 300ms 조용하면 -> 1번만 실행
스로틀(300ms):   입력하는 동안 300ms마다 -> 여러 번 실행되지만 제한됨
```

## 어디에 무엇을 쓰나

```text
[디바운스가 적합]
- 검색어 자동완성: 타이핑을 멈춘 뒤 검색 (중간 입력마다 요청 X)
- 창 크기 조절(resize) 완료 후 레이아웃 재계산
-> "마지막 결과만 중요할 때"

[스로틀이 적합]
- 무한 스크롤: 스크롤 중 일정 간격으로 위치 체크
- 실시간 진행률 표시
-> "진행 중에도 주기적으로 반응해야 할 때"
```

## 간단한 디바운스 구현

```javascript
function debounce(fn, delay) {
  let timer;
  return (...args) => {
    clearTimeout(timer);              // 이전 예약 취소
    timer = setTimeout(() => fn(...args), delay); // 새로 예약
  };
}

// 검색창에 적용
const handleSearch = debounce((query) => {
  fetch(`/api/search?q=${query}`);
}, 300);

input.addEventListener('input', (e) => handleSearch(e.target.value));
```

`clearTimeout`으로 이전 예약을 취소하고 새로 예약하는 것이 디바운스의 핵심이다. 입력이 계속되는 동안은 계속 취소·재예약되다가, 멈추면 그때 한 번 실행된다.

## 실무 포인트

- **디바운스와 스로틀을 헷갈리면 UX가 나빠진다.** 검색 자동완성에 스로틀을 쓰면 타이핑 중간 결과가 계속 뜨고, 스크롤에 디바운스를 쓰면 스크롤을 멈춰야만 반응해 답답하다. 목적에 맞게 골라야 한다.
- **직접 구현하기보다 검증된 라이브러리를 써도 좋다.** lodash의 `debounce`/`throttle`은 엣지 케이스(선행 실행, 취소 등)까지 잘 처리되어 있어 실무에서 널리 쓰인다.
- **React에서는 리렌더링과의 상호작용에 주의해야 한다.** 컴포넌트가 리렌더링될 때마다 디바운스 함수가 새로 만들어지면 제대로 동작하지 않으므로, `useCallback`이나 `useRef`로 함수를 유지해야 한다.

## 마무리 요약

- 디바운스와 스로틀은 자주 발생하는 이벤트의 실행 횟수를 줄이는 기법이다.
- 디바운스는 "이벤트가 멈춘 뒤 한 번", 스로틀은 "일정 시간마다 한 번" 실행한다.
- 검색 자동완성은 디바운스, 스크롤·진행률은 스로틀이 적합하며 목적에 맞게 골라야 한다.
