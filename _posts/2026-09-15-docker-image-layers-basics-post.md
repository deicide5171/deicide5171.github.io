## 도커 이미지는 한 덩어리가 아니다

도커 이미지는 하나의 통짜 파일이 아니라 **여러 층(레이어)이 쌓인 구조**다. Dockerfile의 각 명령(`RUN`, `COPY` 등)이 하나의 레이어를 만든다. 이 구조를 알면 빌드가 왜 빠르거나 느린지, 이미지가 왜 큰지 이해할 수 있다.

## 레이어 구조

```text
Dockerfile:
  FROM node:20        <- 베이스 레이어
  COPY package.json . <- 레이어 1
  RUN npm install     <- 레이어 2
  COPY . .            <- 레이어 3
  CMD ["node","app"]  <- (실행 명령)

각 명령이 이전 레이어 위에 새 층을 얹는다.
```

## 빌드 캐시

| 상황 | 동작 |
|---|---|
| 레이어가 안 바뀜 | 캐시 재사용(빠름) |
| 어떤 레이어가 바뀜 | 그 레이어부터 다시 빌드 |

## 실무 포인트

- **자주 바뀌는 것을 뒤에 두라.** 소스 코드(`COPY . .`)는 자주 바뀌고 의존성(`npm install`)은 덜 바뀐다. `package.json`을 먼저 복사해 `install`을 하고, 소스는 나중에 복사하면, 코드만 바꿨을 때 무거운 `install` 레이어는 캐시를 재사용해 빌드가 빨라진다.
- **레이어 수와 크기를 줄여라.** 불필요한 파일까지 `COPY`하거나 캐시·임시 파일을 남기면 이미지가 커진다. `.dockerignore`로 불필요한 파일을 제외하고, 관련 명령을 묶어 레이어를 줄인다.
- **레이어는 공유된다.** 같은 베이스 이미지를 쓰는 여러 이미지는 그 레이어를 공유해 저장 공간을 아낀다. 그래서 공통 베이스 이미지를 쓰는 것이 효율적이다.

## 마무리 요약

- 도커 이미지는 Dockerfile 명령마다 만들어진 여러 레이어가 쌓인 구조다.
- 바뀌지 않은 레이어는 빌드 캐시로 재사용되어 빌드가 빨라진다.
- 자주 바뀌는 것을 뒤에 두고 `.dockerignore`로 크기를 줄이면 효율적이다.
