## 브라우저에 데이터를 저장하는 여러 방법

로그인 상태나 사용자 설정을 유지하려면 브라우저에 데이터를 저장해야 한다. 방법이 여러 가지인데 이름이 비슷해 헷갈린다. **쿠키(Cookie)**, **로컬스토리지(localStorage)**, **세션스토리지(sessionStorage)** — 이 셋의 차이를 알면 상황에 맞게 고를 수 있다.

## 세 저장소 비교

| 항목 | 쿠키 | 로컬스토리지 | 세션스토리지 |
|---|---|---|---|
| 수명 | 만료일까지 | 지울 때까지 영구 | 탭 닫으면 사라짐 |
| 서버 전송 | 매 요청에 자동 첨부 | 전송 안 됨 | 전송 안 됨 |
| 용량 | 약 4KB | 약 5~10MB | 약 5~10MB |
| 주 용도 | 인증 토큰, 세션 ID | 사용자 설정, 캐시 | 일시적 폼 데이터 |

## 핵심 차이: 서버로 자동 전송되느냐

```text
쿠키: 브라우저가 매 요청에 자동으로 함께 보냄
  -> 서버가 "누구인지" 판단하는 인증에 적합
  -> 대신 매 요청에 실려 크기 제한이 작음(4KB)

localStorage/sessionStorage: 자바스크립트로 읽어야 서버에 보냄
  -> 서버가 몰라도 되는 클라이언트 전용 데이터에 적합
  -> 용량이 크지만 자동 전송 안 됨
```

## 무엇을 언제 쓰나

```text
- 로그인 인증 토큰 -> 쿠키(특히 HttpOnly 쿠키)
- 다크모드 설정, 최근 검색어 -> localStorage
- 여러 단계 폼의 임시 입력값 -> sessionStorage
```

## 실무 포인트

- **인증 토큰을 localStorage에 저장하면 XSS 공격에 취약하다.** 자바스크립트로 접근 가능하기 때문에, 악성 스크립트가 삽입되면 토큰을 통째로 탈취당할 수 있다. 인증 토큰은 자바스크립트로 못 읽는 **HttpOnly 쿠키**에 두는 것이 더 안전하다.
- **HttpOnly 쿠키를 쓰면 CSRF 방어를 함께 고려해야 한다.** 쿠키는 자동 전송되므로, 공격자가 사용자 몰래 요청을 보내는 CSRF 공격에 노출될 수 있다. SameSite 속성이나 CSRF 토큰으로 방어한다.
- **민감한 정보는 어느 저장소에도 평문으로 두지 마라.** 브라우저 저장소는 개발자 도구로 누구나 볼 수 있다. 비밀번호나 민감 개인정보를 그대로 저장하면 안 된다.

## 마무리 요약

- 쿠키는 매 요청에 자동 전송되어 인증에, 로컬스토리지·세션스토리지는 클라이언트 전용 데이터에 적합하다.
- 로컬스토리지는 영구 보관, 세션스토리지는 탭을 닫으면 사라진다는 수명 차이가 있다.
- 인증 토큰은 XSS에 취약한 localStorage보다 HttpOnly 쿠키에 두고, CSRF 방어를 함께 갖추는 것이 안전하다.
