## 빈은 몇 개 만들어질까

스프링에서 빈(bean)은 기본적으로 **애플리케이션에 하나만** 만들어져 공유된다. 그런데 요청마다 새로 만들어야 할 때도 있다. **빈 스코프(bean scope)**는 **빈이 언제, 몇 개 만들어지고 얼마나 유지되는지**를 정한다.

## 주요 스코프

| 스코프 | 설명 |
|---|---|
| singleton | 앱에 하나만(기본값) |
| prototype | 요청(주입)할 때마다 새로 |
| request | HTTP 요청마다 하나(웹) |
| session | HTTP 세션마다 하나(웹) |

## 싱글톤의 함정

```text
싱글톤 빈은 하나를 여러 곳이 공유한다.
-> 빈에 상태(변하는 필드)를 두면 위험!
   여러 요청이 같은 필드를 건드려 데이터가 섞인다.
-> 싱글톤 빈은 상태 없이(stateless) 설계해야 안전
```

## 실무 포인트

- **기본은 싱글톤, 상태를 두지 마라.** 대부분의 서비스·리포지토리 빈은 싱글톤이면 충분하고 효율적이다. 단, 여러 요청이 공유하므로 인스턴스 필드에 요청별 데이터를 저장하면 동시성 버그가 난다. 상태는 메서드 지역 변수나 파라미터로 다룬다.
- **prototype은 특수한 경우에만.** 매번 새 인스턴스가 필요한 드문 경우에만 prototype을 쓴다. 싱글톤 빈이 prototype 빈을 주입받으면, 처음 한 번만 받아 계속 같은 걸 쓰는 함정이 있으니 `ObjectProvider` 등으로 매번 새로 받는다.
- **웹 스코프는 웹 요청 맥락에서만.** request·session 스코프는 HTTP 요청/세션이 있어야 동작한다. 없는 곳에서 주입하면 오류가 나므로 프록시 방식으로 주입한다.

## 마무리 요약

- 빈 스코프는 빈이 언제 몇 개 만들어지고 유지되는지를 정하며, 기본은 싱글톤이다.
- 싱글톤은 하나를 공유하므로 상태(변하는 필드)를 두면 동시성 버그가 나니 stateless로 설계한다.
- prototype·request·session은 특수 상황에서 쓰며 주입 방식에 주의가 필요하다.
