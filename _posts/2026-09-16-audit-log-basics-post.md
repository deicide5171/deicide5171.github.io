## "이 데이터를 누가 지웠지?"

중요한 데이터가 바뀌거나 삭제됐는데 누가 했는지 모르면 문제가 크다. **감사 로그(audit log)**는 **누가(who), 언제(when), 무엇을(what), 어떻게 했는지**를 남기는 기록이다. 보안 사고 추적, 규제 준수, 책임 소재 확인에 쓰인다.

## 일반 로그 vs 감사 로그

| 구분 | 일반 로그 | 감사 로그 |
|---|---|---|
| 목적 | 디버깅·운영 | 책임 추적·규제 |
| 내용 | 시스템 동작 | 누가·무엇을·언제 |
| 보관 | 짧게 순환 삭제 | 길게 안전 보관 |
| 변경 | 자유롭게 | 위변조 방지 |

## 무엇을 남기나

```text
예) 관리자가 회원 정보를 삭제
{
  actor: "admin_kim",       // 누가
  action: "DELETE_USER",    // 무엇을
  target: "user_1234",      // 대상
  timestamp: "2026-09-16...", // 언제
  ip: "10.0.0.5"
}
```

## 실무 포인트

- **중요한 작업만 골라 남겨라.** 모든 걸 감사 로그로 남기면 양이 폭증하고 정작 중요한 것이 묻힌다. 권한 변경, 데이터 삭제, 결제, 로그인 등 "책임이 따르는 행위"에 집중한다.
- **위변조를 막아라.** 감사 로그는 "증거"이므로 나중에 고칠 수 없어야 한다. 추가만 가능(append-only)하게 하거나 별도 저장소·해시 체인으로 무결성을 보장한다.
- **개인정보에 주의.** 감사 로그에 비밀번호·주민번호 같은 민감정보를 그대로 남기면 로그가 유출 시 더 위험하다. 필요한 최소 정보만, 필요하면 마스킹해 남긴다.

## 마무리 요약

- 감사 로그는 누가·언제·무엇을·어떻게 했는지 남겨 책임 추적과 규제 준수에 쓰는 기록이다.
- 디버깅용 일반 로그와 달리 길게 보관하고 위변조를 막아야 한다.
- 중요한 행위만 골라 남기고, 위변조 방지와 민감정보 마스킹을 신경 써야 한다.
