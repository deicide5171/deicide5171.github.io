## 파드를 직접 만들면 관리가 안 된다

쿠버네티스에서 파드를 하나씩 직접 만들면, 파드가 죽어도 아무도 다시 만들어주지 않고 버전 업데이트도 수동이다. **디플로이먼트(Deployment)**는 **"이 앱을 파드 3개로 항상 유지하라"처럼 원하는 상태를 선언**하면, 쿠버네티스가 그 상태를 알아서 맞춰주는 리소스다.

## 디플로이먼트가 해주는 것

| 기능 | 설명 |
|---|---|
| 개수 유지 | 파드가 죽으면 자동 재생성 |
| 스케일링 | 원하는 개수로 늘리고 줄임 |
| 롤링 업데이트 | 무중단으로 새 버전 배포 |
| 롤백 | 문제 시 이전 버전으로 되돌림 |

## 선언적 방식

```text
"원하는 상태"를 적으면 쿠버네티스가 맞춘다:
  replicas: 3   -> 파드 3개 유지
  image: myapp:2.0 -> 이 버전으로

파드 하나가 죽으면 -> 자동으로 새로 만들어 3개 유지
image를 2.1로 바꾸면 -> 롤링 업데이트로 하나씩 교체
```

## 실무 포인트

- **롤링 업데이트가 기본이다.** 이미지 버전을 바꾸면 디플로이먼트가 옛 파드를 하나씩 새 파드로 교체한다. 한 번에 다 바꾸지 않아 서비스가 안 끊긴다. 문제가 생기면 `kubectl rollout undo`로 되돌린다.
- **레플리카 수와 오토스케일.** `replicas`로 고정 개수를 두거나, HPA(오토스케일러)를 붙여 부하에 따라 자동으로 파드 수를 조절할 수 있다.
- **상태 있는 앱엔 StatefulSet.** 디플로이먼트는 파드들이 서로 구분 없는(stateless) 앱에 적합하다. DB처럼 각 파드가 고유 정체성·저장소를 가져야 하면 StatefulSet을 쓴다.

## 마무리 요약

- 디플로이먼트는 원하는 상태(파드 개수·버전)를 선언하면 쿠버네티스가 맞춰주는 리소스다.
- 개수 유지, 스케일링, 롤링 업데이트, 롤백을 자동으로 해준다.
- 롤링 업데이트가 기본이며, 오토스케일과 함께 쓰고 상태 있는 앱엔 StatefulSet을 쓴다.
