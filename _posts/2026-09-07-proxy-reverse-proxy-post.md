## 둘 다 "프록시"인데 왜 다른가

프록시(proxy)는 "대리인"이라는 뜻으로, 중간에서 요청을 대신 전달해주는 서버다. 그런데 **정방향 프록시(forward proxy)**와 **리버스 프록시(reverse proxy)**는 "누구를 대신하느냐"가 정반대다. 이 방향을 이해하면 둘의 차이가 명확해진다.

## 방향의 차이

| 항목 | 정방향 프록시 | 리버스 프록시 |
|---|---|---|
| 누구를 대신 | 클라이언트(사용자) | 서버 |
| 위치 | 클라이언트 앞 | 서버 앞 |
| 대표 용도 | 사내망 접근 제어, 우회 | 로드밸런싱, SSL 종료, 캐싱 |
| 대표 예시 | 회사 프록시 서버 | Nginx, 로드밸런서 |

```text
[정방향 프록시] 클라이언트를 대신
사용자 -> 정방향 프록시 -> 인터넷(여러 서버)
(서버는 프록시가 요청한 것으로 보임 = 사용자를 가림)

[리버스 프록시] 서버를 대신
사용자 -> 리버스 프록시 -> 내부 서버들
(사용자는 프록시가 응답한 것으로 보임 = 실제 서버를 가림)
```

## 리버스 프록시가 하는 일

- **로드밸런싱**: 여러 서버로 요청을 나눠 보냄
- **SSL 종료**: HTTPS 복호화를 프록시가 담당해 뒷단 서버 부담을 덜어줌
- **캐싱**: 자주 요청되는 응답을 프록시가 캐시해 서버 부하 감소
- **보안**: 실제 서버 주소·구조를 외부에 숨김

## 실무 포인트

- **웹 서비스에서 "프록시"라고 하면 보통 리버스 프록시를 뜻한다.** Nginx를 애플리케이션 서버 앞에 두는 구성이 대표적이며, 이것이 리버스 프록시다.
- **정방향 프록시는 주로 클라이언트 쪽 통제에 쓰인다.** 회사에서 특정 사이트 접근을 막거나, 모든 외부 요청을 한 곳으로 모아 로깅·필터링하는 용도다.
- **리버스 프록시 뒤에서는 클라이언트의 진짜 IP가 가려진다.** 그래서 뒷단 서버가 실제 사용자 IP를 알려면 `X-Forwarded-For` 같은 헤더를 프록시가 넘겨주고, 서버는 그 헤더를 읽어야 한다. 이 설정을 빠뜨리면 모든 요청이 프록시 IP에서 온 것처럼 보인다.

## 마무리 요약

- 정방향 프록시는 클라이언트를 대신하고, 리버스 프록시는 서버를 대신한다 — 방향이 정반대다.
- 웹 서비스에서 로드밸런싱·SSL 종료·캐싱을 하는 Nginx 등이 대표적인 리버스 프록시다.
- 리버스 프록시 뒤에서는 클라이언트 IP가 가려지므로 `X-Forwarded-For` 헤더 처리가 필요하다.
