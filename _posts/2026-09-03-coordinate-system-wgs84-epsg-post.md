## 왜 위치가 엉뚱한 데 찍히는가

지도에 점을 찍었는데 바다 한가운데나 아프리카 어딘가에 나타나는 경험은 GIS 초보자가 거의 반드시 겪는다. 원인은 대부분 **좌표계(Coordinate Reference System)**가 서로 맞지 않아서다. 같은 "126, 37"이라는 숫자도 어떤 좌표계로 해석하느냐에 따라 완전히 다른 위치를 가리킨다.

## 알아야 할 핵심 개념

| 용어 | 의미 |
|---|---|
| 지리 좌표계 | 지구를 구/타원체로 보고 위도·경도로 위치 표현 (예: WGS84) |
| 투영 좌표계 | 둥근 지구를 평면 지도에 펼친 뒤 미터 단위로 표현 |
| EPSG 코드 | 각 좌표계에 붙은 고유 식별 번호 |

## 자주 만나는 EPSG 코드

```text
EPSG:4326 (WGS84)
  - GPS가 쓰는 위경도 좌표계. 전 세계 공통.
  - "위도 37.5, 경도 127.0" 형태. 단위는 도(degree).

EPSG:3857 (웹 메르카토르)
  - Google 지도, OSM 등 웹 지도 타일이 쓰는 투영 좌표계.
  - 단위는 미터. 위경도를 평면에 펼친 것.

EPSG:5179 (UTM-K)
  - 한국 국토지리정보원 표준 좌표계.
  - 한국 공공 데이터를 다룰 때 자주 만난다.
```

한국의 공공 데이터(연속지적도, 도로명주소 등)는 EPSG:5179 같은 국내 좌표계로 되어 있는 경우가 많아, 이를 웹 지도(EPSG:4326/3857)에 올리려면 **좌표계 변환**이 필요하다.

## 코드 예제: proj4js로 좌표 변환

```javascript
import proj4 from 'proj4';

// EPSG:5179 정의 등록 (국내 좌표계는 별도 정의가 필요)
proj4.defs('EPSG:5179',
  '+proj=tmerc +lat_0=38 +lon_0=127.5 +k=0.9996 +x_0=1000000 +y_0=2000000 +ellps=GRS80 +units=m +no_defs');

// EPSG:5179 좌표를 WGS84 위경도로 변환
const [lon, lat] = proj4('EPSG:5179', 'EPSG:4326', [1000000, 1900000]);
console.log(lon, lat); // 웹 지도에 쓸 수 있는 위경도
```

## 실무 포인트

- **위도·경도 순서 vs 경도·위도 순서 혼동도 위치 오류의 흔한 원인이다.** GeoJSON은 `[경도, 위도]`, 어떤 라이브러리는 `[위도, 경도]`를 쓰므로, 좌표계가 맞는데도 위치가 어긋나면 순서를 의심해야 한다.
- **데이터 출처에 좌표계 정보(EPSG 코드)가 명시되어 있는지 먼저 확인하라.** Shapefile은 `.prj` 파일에, GeoPackage·PostGIS는 메타데이터에 좌표계가 기록되어 있다.
- **웹 지도 라이브러리는 대부분 내부적으로 EPSG:3857을 쓰지만 입력은 EPSG:4326(위경도)으로 받는다.** 즉 위경도로 좌표를 넣으면 라이브러리가 알아서 투영하므로, 국내 좌표계 데이터만 변환해주면 되는 경우가 많다.

## 마무리 요약

- 지도에서 위치가 어긋나는 가장 흔한 원인은 좌표계 불일치이며, EPSG 코드로 어떤 좌표계인지 식별한다.
- GPS·웹 지도는 WGS84(4326)/웹 메르카토르(3857)를, 한국 공공 데이터는 EPSG:5179 등을 자주 쓴다.
- 국내 좌표계 데이터를 웹 지도에 올리려면 proj4js 등으로 좌표계 변환을 거쳐야 한다.
