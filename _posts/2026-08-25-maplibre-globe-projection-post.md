메르카토르 도법으로 그린 세계 지도에서 그린란드가 아프리카만큼 커 보이는 착시는 웹 지도를 다뤄본 사람이라면 한 번쯤 마주친 문제다. 위도가 극에 가까워질수록 면적이 왜곡되는 것은 평면에 구를 펼치는 투영법의 근본적인 한계이고, Mapbox GL JS나 MapLibre GL JS 같은 타일 기반 웹 지도 라이브러리는 오랫동안 이 왜곡을 안고 살아왔다. 줌인해서 도시 단위를 볼 때는 문제가 크지 않지만, 전 세계 항공편 경로나 글로벌 물류망처럼 지구 전체를 한눈에 보여줘야 하는 화면에서는 왜곡이 그대로 사용자에게 잘못된 인상을 남긴다.

MapLibre GL JS는 이 문제를 해결하기 위해 **globe 투영 모드**를 도입했다. 낮은 줌 레벨에서는 실제로 구체 형태로 지구를 렌더링하고, 사용자가 줌인하면 매끄럽게 익숙한 평면 메르카토르 지도로 전환된다. 이 글에서는 globe 모드가 내부적으로 어떻게 렌더링되는지, 그리고 실전에서 이 모드를 켜고 튜닝하는 방법을 정리한다.

## 핵심 개념 1: 평면 타일 위에 구를 렌더링한다는 것

MapLibre의 벡터 타일 시스템은 원래 메르카토르 좌표계를 전제로 설계됐다. 각 타일은 웹 메르카토르 투영 위의 사각형 영역이고, 줌 레벨마다 타일을 잘게 쪼개는 쿼드트리 구조도 이 평면 좌표계 위에서 정의된다. globe 모드는 이 타일 데이터 자체를 바꾸는 것이 아니라, **동일한 메르카토르 타일 데이터를 GPU 셰이더 단계에서 구면 좌표로 재투영해서 그린다.**

즉 타일링·데이터 포맷은 그대로 유지하면서, 정점 셰이더에서 평면 메르카토르 좌표를 위도·경도로 역산한 뒤 다시 3차원 구면 좌표(x, y, z)로 변환해 카메라에 투영하는 방식이다. 이 덕분에 기존 벡터 타일 소스, 스타일 스펙, 래스터 타일 소스를 그대로 재사용하면서 렌더링 결과만 구체로 바꿀 수 있고, 서버 쪽 타일 파이프라인은 전혀 손댈 필요가 없다.

## 핵심 개념 2: 줌 레벨에 따른 자동 전환

globe 모드의 핵심 UX는 "언제 구체이고 언제 평면인가"의 자연스러운 전환이다. 지구본을 멀리서 보다가 특정 지역을 줌인하면, 그 지역은 지구 표면의 극히 일부만 차지하게 되므로 구면 곡률의 시각적 영향이 사실상 사라진다. MapLibre는 이 성질을 이용해 특정 줌 레벨 임계값(대략 줌 5 부근)을 기준으로 구체 투영과 평면 메르카토르 투영을 부드럽게 블렌딩한다.

낮은 줌에서는 카메라가 구체 전체를 내려다보는 원근 투영으로 렌더링되고, 이때 극지방 근처의 타일은 화면상 픽셀 밀도가 낮아지도록 자연스럽게 압축돼 보인다 — 실제 지구본을 옆에서 보는 것과 같은 효과다. 줌인이 진행되면 카메라 시야각이 좁아지며 화면에 보이는 지표면 곡률이 평면과 거의 구분되지 않게 되고, 이 지점에서 렌더링은 기존 평면 메르카토르 방식으로 자연스럽게 수렴한다.

## 핵심 개념 3: 메르카토르 대비 무엇이 달라지는가

| 구분 | 평면 메르카토르 모드 | Globe 모드 |
|---|---|---|
| 저위도(적도 부근) 면적 왜곡 | 왜곡 없음 | 왜곡 없음(구체 자체로 표현) |
| 고위도(극지방 부근) 면적 왜곡 | 심함(그린란드 과대 표현) | 없음(실제 비율로 표현) |
| 낮은 줌에서의 전체 지구 조망 | 좌우로 무한 반복되는 평면 | 하나의 구체로 자연스럽게 표현 |
| 타일 데이터·스타일 스펙 | 표준 벡터/래스터 타일 | 동일(변경 불필요) |
| GPU 렌더링 부하 | 낮음 | 재투영 연산으로 다소 증가 |

globe 모드가 항상 유리한 것은 아니다. 실내 지도나 특정 도시 단위 서비스처럼 애초에 낮은 줌 레벨을 쓸 일이 없는 애플리케이션이라면 globe 모드의 이점을 거의 체감하지 못하면서 셰이더 연산 비용만 추가로 부담하게 된다. 전 지구적 시각화(항공 노선도, 글로벌 대시보드, 인공위성 궤도 시각화)처럼 낮은 줌 사용이 잦은 서비스에서 효과가 두드러진다.

## 예제: MapLibre GL JS에서 globe 투영 활성화

```javascript
import maplibregl from 'maplibre-gl';

const map = new maplibregl.Map({
  container: 'map',
  style: 'https://demotiles.maplibre.org/style.json',
  center: [127.5, 36.5],
  zoom: 2,
  projection: 'globe', // 'mercator'(기본값) 대신 globe 지정
});

// 런타임에 투영 모드 전환도 가능
map.on('load', () => {
  document.getElementById('toggle-projection').addEventListener('click', () => {
    const current = map.getProjection().type;
    map.setProjection({ type: current === 'globe' ? 'mercator' : 'globe' });
  });
});

// 대기(atmosphere) 효과를 추가해 지구본 가장자리에 은은한 후광 표현
map.on('style.load', () => {
  map.setSky({
    'atmosphere-blend': ['interpolate', ['linear'], ['zoom'], 0, 1, 5, 0],
  });
});
```

## 실무 포인트

- **저사양 기기에서의 성능을 반드시 확인한다**: 구면 재투영 셰이더는 모바일 GPU에서 프레임 드랍을 유발할 수 있다. 대상 사용자층이 저사양 모바일 브라우저 비중이 높다면 globe 모드를 기본값이 아니라 사용자가 켜는 옵션으로 제공하는 것도 방법이다.
- **커스텀 레이어(deck.gl, threebox 등)와의 좌표 정합을 검증한다**: 구면 좌표계로 렌더링되는 동안에도 커스텀 WebGL 레이어가 평면 메르카토르 좌표를 그대로 가정하고 있으면 위치가 어긋난다. globe 모드를 쓸 때는 커스텀 레이어가 MapLibre의 투영 API를 통해 좌표를 변환하는지 확인해야 한다.
- **애니메이션 전환 중 사용자 조작을 막지 않는다**: 줌 레벨 임계값 부근에서 투영이 자동 전환될 때 지도 팬/줌 제스처가 끊기는 느낌을 주지 않도록, 전환 애니메이션 구간에서도 입력 이벤트를 정상 처리하는지 QA 시나리오에 포함시킨다.

## 3줄 요약

- MapLibre의 globe 모드는 타일 데이터를 바꾸지 않고 GPU 셰이더에서 메르카토르 좌표를 구면 좌표로 재투영해, 기존 타일 파이프라인을 그대로 유지하면서 지구본 렌더링을 구현한다.
- 낮은 줌에서는 구체로, 높은 줌에서는 평면 메르카토르로 자연스럽게 전환되며 이는 곡률의 시각적 영향이 줌인할수록 사라진다는 성질을 이용한다.
- 전 지구적 시각화에는 효과가 크지만 도시 단위 서비스에는 이점이 적고 렌더링 비용만 늘 수 있으므로, 서비스 성격에 맞춰 선택적으로 적용해야 한다.
