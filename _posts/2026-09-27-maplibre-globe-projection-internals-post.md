## 왜 지구본 모드가 다시 주목받는가

전 세계 데이터를 다루는 대시보드나 항공·해운 노선 시각화에서는 평면 머케이터 투영의 근본적인 문제가 두드러진다. 극지방으로 갈수록 면적이 극단적으로 부풀려지고, 두 대륙을 잇는 최단 경로(대권 항로)가 지도 위에서는 부자연스럽게 휘어 보인다. Google Maps가 오래전부터 저줌 레벨에서 지구본을 보여줬지만, 오픈소스 웹 지도 라이브러리 생태계에서 이를 표준 스타일 스펙 수준으로 지원하는 것은 비교적 최근의 발전이다. MapLibre GL JS는 `projection: 'globe'` 설정 하나로 이를 활성화할 수 있게 했는데, 흥미로운 점은 이것이 완전히 별도의 3D 렌더링 엔진이 아니라 기존 벡터 타일 파이프라인을 재사용하는 영리한 설계라는 것이다.

## 핵심 개념 1 — 타일 데이터는 그대로, 투영 행렬만 바꾼다

MapLibre의 렌더링 파이프라인은 벡터 타일에서 폴리곤·라인·심볼을 GPU 버퍼로 변환한 뒤, 정점 셰이더에서 이 좌표들을 화면 공간으로 투영하는 구조다. 평면 머케이터 모드에서는 이 투영이 단순한 2D 아핀 변환(이동·회전·스케일)이었다면, Globe 모드에서는 정점 셰이더 단계에서 정규화된 머케이터 좌표(0~1 범위)를 구면 좌표(위경도를 3D 직교좌표로 변환한 값)로 다시 매핑하는 추가 연산이 들어간다. 핵심은 **타일을 가져오고 파싱하고 지오메트리를 만드는 앞단 파이프라인은 완전히 동일하다**는 것이다. 같은 벡터 타일, 같은 스타일 표현식, 같은 CustomLayer가 평면에서도 구면에서도 그대로 동작한다. 오직 정점을 화면에 배치하는 마지막 투영 단계만 달라진다.

## 핵심 개념 2 — 줌 레벨에 따른 평면-구면 보간

Globe 모드의 또 다른 핵심은 줌 레벨이 깊어질수록(사용자가 확대할수록) 화면에 보이는 지구본의 곡률이 시각적으로 감지하기 어려워진다는 사실을 이용한다는 점이다. 실제로 MapLibre는 특정 줌 레벨 임계값을 넘어서면 구면 투영과 평면 투영의 결과가 시각적으로 거의 동일해지므로, 이 근처에서 두 투영 방식을 부드럽게 보간(interpolate)해 전환한다. 사용자 입장에서는 이 전환이 렌더링 방식이 바뀌었다는 것을 눈치채지 못할 정도로 매끄럽게 일어나며, 고줌 레벨에서는 사실상 평면 투영과 동일한 성능 특성을 유지한다. 즉 저줌에서 지구본을 보여주는 매력적인 시각 효과를 얻으면서도, 실제 도시 단위 상세 지도를 그릴 때는 평면 투영의 단순함과 성능을 그대로 누리는 것이다.

| 항목 | 평면(Mercator) 투영 | Globe 투영 |
|---|---|---|
| 타일 데이터 | 동일 | 동일(재사용) |
| 스타일 표현식 | 동일 | 동일(재사용) |
| 정점 셰이더 투영 행렬 | 2D 아핀 변환 | 구면 좌표 매핑 |
| 극지방 면적 왜곡 | 심함 | 없음(구면 표현) |
| 고줌 레벨 동작 | 기본 | 평면 투영으로 자동 수렴 |

## 코드 예제 — Globe 투영 활성화와 대권 항로 표시

```javascript
const map = new maplibregl.Map({
  container: 'map',
  style: 'https://demotiles.maplibre.org/style.json',
  center: [0, 20],
  zoom: 1.5,
  projection: 'globe',   // 이 한 줄로 저줌 레벨에서 지구본 렌더링 활성화
});

map.on('load', () => {
  // 대권 항로(great circle route)는 평면에서 휘어 보이지만
  // globe 투영에서는 실제 최단 경로답게 자연스럽게 표시된다
  map.addSource('flight-route', {
    type: 'geojson',
    data: turf.greatCircle([126.9, 37.5], [-122.4, 37.7]),  // 서울-샌프란시스코
  });
  map.addLayer({
    id: 'flight-route-layer',
    type: 'line',
    source: 'flight-route',
    paint: { 'line-color': '#e0952b', 'line-width': 2 },
  });
});
```

## 실무 포인트

- **CustomLayerInterface와의 호환성을 반드시 확인하라.** 앞서 설명한 대로 앞단 파이프라인은 재사용되지만, 커스텀 WebGL 레이어가 자체적으로 좌표 변환을 하드코딩했다면 Globe 모드에서 좌표가 어긋날 수 있다. MapLibre가 제공하는 투영 유틸리티 함수를 통해 좌표를 변환해야 두 모드 모두에서 정상 동작한다.
- **극지방 근처 데이터 시각화에 특히 유용하다.** 항로, 해류, 극궤도 위성 이동 경로처럼 고위도 지역을 다루는 시각화는 평면 투영에서 왜곡이 가장 심하게 나타나므로, Globe 모드 도입의 우선순위가 가장 높은 사용 사례다.
- **모바일 기기의 GPU 성능을 고려하라.** 구면 좌표 변환은 저사양 기기에서 프레임 드랍을 유발할 수 있으므로, 초기 진입 시 저줌 오버뷰 화면에서만 Globe를 쓰고 실제 콘텐츠 탐색은 평면 투영으로 유도하는 UX 설계가 안전하다.

## 마무리 요약

- MapLibre의 Globe 투영은 별도 렌더 엔진이 아니라, 기존 벡터 타일 파이프라인 위에서 정점 셰이더의 투영 행렬만 구면 좌표 매핑으로 바꾸는 방식으로 구현됐다.
- 줌 레벨이 깊어지면 구면과 평면 투영 결과가 시각적으로 수렴하므로, 이 근처에서 두 방식을 부드럽게 보간해 전환한다.
- 극지방 데이터 시각화에 특히 효과적이지만, 커스텀 레이어 좌표 변환과 저사양 기기의 GPU 부담을 함께 고려해 도입해야 한다.
