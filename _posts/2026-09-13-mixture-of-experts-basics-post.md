## 모델이 커지면 느리고 비싸다

일반적인 LLM은 답 하나를 만들 때 **모델의 모든 파라미터**를 다 사용한다. 모델이 커질수록 정확하지만, 그만큼 계산이 느리고 비싸진다. **MoE(Mixture of Experts, 전문가 혼합)**는 **여러 '전문가' 중 일부만 골라 쓰는** 구조로, 모델은 크게 유지하면서 실제 계산량은 줄인다.

## 일반 모델 vs MoE

| 구분 | 일반(dense) | MoE |
|---|---|---|
| 사용 파라미터 | 매번 전부 | 일부 전문가만 |
| 총 크기 | - | 매우 큼 |
| 실제 계산량 | 큼 | 상대적으로 적음 |

## 동작 개념

```text
여러 개의 '전문가' 신경망 + 라우터(선택기)
입력이 들어오면:
1. 라우터가 "이 입력엔 3번, 7번 전문가가 적합"이라 판단
2. 선택된 전문가만 계산 (나머지는 쉼)
3. 결과를 합쳐 출력

-> 전체 파라미터는 많아도, 매번 쓰는 건 일부
```

## 실무 포인트

- **총 크기와 활성 파라미터가 다르다.** MoE 모델은 "전체 파라미터 수"는 매우 크지만, 한 번 추론에 실제로 쓰는 "활성 파라미터"는 훨씬 적다. 성능은 큰 모델급, 속도·비용은 작은 모델급을 노린다.
- **메모리는 여전히 많이 필요.** 계산량은 줄어도 모든 전문가를 메모리에 올려둬야 하므로, 전체 크기만큼 메모리(VRAM)가 든다. "빠르지만 메모리는 크다"가 특징이다.
- **직접 만들 일은 드물다.** MoE는 모델을 만드는 쪽의 구조 선택이다. API로 모델을 쓰는 입장에선 "왜 큰 모델인데 응답이 빠르고 저렴한가"를 이해하는 배경 지식으로 알아두면 된다.

## 마무리 요약

- MoE는 여러 전문가 중 라우터가 고른 일부만 계산해, 모델은 크게 유지하며 계산량을 줄이는 구조다.
- 총 파라미터는 크지만 매번 쓰는 활성 파라미터는 적어, 성능과 효율을 함께 노린다.
- 메모리는 전체 크기만큼 필요하며, 사용자는 배경 지식으로 알아두면 충분하다.
