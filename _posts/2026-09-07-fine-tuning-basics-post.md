## 이미 똑똑한 모델을 왜 또 학습시키나

GPT나 Claude 같은 모델은 이미 방대한 데이터로 학습되어 웬만한 건 다 한다. 그런데도 **파인튜닝(fine-tuning)**이 필요한 경우가 있다. 파인튜닝은 이미 학습된 모델(사전학습 모델)을 특정 목적·도메인·말투에 맞게 추가로 학습시키는 것이다. "처음부터 학습"이 아니라 "이미 아는 모델에 우리만의 스타일·지식을 덧입히는" 작업이다.

## 파인튜닝이 유용한 경우

| 상황 | 예시 |
|---|---|
| 특정 출력 형식·말투 고정 | 항상 우리 회사 톤앤매너로 답하게 |
| 반복되는 특수 작업 | 특정 형태의 문서를 항상 같은 구조로 분류 |
| 프롬프트로는 안 되는 미세한 스타일 | 예시를 아무리 줘도 안 잡히는 뉘앙스 |

## 파인튜닝 vs 다른 방법

```text
프롬프트 엔지니어링: 지시를 잘 쓰는 것 (가장 먼저 시도, 가장 저렴)
RAG: 외부 지식을 검색해 넣는 것 (최신·사내 정보에 강함)
파인튜닝: 모델 자체의 행동을 바꾸는 것 (말투·형식 고정에 강함)

순서: 프롬프트 -> RAG -> 그래도 안 되면 파인튜닝
파인튜닝은 데이터 준비·학습 비용이 크므로 마지막 수단에 가깝다.
```

## 파인튜닝이 흔히 오해되는 점

```text
오해: "파인튜닝하면 모델이 새 지식을 외운다"
사실: 파인튜닝은 '행동·스타일'을 바꾸는 데 강하지,
      최신 사실을 주입하는 용도로는 비효율적이다.
      최신 정보가 필요하면 RAG가 더 적합하다.
```

## 실무 포인트

- **양질의 학습 데이터가 파인튜닝의 성패를 좌우한다.** 적당히 모은 지저분한 데이터로 학습하면 오히려 성능이 나빠진다. 원하는 입출력 형태의 깨끗한 예시를 충분히 준비하는 것이 핵심이다.
- **전체 파인튜닝보다 LoRA 같은 경량 기법이 실용적이다.** 모델 전체를 학습시키는 것은 비용이 크므로, 일부 파라미터만 학습하는 경량 방식(LoRA/QLoRA)이 널리 쓰인다.
- **먼저 프롬프트·RAG로 충분한지 확인하라.** 파인튜닝은 데이터 준비·학습·버전 관리 부담이 크다. 프롬프트 개선이나 RAG로 해결되면 그것이 훨씬 저렴하고 유연하다.

## 마무리 요약

- 파인튜닝은 이미 학습된 모델에 특정 목적·말투·형식을 덧입히는 추가 학습이다.
- 최신 지식 주입에는 RAG가, 행동·스타일 고정에는 파인튜닝이 적합하다.
- 프롬프트 → RAG → 파인튜닝 순으로 시도하고, 양질의 데이터와 경량 기법(LoRA)이 실무의 핵심이다.
