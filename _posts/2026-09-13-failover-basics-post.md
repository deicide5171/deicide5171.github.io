## 서버 한 대가 죽으면 서비스도 멈추나

서버 한 대로만 서비스를 돌리면, 그 서버가 죽는 순간 서비스 전체가 멈춘다. **페일오버(failover)**는 **주 서버(active)에 장애가 나면 대기 서버(standby)로 자동 전환**해 서비스가 계속되게 하는 기법이다. 고가용성(HA)의 핵심 장치다.

## 구성 방식

| 방식 | 설명 |
|---|---|
| Active-Standby | 평소엔 주 서버만, 장애 시 대기 서버로 전환 |
| Active-Active | 둘 다 일하다 하나 죽으면 나머지가 부담 |

## 동작 흐름

```text
1. 주 서버(A)가 정상 작동, 대기 서버(B)는 준비 상태
2. 헬스 체크로 A의 상태를 계속 감시
3. A가 응답 없음(장애) 감지
4. 트래픽을 B로 전환 -> 서비스 계속
5. A 복구되면 다시 편입(또는 B가 주가 됨)
```

## 실무 포인트

- **감지와 전환이 자동이어야 한다.** 사람이 수동으로 전환하면 그 사이 서비스가 멈춘다. 헬스 체크로 장애를 자동 감지하고 자동 전환하는 구성이 진짜 페일오버다.
- **데이터 동기화가 관건.** 대기 서버가 주 서버의 최신 데이터를 갖고 있어야 전환 후에도 이어진다. DB는 복제(replication)로 동기화하는데, 복제 지연이 있으면 전환 시 일부 데이터 손실이 생길 수 있다.
- **스플릿 브레인을 조심하라.** 네트워크 문제로 두 서버가 서로 "상대가 죽었다"고 오판해 둘 다 주 서버로 동작하면 데이터가 충돌한다. 정족수(quorum)나 펜싱 같은 장치로 이를 막는다.

## 마무리 요약

- 페일오버는 주 서버 장애 시 대기 서버로 자동 전환해 서비스 중단을 막는 고가용성 기법이다.
- Active-Standby·Active-Active 구성이 있고, 헬스 체크로 감지해 자동 전환한다.
- 데이터 동기화와 스플릿 브레인 방지가 안정적 페일오버의 핵심이다.
