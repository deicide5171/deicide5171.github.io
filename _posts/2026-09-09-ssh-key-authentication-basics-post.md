## 매번 비밀번호를 치기 싫다면

서버에 SSH로 접속할 때마다 비밀번호를 입력하는 것은 번거롭고, 무차별 대입 공격에도 취약하다. **SSH 키 인증**은 비밀번호 대신 **한 쌍의 키(공개키·개인키)**로 신원을 증명한다. 한 번 설정하면 비밀번호 없이 안전하게 접속할 수 있다.

## 공개키와 개인키

| 키 | 위치 | 역할 |
|---|---|---|
| 개인키(private) | 내 PC에만 보관 | 절대 공유 금지, 신원 증명 |
| 공개키(public) | 접속할 서버에 등록 | 자물쇠 역할, 공유해도 됨 |

개인키는 나만 가진 열쇠, 공개키는 서버에 걸어두는 자물쇠라고 보면 된다. 자물쇠(공개키)는 남에게 줘도 되지만, 열쇠(개인키)는 절대 넘기면 안 된다.

## 설정 3단계

```text
1. 키 쌍 생성 (내 PC에서)
   ssh-keygen -t ed25519 -C "my@email.com"
   -> id_ed25519(개인키), id_ed25519.pub(공개키) 생성

2. 공개키를 서버에 등록
   ssh-copy-id user@server
   (또는 서버의 ~/.ssh/authorized_keys에 공개키 추가)

3. 접속
   ssh user@server   # 이제 비밀번호 없이 접속
```

## 실무 포인트

- **개인키는 절대 유출하면 안 된다.** 개인키가 새면 누구나 내 신원으로 접속할 수 있다. 깃 저장소에 실수로 커밋하지 않도록 `.gitignore`로 막고, 키에 암호(passphrase)를 걸어 이중으로 보호한다.
- **키가 여러 개면 `~/.ssh/config`로 관리한다.** 서버마다 다른 키를 쓴다면 config 파일에 호스트별 키를 지정해두면 편하다. `ssh 별칭`만으로 접속할 수 있다.
- **비밀번호 로그인은 꺼두는 것이 안전하다.** 키 인증을 설정했다면, 서버의 `sshd_config`에서 `PasswordAuthentication no`로 비밀번호 로그인을 막아 무차별 대입 공격을 원천 차단한다.

## 마무리 요약

- SSH 키 인증은 비밀번호 대신 공개키·개인키 쌍으로 서버 접속 신원을 증명한다.
- 개인키는 내 PC에만, 공개키는 서버의 `authorized_keys`에 등록한다.
- 개인키 유출을 막고(암호 설정·gitignore), 키 인증 후엔 비밀번호 로그인을 꺼두면 더 안전하다.
