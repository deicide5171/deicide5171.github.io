## "인덱스를 탔는데도 느리다?"

인덱스로 원하는 행을 찾아도, 그 행의 나머지 컬럼을 읽으려면 다시 테이블 본체를 뒤진다(테이블 접근). 이 추가 접근을 없애는 것이 **커버링 인덱스(covering index)**다. 쿼리에 필요한 컬럼이 **인덱스 안에 다 들어 있으면** 테이블을 볼 필요가 없다.

## 어떻게 동작하나

```sql
-- 이 쿼리에 필요한 컬럼: user_id, name
SELECT name FROM users WHERE user_id = 100;

-- (user_id, name)를 함께 담은 인덱스
CREATE INDEX idx_cover ON users (user_id, name);
-- → user_id로 찾고, name도 인덱스에 있어 테이블 접근 불필요
```

인덱스가 조회 조건(`user_id`)과 가져올 값(`name`)을 모두 "커버"하므로, 테이블 본체를 읽지 않고 결과가 나온다.

## 일반 인덱스와 비교

| 구분 | 테이블 접근 |
|---|---|
| 일반 인덱스 | 인덱스로 위치 찾고 → 테이블에서 나머지 컬럼 읽음 |
| 커버링 인덱스 | 인덱스만으로 결과 완성(테이블 접근 없음) |

## 실무 포인트

- **자주 쓰는 조회에만.** 인덱스에 컬럼을 많이 넣으면 인덱스가 커지고 쓰기가 느려진다. 빈번한 핵심 쿼리에 한해 적용한다.
- **SELECT * 는 커버가 어렵다.** 모든 컬럼을 다 인덱스에 넣을 순 없으니, 꼭 필요한 컬럼만 조회하는 쿼리에서 효과가 크다.
- **컬럼 순서가 중요.** 조건에 쓰는 컬럼을 앞에, 가져올 컬럼을 뒤에 두는 식으로 인덱스 설계를 맞춘다.

## 마무리 요약

- 커버링 인덱스는 쿼리에 필요한 컬럼을 인덱스에 모두 담아 테이블 접근을 없앤다.
- 조건 컬럼과 조회 컬럼을 함께 인덱스에 넣어 "커버"하게 만든다.
- 인덱스 비대화·쓰기 부담이 있으니 빈번한 핵심 쿼리에만 적용한다.
